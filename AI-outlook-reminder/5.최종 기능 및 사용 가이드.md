# 최종 기능 및 사용 가이드

> 여기서 ‘최종’은 **2026-10-08까지 구현한 로컬 PoC**를 뜻한다. 회사 배포가 완료된 제품은 아니다. 메일을 분석해 할 일을 로컬 웹에 보여 주며 **Microsoft To Do는 사용하지 않는다.**

관련 문서: [[3.현재 구현 내용]] · [[4.테스트 및 검증 결과]]

## 1. 무엇을 할 수 있나

| 기능 | 사용자가 얻는 결과 |
|---|---|
| 자동·수동 메일 분석 | 새로 들어온 메일에서 놓치면 안 되는 업무 확인 |
| 요약과 판단 근거 | 왜 회신·처리가 필요한지 원문 근거와 함께 확인 |
| 업무 분류 | 처리할 업무, 확인 필요, 완료, 제외 목록으로 정리 |
| 기한 표시 | 언제까지 해야 하는지 확인. 모호하거나 없는 기한도 구분 |
| 업무별 알림 | 기본 하루 전 또는 직접 지정한 시각에 웹 알림 |
| 완료 처리 | 실제 처리한 업무를 완료 목록으로 이동 |
| 모델 변경 | 사용할 LLM 서버 주소·키·모델을 직접 설정 |

**실제 답장·서류 작성·청구 처리는 Outlook이나 기존 업무 시스템에서 한다.** 이 앱의 완료 버튼이 메일을 보내거나 실제 업무를 수행하지는 않는다.

## 2. 설치와 실행

Windows, Python 3.12 이상, 최신 브라우저가 필요하다. 실제 연결에는 인터넷과 Microsoft 사서함·앱 Client ID·LLM API 키가 필요하다.

최초 설치:

```powershell
cd C:\Users\염정운\project\AI-outlook-reminder
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m outlook_reminder
```

이후 실행은 마지막 명령만 사용한다. 테스트 도구가 필요 없다면 설치 시 `".[test]"` 대신 `.`을 사용할 수 있다.

브라우저에서 [로컬 앱 열기](http://localhost:8765/)로 접속한다. 서버를 실행한 터미널은 사용 중 켜 둔다. 종료할 때는 터미널에서 `Ctrl+C`를 누른다. 포트가 사용 중이면 실행 명령 뒤에 `--port 8766`을 붙이고 해당 포트로 접속한다.

### 계정 없이 시연하기

실제 연결 설정이 없는 첫 실행은 목업 모드다. ‘합성 메일 수신 테스트’에서 사례를 추가하고 ‘지금 가져와서 분석’을 누르면 업무·기한·알림·완료를 시험할 수 있다. **모의 LLM이므로 실제 모델 정확도를 평가하는 모드는 아니다.** 실제 연결 설정을 저장한 이후에는 재실행해도 실제 계정 모드로 열린다.

## 3. Microsoft 계정 최초 연결

### 관리자·개발자 준비

1. Microsoft Entra에 앱을 등록한다. 개인 시험은 개인 Microsoft 계정을 지원하도록 설정한다.
2. 모바일 및 데스크톱 앱의 리디렉션 URI를 `http://localhost`로 설정한다.
3. Application (client) ID를 확인한다. **Client secret은 필요 없다.**
4. Graph 위임 권한 `User.Read`, `Mail.Read`를 준비한다.

현재 기능은 메일 발송·수정, To Do, 캘린더 권한이나 Copilot 라이선스를 요구하지 않는다. 회사 계정은 조직 정책에 따라 관리자 승인이 필요하며, 개인 계정 시험만으로 회사 사용 가능 여부가 확인되지는 않는다.

### 사용자 연결

1. 웹의 **Microsoft Graph 연결 설정**을 연다.
2. Client ID와 계정 종류를 입력한다.
3. ‘Microsoft 로그인·연결 확인’에서 로그인하고 권한 동의를 완료한다.
4. 연결 상태를 확인한 뒤 LLM 설정을 진행한다.

**Gmail 주소로 Microsoft에 로그인해도 Graph가 Gmail을 읽는 것은 아니다.** 시험 메일은 같은 Microsoft 계정에 연결된 실제 Outlook 수신 주소로 보낸다. 로그인 주소와 Outlook 별칭이 달라도 사용할 수 있다.

## 4. LLM 설정과 시작

**LLM 프로바이더 설정**에 다음을 입력한다.

| 입력 | 설명 |
|---|---|
| 기본 API 주소 | 예: `https://codex-lb.zen-ai.co.kr/v1`, `https://api.deepseek.com` |
| 모델 ID | 해당 서버가 제공하는 정확한 ID. LB 검증 모델은 `gpt-6.1-sol` |
| API 키 | 사용자가 발급받은 키를 키 입력란에 직접 입력 |

지원 대상은 **HTTPS OpenAI 호환 Chat Completions 및 JSON 응답 모드**다. 기본 주소 뒤의 `/chat/completions`는 앱이 붙이므로 직접 덧붙이지 않는다. 모델 목록은 자동 조회하지 않는다.

저장만으로 유료 호출하지 않는다. 설정을 저장하면 모니터링이 일시 중지되므로 전송 대상과 비용 안내를 확인한 뒤 **모니터링 시작**을 누른다.

- 같은 주소에서 키를 비워 저장하면 기존 저장 키를 유지한다.
- 주소를 바꾸면 기존 키를 넘기지 않으므로 새 키를 입력해야 한다.
- 분석 중에는 설정을 변경할 수 없다.
- 모델·프롬프트가 바뀌어도 과거 결과를 자동 재분석하지 않는다.

**최초 모니터링 시작 시각 이후 메일만 대상이다.** 연결 버튼을 누른 시각이나 앱을 처음 설치한 시각과 구분한다.

## 5. 매일 사용하는 순서

1. 앱을 실행한다. 모니터링 활성 상태가 저장되어 있으면 수집을 재개한다.
2. 급히 확인하려면 **지금 가져와서 분석**을 누른다. 그 외에는 30분마다 자동 실행한다.
3. **처리할 업무**와 **확인 필요**를 열어 요약·원문 근거·기한을 확인한다.
4. 필요하면 업무별 알림 시각을 바꾼다.
5. Outlook 등에서 실제 업무를 처리하고 앱에서 **완료 처리**한다.

| 목록 | 확인할 내용 |
|---|---|
| 처리할 업무 | 명확한 요청에 따라 직접 수행할 행동 |
| 확인 필요 | 조건·담당자·기한 등 추가로 확인해야 할 근거 |
| 완료한 업무 | 사용자가 완료 표시한 항목 |
| 제외된 메일 | 업무가 아니라고 분류된 메일. 누락 의심 시 판단 근거 확인 |

재시작해도 수집 기준은 초기화되지 않는다. 중지 중 들어온 메일도 재개 후 처리할 수 있다. ‘수집 일시 중지’는 기존 알림 예약까지 끄는 버튼이 아니다.

## 6. 기한과 알림 사용

처리할 업무·확인 필요 모두 **확정 마감 하루 전 알림**이 기본이다.

| 예시 | 알림 |
|---|---|
| 10월 9일 18:00 마감 | 10월 8일 18:00 |
| 10월 9일, 시간 없음 | 10월 8일 09:00, 한국 시간 |
| 기한 없음·미확정 | 자동 예약 없음. 원하는 미래 시각 직접 입력 |

업무 상세의 **이 업무의 알림**에서 날짜·시간을 지정하고 ‘시각 저장’을 누른다. ‘기한 1일 전 알림’은 기본 방식으로 복귀하고, ‘알림 끄기’는 해당 예약을 해제한다.

후속 메일로 기한 변경 제안이 생기면 확인 후 ‘변경된 기한 적용’을 누른다. 기한 연동 알림은 재계산하지만 사용자가 직접 지정한 알림은 유지한다. 알림 시각을 바꾸는 것은 업무 마감일 자체를 수정하는 기능이 아니다.

**알림은 웹 팝업·배너·알림 센터에 한 번 표시한다.** Windows 우측 하단 알림과 일정 간격 반복 알림은 아직 없다. 이미 표시한 팝업은 같은 브라우저에서 새로고침해도 반복 표시를 줄이며, 발생 내역은 알림 센터에서 확인한다.

브라우저만 닫고 서버가 켜져 있으면 발생 내역을 저장한다. PC·서버가 꺼져 있으면 정시에 처리할 수 없고 다음 실행에서 지난 예약을 안내한다. 완료 처리 후 되돌린 업무는 필요하면 알림을 직접 다시 켠다.

## 7. 사용 중 확인 사항

| 상황 | 확인 방법 |
|---|---|
| 새 메일이 나오지 않음 | 실제 Outlook 수신 주소, 받은편지함, 최초 모니터링 시작 이후 수신 여부 확인 |
| 키 저장 후 분석하지 않음 | 설정 저장 시 일시 중지되므로 모니터링 재시작 |
| LLM 오류 | 주소·모델 ID·키·쿼터와 JSON 모드 호환성 확인. 모든 실패가 키 오류는 아님 |
| 기존 메일 분류가 그대로임 | 이미 처리한 메일은 자동 재분석하지 않음 |
| 기한이 없거나 확인 필요로 표시됨 | 원문 근거·조건·날짜 충돌 확인. 필요한 알림은 직접 지정 |
| 완료했는데 알림 내역이 남음 | 완료는 향후 예약 해제이며 기존 발생 기록은 유지 |
| 메일과 앱 시각이 다름 | Outlook 시간대 확인. 앱은 한국 시간 기준 |

## 8. 운영 전 알아둘 점

키·로그인 토큰은 Windows DPAPI로 보호하지만 **메일과 분석 결과는 로컬 SQLite에 평문 저장**된다. 데이터는 `%LOCALAPPDATA%/AIOutlookReminder`에 있으므로 DB 공유·백업 시 업무메일이 포함된다는 점을 고려한다.

실제 분석은 메일 내용을 외부 LLM 서버로 전송한다. 회사 도입 전 외부 전송 허용 여부와 공급자 보관 정책·비용을 확인해야 한다. 현재는 회사 배포·첨부파일·공동메일함·다중 사용자·24시간 서버 운영을 구현하지 않았다.

개인 계정의 실제 수집·분석·화면 표시 검증은 완료했으며, 상세한 시험 범위와 미검증 사항은 [[4.테스트 및 검증 결과]]를 참고한다.
