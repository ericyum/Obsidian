# Superpowers

**기준일:** 2026-09-01  
**대상 환경:** Codex Plugin과 Software 개발 작업

## 1. Superpowers란?

Superpowers는 Coding Agent가 Software 개발 작업을 일정한 절차로 수행하도록 돕는 오픈소스 Plugin이다.

별도의 AI Model이나 Coding IDE가 아니라 Codex 같은 Agent에 다음 Workflow를 추가한다.

```text
아이디어와 요구사항 확인
→ 설계 합의
→ 구현 계획
→ Test 중심 구현
→ Debugging과 검증
→ 결과 Review
```

핵심 목적은 Agent가 요청을 받자마자 코드를 수정하면서 요구사항을 놓치는 일을 줄이고, **설계·구현·검증 사이에 명확한 확인 단계**를 두는 것이다.

## 2. 핵심 기능

| Skill | 역할 |
|---|---|
| `brainstorming` | 요구사항과 제약을 확인하고 구현 전에 설계를 합의 |
| `writing-plans` | 승인된 설계를 파일·Task·Test 단위의 구현 계획으로 변환 |
| `executing-plans` | 작성된 Plan을 검토하고 단계별로 실행·검증 |
| `test-driven-development` | 실패 Test를 먼저 만들고 최소 구현으로 통과 |
| `systematic-debugging` | 증상부터 수정하지 않고 원인을 조사한 뒤 해결 |
| `verification-before-completion` | 완료를 주장하기 전에 Test와 명령 결과를 직접 확인 |
| `requesting-code-review` | 구현 결과가 요구사항과 품질 기준을 충족하는지 검토 요청 |
| `receiving-code-review` | Review 의견을 코드와 대조한 뒤 타당한 내용만 반영 |
| `dispatching-parallel-agents` | 서로 독립적인 작업을 여러 Agent에 분리 |

## 3. 대표적인 작업 흐름

```mermaid
flowchart LR
    U[사용자 요청] --> B[brainstorming]
    B --> S[설계 승인·spec]
    S --> W[writing-plans]
    W --> P[구현 plan]
    P --> E[executing-plans]
    E --> T[Test·구현]
    T --> V[verification]
    V --> R[결과 보고]
```

모든 작업이 긴 spec과 plan을 필요로 하는 것은 아니다.

| 분류 | 의미 | 진행 방식 |
|---|---|---|
| Spike | 가능성 조사 | 조사 계획 승인 후 최소 비용으로 확인 |
| Bounded | 기존 코드의 작은 변경 | 짧은 설계와 승인 후 구현 |
| Architectural | 새 시스템·큰 구조 변경 | 설계 spec과 구현 plan 작성 후 실행 |

작업의 크기와 상관없이 **설계 또는 수정 방향을 사용자에게 확인받기 전에는 구현하지 않는 것**이 `brainstorming`의 핵심이다.

## 4. 설치 방법

Codex의 Plugin 화면에서 다음 순서로 설치한다.

```text
1. Plugin 화면 열기
2. Superpowers 검색
3. Superpowers 상세 화면 열기
4. “설치” 선택
5. 필요한 Skill 활성화 확인
6. 새 채팅 시작
```

설치 후 새 채팅을 열어야 Bundled Skill이 정상적으로 로드된다.

## 5. 사용하는 방법

### 5-1. 일반 요청에서 자동 적용

요청 내용이 Skill의 목적과 일치하면 Codex가 필요한 Superpowers Skill을 자동으로 선택할 수 있다.

```text
회의록 Agent에 새로운 기능을 추가하고 싶어.
구현 전에 요구사항과 설계부터 같이 정리해줘.
```

이와 같은 요청에는 `brainstorming`이 먼저 적용되는 것이 적절하다.

### 5-2. Plugin 전체 선택

Codex 입력창에서 `@`를 입력해 Superpowers Plugin 전체를 선택할 수 있다.

```text
@Superpowers 새로운 기능의 설계부터 구현까지 도와줘.
```

### 5-3. 특정 Skill 직접 호출

특정 Skill을 반드시 사용하려면 `/` 목록에서 Superpowers의 Namespaced Skill을 선택한다.

```text
/Superpowers:Brainstorming 새로운 요약 기능의 요구사항과 설계를 정리해줘.
```

```text
/Superpowers:WritingPlans 승인된 spec을 기준으로 구현 계획을 작성해줘.
```

```text
/Superpowers:ExecutingPlans 작성된 구현 계획을 단계별로 실행해줘.
```

Codex Version이나 UI에 따라 표시 이름이 달라질 수 있으므로 직접 외워 입력하기보다 `/` 명령 목록에서 실제로 표시되는 Skill을 선택하는 것이 가장 확실하다.

## 6. `AGENTS.md`, specs, plans와의 관계

Superpowers와 프로젝트 문서는 서로 다른 역할을 가진다.

| 구성요소 | 역할 |
|---|---|
| `AGENTS.md` | 저장소에서 항상 지켜야 할 목적·보안·Test·Git 규칙 |
| `docs/superpowers/specs` | `brainstorming`에서 합의한 설계와 요구사항 |
| `docs/superpowers/plans` | 승인된 spec을 구현 가능한 Task로 분해한 계획 |
| Superpowers Skills | 설계·계획·구현·검증 문서를 만드는 작업 절차 |

```text
AGENTS.md
→ 모든 작업에 적용되는 프로젝트 규칙

brainstorming
→ 합의된 설계
→ docs/superpowers/specs

writing-plans
→ 구현 계획
→ docs/superpowers/plans

executing-plans
→ 코드·Test·검증 결과
```

`AGENTS.md`는 Session 시작 시 Codex가 읽는 프로젝트 지침이다. 반면 specs와 plans의 모든 파일이 자동으로 읽힌다고 가정하지 않고, 새 작업에서는 관련 문서 경로를 요청에 명시하는 것이 안전하다.

## 7. 프로젝트 방침이 우선하는 경우

Superpowers의 기본 Workflow에는 Branch, Git worktree, Commit과 PR 관련 단계가 포함될 수 있다. 그러나 사용자 요청이나 프로젝트의 `AGENTS.md`에 별도 방침이 있으면 그 방침을 우선한다.

현재 회의록 Agent POC의 예:

```text
- 현재 작업 Directory에서 작업
- 별도 Branch와 worktree를 만들지 않음
- 사용자 요청 없이 Commit하지 않음
- PR과 Draft PR을 만들지 않음
```

이러한 예외는 Superpowers를 끄는 것이 아니다. 설계·Test·Debugging·검증 Workflow는 사용하면서 Git 실행 방식만 프로젝트에 맞게 조정하는 것이다.

## 8. 새 채팅에서 사용하는 예

자동 적용을 기대하는 방식:

```text
AGENTS.md와 관련 spec을 읽어줘.
회의록 Agent에 새로운 기능을 추가하려고 하니 구현 전에 설계부터 정리해줘.
```

Skill을 명시하는 방식:

```text
/Superpowers:Brainstorming

AGENTS.md와 docs/superpowers/specs의 관련 문서를 읽고,
새로운 기능의 요구사항과 설계를 정리해줘.
```

설계 승인 후:

```text
/Superpowers:WritingPlans

승인된 spec을 기준으로 구현 계획을 작성해줘.
AGENTS.md의 Git 작업 방침을 따라줘.
```

## 9. 핵심 정리

> Superpowers는 Coding Agent가 아이디어를 곧바로 구현하지 않고, 요구사항 확인·설계 승인·구현 계획·Test·Debugging·검증을 일관된 Workflow로 수행하도록 돕는 Plugin이다. 일반 요청에서 필요한 Skill이 자동으로 적용될 수 있으며, Plugin 전체는 `@Superpowers`, 특정 Skill은 `/Superpowers:Brainstorming` 같은 Namespaced 명령으로 선택할 수 있다. `AGENTS.md`는 프로젝트의 상시 규칙이고, specs와 plans는 Superpowers Workflow가 남기는 설계·구현 산출물이다.
