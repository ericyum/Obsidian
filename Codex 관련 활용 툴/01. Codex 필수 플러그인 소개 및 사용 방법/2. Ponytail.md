# Ponytail
**기준일:** 2026-09-01  
**대상 환경:** Codex의 플러그인 화면과 `zen-ai-meeting-agent-test`

## 1. Ponytail이란?

Ponytail은 AI Coding Agent가 필요 이상으로 많은 코드, 추상화와 의존성을 만들지 않도록 안내하는 오픈소스 Plugin이다.

핵심 목적은 다음과 같다.

> 문제와 기존 코드를 충분히 이해한 뒤, 요구사항을 만족하는 가장 작은 안전한 구현을 선택한다.

Ponytail은 별도의 AI Model이나 Coding IDE가 아니다. Codex 같은 Coding Agent에 최소 구현 원칙, 검토 Skill과 Lifecycle Hook을 추가한다.

## 2. Ponytail의 핵심 기능

### 2-1. 최소 구현 Ladder

코드를 작성하기 전에 다음 순서로 판단한다.

```text
1. 이 기능이 정말 필요한가?
2. 현재 코드베이스에 이미 같은 구현이나 Pattern이 있는가?
3. 표준 라이브러리로 해결할 수 있는가?
4. OS·Browser·Framework의 기본 기능으로 해결할 수 있는가?
5. 이미 설치된 의존성으로 해결할 수 있는가?
6. 한 줄 또는 더 작은 변경으로 충분한가?
7. 그 어느 것도 아니면 동작하는 최소 코드를 작성한다.
```

최소 구현은 Code Golf를 뜻하지 않는다. 다음 항목은 줄이거나 생략하지 않는다.

- 보안과 권한 검증
- 오류 처리와 데이터 손실 방지
- 접근성
- 사용자 요구사항
- 필요한 테스트와 검증

### 2-2. Mode와 검토 Skill

| 기능 | 역할 |
|---|---|
| `ponytail` | `lite`, `full`, `ultra`, `off` Mode 선택 |
| `ponytail-review` | 현재 변경사항에서 과잉 구현을 찾아 검토 |
| `ponytail-audit` | 저장소 전체의 과잉 구현을 점검 |
| `ponytail-debt` | 미뤄둔 최소화 관련 부채 확인 |
| `ponytail-gain` | Ponytail의 측정 결과 확인 |
| `ponytail-help` | 사용 가능한 기능과 사용법 확인 |

Plugin의 Lifecycle Hook은 Ponytail 규칙을 Session과 Prompt 흐름에 맞춰 다시 적용한다.

## 3. Codex 화면에서 설치하는 방법

이 환경에서는 Codex CLI를 별도로 설치하지 않고 Plugin 화면에서 다음 순서로 설치할 수 있음을 직접 확인했다.

```text
1. 플러그인 화면의 “추가”
2. “플러그인 마켓플레이스 추가”
3. 출처: DietrichGebert/ponytail
4. Git ref: main
5. Sparse 경로: 비움
6. “마켓플레이스 추가”
7. Ponytail 검색
8. “설치”
```

입력값을 표로 정리하면 다음과 같다.

| 항목 | 입력값 |
|---|---|
| 출처 | `DietrichGebert/ponytail` |
| Git ref | `main` |
| Sparse 경로 | 빈 값 |

Ponytail 저장소 전체가 Plugin Package이므로 `plugins/codex` 같은 Sparse 경로를 입력하지 않는다.

설치가 끝나면 Codex를 새로고침하거나 다시 시작하고 **새 채팅**을 연다. Hook 실행에 대한 신뢰·승인 요청이 나타나면 실행 내용을 검토한 뒤 허용한다.

## 4. 사용하는 방법

### 4-1. 일반 작업에 자동 적용

Plugin이 활성화된 새 채팅에서 평소처럼 Coding 작업을 요청한다.

```text
현재 구현을 재사용하면서 이 기능을 가장 작은 변경으로 추가해줘.
기존 보안과 테스트 조건은 유지해줘.
```

Ponytail은 요청에 맞는 최소 구현 원칙을 적용한다.

### 4-2. 명시적으로 호출

Codex 화면에서는 **Plugin 전체 선택**과 **Plugin 안의 특정 Skill 호출** 문법이 다르다.

| 목적 | 호출 방식 |
|---|---|
| Ponytail Plugin 전체를 선택 | `@ponytail` |
| Ponytail의 특정 Skill을 직접 실행 | `/Ponytail:<SkillName>` |

`@ponytail`은 Ponytail Plugin 전체를 현재 요청에 사용하도록 선택하는 방식이다.

예시:

```text
@ponytail 이 작업에 Ponytail 원칙을 적용해줘.
```

Review처럼 Plugin 안의 특정 Skill을 명시적으로 실행할 때는 `/` 명령 목록에서 Namespaced Skill을 선택한다.

```text
/Ponytail:PonytailReview 현재 변경사항에 불필요한 추상화나 의존성이 있는지 검토해줘.
```

```text
/Ponytail:PonytailAudit 이 저장소 전체에서 과잉 구현된 부분을 점검해줘.
```

다른 Bundled Skill도 같은 방식으로 `/`를 입력한 뒤 화면에 표시되는 Ponytail Skill을 선택한다. Codex Version이나 UI에 따라 표시 이름이 달라질 수 있으므로 명령을 직접 외워 입력하기보다 Slash 명령 목록에서 선택하는 것이 가장 확실하다.

Mode의 의미는 다음과 같다.

| Mode | 의미 |
|---|---|
| `lite` | 최소 구현 원칙을 가볍게 적용 |
| `full` | 기본 강도로 적용 |
| `ultra` | 과잉 구현을 더 엄격하게 점검 |
| `off` | Ponytail 적용 중지 |

### 4-3. 설치 확인

새 채팅에서 다음을 확인한다.

- Plugin 설치 목록에 Ponytail이 나타난다.
- `@` 입력 시 Plugin 전체를 선택하는 `ponytail`이 나타난다.
- `/` 입력 시 `/Ponytail:PonytailReview` 같은 Bundled Skill이 나타난다.
- Ponytail Help Skill을 선택하면 사용 가능한 기능을 설명한다.
- 구현 요청 시 기존 코드와 표준 기능을 먼저 재사용하는지 확인한다.

## 5. 현재 회의록 Agent POC에서의 적용

현재 POC에는 두 계층으로 Ponytail 원칙이 적용된다.

```text
Ponytail Plugin
└─ Mode·Skill·Hook 제공

프로젝트 AGENTS.md
└─ POC에 맞게 축약한 Ponytail 최소 구현 원칙을 상시 제공
```

프로젝트 경로:

```text
C:\Users\염정운\project\zen-ai-meeting-agent-test
```

`AGENTS.md`의 프로젝트 지침은 Ponytail을 사용하더라도 유지한다. 특히 다음 항목은 최소 구현을 이유로 축소할 수 없다.

- 회의록 Agent 설계 불변 조건
- API Key와 회의록 원문의 보안
- Backend 권한 검증
- 오류 처리와 데이터 손실 방지
- 지정된 테스트와 검증
- 사용자의 Git 작업 방침

## 6. 핵심 정리

> Ponytail은 Coding Agent가 요구사항보다 큰 구조를 만들지 않고, 기존 코드·표준 기능·기존 의존성을 우선 사용해 가장 작은 안전한 구현을 선택하도록 돕는 Plugin이다. 이 환경에서는 Codex의 Plugin Marketplace 추가 화면에 `DietrichGebert/ponytail`, Git ref `main`, 빈 Sparse 경로를 입력해 CLI 없이 설치할 수 있다. 설치 후 새 채팅에서 자동으로 사용하거나, Plugin 전체는 `@ponytail`, 특정 Skill은 `/Ponytail:PonytailReview` 같은 Namespaced 명령으로 선택해 사용한다.
