# AGENTS.md의 개념과 작성 방법

## 1. 개념

`AGENTS.md`는 Codex가 프로젝트에서 작업하기 전에 읽는 **프로젝트 지침 파일**이다. Claude Code의 `CLAUDE.md`와 같은 계층으로 볼 수 있으며, Codex Harness를 저장소의 목적과 규칙에 맞게 조정하는 대표적인 하네스 엔지니어링 산출물이다.

`AGENTS.md` 자체가 Harness 전체는 아니다. Codex라는 Harness에 프로젝트 맥락, 금지사항과 검증 기준을 공급하는 구성요소다.

## 2. 무엇을 작성하는가

| 영역 | 작성 예시 |
|---|---|
| 프로젝트 목적 | 이 저장소가 제품인지 POC인지 |
| 기술 경계 | Python 버전, Framework, 실제 코드와 대역 |
| 구현 원칙 | State 소유권, 보안 불변 조건, Naming |
| 테스트 | 기본 테스트 명령, 완료 기준 |
| 문서화 | 코드 변경 시 함께 갱신할 문서 |
| Git 방침 | Branch·worktree·Commit·PR 허용 여부 |
| 안전 | API 키, 개인정보, 파괴적 명령 처리 |

## 3. 탐색과 적용 범위

Codex는 실행을 시작할 때 프로젝트 루트에서 현재 작업 디렉터리까지 `AGENTS.md` 계열 파일을 탐색해 지침 Chain을 만든다. 하위 디렉터리의 지침이 더 구체적인 범위에 적용될 수 있다.

```text
~/.codex/AGENTS.md              전역 기본 지침
└─ project/AGENTS.md            저장소 전체 지침
   └─ src/service/AGENTS.md     특정 하위 영역 지침
```

현재 세션 도중 새로 만든 `AGENTS.md`는 세션 시작 시 자동 주입되지 않았을 수 있다. 새 세션을 열거나 현재 요청에서 파일을 직접 읽으라고 지시하면 안전하다.

## 4. 좋은 작성 원칙

- 저장소 전반에 반복 적용할 규칙만 적는다.
- 모호한 가치보다 검증 가능한 행동을 적는다.
- 사용 가능한 정확한 명령과 경로를 제시한다.
- 특정 기능의 긴 설계는 specs로 분리한다.
- 일시적인 작업 지시는 현재 대화나 plan에 둔다.
- 규칙이 충돌할 때의 우선순위와 예외를 명확히 한다.

## 5. 예시

```md
# 프로젝트 작업 지침

## 목적
- 이 저장소는 Python·LangGraph 기반 독립 POC다.

## 보안
- API 키와 회의록 원문을 소스와 Trace에 저장하지 않는다.

## 테스트
- 변경 후 `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`를 실행한다.

## Git
- 별도 worktree와 Branch를 생성하지 않는다.
- 사용자의 요청 없이 Commit하거나 PR을 만들지 않는다.
```

## 6. `AGENTS.md`에 넣지 않을 내용

- 특정 기능의 상세 Graph 설계 전체
- 일회성 명령 결과
- 실제 API 키와 비밀 값
- 완료된 Task의 세세한 작업 일지
- 특정 날짜에만 유효한 임시 계획

이러한 내용은 spec, plan, 보안 저장소 또는 작업 기록에 나누어 둔다.
