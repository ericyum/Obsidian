## 2. CU 계산 공식

```
CU = 1.90385 × ( INPUT_TOKENS × inTok/1000 + OUTPUT_TOKENS × outTok/1000
                 [+ WRITE_CACHED × wTok/1000 + READ_CACHED × rTok/1000 ] )
```

- **1 GenAI Token = 1.90385 CU** (현재 계산기 preload 역추출 상수. SAP 공식 문서 명시 아님). Note 3437766 GenAI Token 단가 == 계산기 INPUT/OUTPUT_TOKENS.
- 주의: **INPUT_TOKENS(SAP GenAI 토큰율) ≠ 공식 API USD 단가**. 두 축 독립.
- **모델 availability 최종 기준 = Model Discovery Endpoint**(`/v2/lm/scenarios/foundation-models/models`). 본 문서의 계산기·Note는 시점 기준이며, 등록 여부 충돌 시 Discovery Endpoint가 우선. Gemini 3.1 Flash-Lite 이중 등록(§3-1 주의)처럼 계산기 내 데이터 정합성 문제는 Discovery Endpoint로 최종 확인 필요.

## 6. 프롬프트 캐싱 효과 (예시: Claude Opus 4.7, 8턴)

- 캐시쓰기 1.25× 입력, 캐시읽기 0.1× 입력. 8턴, 매턴 5k 신규, 컨텍스트 10k→45k, 출력 3k/턴(누적입력 ~220k, 이 중 200k 캐시 적중 가정).
- **캐싱 작동(SAP 프로바이더 경유)**: 현재 SAP AI Core에서 각 프로바이더(OpenAI·Anthropic·Google) 캐싱 기능 사용 확인, 계산기에도 READ_CACHED/WRITE_CACHED 요율 존재. OpenAI=암시적(자동), Anthropic=명시적(`cache_control`), Gemini=`cached_content`. 중간 Orchestration 레이어 존재 → 지원 범위·동작은 SAP 릴리스 따라 변동 가능.
- **캐싱 미지원 모델**: Gemini 3.5 Flash·3.1 Flash-Lite는 계산기 READ_CACHED=0 → SAP 경유 캐싱 효과 없음(공식 API 직접은 Gemini 자체 `cached_content` 가능).
