## 2. Graph를 구상하는 순서

### 2-1. 전체 업무를 큰 워크플로우로 나눈다

먼저 구현 상세를 고려하지 말고 전체 업무를 큰 단위로 나눈다.

```text
회의록 기반 검색 및 답변 업무
├─ 사용자 입력 초기 상태
├─ 관련 회의록 검색·선택
└─ 회의록 질문·답변
```

이 단계의 그림은 **업무 개요도**이며, 아직 Node·State·Edge가 엄격히 정의된 Graph는 아니지만 **일단 이 각각이 업무 단위인 Node인 것이다.**

### 2-2. 현재 Graph의 State 집합을 정한다

2-1에서 나눈 단위들에서 업무가 흐르는 순서를 따라 그려보면서
**다음에 실행할 업무가 달라지는 지점**을 찾는다. 이 차이를 State로 구분한다.

```text
State = { none, search, question }
```

- `none`에서 검색 요청으로 판단된다 → `search`
- `none`에서 질문 요청으로 판단된다 → `question`

State는 이후 Node와 Edge를 나누는 기준이 되므로, Node를 최종 정의하기 전에 먼저 정한다.

### 2-3. State까지 정의된 Node를 최종 정의한다

각 State에서 실행할 업무를 `Input + 현재 State → Node 내부 State 갱신 → Output`으로 정의한다.

| Node      | Input State | 주요 Input  | Node 내부 State 갱신       | Output      |
| --------- | ----------- | --------- | ---------------------- | ----------- |
| 사용자 의도 판단 | `none`      | 사용자 요청    | `search` 또는 `question` | 검색·질문 판단 결과 |
| 회의록 검색·선택 | `search`    | 검색 조건     | `none`                 | 검색 결과·응답    |
| 회의록 질의    | `question`  | 질문·회의록 ID | `none`                 | 원문 기반 답변    |

### 2-4. Node 사이를 Edge로 연결한다

Node 내부에서 갱신된 State를 기준으로 Node 사이를 연결한다.

```text
[사용자 의도 판단 Node]
├─ State: search   → [회의록 검색·선택 Node]
└─ State: question → [회의록 질의 Node]
```

이때 각 Edge의 조건을 **코드로 고정할지, LLM의 의미 판단에 맡길지**도 함께 정한다.

### 2-5. Node 내부를 다시 세부 워크플로우로 나눈다

하나의 Node 안쪽에서
 - 여러 워크플로우로 나눠지고
 - 특히 다른 경로로 갈라지는 구조라면
그 Node를 **Subgraph**로 펼친다.

```text
상위 Node: 회의록 검색·선택
상위 State: search

Search Subgraph
├─ 후보 검색·결과 판단 Node
├─ 결과 없음 응답 Node
├─ 단일 후보 선택 Node
├─ 복수 후보 HITL Node
└─ 검색 응답 준비 Node
```

Subgraph에서는 상위 State (이 예시에서는 `search`)를 유지하면서도 내부 분기를 설명하기 위한 더 세밀한 State 집합을 둘 수 있다.

### 2-6. 더 이상 분기할 필요가 없을 때까지 반복한다

```text
업무 개요도
→ 최상위 Graph
→ Node를 펼친 Subgraph
→ Subgraph 내부의 더 작은 Subgraph
→ 최종 Node 내부 처리 순서도
```

다음 중 하나라도 해당하면 Node를 더 나누는 것을 검토한다.

- 결과에 따라 다음 업무가 달라지는가?
- 별도의 실패·재시도 처리가 필요한가?
- Human in the Loop로 중단되는가?
- 독립적으로 확인할 State 전이가 있는가?
- 하나의 Node로 보기에 책임이 너무 큰가?

이런 구분이 필요하지 않다면 더 이상 Graph를 펼치지 않고 Node 내부 로직이나 순서도로 마무리한다. 그 Graph가 최종 순서도인 것이다.

## 핵심 정리

```text
1. 전체 업무를 워크플로우로 나눈다. (Node 1차 정의)
2. 다음 업무가 달라지는 지점을 State로 정의한다.
3. State까지 정의된 Node를 최종 정의한다.
4. 갱신된 State에 따라 Edge를 연결한다.
5. Node 안에 다시 분기가 있다면 Subgraph로 펼친다.
6. 더 이상 나눌 필요가 없을 때까지 반복한다.
```

> **Node는 현재 State상태에서 Input을 받아, Node 내부의 정해진 지점에서 State를 갱신한 뒤 Output을 반환하는 업무 단위다. 
> State는 이후 Edge과 Node를 선택하는 기준이며,
> Edge는 갱신된 State에 따라 다음 Node로 이동하는 경로다.**
