# LangGraph 로컬 Trace 기능과 LangSmith 비교

**문서 성격:** 회의록 Agent POC Trace 구현 해설  
**기준일:** 2026-08-31  
**대상 코드:** `zen-ai-meeting-agent-test`

이 문서는 현재 회의록 Agent POC의 Trace 화면이 어떤 LangGraph 기능을 사용해 만들어졌는지 설명하고, 같은 목적에 사용할 수 있는 LangSmith 서비스와의 차이를 정리한다.

현재 POC의 Trace는 LangSmith에서 가져온 화면이 아니다. **오픈소스 LangGraph가 실행 중 제공하는 debug event stream을 Python 코드가 수집하고, POC가 직접 만든 변환기와 로컬 웹 화면으로 보여주는 구조**다.

## 1. 핵심 결론

```text
LangGraph
→ Graph 실행과 debug event stream 제공

현재 POC
→ event를 안전한 JSON으로 변환
→ SSE로 즉시 전송
→ 로컬 웹 화면에서 Node·Edge·State로 표시

LangSmith
→ Trace를 서버에 수집·저장하고 검색·모니터링·평가하는 별도 서비스
```

- LangGraph 라이브러리는 Graph 실행 과정의 Node, Task, Checkpoint와 Subgraph 정보를 로컬 코드에서 받을 수 있는 Streaming API를 제공한다.
- 현재 POC는 이 API를 사용하므로 LangSmith 계정이나 LangSmith API Key 없이 Trace 화면을 실행할 수 있다.
- LangGraph가 제공하는 것은 **실행 이벤트와 State 접근 기능**이고, 현재 브라우저 화면·이벤트 명칭·민감정보 필터·SSE 전송은 이 POC가 직접 구현했다.
- LangSmith는 실행 이벤트를 장기간 보관하고 검색·비교·평가·모니터링·협업할 수 있게 하는 관리형 Observability 서비스다.
- 현재 POC에서 LangSmith로 데이터를 보내는 설정은 없다.

## 2. 용어 구분

### 2-1. LangGraph

LangGraph는 State를 가진 Agent와 Workflow를 Node·Edge 구조로 실행하기 위한 오픈소스 라이브러리다. 현재 POC에서는 다음 기능을 담당한다.

- 최상위 Agent Graph와 Search·Question Subgraph 실행
- Node와 조건 Edge 실행
- State 부분 업데이트와 Reducer 적용
- Checkpoint 저장과 복구
- Human in the Loop 중단·재개
- Graph 실행 이벤트 Streaming

LangGraph 자체는 MIT License로 배포된다.

### 2-2. 현재 POC의 로컬 Trace

현재 코드가 LangGraph 실행 이벤트를 받아 직접 만든 **발표·디버깅용 로컬 실행 관찰 화면**이다.

이 문서에서는 편의상 Trace라고 부르지만, LangSmith가 정의하는 서버 저장형 Trace와 완전히 같은 제품 기능은 아니다. 더 정확히는 다음에 가깝다.

> **LangGraph debug event stream 기반의 로컬 실행 시각화 도구**

### 2-3. LangSmith

LangSmith는 LangChain·LangGraph 및 일반 LLM 애플리케이션의 실행을 Trace로 수집하고 저장·검색·평가·모니터링하는 별도 서비스다.

LangGraph 라이브러리를 사용한다고 LangSmith가 자동으로 필수 사용되는 것은 아니다. LangSmith Tracing을 사용하려면 계정·API Key와 활성화 설정이 필요하다.

## 3. 현재 POC가 사용하는 LangGraph 클래스와 기능

| LangGraph 요소 | 의미 | 현재 POC에서의 사용 위치와 역할 |
|---|---|---|
| `StateGraph` | Node·Edge·State Schema를 조립하는 Graph Builder | `agent_graph.py`, `recording_graph.py`에서 최상위 Graph와 Subgraph 구성 |
| `START`, `END` | Graph의 시작·종료 경계 | 각 Graph와 Subgraph의 고정 진입·종료 Edge 정의 |
| `compile()` | Builder를 실행 가능한 Graph 객체로 변환 | Runtime이 Checkpointer를 연결한 Agent Graph 생성 |
| 컴파일된 Graph의 `stream()` | 실행 결과를 Iterator 형태의 Event Stream으로 반환 | `runtime.py`의 `iter_agent_traced()`와 `iter_resume_agent_traced()` |
| `stream_mode="debug"` | Task·결과·Checkpoint 등 상세 Debug Event 반환 | Node 시작·완료와 기술 State Snapshot 수집 |
| `subgraphs=True` | 부모 Graph뿐 아니라 중첩 Subgraph Event도 함께 반환 | Agent Graph, Search Subgraph, Question Subgraph 구분 |
| Event namespace | Event가 어느 Graph·Subgraph에서 발생했는지 표시 | 화면의 `Agent Graph`, `Search Subgraph`, `Question Subgraph` 이름 결정 |
| `SqliteSaver` | Graph State Snapshot을 SQLite에 저장하는 Checkpointer | HITL, State 조회와 실행 복구를 위한 로컬 Checkpoint |
| `get_state()` | 특정 Thread의 현재 State Snapshot 조회 | Stream 실행 후 현재 State와 Interrupt 확인 |
| `get_state_history()` | Thread의 과거 State Snapshot 조회 | 테스트에서 영속 State 필드와 원문 비저장 검증 |
| `interrupt()` | Node 실행을 중단하고 사용자 입력을 기다림 | 복수 후보 선택과 새 ID 추가·대체 HITL |
| `Command(resume=...)` | 중단된 Graph를 사용자 입력으로 재개 | CLI와 웹 화면의 `/select`, `/merge` 처리 |
| `Runtime[AgentContext]` | 호출 시 전달하는 비영속 Runtime Context | `user_id`, `thread_id`, 현재 `request` 전달 |
| `UntrackedValue` | 실행 중에는 전달하지만 Checkpoint에는 직렬화하지 않는 채널 | Question 원문을 Q3 Model 호출까지만 전달 |

이 가운데 Trace 화면의 핵심 기능은 `stream()`, `stream_mode="debug"`, `subgraphs=True`와 namespace다. `SqliteSaver`, `interrupt()`와 `Command`는 Trace 자체를 그리는 기능은 아니지만 State Snapshot과 HITL 중단·재개가 실제 실행 흐름에 나타나게 한다.

## 4. 현재 코드에서 Trace가 만들어지는 과정

### 4-1. Agent Graph 실행

`src/meeting_agent/runtime.py`의 `iter_agent_traced()`는 다음 방식으로 실제 Graph를 실행한다.

```python
for namespace, event in self.agent_graph.stream(
    payload,
    config,
    context=context,
    stream_mode="debug",
    subgraphs=True,
):
    yield from debug_event_to_trace(namespace, event)
```

여기서 중요한 점은 다음과 같다.

- 별도로 Trace 전용 Graph를 실행하지 않는다.
- 실제 사용자 요청을 처리하는 동일한 Agent Graph를 실행한다.
- `.stream()`이 반환한 실제 실행 Event를 하나씩 즉시 변환한다.
- `subgraphs=True`이므로 Search·Question Subgraph 내부 Event도 포함한다.

HITL 재개도 `iter_resume_agent_traced()`에서 같은 방식을 사용한다.

```python
self.agent_graph.stream(
    Command(resume=answer),
    config,
    context=context,
    stream_mode="debug",
    subgraphs=True,
)
```

따라서 사용자가 후보를 선택하거나 ID 추가·대체를 결정한 이후의 재개 경로도 실제 LangGraph Event로 관찰할 수 있다.

### 4-2. Debug Event 변환

`src/meeting_agent/tracing.py`의 `debug_stream_to_trace()`가 LangGraph Event를 POC 화면용 JSON으로 바꾼다.

| LangGraph debug event | 현재 화면에서의 의미 |
|---|---|
| `task` | Node 시작 |
| `task_result` | Node 완료, 출력, 판단값과 Interrupt |
| `checkpoint` | LangGraph 복구용 기술 State Snapshot과 다음 실행 Node |
| namespace 없음 | 최상위 `Agent Graph` |
| `search_subgraph:*` namespace | `Search Subgraph` |
| `question_subgraph:*` namespace | `Question Subgraph` |

예를 들어 `llm_goal_condition`의 `task_result`에서 `llm_decision` Event를 찾아 `search`, `question`, `direct` routing을 화면에 표시한다. 종료는 별도 LLM `none` 판단이 아니라 Search·Question 응답의 `follow_up=false`를 읽는 고정 Condition으로 결정한다.

이 변환 과정은 LangGraph의 기본 UI가 아니라 현재 POC가 직접 작성한 코드다.

### 4-3. 안전한 State만 선택

`tracing.py`의 `safe_state()`는 화면에 표시할 State Key를 Allowlist 방식으로 제한한다.

```text
ScratchPad
authorized_meeting_ids
recording_modal_status
candidates
selected_ids
merge_mode
tool_status
tool_error
last_result
```

`safe_value()`는 사전 안의 다음 Key를 제거한다.

```text
transcript
api_key
Authorization
```

원문은 먼저 `UntrackedValue`로 Checkpoint 저장 자체를 막고, Trace 변환에서도 Allowlist와 `safe_value()`로 방어한다. API Key 역시 Trace JSON에 넣지 않는다. 이 필터는 현재 POC가 책임지고 구현한 경계다.

### 4-4. 브라우저 화면 표시

`src/meeting_agent/web_demo.py`는 `/api/command` 요청에 `text/event-stream`으로 응답한다.

```text
node/state event ...
→ final response/state/interrupt event
```

브라우저 JavaScript는 Fetch `ReadableStream`으로 SSE frame을 읽는 즉시 Event를 표시한다.

- 상위 Graph와 Subgraph 들여쓰기
- Node 시작·완료
- Edge와 다음 Node
- LLM 목표 판단값
- 기술 State Snapshot 표시·숨김

기술 State Snapshot은 발표 중 업무 Checkpoint와 혼동하지 않도록 기본적으로 숨긴다.

## 5. 현재 화면은 완전한 실시간 Streaming인가?

현재 구현은 Graph 이벤트 단위의 실시간 Streaming UI다.

```text
Graph 실행 시작
→ Python이 debug event 하나를 안전한 Trace event로 변환
→ SSE frame을 즉시 write·flush
→ 브라우저 Fetch ReadableStream이 즉시 수신
→ Trace panel에 즉시 추가
```

따라서 DeepSeek 응답을 기다리는 동안에도 이미 시작된 Node와 Subgraph가 화면에 보인다. 답변 토큰 자체를 한 글자씩 보내는 LLM token streaming은 범위 밖이며, Graph event streaming과 구분한다.

## 6. 녹화 Trace는 Agent Trace와 어떻게 다른가?

Search·Question Agent Trace와 녹화 Trace 모두 실제 LangGraph `stream_mode="debug"` Event에서 생성한다. 녹화 명령은 `iter_recording_traced()`가 결정적 Recording Workflow를 실행하면서 Event를 즉시 전달한다.

```text
Recording Workflow Node 시작
→ recording_modal_and_backend Node 완료
→ END Edge
→ 하네스가 recording_modal_status를 Agent State에 반영
→ Agent Checkpoint 동기화 완료 Event
```

두 Trace의 실행 근거는 같고, 녹화에는 모달 결과를 Agent State에 동기화하는 업무 경계가 하나 더 이어진다.

| 구분 | Trace 생성 방식 |
|---|---|
| Agent Graph·Search·Question | 실제 LangGraph debug event stream |
| Recording Workflow | 실제 LangGraph debug event stream + 실제 Agent Checkpoint 동기화 완료 Event |

녹화 Trace는 실행 완료 결과로 Node 목록을 사후 재구성하지 않는다. Node 시작·완료는 Recording Workflow의 실제 debug event를 변환하고, `recording_modal_status` 업무 Checkpoint 표시는 실제 `update_state()`가 완료된 뒤에만 전송한다.

## 7. LangGraph 로컬 Trace와 LangSmith 비교

| 항목 | 현재 POC의 LangGraph 로컬 Trace | LangSmith |
|---|---|---|
| 제공 주체 | LangGraph 실행 Event + POC 자체 UI | LangChain의 관리형 Observability 서비스 |
| 실행 위치 | 현재 Python 프로세스와 로컬 브라우저 | LangSmith SaaS 또는 계약에 따른 별도 환경 |
| 계정·API Key | 필요 없음 | LangSmith 사용 시 필요 |
| 기본 데이터 저장 | Trace Event는 메모리, Graph State는 로컬 SQLite | Trace를 LangSmith Project에 저장 |
| Node·Subgraph 관찰 | 현재 코드가 직접 변환·표시 | Framework 연동으로 Run Tree 표시 |
| LLM Prompt·응답 관찰 | 현재 POC가 선택한 값만 표시 | 설정된 Trace의 입력·출력과 중첩 Run 관찰 |
| 장기 검색 | 없음 | Project, Trace, Run, Thread 검색·필터 |
| 비교·분석 | 없음 | 실행 비교, Feedback, Annotation과 Dataset 연계 |
| Evaluation | 없음 | Offline·Online Evaluation 기능 |
| 운영 Monitoring | 없음 | 지연, 오류, 사용량과 품질 모니터링 |
| 협업 | 로컬 화면 공유 수준 | 팀 Workspace와 Trace 공유 |
| 보존 기간 | POC 구현과 로컬 파일 관리에 따름 | LangSmith Plan과 Trace 종류에 따름 |
| 커스터마이징 | 코드로 자유롭게 변경 | 제공되는 UI와 API 범위에서 사용 |
| 비용 | LangGraph 라이브러리 자체는 무료 | 무료 포함량과 사용량 기반 과금이 존재 |

### 7-1. 비용 구분

LangGraph 오픈소스 라이브러리와 현재 POC의 로컬 Trace UI에는 LangSmith Trace 사용료가 발생하지 않는다.

다만 다음 비용은 별개다.

- 실제 DeepSeek API 호출 비용
- 실행 PC·서버의 Compute와 Storage
- LangSmith를 활성화했을 때의 Plan·Trace 사용량

2026-08-31 기준 LangSmith Developer Plan은 1인 무료 Seat와 월 5,000개의 Base Trace 포함량을 안내하고 있으며, 초과 사용은 사용량 기반 과금 대상이다. 가격과 포함량은 변경될 수 있으므로 실제 도입 시 공식 가격 페이지를 다시 확인한다.

## 8. 데이터와 보안 경계

### 8-1. 현재 LangGraph 기능만으로 외부 DB에 전송되는가?

현재 POC처럼 Python 안에서 `StateGraph`, `stream()`과 직접 생성한 `SqliteSaver`를 사용하는 경우 Graph State와 debug event가 자동으로 LangGraph 또는 LangChain 회사의 DB로 전송되지는 않는다.

현재 데이터 위치는 다음과 같다.

| 데이터 | 현재 위치 |
|---|---|
| LangGraph debug event | 실행 중 Python 프로세스 메모리 |
| 브라우저 Trace JSON | 로컬 HTTP 응답과 브라우저 메모리 |
| Agent Checkpoint | 로컬 `data/checkpoints.db` |
| POC 회의록·권한·녹화 데이터 | 로컬 `data/app.db` |

로컬 SQLite와 Checkpoint의 암호화·보존 정책은 이 POC에서 수용한 로컬 실험 범위로 본다. 실제 제품 운영 보안 사양으로 해석하지 않는다.

### 8-2. LangSmith를 활성화하면 달라지는 점

LangSmith Tracing은 일반적으로 다음 환경 설정을 통해 활성화한다.

```text
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=<LangSmith API Key>
```

활성화되면 설정과 Instrumentation 범위에 따라 Graph·LLM 실행의 입력, 출력과 Metadata가 LangSmith로 전송될 수 있다.

현재 POC 저장소에는 LangSmith를 활성화하는 코드와 설정이 없다. 고객 데이터 사용 가능성이 있는 환경에서는 실수로 상위 Shell·IDE·CI 설정을 상속하지 않도록 다음 값을 명시할 수 있다.

```text
LANGSMITH_TRACING=false
```

### 8-3. 현재 POC에서 실제 외부 전송이 발생하는 경로

현재 기본 Model Provider인 `DeepSeekMeetingModel`은 `https://api.deepseek.com/chat/completions`를 호출한다. Question 실행에서는 조회한 회의록 원문이 현재 Model Context의 `documents`에 포함되어 DeepSeek API로 전달된다.

```text
LangGraph 로컬 Trace
→ 외부 전송 없음

LangSmith 설정 없음
→ LangSmith 전송 없음

DeepSeekMeetingModel 사용
→ Prompt·요청·필요한 회의록 원문이 DeepSeek API로 전송
```

따라서 현재 POC에서 외부 데이터 전송을 판단할 때 핵심은 LangGraph debug stream보다 **실제 LLM Provider 선택**이다.

- 더미 데이터와 `RuleBasedMeetingModel`: 외부 LLM 전송 없음
- 더미 데이터와 `DeepSeekMeetingModel`: 더미 데이터가 DeepSeek으로 전송
- 실제 고객 데이터와 외부 LLM: 고객사·회사 보안 정책과 계약 검토가 선행되어야 함

### 8-4. SAP 컨설팅 POC에서의 판단

이 저장소는 합성 더미 데이터로 설계 성립 여부를 검증하는 로컬 POC다. 다음 조건이면 현재 Trace 방식은 POC 목적에 적합하다.

- 실제 고객 데이터를 사용하지 않는다.
- LangSmith Tracing을 활성화하지 않는다.
- 외부 LLM을 사용할 때 전송 데이터가 더미 데이터임을 확인한다.
- Trace 서버는 기본 `127.0.0.1`로 실행한다.
- POC의 로컬 DB를 제품 운영 저장소로 간주하지 않는다.

향후 실제 SAP 고객 데이터로 확장하는 시점에는 LangGraph 사용 여부만 볼 것이 아니라 LLM Provider, Network Egress, Trace 저장 위치와 고객사 계약을 함께 검토해야 한다.

## 9. 현재 로컬 Trace가 제공하지 않는 것

현재 구현은 Graph 설계가 실제로 실행되는지를 설명하기 위한 POC다. 다음 기능은 제공하지 않는다.

- 여러 서버와 프로세스에 걸친 분산 Trace
- Trace의 장기 보존·검색·태그·필터
- 사용자별 Trace 접근 권한
- Trace 간 Prompt·Model 성능 비교
- Dataset과 자동 Evaluation
- 운영 지표·경보·오류율 Dashboard
- Token·비용 분석
- 고객별 보존 기간과 삭제 정책 관리
- LLM 답변의 Token 단위 Streaming

이 기능이 필요해질 때는 LangSmith, OpenTelemetry 기반 Observability 또는 사내 관측 시스템을 비교한다.

## 10. 현재 POC에 로컬 Trace가 적합한 이유

현재 POC의 질문은 “회의록 Agent 설계가 Python과 LangGraph로 기술적으로 성립하는가?”다.

이 목적에서는 다음 내용을 확인하면 충분하다.

- LLM 역할이 `goal → candidate → search response → goal → question response`로 이어지는가?
- 실제 Search·Question Subgraph가 실행되는가?
- HITL이 중단되고 같은 Graph가 재개되는가?
- Search·Question 결과 뒤 `follow_up` 고정 Condition과 Checkpoint 경계가 보이는가?
- 기술 State Snapshot과 업무 Checkpoint를 구분할 수 있는가?
- 회의록 원문과 API Key가 Trace에 그대로 나타나지 않는가?

현재 로컬 Trace는 이 질문에 직접 답하며 외부 Trace 서비스를 추가하지 않아 POC의 범위를 작게 유지한다.

## 11. LangSmith 도입을 검토할 조건

다음 요구가 생기면 LangSmith 또는 동등한 Observability 제품을 검토할 수 있다.

1. 개발자 여러 명이 같은 Trace를 장기간 공유해야 한다.
2. 운영 환경의 실패를 Request·Thread 단위로 검색해야 한다.
3. Prompt나 Model 변경 전후 품질을 Dataset으로 비교해야 한다.
4. 사용자 Feedback과 Trace를 연결해야 한다.
5. 지연 시간, Token, 비용과 오류율을 지속적으로 모니터링해야 한다.
6. Online Evaluation과 이상 실행 탐지가 필요하다.
7. 분산 Worker와 외부 Tool 호출을 하나의 Run Tree로 추적해야 한다.

이때는 기능뿐 아니라 다음 보안·계약 항목을 함께 확인한다.

- 고객 데이터 외부 전송 허용 여부
- 데이터 저장 Region과 보존 기간
- DPA, 접근 통제, 감사와 삭제 정책
- Trace Sampling과 민감정보 마스킹
- SaaS, Hybrid 또는 Self-hosted 선택

## 핵심 정리

> 현재 회의록 Agent POC는 LangSmith 없이도 LangGraph의 `stream_mode="debug"`와 `subgraphs=True`를 사용해 실제 Agent Graph와 Search·Question Subgraph의 실행 Event를 로컬에서 관찰한다. LangGraph는 실행 Event와 Checkpoint·HITL 기능을 제공하고, POC는 이를 안전한 JSON과 브라우저 Trace 화면으로 변환한다. LangSmith는 여기에 서버 저장·검색·평가·모니터링·협업을 추가하는 별도 서비스다. 현재 POC의 LangGraph Trace와 SQLite Checkpoint는 로컬에 머물며, 실제 외부 데이터 전송 여부는 LangSmith 활성화 설정과 DeepSeek 같은 LLM Provider 호출을 기준으로 판단해야 한다.
