# Codex-LB 로컬 LLM 테스트 임시 설정 매뉴얼

## 목적

Codex-LB는 배포 대상 Provider가 아니며, 로컬 LLM/E2E 검증 때만 임시 Gateway로 사용한다. 테스트가 끝나면 환경변수와 프로세스를 원래 상태로 되돌린다.

## 사전 조건

- Codex-LB가 로컬 127.0.0.1:2455에서 실행 중이어야 한다.
- 테스트 PostgreSQL과 Zen AI 의존 서비스가 실행 중이어야 한다.
- API 키는 외부 키 파일에서 읽고 문서·소스·Git에 복사하지 않는다.

## PowerShell 임시 설정

현재 PowerShell 창에서만 다음 값을 설정한다.

$env:OPENAI_BASE_URL = "http://127.0.0.1:2455/v1"
$env:OPENAI_API_KEY = "<외부 키 파일의 값>"

프로젝트의 .env 파일을 직접 수정하지 않는다. 새 PowerShell 창에는 값이 전달되지 않는다.

## 서버 실행

1. PostgreSQL과 Codex-LB를 실행한다.
2. 기존 3002 포트를 사용하는 프로세스가 있으면 종료하거나 기존 서버를 재사용한다.
3. 프로젝트 폴더에서 npm run dev를 실행한다.
4. 브라우저에서 http://localhost:3002로 접속한다.
5. 테스트 커뮤니티와 회의록 Agent를 준비한다.

## 확인 명령

Gateway 모델 목록과 서버 응답을 확인한다. 출력에 API 키가 포함되지 않는지 확인한다.

Invoke-WebRequest http://127.0.0.1:2455/v1/models

이후 Provider 계약, 검색/HITL, 질문, Recording Tool, 브라우저 제어 명령을 순서대로 테스트한다.

## 테스트 후 원상복구

PowerShell 세션에서 다음을 실행한다.

Remove-Item Env:OPENAI_BASE_URL -ErrorAction SilentlyContinue
Remove-Item Env:OPENAI_API_KEY -ErrorAction SilentlyContinue

Codex-LB 프로세스를 종료하고 Zen AI 서버를 재시작한다. .env, manifest, 배포 설정에 Codex-LB 주소나 개인 키가 남아 있지 않은지 git diff와 검색으로 확인한다.

## 배포 주의

Codex-LB 주소와 개인 키는 로컬 테스트 전용이다. 배포에서는 회사가 지정한 OpenAI-compatible Provider와 운영용 키를 사용한다. Codex-LB 전용 설정을 운영 manifest나 공통 AI Provider에 상시 반영하지 않는다.

## 문제 대응

- connection refused: Codex-LB가 실행 중인지와 2455 포트를 확인한다.
- 401/403: 키를 다시 읽되 화면·로그에 출력하지 않는다.
- 60초 timeout: Gateway 지연으로 분류하고 동일 테스트를 재시도한다. HITL 상태가 사라지지 않는지 함께 확인한다.
- JSON 계약 오류: raw 응답을 문서에 복사하지 말고 Provider의 안전한 오류 로그와 계약 테스트 결과만 기록한다.
