# Trace 설계와 검증 요약

기준: 2026-09-22 · zen-ai `agent/trace-fix` 로컬 구현. 운영 적용 전.

## 목적과 설계 판단

- 목적: 요청 접수부터 Agent·Tool·HITL·응답 게시·종료까지 관측하여 장애 위치를 찾는다.
- 관측 범위: Agent 실행 단계와 Tool API의 결과 상태. Tool 내부 로직은 추적하지 않는다.
- 외부 서비스: 고객 데이터의 외부 전송을 피하고 상용 로그·Trace 제품은 도입하지 않는다. 모든 제품이 외부 전송을 강제한다는 뜻은 아니다.
- 보관 결정: 사용자가 재시작·상한에 따른 유실을 허용했다. 영속 Trace 관리 복잡성을 줄이기 위해 **Agent 서버 프로세스 메모리만** 사용한다.
- 구현 선택: Trace DB 쓰기를 제거한다. 인증/업무 DB는 권한 확인에 계속 사용한다.
- 미래 템플릿: 관측·정보 보호 계약은 재사용하되, 저장 구조와 실행 연결은 템플릿 구현 당시 환경에서 다시 판단한다. 현재 Builtin 구조를 그대로 고정하지 않는다.

## 현재 구현

- 적용: Builtin 실행 경로, 특히 회의 Agent. 미래 템플릿·팀 실행까지 구현된 것은 아니다.
- 흐름: 요청 → Worker → Agent/모델 → Tool/HITL → 응답 게시 → 종료. 성공·실패·취소·대기·관측 불완전을 구분한다.
- 전달·보관: 제한된 서버 메모리 + 호출자 전용 SSE. **스레드의 각 질문 바로 아래** 접이식 `처리 과정`을 표시한다. 후속 질문·HITL 응답마다 별도 묶음이다.
- 표시: 한국어 고정 처리 설명이며 LLM 비공개 추론 원문이 아니다. 펼침 유지·순번 병합·새 단계 버튼·재연결 보충을 적용한다.
- 조회: 현재 커뮤니티·채널 접근 권한이 있는 호출자 본인만 허용. 관리자도 우회 조회하지 않는다.
- 수명: 최대168시간/1000요청/요청당500이벤트·256KiB/서버payload32MiB. 브라우저payload8MiB 이하. 재시작·상한으로 더 일찍 유실 가능하다. 메모리 청소는60초 주기다.
- 출력 허용: 시각·순번·단계·상태·소요시간·임의 관측 표식/실행 관계·안전한 오류 코드.
- 출력 제외: 실제 사용자/스레드/회의록 등의 ID, 대화·본문·프롬프트, Tool 입출력·내부 상태, 키·토큰·원본 예외. 소유권 확인용 ID는 내부 권한 메타데이터에만 보관한다.
- 책임 분리: State·Checkpoint·기존 `agent_run_spans`와 별도. 저장 실패가 Agent 업무를 실패시키지 않는다.
- 한계: 단일 프로세스 전제. 재시작하면 과거 Trace는 사라지지만 대화·State·HITL 업무는 보존된다. 새로고침은 같은 프로세스에 남은 기록만 재조회한다.
- `0085`는 Trace 두 테이블/전용 함수·정책만 제거한다. 기존 State/Checkpoint/`agent_run_spans`는 보존한다. 구버전 종료→migration→신버전 기동이 필요하다.

## 검증 결과

| 검증 | 결과 |
| --- | --- |
| 실제 원격 Codex-LB + 격리 PostgreSQL 및 핵심 | 72통과, skip0. 검색·질문·녹음 제어·HITL |
| 0084→0085 및 회의 runtime | 13통과·실제LB1skip. populated Run/State/ToolState/Checkpoint/span 보존, 제거 재실행 확인 |
| UI·stream·정제 집중 검증 | 57통과. 리뷰 발견3건 실패 재현 후 수정·통과 |
| 실제 브라우저 | 질문별 한국어 Trace·펼침 유지·HITL 대기/잘못된 선택·재시작 후 대화 유지와 Trace 유실 확인. 전체 시나리오 완료를 의미하지 않음 |
| 전체 최종 실행 | 4300통과/34실패/24skip·unhandled1. Windows symlink/getuid/bash/권한 관련 실패. 전체 통과 아님 |
| 정적 검사·빌드 | check·knip·Prettier·diff 검사·production build 통과. ESLint 오류0/기존 경고11, client bundle 유출0건 |
| 사용자 서비스/운영 DB | 0085 미적용. 격리 테스트 DB만 검증 |

- 격리 PostgreSQL은 실제 DB이며 사용자 데이터 보호를 위해 분리했다. 운영 DB에는 적용하지 않았다.
- 브라우저는 테스트 세션 사용. 실제 모델 호출은 별도 통합 검증이며 OIDC·마이크 녹음/전사 완료 검증은 아니다.
- 두 사용자 동시 브라우저 E2E 추가 완료: Chrome A/내장 브라우저 B에서 다른 스레드·같은 스레드 호출, 본인 Trace만 표시, HITL 취소/재개 독립성, 실행 중 새로고침과 펼침 유지 확인.
- 실제 HTTP/SSE 추가 검증: 각13이벤트가 본인에게만 전달, 본인 상세10건 성공/타인 상세10건404/비로그인401. 관련 통합·UI51통과/실제LB1skip. 일반 Agent/SAP 확장 및 마이크·전사는 이번 범위에서 제외.
