# Builtin과 일반 에이전트의 버전 관리 차이

## 핵심 결론

- **실행 정의의 release 체계와 ‘실행 버전 갱신’ 버튼은 Builtin 전용**이다.
- 기존 일반 에이전트에도 **사용자 설정의 버전 관리**는 있다. `agents.version`과 `agent_versions`를 사용한다.
- **향후 신규 템플릿은 기존 일반 에이전트의 버전 관리 구조를 유지한다.** Builtin release 체계를 가져오지 않는다.
- 이 문서는 버전 관리에 관한 설명이며, Trace 기록의 버전이나 보관 정책과는 별개다.

## 두 방식의 비교

| 구분 | Builtin 에이전트 | 기존 일반 에이전트 |
| --- | --- | --- |
| 정의 방식 | 개발자가 manifest·코드로 정의 | 사용자가 만들기 화면에서 설정 |
| 코드 정의 버전 | `definition_revision` | 같은 Builtin revision 체계 없음 |
| 실행 release 기록 | `builtin_definition_releases` | 같은 Builtin release 체계 없음 |
| 카드가 사용하는 release | `definition_release_epoch` | 같은 참조값 없음 |
| 사용자 설정 버전 | `config_epoch` | `agents.version` |
| 설정 이력 테이블 | `builtin_instance_config_versions` | `agent_versions` |
| 별도 실행 버전 갱신 버튼 | 있음 | 같은 기능 없음 |

## Builtin에서 각 값이 뜻하는 것

- **`definition_revision`**: manifest에 개발자가 명시하는 정의 버전. 다른 Builtin을 수정했다고 자동 증가하지 않는다.
- **release**: 실행 정의를 DB에 등록한 기록.
- **`release_epoch`**: 해당 Builtin의 release 등록 번호. revision과 반드시 같은 숫자는 아니다.
- **`definition_release_epoch`**: 카드가 사용할 release를 가리키는 값.
- **`config_epoch`**: 카드가 사용할 사용자 설정 기록을 가리키는 값. release와 별개다.

### 파일과 테이블의 연결

```text
manifest 등 정의 파일 → compile → registry 생성 파일
                                      ↓ release 등록
                           builtin_definition_releases
                                      ↑ definition_release_epoch
agent_principals → builtin_agent_instances
                                      ↓ config_epoch
                           builtin_instance_config_versions
```

- 모두 별도 DB라는 뜻이 아니다. **registry는 생성 파일**, 나머지 위 이름들은 PostgreSQL의 **테이블**이다.
- `agent_principals.kind`는 `custom` / `builtin`을 구분하는 식별 정보다. 실제 호출에서는 채널 멤버 정보 등도 함께 확인한다.
- 실행 코드는 DB의 release와 현재 registry 정의를 확인하고, `executorId`에 해당하는 실행기로 연결한다.
- compile과 DB release 등록은 별도 단계다. 새 release 등록만으로 기존 카드의 참조가 자동 갱신되지는 않는다.

## 사용자 설정 저장 방식

### Builtin

- 최초 카드 등록 시 **`config_epoch = 1`과 최초 설정 행이 자동 생성**된다.
- 설정 변경·저장 시 새 설정 행을 추가하고 카드의 `config_epoch`를 함께 갱신한다. 이전 행은 보존한다.
- 최신 행을 무조건 찾는 것이 아니라 **해당 카드의 `config_epoch`와 일치하는 행**을 읽는다.
- 최대 토큰·최대 라운드가 미지정이면 카드가 사용하는 release의 값을 따른다. 지정하면 허용 상한 내 설정값을 사용한다.
- 예: release 최대 토큰 8,000 → 미지정이면 8,000, 4,000으로 저장하면 4,000. 10,000은 상한 초과로 저장 거부.

### 일반 에이전트

- 최초 생성: `agents.version = 1`, `agent_versions`에 1번 설정 기록 추가.
- 최대 토큰 등 설정 변경·저장: `agents.version = 2`, `agent_versions`에 2번 설정 기록 추가.
- **1번 기록을 2번으로 덮어쓰지 않는다.** 이전 설정 이력은 보존한다.
- Builtin처럼 별도의 실행 release 갱신 버튼을 누르는 방식은 아니다.

## 이번 수정과 향후 방향

- 이번 Builtin 수정: 특정 회의 에이전트만 허용하던 전환 제한을 없애고, 모든 Builtin이 해당 에이전트의 최신 release로 갱신하는 공통 경로를 사용하도록 변경.
- 버튼이 바꾸는 핵심 값: **`builtin_agent_instances.definition_release_epoch`**. 새 release 생성이나 사용자 설정 변경이 아니다.
- 권한·설정·실행 중 Run·동시성 검사는 유지하며, 기존 대화·State·Tool State·HITL 데이터는 그대로 보존한다. 과거 HITL 재개 호환성까지 보장하지는 않는다.
- **신규 템플릿은 `version`·`agent_versions`를 기본으로 한다.** 기존 일반 에이전트 구조를 뒤엎거나 Builtin release 체계를 이식하지 않는다.
