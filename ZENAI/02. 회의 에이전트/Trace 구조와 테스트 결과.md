# Trace 설계와 검증 요약

기준: 2026-09-21 · zen-ai

## 목적과 설계 판단

- 목적: 요청 접수부터 Agent·Tool·HITL·응답 게시·종료까지 관측하여 장애 위치를 찾는다.
- 관측 범위: Agent 실행 단계와 Tool API의 결과 상태. Tool 내부 로직은 추적하지 않는다.
- 외부 서비스: 고객 데이터의 외부 전송을 피하고 상용 로그·Trace 제품은 도입하지 않는다. 모든 제품이 외부 전송을 강제한다는 뜻은 아니다.
- 보관 결정: 메모리만으로는 종료·새로고침 후 장애 조사가 어려워 서버 측 보관을 추가한다.
- 구현 선택: 별도 DB 서버나 로그 관리 제품을 만들지 않고 **기존 PostgreSQL에 Trace 전용 테이블**을 둔다. 권한·만료·조회에 필요한 최소 기능만 구현한다.
- 미래 템플릿: 관측·정보 보호 계약은 재사용하되, 저장 구조와 실행 연결은 템플릿 구현 당시 환경에서 다시 판단한다. 현재 Builtin 구조를 그대로 고정하지 않는다.

## 현재 구현

- 적용: Builtin 실행 경로, 특히 회의 Agent. 미래 템플릿·팀 실행까지 구현된 것은 아니다.
- 흐름: 요청 → Worker → Agent/모델 → Tool/HITL → 응답 게시 → 종료. 성공·실패·취소·대기·관측 불완전을 구분한다.
- 전달·보관: 실시간 SSE/패널 + `agent_trace_requests`(권한 메타데이터), `agent_trace_events`(정제 이벤트).
- 조회: 현재 커뮤니티·채널 접근 권한이 있는 호출자 본인만 허용. 관리자도 우회 조회하지 않는다.
- 수명: 생성 후 **168시간**, 연장 없음. 만료 시 API 차단 및 버튼·목록·열린 상세 제거. DB 정리는 서버 시작 시/5분 주기로 최대 100요청씩 수행한다.
- 출력 허용: 시각·순번·단계·상태·소요시간·임의 관측 표식/실행 관계·안전한 오류 코드.
- 출력 제외: 실제 사용자/스레드/회의록 등의 ID, 대화·본문·프롬프트, Tool 입출력·내부 상태, 키·토큰·원본 예외. 소유권 확인용 ID는 내부 권한 메타데이터에만 보관한다.
- 책임 분리: State·Checkpoint·기존 `agent_run_spans`와 별도. 저장 실패가 Agent 업무를 실패시키지 않는다.
- 한계: 강제 종료 직전 이벤트의 무손실 저장·재시작을 넘는 실행 연결 복원은 보장하지 않는다. 백업에서의 만료 데이터 삭제는 별도 정책이 필요하다.

## 검증 결과

| 검증 | 결과 |
| --- | --- |
| Trace·RLS·회의 Runtime·UI 집중 검증 | 315 통과, 실제 모델 선택 테스트 1개 제외 |
| 실제 원격 Codex-LB + 격리 PostgreSQL | 13 통과: 검색·질문·녹음 제어·HITL |
| 실제 브라우저 + Next API + 격리 PostgreSQL | 본인/타인/관리자 권한, 201개 이벤트 조회, 만료, 새로고침·서버 재시작 후 재조회 확인 |
| 전체 테스트 실행 기록 | 4,265 통과 / 35 실패 / 24 제외. Windows 제약 및 avatar 행 순서 실패 포함 |
| avatar 순서 의존성 수정 후 | schema·Trace DB 테스트 38 통과. 전체 테스트 재실행은 하지 않음 |
| 정적 검사·빌드 | check·lint·Prettier·knip 통과. Trace 구현 최종 빌드 통과; 후속 avatar 테스트 수정 뒤 빌드는 재실행하지 않음 |
| 실제 로컬 앱 DB | `0081` 적용 완료. 미적용 0개, Trace 테이블 강제 RLS 및 재실행 정상 확인 |

- 격리 PostgreSQL은 실제 DB이며 사용자 데이터 보호를 위해 분리했다. 운영 DB에는 적용하지 않았다.
- 브라우저는 테스트 세션 사용. 실제 모델 호출은 별도 통합 검증이며 OIDC·마이크 녹음/전사 완료 검증은 아니다.
