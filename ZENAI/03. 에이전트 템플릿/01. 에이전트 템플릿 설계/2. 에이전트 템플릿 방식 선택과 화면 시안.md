# 에이전트 템플릿화 — 방식 선택 토글과 개선 후 화면 시안

> **작성일:** 2026-10-01
> **기준:** [[1. 목표·상태·상황 기반 행동 플랜]]
> **문서 성격:** 구현 전 **검토용 화면 시안**. 기존 화면의 모든 항목을 재현한 스크린샷이 아니며, 저장·실행 계약과 신규 필드는 조사 후 확정한다.

## 1. 화면의 핵심

**‘에이전트 만들기’ 상단에서 기존 방식과 템플릿 방식을 선택**한다. 켜짐/꺼짐 의미가 불명확한 단일 스위치 대신 **두 선택지가 보이는 토글**로 표현한다. ‘신규’는 시간이 지나면 의미가 흐려지므로 화면 문구는 **기존 방식 / 템플릿 방식**을 제안한다.

**고객사가 사용 중인 생성·설정·실행은 그대로 보존**한다. 화면에서 방식을 고르는 것과 실행 엔진을 두 개 복제하는 것은 별개이며, AI SDK 조립 경계는 1번 문서의 조사 이후 결정한다.

## 2. 단독 에이전트 만들기 — 1차 대상

![[템플릿_에이전트_방식_선택.svg]]

[편집 가능한 Excalidraw 원본](Excalidraw/템플릿_에이전트_방식_선택.excalidraw)

**왼쪽은 기존 방식을 선택했을 때, 오른쪽은 템플릿 방식을 선택했을 때의 같은 생성 화면**이다. 두 개의 생성 창을 동시에 띄우는 제안이 아니다.

| 영역 | 기존 방식 | 템플릿 방식 시안 |
| --- | --- | --- |
| **방식 선택** | 기존 방식 선택 | 템플릿 방식 선택 |
| **기본 정보** | 기존 이름·호출 주소·설명 등 유지 | 같은 기본 정보 사용 |
| **업무 지침** | 기존 시스템 프롬프트 | 역할·목표·지침 입력으로 표현. 별도 저장 필드로 나눌지는 미정 |
| **모델·Tool** | 기존 설정과 동작 유지 | 허용된 모델·Tool 선택. 기존 연결·권한 경계 재사용 검토 |
| **실행 처리** | 기존 경로 유지 | HITL 대기·재개·취소, 시간 초과·실패 처리를 공통 기반으로 제공하는 방향 |
| **Trace** | 기존 동작을 강제로 변경하지 않음 | 일반 처리 단계·Tool 구조 표시. **LLM 추론 텍스트는 현재 미표시** |
| **팀 관계** | 기존 설정 보존 | 이 화면에 상하·병렬 관계를 추가하지 않음. 팀에서 정의 |

**HITL·Trace를 매번 사용자가 켜야 하는 기능 스위치로 그리지 않았다.** 공통 실행 기반 후보라는 방향을 보여주는 안내 영역이다. 기본 적용 범위와 정책은 상세 설계에서 확정한다.

**현재 UI의 ‘작업 공간(되묻기)’ 스위치와 방식 선택 토글은 다른 항목**이다. 기존 작업 공간 기능을 삭제하거나 새 템플릿 선택과 같은 의미로 바꾸지 않는다.

## 3. 토글을 바꿀 때의 제안 동작

| 상황 | 시안의 제안 |
| --- | --- |
| **처음 생성 화면 열기** | 기존 방식 기본 선택. 고객사 기존 경로를 우선 보존 |
| **새 Agent 작성 중 방식 변경** | 이름·설명 등 공통 입력은 유지하고 방식별 초안은 구분. 버려지는 입력이 있으면 전환 전 안내 |
| **기존 Agent 편집** | 기존 저장 방식을 그대로 사용. 토글로 즉시 변환하지 않음 |
| **템플릿 Agent 편집** | 생성 시 선택한 방식으로 편집. 방식 변경은 별도 이관 설계 전까지 제공하지 않는 안 |
| **저장** | 일반 Agent의 version·agent_versions 기반. Builtin release·epoch 체계를 노출하지 않음 |

**이 표는 안전한 화면 동작을 위한 제안이며 구현 완료·정책 확정 사항은 아니다.** 단순 토글 조작이 기존 Agent의 실행 방식이나 저장 이력을 바꾸지 않게 하는 것이 핵심이다.

## 4. 팀 만들기 — 후속 단계 개념안

![[템플릿_팀_방식_선택.svg]]

[편집 가능한 Excalidraw 원본](Excalidraw/템플릿_팀_방식_선택.excalidraw)

**단독 Agent 검증 후 팀 화면을 확장**한다. 기존 팀은 유지하고, 템플릿 방식 팀에서는 **참여 Agent → 관계 → 전달값**을 구분해 설정하는 방향이다. 그림의 드롭다운·매핑 표는 개념안이며 현재 지원 기능이라는 뜻이 아니다.

| 화면 영역 | 사용자에게 보여줄 의미 |
| --- | --- |
| **참여 Agent** | 기존에 만든 Agent를 선택해 팀 역할에 배치 |
| **실행 관계** | 순차 실행·상하 위임·병렬 실행을 구분. 그림의 좌우 위치만으로 의미를 정하지 않음 |
| **전달값** | 어느 Agent의 어떤 출력이 다음 Agent의 어떤 입력으로 가는지 명시 |
| **제약 안내** | 모든 대화·State를 자동 공유하지 않음. 수신 Agent의 권한을 넓히지 않음 |

**그림에는 단순한 A → B 순차 실행 예시만 표시**했다. 상하 위임·병렬·결과 취합의 구체적인 편집 방식은 조사 후 설계하며, 처음부터 범용 그래프 편집기 전체를 만들자는 제안이 아니다.

## 5. 이번 문서에서 확정하지 않는 것

**아직 결정하지 않는 사항:** DB 함수의 코드 이전 범위, AI SDK 조립 경로 분리 범위, 실제 Tool 연결 UI, 모델 연결 관리 화면, 팀 입력·출력 스키마와 매핑 저장 방식.

**LLM 추론 텍스트 미표시를 템플릿화의 선행 차단 조건으로 삼지 않는다.** 일반 Trace를 유지한 채 단독 Agent 조사·설계부터 진행한다.
