# 에이전트 템플릿 — 목표·상태·상황 기반 행동 플랜

기준: 2026-09-21 · 합의한 방향성. 상세 구현 설계는 조사 후 확정한다.

## 목표

- 최종 결과: 설정으로 독립 Agent를 만들고, 검증 후 여러 Agent를 연결한 팀으로 확장한다.
- 완료 기준: 단독 실행 → 팀 실행 순으로 정상·실패·HITL·권한·Trace를 검증한다.
- 보존: 고객사가 사용하는 기존 Agent/팀 생성 기능과 데이터·동작.
- 범위 밖: 당장의 MCP 서버 구축, 기존 생성 기능의 일괄 교체.

## 상태

- 확보: 회의 Builtin의 Tool 계약·HITL·State/Checkpoint 분리·Trace 구현 및 관련 검증.
- 재사용 후보: 범용 실행 제어, HITL 대기/재개, Tool 결과에 따른 진행·대기·종료, 보안·관측 계약.
- 미구현: 신규 생성 화면, 범용 템플릿 Runtime, 팀 관계 설정·실행.
- 미확인: 기존 공용 코드의 재사용 범위와 Builtin 의존성, 신규 Provider 연결·권한·저장 구조.

## 상황

- 사용 방식: 커뮤니티 내 Agent를 생성해 채널에서 사용하고, 필요할 때 연결하여 팀을 구성한다. 실제 접근 범위는 기존 권한 구조를 조사해 확정한다.
- 기존 고객 보호: Agent 만들기 화면의 토글로 신규 화면에 진입한다. 팀 만들기도 이후 별도 토글로 확장한다.
- 관계 설정: Agent 생성에 `orchestrator` 항목을 두지 않는다. 팀 구성 화면에서 상하·선후 관계와 실행 규칙을 설정한다.
- 공통 실행: 검증된 범용 Harness 기능은 기본 실행 기반에 포함한다. 업무별 판단·상태 전이는 가능한 한 Tool이 담당한다.
- Provider: SAP에 고정하지 않고 엔드포인트·모델·인증 설정으로 연결한다. 임의 URL 접근과 키 보관의 보안 경계를 검증한다.
- MCP: 서버 구축은 장기 과제다. 지금은 향후 MCP 연결이 가능한 계약과 로컬 어댑터를 사용한다. 실제 서버·분산 처리를 구현한 것으로 간주하지 않는다.
- **진행 순서: 먼저 에이전트 부분만 구현해 잘 동작하는지 확인한 뒤, 팀 에이전트 부분을 추가하고 다시 검증하는 방식으로 차근차근 진행한다.**

## 차이와 판단

- 차이: 특정 Builtin 구현을 설정으로 생성 가능한 공통 실행 기반으로 옮겨야 한다.
- 계약: Tool 허용 여부는 Harness/Platform이 강제한다. Tool 의미는 name·description·JSON Schema로 전달한다. 사용자 System Prompt는 역할·말투·업무 선호·응답 형식을 자유롭게 작성한다.
- 저장: Agent State·Tool State·Checkpoint 책임을 분리한다. 미래 템플릿은 `agent_runs.builtin_checkpoint` 호환 경로를 전제로 하지 않는다. 물리 테이블은 조사 후 결정한다.
- Trace: 요청부터 최종 종료까지 동일한 관측 계약을 적용한다. 호출자 전용·민감정보 제외 원칙을 유지하고 팀 관계 및 보관 구조는 해당 단계에서 구체화한다.

## 행동 플랜

| 단계·행동 | 목적 | 산출물·완료 기준 |
| --- | --- | --- |
| 1. 기존 생성·Runtime·권한 조사 | 고객 기능 보존과 재사용 범위 확인 | 공용/Builtin 전용/신규 필요 기능 대응표 |
| 2. 단독 Agent 계약 결정 | Prompt·Tool·Policy·Provider·저장 책임 분리 | 최소 설정 항목과 실행/보안 계약 |
| 3. 신규 Agent 화면·실행 구현 | 토글로 독립 진입, 공통 Harness 기본 제공 | 기존 기능을 유지하는 단독 Agent 생성·실행 |
| 4. 단독 Agent 검증 | 팀 확장 전 기반 확인 | 성공·실패·취소·HITL·권한·Provider 오류·Trace/만료 E2E 및 기존 기능 회귀 |
| 5. 팀 관계·실행 규칙 결정 | 개별 Agent 정의와 팀 내 역할 분리 | 관계도, 입력/결과 전달, 실패·재개·종료 규칙; 순환·권한 검증 기준 |
| 6. 신규 팀 화면·실행 및 검증 | 검증된 Agent들을 연결 | 팀 토글·관계 설정·실행, 분기 실패/HITL/취소·Trace 관계 E2E 및 단독 실행 회귀 |

- 진입 조건: 4단계 검증을 마친 뒤 5~6단계에 착수한다.
- 각 단계에서 상세 설계·테스트 결과를 갱신한다. MCP 서버는 별도 합의 후 추진한다.
