# 회의 Builtin 업무 정책 분리와 테스트 결과

> **2026-10-02 구현 기록.** 템플릿을 만들기 전에 회의 Builtin의 업무 판단과 DB의 저장 책임을 정리했다. **스킬·템플릿 자체를 구현한 것은 아니다.**

## 1. 무엇을 수정했나?

**업무 판단은 TypeScript 코드가 결정하고, DB는 권한과 저장 안전성을 계속 강제한다.**

| 항목 | 이전 | 변경 후 |
| --- | --- | --- |
| **종료 안내 문구** | 코드에서 만든 문구를 SQL이 다시 덮어쓰는 경로 존재 | `terminal-policy.ts`에서 결정. adapter와 초기화 전 cleanup에서 재사용 |
| **완료 / 사용자 선택 대기** | SQL이 `pendingHitl`을 해석 | 코드가 `turnStatus: done / hitl_waiting`을 전달하고 DB가 검증·저장 |
| **업무 상태 검증** | 저장 단계의 DB 검증에 일부 의존 | 기존 `parseState`로 저장 전 검사. checkpoint의 알 수 없는 key·잘못된 UUID·배열형 mode 등을 거절 |
| **migration** | 과거 정의 누적 | 새 `0093_meeting-policy-boundary.sql` 추가. 과거 migration은 수정하지 않음 |

예를 들어 timeout 문구는 **“처리 시간 제한을 초과했습니다.”**로 코드가 결정한다. 회의 이외 Builtin의 기존 기본 안내는 유지했다.

## 2. DB에 남긴 것은?

- **현재 사용자·문서 접근권한**, worker claim·slice 검증.
- **잠금·CAS**: 동시에 실행되거나 오래된 worker가 저장하는 상황 방지.
- **원자적 저장**: 상태·HITL 정리·답변·cursor·실행 종료를 같은 transaction에서 확정.
- **실패·취소 시 마지막 정상 상태 보존**, 중복 게시 방지.
- **구 checkpoint 호환**: `turnStatus`가 없으면 기존 방식으로 해석.

**“SQL을 전부 코드로 옮겼다”가 아니라 “업무 정책만 분리하고 DB 보호는 보존했다”가 정확하다.**

## 3. 무엇을 테스트했나?

| 검사 | 결과 |
| --- | --- |
| **check / lint / knip / Builtin 생성물 검사** | 통과. lint 오류 0, 기존 경고 13 |
| **자동 테스트** | Linux 4,666건 + Windows bootstrap 19건 = **4,685건 통과**, 기존 조건부 skip 27건 |
| **DB 통합 테스트** | 명시/구 checkpoint, 중복 종료, 잘못된 claim/community, 문서 권한 회수, 게시 실패 rollback |
| **브라우저 E2E** | 검색 → 번호 선택 → 최종 답변, 후속 질문, 추가·대체, 두 선택 구간 취소 |
| **오류·기존 기능 회귀** | timeout 문구 → 재질문 성공, 일반 Agent 생성·등록·호출, background 저장·결과 전달 |

**검증 한계:** 브라우저는 실제 UI·worker·폐기용 PostgreSQL에 **로컬 모의 LLM**을 연결했다. 실제 SAP/Codex-LB 응답 품질·음성 전사·교차 모델 evaluator는 검증하지 않았다. background는 실제 로컬 계산 저장과 모의 문장 전달을 확인했으며, 모델의 계산 해석 품질 검증은 아니다. 과거 DB upgrade 후 유효 terminal 호출을 별도 fixture로 묶은 검증도 남아 있다.

## 4. 현재 적용 상태와 다음 단계

**검증 당시 운영/공유 DB 적용, 커밋·푸시·merge는 하지 않았다.** 이후 적용 시 migration과 worker 코드를 함께 배포해야 한다. migration만 먼저 적용하면 구 worker의 안내 문구가 달라질 수 있다.
