# ZEN AI의 현재 상황과 공지사항 방향

ZEN AI는 SAP를 이용하는 고객사와 우리 회사의 임직원이 채팅방에서 업무용 AI 에이전트를 사용하는 커뮤니티 기반 풀스택 서비스다. 개발자는 업무에 도움이 되는 에이전트를 만들고 사용 권한을 부여하며, 사용자는 익숙한 채팅 환경에서 해당 에이전트를 호출해 업무를 수행한다.

공지사항은 이러한 사용자에게 새 에이전트와 기존 에이전트의 개선점을 알리는 역할을 한다. 첫 화면에서는 무엇이 달라졌고 어떻게 사용할 수 있는지를 짧게 전달하고, 자세한 설명은 클릭해서 확인하도록 하는 방향을 지향한다.

## ZEN AI의 서비스 구조

### 커뮤니티를 기준으로 분리되는 이용 환경

관리자(admin)는 고객사 사용자 또는 우리 회사의 임직원을 특정 커뮤니티에 초대할 수 있다. 각 커뮤니티는 SAP BTP의 Global Account에 비유할 수 있는 독립적인 이용 단위다. 커뮤니티별로 사용 환경이 분리되어 다른 커뮤니티에 영향을 미치지 않는다.

사용자는 자신이 초대된 커뮤니티에 접속한다. 접속 후에는 Discord와 유사한 UI에서 채팅과 협업 기능을 이용한다. 사용자 간 소통과 협업은 같은 커뮤니티 안에서 이루어진다.

### 채팅과 회의록을 통한 협업

커뮤니티의 사용자는 자유롭게 채팅방을 만들고 같은 커뮤니티의 다른 사용자를 초대할 수 있다. 다이렉트 메시지(DM)를 통한 1대1 채팅도 가능하다. 다른 커뮤니티의 사용자와는 이러한 방식으로 소통하지 않는다.

회의록 녹음 기능도 내장되어 있다. 사용자는 녹음한 회의록을 원하는 채팅방에 공유할 수 있으며, 공유받은 사람만 해당 회의록을 편집할 수 있다.

이러한 채팅과 협업 기능은 Discord나 Slack과 유사한 사용 기반을 제공한다. 이 환경 안에서 업무용 AI 에이전트를 함께 사용할 수 있다는 점이 ZEN AI의 핵심이다.

## 에이전트를 중심으로 하는 핵심 사용 흐름

개발자는 특정 커뮤니티에서 업무에 도움이 되는 에이전트를 만들고, 원하는 사용자에게 사용 권한을 부여한다. 권한을 받은 사용자는 해당 에이전트를 채팅방 채널에 초대해 사용할 수 있다.

에이전트의 사용 흐름은 다음과 같다.

1. 개발자가 특정 커뮤니티에 에이전트를 만든다.
2. 개발자가 해당 에이전트를 사용할 사람들에게 권한을 부여한다.
3. 권한을 받은 사용자가 에이전트를 채팅방 채널에 초대한다.
4. 사용자가 `@` 멘션으로 에이전트를 호출하고 업무를 요청한다.
5. 호출한 메시지를 시작점으로 스레드가 생성되며, 별도의 에이전트 세션이 만들어진다.
6. 사용자는 그 스레드에서 해당 에이전트와 계속 상호작용한다.

**개발자가 고객사와 임직원의 업무에 도움이 되는 에이전트를 제공하고, 사용자가 ZEN AI의 채팅방에서 이를 이용하는 것**이 서비스의 중심이다. 채팅방과 스레드는 사람 사이의 협업 공간이면서 에이전트에게 일을 요청하고 결과를 이어서 확인하는 공간이다.

## 주요 이용자와 정보 요구

주요 이용자는 SAP를 이용하는 고객사 사용자와 우리 회사의 임직원으로 상정한다. AI나 에이전트에 관한 지식이 거의 없는 사용자도 이용할 수 있어야 한다.

공지사항을 설계할 때는 사용자가 AI나 에이전트의 원리를 깊이 이해하기보다, 자신의 업무에 어떤 기능을 사용할 수 있고 무엇이 개선되었는지를 간단히 알고 싶어 한다는 전제를 둔다.

이용자가 공지에서 우선 확인하려는 내용은 다음과 같다.

- 새로 사용할 수 있는 기능이나 에이전트는 무엇인가.
- 기존에 사용하던 기능은 무엇이 좋아졌는가.
- 해당 기능을 어떻게 사용할 수 있는가.

기술적 배경이나 상세한 설명이 필요한 사용자는 추가로 들어가서 읽을 수 있어야 한다. 모든 사용자에게 처음부터 같은 깊이의 이해를 요구하지 않는다.

## 공지사항이 필요한 현재 상황

ZEN AI의 기초적인 서비스 뼈대는 마련되어 있지만, 개발자가 새 에이전트를 만들거나 기존 에이전트를 개선해도 별도로 알리지 않으면 사용자가 변경 사항을 알기 어렵다. 에이전트를 제공하는 것과 사용자가 그 존재와 활용 방법을 아는 것은 별개의 문제다.

따라서 UI 안에서 업데이트를 발견할 수 있는 공지사항 항목이 필요하다. 공지의 주된 내용은 새로운 에이전트의 소개와 기존 에이전트의 개선점이 될 가능성이 높다.

공지사항은 사용자가 변경 사항을 빠르게 파악하고 실제 사용 방법을 이해하도록 도와야 한다.

## 공지사항의 정보 전달 방향

### 첫 화면은 짧고 핵심적으로 구성

공지사항의 첫 화면은 정보 밀도를 낮게 유지한다. 각 공지에는 어떤 업데이트인지, 무엇을 할 수 있는지, 어떻게 사용하는지를 간단한 몇 줄로 전달한다.

새 에이전트 공지에서는 이름과 함께 어떤 업무에 도움이 되는지를 설명한다. 기존 에이전트의 업데이트 공지에서는 사용자가 체감할 개선점을 중심으로 설명한다. 표현은 AI 지식이 거의 없는 사용자도 이해할 수 있는 쉬운 말로 쓴다.

### 자세한 설명은 클릭해서 확인

추가 설명은 공지를 클릭한 뒤 확인하도록 구성한다. 상세 화면에서는 첫 화면의 짧은 설명만으로 충분하지 않은 사용자를 위해 구체적인 사용 방법과 변경 내용을 제공한다.

첫 화면과 상세 화면의 역할은 다음과 같이 나눈다.

- **첫 화면:** 무슨 업데이트가 있고, 어떤 업무에 도움이 되며, 어떻게 사용하는지를 빠르게 파악한다.
- **상세 화면:** 필요한 사용자가 구체적인 사용 방법과 변경 내용을 더 자세히 확인한다.

이용자가 공지사항을 읽기 위해 AI나 에이전트의 구조부터 학습할 필요는 없어야 한다. 공지사항은 사용자가 필요한 기능을 발견하고 이용하는 데 필요한 정보를 우선 제공한다.
