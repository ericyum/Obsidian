# ZEN AI 튜토리얼 UI 비교와 권장 방향

튜토리얼의 목표는 **에이전트 초대 → @로 요청 → 스레드에서 결과 확인**이라는 공통 사용법을 익히는 것이다. 기본 화면 소개, 실제 조작을 돕는 실습, 필요할 때 재개하는 흐름을 연결한다.

공지는 에이전트별 기능·활용 예시·얻을 결과를 설명하고, **튜토리얼은 여러 에이전트에 공통으로 적용되는 기본 조작법을 담당한다.** 새 공지를 읽을 때마다 전체 온보딩을 반복하지 않는다.

기준: [현재 상황과 서비스 구조](<../00. ZEN AI의 현재 상황과 공지사항 방향.md>) · [튜토리얼 UI 조사](<../../01. UI 조사/02. 튜토리얼 UI.md>).

## ZEN AI 상황에서의 판단 기준

| 사용자와 서비스의 조건 | 튜토리얼의 방향 |
| --- | --- |
| AI에 익숙하지 않은 직원도 사용한다. | 개념 설명보다 업무 결과와 다음 행동을 알려준다. |
| 에이전트의 기본 사용 흐름은 공통이다. | 초대·멘션·스레드를 익히고 다른 에이전트에도 응용한다. |
| 에이전트별 준비 자료·권한은 다를 수 있다. | 접근 가능한 실습을 제공하고 필요한 조건만 짧게 안내한다. |
| 업무가 목적이며 긴 안내를 부담스러워할 수 있다. | 설명을 줄이고 건너뛰기·힌트·FAQ를 제공한다. |
| 실습 도중 중단하거나 나중에 다시 찾을 수 있다. | 진행 위치를 유지하고 재진입 경로를 명확히 한다. |

## 우선 참고할 사례와 채택 범위

### 키안닷컴 · 기본 화면 소개

**짧은 환영 카드, 시작·건너뛰기 선택, 진행 표시와 다시 찾는 위치 안내를 채택한다.** 긴 화면 투어를 그대로 반복하지 않는다.

![키안닷컴의 환영 카드와 시작·건너뛰기 선택](<../../01. UI 조사/튜토리얼 조사 자료/2026-10-14/사용자 제공 예시/00-kian-welcome.png>)

### Driver.js · 실제 조작 안내

**현재 대상 강조와 숫자 진행 표시를 채택하고, ZEN AI에서는 실제 초대·요청·결과 확인 행동에 따라 진행한다.**

![Driver.js의 대상 옆 안내와 숫자 진행 표시](<../../01. UI 조사/튜토리얼 조사 자료/2026-10-14/02-driver-progress.png>)

두 방식은 소개와 실습이라는 서로 다른 역할이므로 두 HTML 모두에 포함한다. 조사 화면은 참고 사례이며, 라이브러리 도입이나 외부 서비스의 완료 판정을 그대로 적용한다는 뜻은 아니다.

## 두 HTML의 안내 위치 비교

| 시안 | 평소 안내 위치 | 사용자 입장에서의 장점 | 고려할 점 |
| --- | --- | --- | --- |
| [1. 사이드바형](<튜토리얼 HTML 시안/01-체크리스트와-실습.html>) | 채널 옆 패널에 현재 행동·전체 순서·진행 상태 | **현재 할 일과 남은 과정을 함께 파악한다.** | 채널 너비를 사용한다. 작은 화면에서는 채널 위로 이동한다. |
| [2. 상단 바형](<튜토리얼 HTML 시안/02-화면-위치-안내.html>) | 채널 위 바에 현재 단계·설명·행동 | **채널 너비를 유지하면서 짧은 안내를 따른다.** | 상단 안내가 세로 공간을 사용한다. |

1번을 우선 검토하되, 안내량과 배치는 실제 사용자 의견으로 확인한다. **두 시안의 차이는 안내 위치이며, 소개·실습 기능의 유무가 아니다.**

## 권장하는 튜토리얼 구성

### 1. 소개와 실습

| 구성 | 현재 시안의 방식 | 방향과 의도 |
| --- | --- | --- |
| 기본 화면 소개 | 채널·에이전트·입력창을 짧게 소개하고 건너뛰기 제공 | 처음부터 모든 메뉴를 학습하게 하지 않는다. |
| 첫 실습 | 샘플 자료로 초대 → @요청 → 스레드 열기 → 결과 확인 | **설명을 읽는 데서 끝내지 않고 직접 조작한다.** |
| 두 번째 실습 | 다른 에이전트로 응용하고 설명은 줄이며 필요할 때 힌트 제공 | 공통 사용법을 익혔는지 확인한다. 필수 여부는 사용자 자문 후 정한다. |
| 초록색 대상 강조 | 두 시안의 1·2회차 모두 힌트 없이 현재 조작 대상 표시 | **안내창을 닫아도 어디를 조작할지 찾는다.** |
| 상세 실습 안내창 | 첫 실습에서 자동으로, 두 번째 실습에서는 힌트 요청 시 표시 | 필요한 설명량을 조절한다. 닫아도 일반 안내와 실습은 유지한다. |
| FAQ | 개념·설치·저장·복귀·작업 지속 등은 필요한 순간에 확인 | 첫 실습의 설명량을 줄인다. 실제로 확인된 동작만 안내한다. |

### 2. 중단·재개·완료

| 상황 | 구성 | 방향과 의도 |
| --- | --- | --- |
| 완료 전 중단 | 건너뛰기·나중에 하기, 왼쪽 온보딩 메뉴에서 재개 | 업무 흐름을 존중하고 이어서 할 위치를 남긴다. |
| 온보딩 완료 | 체크리스트의 두 항목 확인 후 사용자가 ‘온보딩 완료’ 선택 | 완료 처리 후 왼쪽 온보딩 메뉴를 숨긴다. |
| 완료 후 재방문 | 프로필 → 설정 → 온보딩에서 소개·실습 다시 열기 | 기존 완료 상태를 유지하면서 다시 참고한다. |

**소개 종료·수동 체크·실습 결과 확인·온보딩 완료는 서로 다른 상태다.** 결과를 확인했다는 표시를 실제 업무 성공이나 답변 정확도의 보증으로 사용하지 않는다.

## 쟁점과 다음 설계에서 정할 사항

### 1. 안내 단계가 많아 사용자가 번거롭게 느낄 가능성

**화면 소개 → 체크리스트 → 첫 실습 → 두 번째 실습 → 완료 확인이 이어지면, 실제 사용자는 귀찮거나 업무를 방해받는다고 느낄 수 있다.** 현재 구성이 적절한 분량인지는 아직 확인하지 않았다.

- **향후 SAP 고객사 사용자와 사내 임직원에게 자문을 구하고 실제 사용 과정을 관찰한다.** 도움이 된 안내, 불필요하게 반복된 단계, 중단하고 싶은 지점을 확인한다.
- 소개 길이, 두 번째 실습의 필수 여부, 확인 클릭 수, 반복 노출 범위를 검토해 **줄일 단계와 선택적으로 제공할 단계를 정한다.** 3~5분은 검증 전 목표다.

### 2. 제품 적용 전에 정할 사항

- 실습 에이전트·샘플 자료·권한을 정하고, 접근 불가·응답 지연·오류 시의 안내와 대체 경로를 준비한다.
- 진행 저장·완료의 근거·새 시도의 이력 보존을 정한다. 재개·재시도가 메시지나 실행을 중복 생성하지 않도록 하고, 복귀 가능성과 백그라운드 실행 지속은 구분해 안내한다.

## 시안의 범위

현재 HTML은 ZEN AI의 화면 틀에 가상 에이전트와 고정 결과를 넣은 시안이다. 실제 AI·로그인·권한·서버 저장은 연결하지 않았으며, 진행은 같은 브라우저의 로컬 저장소에만 남는다. 학습 효과와 적정 안내량은 사용자 검증이 필요하다.
