# 개발자 대시보드 방향과 탭 구성

**기본 화면은 ‘전체 에이전트 비교’로 한다.** 개발자가 먼저 살펴볼 에이전트를 고르고, 문제 실행의 근거를 확인해 다음 개선 작업을 정하는 화면이다. 공지사항은 기능 발견, 튜토리얼은 첫 사용을 돕고, 대시보드는 제공한 에이전트의 운영과 개선을 돕는다.

## 현재 상황과 개발자의 질문

ZEN AI는 SAP 고객사와 사내 임직원이 커뮤니티의 채팅방에서 업무용 에이전트를 사용하는 서비스다. 개발자는 에이전트를 제공하지만, 사용량만으로 결과가 유용했는지 알 수 없고 개별 실행만 읽어서는 어디부터 개선할지 고르기 어렵다.

현재 앱에는 커뮤니티 소유자·관리자가 보는 **실행 이력과 대화·호출 흐름 상세**가 있다. 이를 근거 화면으로 활용하고, 앞에 비교와 우선순위 판단을 돕는 요약을 추가한다.

- 어떤 에이전트가 얼마나 쓰이며, 어느 대상부터 확인해야 하는가?
- 실패하거나 느려진 실행은 무엇이고, 어느 모델·도구 단계와 관련되는가?
- 사용자 평가는 어떠하며, 버전별 차이를 설명할 표본이 충분한가?
- 관측한 사실을 바탕으로 다음에 무엇을 확인하고 바꿔야 하는가?

## 하나의 HTML 안에서 전환하는 세 탭

| 탭 | 화면의 중심 | 개발자 입장에서 얻는 장점 | 한계와 적합한 순간 |
| --- | --- | --- | --- |
| 전체 비교 | 요약 지표, 에이전트 비교표, 기간별 추세 | 같은 조건에서 사용량·실패·지연을 비교해 **오늘 볼 대상을 빨리 고른다**. 여러 개의 상세를 따로 열 필요가 줄어든다. | 숫자는 원인까지 설명하지 않는다. 매일의 시작 화면에 적합하다. |
| 문제 추적 | 이상 분류 → 해당 실행 목록 → 호출 타임라인 | 높은 실패율이나 긴 실행을 **실제 질문·응답·도구 단계로 확인한다**. 요약과 개별 근거 사이의 이동이 짧다. | 이미 조사할 문제가 있을 때 강하다. 전체 사용 추세를 훑는 첫 화면으로는 복잡하다. |
| 개선 검토 | 관측 근거·가설·다음 확인 카드, 같은 기간의 버전별 표본 | 숫자를 읽고 끝내지 않고 **검토할 작업을 정한다**. 관측 사실과 해석을 나눠 팀 논의에 사용하기 쉽다. | 우선순위와 원인은 확정 판정이 아니다. 표본이 적으면 결론을 유보해야 한다. |

[대시보드 HTML](<대시보드 HTML 시안/01-전체-에이전트-비교형.html>) 하나에서 세 탭을 모두 사용한다. 기존 2·3번은 시작 탭만 달랐으므로 정리했다.

## 권장 사용 흐름

**전체 비교를 기본으로 열고 → 의심되는 행에서 문제 추적으로 확인 → 반복되는 문제를 개선 검토의 항목으로 정리한다.** 세 탭은 한 대시보드 안에서 서로 다른 분석 단계로 이어진다.

첫 화면은 비교표를 가장 크게 배치한다. 기간·커뮤니티·집계 기준을 공통으로 유지하고, 요약 지표와 추세는 비교표를 해석할 정도로만 둔다. 비용·정확도·자동 개선 기능을 근거 없이 채워 넣지 않는다.

## 시안을 읽을 때

모든 수치는 **합성 예시 데이터**다. 초기 비교 대상은 사용자 에이전트(custom)이며 내장 에이전트는 포함하지 않는다. 커뮤니티 선택은 독립된 가상 데이터셋 전환 예시이고, 실제 권한 확대를 뜻하지 않는다. 현재 운영 조회 권한은 해당 커뮤니티의 소유자·관리자다.

집계 단위는 **실행 Run**이다. 실행 완료는 업무 성공과 다르며, 적은 사용량은 낮은 품질을 뜻하지 않는다. 이 HTML은 화면 검토용으로 실제 집계 API나 운영 기능을 구현한 결과가 아니다. 자세한 정의는 [지표 정의와 구현 전 확인사항](<03. 지표 정의와 구현 전 확인사항.md>)을 따른다.
