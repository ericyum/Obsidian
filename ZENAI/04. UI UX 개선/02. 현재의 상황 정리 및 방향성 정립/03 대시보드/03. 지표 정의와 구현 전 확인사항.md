2026-10-15 로컬 소스·문서를 확인한 설계 기준이다. 운영 배포·실제 수집률을 검증한 결과는 아니다. 단일 HTML의 세 탭은 사용자 에이전트(custom)의 **가상 Run 데이터**를 사용하며, 실제 지표 집계 기능과 연결하지 않는다.

## 지표의 단위와 계산

| 항목 | 이번 설계 기준 |
| --- | --- |
| 기간 | Run 생성 시각 기준으로 선택한다. 기간·시간대·집계 기준 시각을 표시하고 카드·표·차트에 같은 조건을 적용한다. |
| 실행 수 | 기간 안 Run 행 수. 사용자 요청 수·업무 해결 건수로 부르지 않는다. |
| 실패율 | `failed / (done + failed)`와 분자·분모를 함께 표시한다. 취소·대기·실행 중은 별도로 표시한다. 분모가 없으면 ‘—’다. |
| 기술적 완료 | `done`. 답변 게시 또는 실행 조각의 완료이지 정확도·업무 해결의 보증이 아니다. |
| 소요 시간 | 시안은 `done + failed` 중 `durationMs`가 기록된 실행의 p95와 유효 표본 수를 표시한다. 오름차순 표본의 `ceil(0.95 × n)`번째 값이다. 운영 연결 시 p50 추가를 검토한다. 요청 제출부터 화면 표시까지의 전체 체감 시간은 아니다. |
| 사용자 평가 | 👍/👎 수, 평가된 Run 수/전체 Run 수를 함께 표시한다. 시안 표본은 Run당 평가 하나다. 실제 서비스에서는 한 Run에 여러 평가자가 있을 수 있어 평가 수와 평가된 실행 수가 다르다. |
| 기록된 토큰 | 시안은 기록된 입력·출력 토큰의 합계와 기록이 있는 실행 수를 표시한다. 운영 화면에서는 입력·출력을 구분하는 것이 권장된다. 미기록·일부 수집은 0으로 대체하지 않는다. 토큰은 청구 금액이 아니다. |
| 기록 상태 | `captured / partial / not_captured`. 일부 기록만으로 전체 흐름·총소비를 확정하지 않는다. |

한 요청은 여러 Run 조각으로 이어질 수 있다. 사용자 에이전트의 `sliceNo`와 내장 에이전트의 `sliceCount`는 의미가 다르다. `agent_tasks`도 모든 요청을 포괄하는 원장이 아니라 스레드+에이전트의 작업 공간이며, 후속 요청에서 재사용된다. **요청 단위 지표는 연결 규칙을 정의한 뒤 추가한다.**

## 현재 데이터로 가능한 범위

| 구분 | 항목 | 남은 일 |
| --- | --- | --- |
| 현 데이터로 가능 | 개별 실행의 상태·버전·모델·질문/답변·시간·기록된 토큰·평가·호출 흐름 | 기존 실행 이력과 상세를 재사용한다. 삭제·잘림·누락 표시를 유지한다. |
| 집계 필요 | 에이전트별 실행·실패율, 추세, p50/p95, 고유 호출자, 평가 참여율, 기록된 토큰 합계 | 기간 전체를 대상으로 서버 집계 계약을 추가한다. 현재 목록의 25~50개만 합산하지 않는다. |
| 집계·조회 확장 필요 | 도구별 오류/소요, 버전별 동일 기간 비교 | Span·실패 이벤트를 정규화하고 표본·종류·모델 조건을 유지한다. 중첩 Span 시간을 전부 더하지 않는다. |
| 추가 연결·계측 필요 | 요청 단위 최종 결과, 전체 사용자 대기 시간, 사용 전환, 업무 해결률·절약 시간 | 요청 연결키·결과 전달 시각·노출/권한 모집단·업무 성공 판정이 필요하다. |
| 추가 계측 필요 | 금액 비용·예산·ROI | 시점별 단가·통화·토큰 종류·캐시·수집 범위를 정의한다. 미산정을 0원으로 표시하지 않는다. |

현재 이력 API는 목록·상세이며, `taskId`·`sliceNo`를 반환하지 않는다. Run별 실패 사유도 목록의 구조화된 필드가 아니므로 ‘실패 원인 순위’에는 별도 조회 계약이 필요하다.

## 비교를 잘못 읽지 않기 위한 조건

- **낮은 사용량 ≠ 낮은 품질.** 활성 상태·권한 부여·공지 노출·업무 빈도부터 확인한다. 사용 0, 수집 없음, 접근 불가를 구분한다.
- **평가 없음 ≠ 불만족.** 현재 평가 입력은 custom 실행의 채널 멤버에게 허용된다. 내장 에이전트와 같은 평가 기준으로 비교하지 않는다. 동일 평가를 다시 누르면 취소되고, 사용자·Run당 하나다.
- **토큰 0도 원천 확인이 필요하다.** Trace는 미제공 값을 null로 다루지만 기존 usage 변환에는 `?? 0` 경로가 있다. 이미 저장된 0에서 미반환 여부를 복원할 수 없다.
- **전후 차이 ≠ 변경 효과 확정.** 같은 기간에도 버전별 업무 난도·모델·사용자 구성이 다를 수 있다. 표본 수와 평가 참여율을 함께 제시한다.
- **개선 카드는 검토 후보다.** 관측한 사실 → 가설 → 다음 확인을 분리한다. 기존 👎 기반 개선 제안 코드가 있어도 자동 평가·자동 안전 배포가 된다는 뜻은 아니다.

## 권한과 운영 연결 전 확인

1. 조회자는 활성 커뮤니티의 owner/admin 멤버여야 한다. 플랫폼 관리자·지원 세션·에이전트 제작자라는 이유만으로 실행 원문 접근을 허용하지 않는다. 커뮤니티 간 합산은 별도 권한 계약 없이 추가하지 않는다.
2. 원본 삭제에 따른 `contentRedacted`와 비밀값 가림·잘림을 그대로 적용한다. 숨겨진 호출자·질문·답변·평가 메모를 추정해 복원하지 않는다.
3. 이력 마이그레이션의 실제 운영 적용, 경로별 수집률, 집계 갱신 주기·시간대·큰 기간 조회 성능을 확인한다.
4. 회의 원본 삭제와 저장된 추적 사본 삭제는 현재 연결되지 않으며 자동 보존기간 정책도 없다. 운영 상세·내보내기를 넓히기 전 보존·삭제 범위를 결정한다.
