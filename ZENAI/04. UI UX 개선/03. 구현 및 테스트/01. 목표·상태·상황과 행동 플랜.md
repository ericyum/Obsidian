# 공지사항·튜토리얼 구현 행동 플랜

> **목표:** 사용자가 새 에이전트의 업무 효과를 이해하고, 실제 AI 답변을 안전하게 체험한다.
> **상태:** UI 시안과 설계는 확보했으나 제품 기능·진행 저장·전용 Builtin은 아직 미구현이다.
> **상황:** 고객사별 커뮤니티가 분리된 서비스가 운영 중이므로, 기존 채팅·회의·에이전트와 운영 데이터를 보존해야 한다.

## 1. 목표

| 항목     | 완료 기준                                                                             |
| -------- | ------------------------------------------------------------------------------------- |
| 공지사항 | **업무 효과·질문·결과 예시를 카드 첫 화면에서 확인**하고 관리자가 배포 없이 게시·회수 |
| 튜토리얼 | **우측 체크리스트와 초록 강조**를 따라 개인 연습방에서 실제 AI 답변·후속 질문 체험    |
| 재접속   | 서버의 계정별 진행을 사용해 **이미 소개를 본 계정에 자동 소개를 반복하지 않음**       |
| 안전     | 운영 배포·운영 DB 변경 없이 **격리된 로컬 앱·DB·합성 계정**으로 검증                  |
| 검증     | 기준↔테스트 매핑, 하네스 게이트·교차 검토, 실제 브라우저 E2E와 증거 기록              |

보존할 것은 커뮤니티 격리·권한, 기존 채팅·회의/SAP 에이전트, Builtin 실행의 취소·기한·중복 방지다. 이번 작업에 운영 배포·main 병합·실제 동료 초대·실제 업무 데이터 사용은 포함하지 않는다.

## 2. 현재 상태

| 확보한 것                  | 재사용                                | 아직 필요한 것                                    |
| -------------------------- | ------------------------------------- | ------------------------------------------------- |
| 공지 카드형 HTML·비교 문서 | 화면 구성과 선택 이유                 | DB·목록/상세·작성/게시 화면                       |
| 튜토리얼 우측 바 HTML      | 소개·체크리스트·실습 강조             | 서버 진행·개인 연습방·실제 성공 판정              |
| 회의 Builtin·템플릿        | 공통 worker·도구 대화·스킬·Trace·권한 | 연습 도우미의 정의·프롬프트·가상 자료 도구·어댑터 |
| 기존 설계·실행 계획        | 공지/튜토리얼 계약·테스트 목록        | 첫 방문 UI와 전체 흐름을 잇는 통합 조건           |

구현 기준 커밋은 **3376d89**다. 원래 작업 폴더의 추론 표시·실행 제한 관련 미커밋 변경은 이번 구현에 섞지 않는다. 새 작업 공간에서 기존 기준을 먼저 검사한다. 이전 작업의 통과 기록을 이번 구현의 성공 근거로 재사용하지 않는다.

## 3. 제품과 운영 상황

| 상황                                           | 구현에 주는 제약                                              |
| ---------------------------------------------- | ------------------------------------------------------------- |
| 사용자: SAP 고객사·임직원, AI 지식이 많지 않음 | 기술 용어보다 **도움받는 업무와 결과** 중심                   |
| 커뮤니티별 고객사 데이터 격리                  | 모든 공지와 연습방의 커뮤니티를 서버가 확인                   |
| 공개 채널과 실제 동료가 이미 사용 중           | 가입·직원 초대는 **모의 안내**, 실제 데이터 변경 없음         |
| 에이전트 사용에는 설치·부여·채널 초대가 필요   | 기존 권한 사용, 사용자 요청으로 관리자 권한 우회 금지         |
| 동일 계정이 여러 기기·커뮤니티 이용            | 계정 공통 소개/진행과 커뮤니티별 연습방을 분리                |
| 운영 서버가 계속 서비스 중                     | 기존 환경 파일·컨테이너·배포 설정 변경 금지, 새 기능 기본 OFF |

## 4. 차이와 판단

![](Excalidraw/01-목표에서-검증까지.svg)

| 차이                                      | 판단                              | 이유                                        |
| ----------------------------------------- | --------------------------------- | ------------------------------------------- |
| 시안은 고정 데이터, 제품은 지속 운영 필요 | 공지 전용 테이블과 관리 화면 추가 | 게시할 때마다 코드 배포하지 않기 위해       |
| 시안 답변은 샘플, 실제 AI 경험 필요       | Builtin 연습 도우미 추가          | 기존 실행 기반을 쓰면서 실제 모델 응답 체험 |
| 로그인 기록만으로 경험 여부 판정 불가     | 소개 확인·진행·완료를 서버 저장   | 재로그인·다른 PC에서도 동일하게 판단        |
| 실채널 가입·동료 초대가 부담              | 모의 안내와 사용자 전용 비공개 방 | 타인과 기존 업무에 영향을 주지 않기 위해    |
| 새 기능의 운영 영향 검증이 없음           | 기본 OFF + 별도 작업 공간·DB·포트 | 완료 전 운영 노출과 데이터 혼입 차단        |

**1회차의 실제 답변과 같은 스레드 후속 질문을 기본 완료 조건으로 제안한다. 2회차는 ‘한 번 더 연습’으로 제공하고 초록 강조를 다시 표시한다.** 강제 단계 수는 사용자 자문에 따라 조정한다. 건너뛰기·나중에 하기·다시 열기를 제공하되, 건너뛰기를 실제 체험 완료로 기록하지 않는다.

## 5. 행동 플랜

| 순서 | 행동                     | 목적                            | 산출물·통과 조건                                  |
| ---- | ------------------------ | ------------------------------- | ------------------------------------------------- |
| 1    | 자료·현재 코드·환경 확인 | 출발점과 운영 경계 확정         | 이 문서·격리 환경·기준 검사 결과                  |
| 2    | 요구와 기존 기반 대응    | 새로 만들 부분 최소화           | 다음 설계 문서·Excalidraw 그림·권한/상태 표       |
| 3    | 공지사항 구현            | 카드와 게시 운영 완성           | 전용 DB·API·사용자/관리자 화면·테스트             |
| 4    | 연습 Builtin 구현        | 실제 AI 응답 경로 완성          | 정의·스킬·도구·어댑터·회귀 검증                   |
| 5    | 첫 방문·우측 바 연결     | 저장·재개·체험을 실제 UI로 연결 | 계정 진행·개인 연습방·첫/두 번째 실습 강조        |
| 6    | 격리 환경 E2E            | 사용자 행동으로 완료 기준 확인  | 브라우저 스크린샷·실제 run/DB 증거·실패/한계 기록 |

각 소스 변경은 **intent → 테스트 매핑 → 저장소 하네스 → 게이트·evaluator → draft PR** 경로를 따른다. 문서 작성 이후 구현까지 진행하라는 이번 요청을 실행 근거로 삼는다. 운영 배포·main 병합은 이 경로의 자동 후속 작업으로 실행하지 않는다.
