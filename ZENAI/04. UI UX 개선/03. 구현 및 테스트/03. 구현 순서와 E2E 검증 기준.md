## 1. 실행 순서

| 순서 | intent                    | 구현 범위                                                        | 검증                                         |
| ---- | ------------------------- | ---------------------------------------------------------------- | -------------------------------------------- |
| A    | `community-announcements` | 기능 OFF 기본값·공지 DB/RLS·API·카드/상세·관리 화면              | 격리·게시 상태·권한·미리보기·복사            |
| B    | `tutorial-builtin-agent`  | 가상 자료 Builtin·공통 실행 재사용·등록/초대/답변                | 스킬·도구·취소·권한·회귀·실제 AI             |
| C    | `tutorial-onboarding`     | 기능 OFF 기본값·계정 진행·첫 소개·개인 방·우측 안내·1/2회차 강조 | 새로고침·재로그인·실제 완료 근거·부정 테스트 |

**실행 조정:** B→C의 구현 순서를 유지하되 `tutorial-experience` 하나의 intent로 연결한다. Builtin과 우측 안내가 함께 있어야 실제 체험을 검증할 수 있기 때문이다. B/C 수용 기준 13개와 전체 게이트·교차 모델 판정은 모두 유지한다.

**각 변경은 테스트 red → 구현 green → check/lint/knip/vitest → evaluator 순서다.** 운영 배포와 main 병합은 하지 않는다. 이미 있는 다른 작업을 이번 커밋에 포함하지 않는다.

## 2. 테스트 환경

| 대상 | 전용 환경                                                                           |
| ---- | ----------------------------------------------------------------------------------- |
| 소스 | Codex managed worktree `ui-ux-onboarding-announcements/zen-ai`                      |
| DB   | 새 컨테이너 `zen-ai-uiux-test-20261020`, localhost:55436                            |
| 앱   | localhost:3047 예정. 이미 사용 중이면 빈 포트로 조정 후 결과에 기록                 |
| 계정 | 가상의 관리자·일반 멤버·타 커뮤니티 멤버                                            |
| 자료 | 공개 문서나 실제 회사 자료가 아닌 고정 가상 업무 메모                               |
| AI   | 기존 로컬 모델 게이트웨이 사용. 실제 모델 응답과 고정 transport fixture를 구분 기록 |

운영 DB 주소·키·토큰·세션 비밀값은 문서·스크린샷·Git에 기록하지 않는다. 필요 설정은 비추적 로컬 파일에만 저장한다. 실제 사용자 계정에 채널 가입이나 초대를 수행하지 않는다.

## 3. 실사용 E2E

| ID  | 브라우저에서 할 행동                | 통과 기준                                                      |
| --- | ----------------------------------- | -------------------------------------------------------------- |
| E1  | 관리자로 공지 초안 작성·미리보기    | 카드와 관리 미리보기 동일, 일반 멤버에게 초안 비노출           |
| E2  | 게시 후 일반 멤버로 공지 열기       | **상세 클릭 없이 업무 효과·질문·결과·조건 확인**               |
| E3  | 질문 복사·상세·목록 복귀·수정·회수  | 복사 원문 일치, 수정 반영, 회수 후 일반 상세 접근 거절         |
| E4  | 타 커뮤니티에서 공지/관리 URL 접근  | 내용·초안·작성 권한이 노출되지 않음                            |
| E5  | 처음 보는 계정으로 로그인/접속      | 소개 1회, 나중에 하기 후 반복 팝업 없음, 메뉴 재개 가능        |
| E6  | 모의 채널/초대 안내 진행            | 실제 공개 채널 멤버·동료 초대 데이터 변화 없음                 |
| E7  | 개인 연습방 시작·다시 시작·새로고침 | 같은 비공개 방, 타 사용자 접근 불가, 진행 복원                 |
| E8  | 연습 도우미 초대·멘션·스레드 열기   | 우측 안내와 초록 강조, **실제 AI 답변**과 같은 root의 성공 run |
| E9  | 같은 스레드에서 후속 질문           | 실제 두 번째 응답, 서버에서 기본 체험 완료 확인                |
| E10 | 재로그인·다른 브라우저 세션         | 자동 소개 없음, 서버의 완료 상태 유지                          |
| E11 | 한 번 더 연습 선택                  | 새 root·2회차 초록 강조, 첫 실행 증거 재사용 안 됨             |
| E12 | 모델 실패·권한 해제·취소 조건       | 거짓 완료·늦은 성공 없음, 오류·재시도 안내                     |
| E13 | 기능 OFF                            | 기존 홈·채팅 정상, 새 메뉴·자동 소개·새 API 비노출             |
| E14 | 데스크톱·390px 화면·키보드          | 카드 결과·안내 읽기 가능, 가로 잘림 없음, 초점·닫기·재개 가능  |

보안·동시성·실행 중 권한 해제 등은 자동 통합 테스트로도 검증한다. 브라우저로 하지 않은 항목을 ‘실사용 E2E 통과’라고 기록하지 않는다. 실제 모델 미연결 시 fixture 성공으로 실제 AI 체험을 대체했다고 주장하지 않는다.

## 4. 완료 판정

**문서 작성, 구현 완료, 게이트 통과, 실제 AI E2E, 운영 배포는 서로 다른 상태다.** [결과 문서](04.%20구현%20및%20테스트%20결과.md)에 각각의 상태·명령·근거·스크린샷·미완료 사유를 기록한다.

구현 완료 시 생성된 draft PR을 현재 Codex 작업에 첨부한다. 운영 배포 없이 검토 가능한 상태로 제시하고, 남은 오류나 교차 모델 검토의 한계가 있으면 그대로 기록한다.
