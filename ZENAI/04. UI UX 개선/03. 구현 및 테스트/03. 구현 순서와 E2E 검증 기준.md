## 1. 실행 순서

| 순서 | 구현·검증 내용                                                                                                                      | 현재 상태                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| A    | `community-announcements`: 공지 DB/RLS·API·카드/상세·관리, 게시·격리·권한·복사 검증                                                 | 구현·검증 후 이번 배포에서 제외. 로컬 보관본으로 분리                |
| B→C  | `tutorial-builtin-agent`·`tutorial-onboarding`을 `tutorial-experience`로 통합. 연습 Builtin → 진행 저장·소개·개인 방·우측 안내 연결 | 초기 하네스·독립 검토 후 통합 보완. PR #276 main 반영                |
| D    | main 변경·migration 충돌 결합, HTML 시안 기준 화면 복원, 최신 빌드 Chrome·HTTP/DB·자동 회귀                                         | 버전별 성공·실패·보류를 결과 문서에 분리 기록                        |
| E    | 전체 리뷰에서 fixture DB 대상 검증과 튜토리얼 공용 스킬 실행 연결 수정                                                              | 관련 98개 통과. 일회성 도구와 필수 회귀 테스트 구분·정리             |
| F    | 회의 runtime CI 연쇄 실패 4건의 타이머·HTTP·fixture 종료 처리 안정화                                                                | 관련 82개 통과·기존 skip 1개. 제품의 실제 timeout 경계 문제와 별개   |
| G    | 운영에서 튜토리얼 안내·재진입 미노출 확인 후 전용 활성화 gate 제거                                                                  | PR #277 main 반영. 관련 3개 파일·29개 통과, 최종 운영 화면 재확인 전 |

**초기 실행 조정:** Builtin과 우측 안내가 함께 있어야 실제 체험을 검증할 수 있어 B→C를 하나의 intent로 연결했다. 초기 수용 기준 13개를 유지했고 이후 보완 기준·테스트 매핑을 추가했다. 공지의 보관·복원은 튜토리얼 재진입의 선행 조건이 아니다.

초기 구현은 **테스트 red → 구현 green → check/lint/knip/vitest → evaluator** 순서였다. 이후 통합·리뷰·CI·활성화 수정은 사용자 승인 직접 편집 예외로 진행했다. 초기 ACCEPT와 후속 게이트·부분 회귀를 구별하며 전체 green이나 새 evaluator 판정을 소급해 주장하지 않는다. 커밋·push 이후 사용자가 PR #276·#277을 머지했다.

## 2. 테스트 환경

다음은 **10월 20~21일에 사용한 격리 환경 이력**이다. 상시 실행 환경이나 다시 만들라는 지시가 아니다. 임시 서버·컨테이너는 검증 뒤 정리했으며, 현재 포트·실행 상태를 새로 확인하지 않았다.

| 대상 | 전용 환경                                                                           |
| ---- | ----------------------------------------------------------------------------------- |
| 소스 | Codex managed worktree `ui-ux-onboarding-announcements/zen-ai`                      |
| DB   | 새 컨테이너 `zen-ai-uiux-test-20261020`, localhost:55436                            |
| 앱   | localhost:3047, 합성 세션 프록시3048, 별도 OFF 검증3049를 당시 사용                 |
| 계정 | 가상의 관리자·일반 멤버·타 커뮤니티 멤버                                            |
| 자료 | 공개 문서나 실제 회사 자료가 아닌 고정 가상 업무 메모                               |
| AI   | 기존 로컬 모델 게이트웨이 사용. 실제 모델 응답과 고정 transport fixture를 구분 기록 |

운영 DB 주소·키·토큰·세션 비밀값은 문서·스크린샷·Git에 기록하지 않는다. 필요 설정은 비추적 로컬 파일에만 저장한다. 실제 사용자 계정에 채널 가입이나 초대를 수행하지 않는다.

후속 통합에는 별도 gate/DB 컨테이너 2개를 사용하고 정리했다. 공지까지 검증할 때는 보관 소스를 **격리 사본에만 복원**했으므로 그 E2E 성공을 이번 배포의 공지 제공으로 해석하지 않는다. 실제 Chrome 조작·HTTP/DB 검사·자동 fixture 검사를 결과에서 분리한다.

## 3. 실사용 E2E

E1–E4는 공지 정식 복원 시 다시 실행할 기준이며 현재 배포 완료 조건이 아니다. E5–E12·E13b는 튜토리얼 기준이다. 아래 표는 **검증 기준**이지 모두 최신 버전에서 통과했다는 결과표가 아니다.

| ID   | 브라우저에서 할 행동                | 통과 기준                                                                                                                  |
| ---- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| E1   | 관리자로 공지 초안 작성·미리보기    | 카드와 관리 미리보기 동일, 일반 멤버에게 초안 비노출                                                                       |
| E2   | 게시 후 일반 멤버로 공지 열기       | **상세 클릭 없이 업무 효과·질문·결과·조건 확인**                                                                           |
| E3   | 질문 복사·상세·목록 복귀·수정·회수  | 복사 원문 일치, 수정 반영, 회수 후 일반 상세 접근 거절                                                                     |
| E4   | 타 커뮤니티에서 공지/관리 URL 접근  | 내용·초안·작성 권한이 노출되지 않음                                                                                        |
| E5   | 진행 기록이 없는 멤버로 로그인/접속 | 소개 1회, 나중에 하기 후 반복 팝업 없음. owner/admin/member 모두 메뉴 재개 가능                                            |
| E6   | 모의 채널/초대 안내 진행            | 실제 공개 채널 멤버·동료 초대 데이터 변화 없음                                                                             |
| E7   | 개인 연습방 시작·다시 시작·새로고침 | 같은 비공개 방, 타 사용자 접근 불가, 진행 복원                                                                             |
| E8   | 연습 도우미 초대·멘션·스레드 열기   | 우측 안내와 초록 강조, **실제 AI 답변**과 같은 root의 성공 run                                                             |
| E9   | 같은 스레드에서 후속 질문           | 실제 두 번째 응답, 서버에서 기본 체험 완료 확인                                                                            |
| E10  | 재로그인·다른 브라우저 세션         | 자동 소개 없음, 서버의 완료 상태 유지                                                                                      |
| E11  | 한 번 더 연습 선택                  | 새 root·2회차 초록 강조, 첫 실행 증거 재사용 안 됨                                                                         |
| E12  | 모델 실패·권한 해제·취소 조건       | 거짓 완료·늦은 성공 없음, 오류·재시도 안내                                                                                 |
| E13a | 공지 배포 제외·향후 기능 OFF        | 현재 활성 코드에 공지 연결 없음. 복원 후에는 공지 OFF의 메뉴/API 차단과 기존 채팅 정상 확인                                |
| E13b | 튜토리얼 전용 flag 없이 재진입      | 유효한 현재 커뮤니티의 모든 멤버에게 AI 사용 연습 제공. 완료 기록 유지, 미인증·비멤버 거절. 공통 커뮤니티 설정 자체는 보존 |
| E14  | 데스크톱·390px 화면·키보드          | 카드 결과·안내 읽기 가능, 가로 잘림 없음, 초점·닫기·재개 가능                                                              |

보안·동시성·실행 중 권한 해제 등은 자동 통합 테스트로도 검증한다. 브라우저로 하지 않은 항목을 ‘실사용 E2E 통과’라고 기록하지 않는다. 실제 모델 미연결 시 fixture 성공으로 실제 AI 체험을 대체했다고 주장하지 않는다.

**남은 범위:** PR #277 이후 owner/admin/member의 실제 운영 화면, 첫 방문·완료 계정 재진입은 아직 브라우저로 재확인하지 않았다. 모바일 E14의 수정 후 390px 표시·접기·입력·재개도 데스크톱 우선 요청에 따라 보류했다. 추론 텍스트는 공급자의 공개 추론 이벤트가 반환된 경우와 미반환된 경우를 구별하며, 모든 실행에서 반드시 표시돼야 한다는 기준은 두지 않는다.

## 4. 완료 판정

**문서 작성, 구현 완료, 게이트 통과, 실제 AI E2E, 운영 배포는 서로 다른 상태다.** [결과 문서](04.%20구현%20및%20테스트%20결과.md)에 각각의 상태·명령·근거·스크린샷·미완료 사유를 기록한다.

최신 main 반영 여부는 Git 이력으로, 운영 반영 여부는 배포 실행과 실제 화면으로 따로 확인한다. PR 머지 성공만으로 배포·운영 DB·최종 브라우저까지 검증 완료라고 쓰지 않는다. 관련 29개 통과 같은 부분 검사와 전체 저장소 green도 구별한다. 이번 문서 갱신에서는 새 E2E·제품 게이트·배포를 실행하지 않았다.
