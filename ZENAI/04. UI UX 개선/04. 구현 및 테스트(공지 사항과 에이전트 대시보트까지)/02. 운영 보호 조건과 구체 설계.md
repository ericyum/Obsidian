## 2. 데이터와 판단 범위
| 요소 | 원천 | 연결·표시 원칙 |
| --- | --- | --- |
| KPI·일별/에이전트별/버전별 통계 | agent_runs와 기존 안전한 이력 요약 | **현재 목록 25~50개가 아닌 기간 전체**를 서버에서 집계한다. 현재는 기간 내 실행별 기존 안전 요약을 재사용하므로 **운영 규모 성능은 별도 측정이 필요하다.** |
| 0회 에이전트 | 현재 custom/builtin 목록 + 실행 이력 | 현재 활성 상태와 조회 기간 내 0회를 구분한다. 이력에만 남은 에이전트도 보존한다. |
| 질문·답변·모델·도구 | 기존 이력 상세·agent_run_spans | 기존 상세 컴포넌트를 재사용하고 삭제·본문 생략·잘림을 유지한다. |
| 실패 원인 | 일반 agent.run_failed / 내장 message.posted의 종료 코드 | 허용된 코드·진단만 표시한다. 원본 payload나 숨겨진 본문을 공개하지 않는다. |
| 토큰 | span 합계, 없으면 usage_events | **기록된 입력/출력 토큰**과 기록 범위를 표시한다. 비용으로 바꾸지 않는다. |
| 피드백 | custom 실행의 사용자별 up/down | 평가 수와 평가된 실행 수를 구분한다. 내장 평가 미지원·미평가는 별도다. |
| 추적 상태 | traceAvailability와 payloadsOmitted | **의도적 본문 생략을 수집 장애로 오인하지 않는다.** 과거 완전성은 복구할 수 없다. |

**실행 건수 = Run 행 수. 실패율 = failed / (done + failed).** 취소·대기·실행 중은 별도로 보고 분모 0은 ‘—’다. p95는 done/failed 중 소요 시간이 있는 표본의 nearest rank이며 n을 표시한다. 날짜는 KST·Run 생성 시각 기준으로 통일하고 기본 7일/14일을 제공한다.

현재 데이터로 **실제 비용·정답률·업무 해결률·첫 응답 시간·공지 효과·버전 변경의 인과 효과**는 제공하지 않는다. 추가 계측을 전제로 한 가상 점수도 만들지 않는다.

## 3. 권한과 운영 보호
| 경계 | 설계 |
| --- | --- |
| 화면·메뉴 | 서버가 해석한 커뮤니티 역할이 owner/admin일 때만 노출한다. |
| API·DB | 기존 실행 이력과 같은 서버 역할 검사 + DB 관리자 검사를 적용한다. 요청의 communityId/agentId로 범위를 넓힐 수 없다. |
| DB 활성화 계약 | 대시보드 집계 함수도 기존 activation의 **정확한 소유자·반환형·STABLE·search_path·실행 권한 검사**에 등록했다. 권한을 넓히지 않고 누락된 계약만 보완했다. |
| 원문 삭제 | 기존 contentRedacted 규칙을 재사용한다. 집계 호출자에서도 숨겨진 ID를 복원하지 않는다. |
| 데이터 양 | 서버 집계는 본문을 브라우저로 전송하지 않는다. 근거 목록은 페이지 단위, 상세는 선택한 실행만 읽는다. |
| 로컬 적용 | 로컬 호스트를 검증한 연결에만 마이그레이션을 적용한다. 기존 두 컨테이너와 3002를 사용한다. |
| 문서·그림 | Obsidian에 둔다. 저장소에 같은 스크린샷·설계 복사본을 만들지 않는다. |

## 4. 변경 경계
