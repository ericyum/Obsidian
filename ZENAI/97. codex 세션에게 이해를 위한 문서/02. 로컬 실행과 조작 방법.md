## 2. 필요한 서비스와 비공개 설정

| 구성 | 역할·현재 로컬 관측 | 설정 이름 |
| --- | --- | --- |
| PostgreSQL | 기존 `zen-ai-postgres-1`, 5432, 앱 DB `zenai_hive` | POSTGRES_URL / POSTGRES_WORKER_URL / POSTGRES_MIGRATION_URL |
| LiteLLM | 기존 `zen-ai-litellm-local`, 4000 | OPENAI_BASE_URL / OPENAI_API_KEY / MODELS / TASK_MODEL |
| 로그인 | 회사 OIDC·로컬 세션·멤버십 | OPENID_* / APP_ORIGIN / COOKIE_* |
| 스킬 파일 | DB 버전에 연결된 비공개 본문 | AGENT_SKILL_ROOT |
| 합성 실행기 | 필요한 백그라운드 시험만 | SLOW_SUM_* |
| 음성 인식 | 실제 녹음·전사 별도 범위 | AICORE_* |

기존 두 컨테이너의 정확한 이름을 확인한 뒤 중지돼 있을 때만 시작한다. Docker 권한 오류를 엔진 정지로 단정하거나 새 컨테이너를 중복 생성하지 않는다. `docker system prune`·볼륨 초기화는 실행하지 않는다.

```powershell
docker start zen-ai-postgres-1 zen-ai-litellm-local
```

`.env.example`는 설정 이름 설명이지 실제 값이 아니다. 기존 `.env`를 덮어쓰거나 추적 파일로 올리지 않는다. 로컬 `.env`가 운영을 자동 변경하지 않으며 운영은 별도 `.env.prod`·배포 환경 주입을 사용한다.

앱은 제한된 runtime, 워커는 worker, DDL은 migration/관리 연결을 쓴다. 앱을 owner/superuser로 실행해 오류를 숨기지 않는다.

## 3. 모든 DB 도구와 앱의 환경 해석 통일

**앱과 같은 값을 읽어야 하는 스크립트에는 `scripts/load-env.ts`를 먼저 import한다.** 이 파일은 `@next/env.loadEnvConfig(process.cwd(), true)`를 사용한다. `node --env-file=.env`는 Next와 `$` 확장·escape 해석이 달라 DB 암호나 SAP 비밀값이 달라질 수 있다. 과거 문서의 해당 명령을 그대로 쓰지 않는다.

부모 셸에 이미 주입된 값이 파일보다 우선할 수 있으므로 새 PowerShell에서 대상만 안전하게 확인한다. 값을 로그에 출력하거나 공유 DB 암호를 맞바꾸지 않는다.

## 4. 로컬 DB·Builtin 실행 정의 최신화

백업·대상 검증 후 정식 마이그레이션을 사용한다.

```powershell
npm run builtin-agents:compile
node --import ./scripts/load-env.ts node_modules/tsx/dist/cli.mjs scripts/migrate.ts
```

10/26 병합은 main의 `0110_agent-history-export` 뒤 우리 `0111~0116`이었다. 10/28 통합은 main0118~0120을 보존한 0121~0124까지 포함하므로 최신 journal과 대상 DB의 적용 이력을 먼저 대조한다. 스키마 적용 뒤 Builtin 릴리스 게시도 수행하므로 둘의 성공을 구분한다. 스키마 성공 후 릴리스 게시 실패가 앞선 DDL을 자동 취소하지 않는다.

‘현재 release 6 · 최신 준비 필요’는 단순 UI 오류가 아니다. 현재 코드 컴파일·DB 릴리스 게시·인스턴스의 활성 release를 각각 확인하고 정식 업그레이드를 사용한다. 회의 manifest의 definitionRevision 8과 DB release epoch는 다른 번호다. 기존 release 행을 수정·삭제하거나 같은 revision에 다른 digest를 강제로 넣지 않는다.

역할 관련 오류는 `docs/runbooks/builtin-db-role-bootstrap.md`, 정의는 `docs/runbooks/builtin-definition-releases.md`를 따른다. 프로비저닝을 무조건 재실행하면 클러스터 공유 역할 암호가 바뀔 수 있다.

## 5. 웹 서버 개발 실행

일반 명령 `npm run dev`는 Builtin 컴파일과 PDF preview 준비를 포함한다. Ready·리스너 없이 프롬프트가 돌아왔다면 서버가 뜬 것이 아니다.

10/23에는 PDF 준비를 제외했다. **10/26에는 준비 단계만 bundled Node24로 실행하여 PDF.js 자산 준비까지 성공**했고 webpack·앱은 Node22였다. 아래 수동 우회는 준비 제외를 선택할 때의 과거 방법이며 기본 권장은 정상 prebuild/build 경로다. 자산 준비 성공만으로 브라우저 PDF 미리보기를 통과 처리하지 않는다.

```powershell
npm run builtin-agents:compile
node node_modules/next/dist/bin/next dev --webpack -p 3002
```

개발 모드는 초기 컴파일이 느릴 수 있다. 반복 사용자 검사는 아래 production build가 더 적합하다. 실행 중인 3002를 다른 세션과 공유하면 먼저 중지 일정을 조율한다.

## 6. production 빌드와 standalone 실행

`npm run build`는 preview 준비를 포함한다. 이번에 성공한 것은 **preview를 제외한 Builtin 컴파일→Next webpack build→클라이언트 번들 검사**다.

```powershell
npm run builtin-agents:compile
node node_modules/next/dist/bin/next build --webpack
if ($LASTEXITCODE -ne 0) { throw 'Next build 실패' }
npm run builtin-agents:check-client-bundle
if ($LASTEXITCODE -ne 0) { throw '클라이언트 번들 검사 실패' }

New-Item -ItemType Directory -Force -Path '.next/standalone/.next' | Out-Null
Copy-Item -LiteralPath '.next/static' -Destination '.next/standalone/.next/static' -Recurse -Force
if (Test-Path -LiteralPath 'public') {
    Copy-Item -LiteralPath 'public' -Destination '.next/standalone/public' -Recurse -Force
}
Copy-Item -LiteralPath '.generated' -Destination '.next/standalone/.generated' -Recurse -Force

$env:PORT = '3002'
$env:HOSTNAME = '127.0.0.1'
node --import ./scripts/load-env.ts .next/standalone/server.js
```

위 복사는 새 standalone 폴더를 기준으로 한다. 이미 대상 폴더가 있으면 PowerShell이 폴더를 중첩 복사할 수 있으므로 실제 `.next/standalone/.next/static`, `public`, `.generated` 내부 경로를 확인하고 파일 내용만 덮어쓴다. 일괄 삭제로 해결하지 않는다. Windows에서 Node `cpSync` 복사 helper가 native crash한 사례가 있어 최종 빌드는 PowerShell 복사를 사용했다.

`http://localhost:3002`에서 로그인·화면을 확인하고 `/healthcheck/ready` 200을 보조 증거로 사용한다. readiness만으로 모델·브라우저 E2E 완료라고 하지 않는다. 중지는 실행 터미널 Ctrl+C이며 PID를 확인하지 않고 모든 node를 종료하지 않는다.

## 7. 로그인과 실제 화면 조작

- localhost와 127.0.0.1은 쿠키 호스트가 다르다. 로그인과 후속 링크의 호스트를 통일한다.
- HTTP 로컬의 COOKIE_SECURE 문제와 운영 HTTPS 보안을 구분하며 운영 정책을 약화하지 않는다.
- `/manage/agents`: 일반/하네스 생성·Builtin 설정·허용 모델·도구·추론 강도. 허용 모델에 포함된 모델만 요청에서 선택할 수 있다. 조합별 새 스레드를 사용한다.
- `/settings/guide`: 본인 진행·다시 연습. 완료자는 일반 채팅 상시 버튼이 없는 것이 의도다.
- `/announcements`: 기본 에이전트 소식과 서비스 소식을 전환한다. 작성/회수는 커뮤니티 설정의 공지 관리(owner/admin)다.
- `/agent-dashboard`: 전체 비교/문제 추적/에이전트 분석. 소속 커뮤니티 관리 권한이 필요하다.
- 호출에는 사용자 grant·채널 멤버십·에이전트 참여·활성화·실행 release 준비가 모두 필요하다.

## 8. 추론 설정·LiteLLM

앱의 일반·생성 하네스·회의 Builtin은 공통 Chat 전송이다. `MEETING_MODEL_API=sap-mixed`는 현재 읽지 않는다. GPT의 SAP Responses 변환과 Claude Chat 선택은 LiteLLM 모델 설정/호환 이미지가 담당한다.

MODELS는 앱에 모델 능력·선택 가능한 추론 강도를 알려주는 설정이다. 로컬에서 사라지면 선택 UI가 비활성화될 수 있다. 값은 모델 카탈로그·기존 예제 형식과 맞춰 관리하고 공급자가 추론을 반드시 반환한다고 보장하지 않는다. 실제 모델 호출에서 반환된 공개 추론은 owner 실시간 trace로 전달되며 DB에 저장하지 않는다.

운영 변경은 `docs/runbooks/litellm-deploy.md`가 기준이다. LITELLM_DEPLOY_ENABLED=true만 저장했다고 바로 배포되지 않는다. image-only가 기본이며 최초 GPT Responses 전환은 gpt-responses 모드와 세 URL 준비가 필요하다. `Ops task=litellm-check`는 관측이지 apply 작업이 아니다. 비밀 URL·키를 이 문서에 쓰지 않는다.

## 9. 스킬 저장소와 선택적 합성 실행기

AGENT_SKILL_ROOT는 실제 존재하는 비공개 절대 디렉터리여야 한다. 이 PC는 `.context/agent-skills/agent-specific`을 사용하며 앱·워커가 같은 파일을 읽어야 한다. public 폴더로 옮기지 않는다. DB와 스킬 파일을 함께 백업한다.

slow_sum은 약65초의 메모리 기반 시험 서비스다. 도구 선택과 백그라운드 허용을 모두 켜야 하며 실제 내구성 업무 실행기와 다르다.

```powershell
node --import ./scripts/load-env.ts src/lib/meeting-agent/slow-sum-executor.mjs --local
```

SLOW_SUM_EXECUTOR_URL/TOKEN/LOCAL_PORT/CALLBACK_URL은 기존 비공개 설정을 사용한다. 토큰을 trace나 모델에 제공하지 않는다. 앱과 실행기는 각각 실행한다. `docs/local-background-pilot.md`의 독립 시험 런처는 DB·생성 registry를 바꾸는 특별 환경이므로 일반 .env에서 무작정 실행하지 않는다.

## 10. 암호 인증 실패의 확인 순서

1. 실제 앱의 host/port/DB/역할을 확인한다(비밀번호 출력 금지).
2. scripts/load-env.ts와 같은 해석인지, 부모 셸에 오래된 POSTGRES_*가 남았는지 확인한다.
3. DB 역할 bootstrap 또는 테스트 wrapper가 같은 클러스터 암호를 바꾸었는지 확인한다.
4. 승인된 로컬 대상에서 정상 연결을 검증하고 필요한 원복만 한다. 스키마 초기화·owner 연결로 우회하지 않는다.
5. `.context/notice-dashboard-run.mjs test`는 공유 역할 암호를 바꾸는 예전 검증 wrapper이므로 사용하지 않는다. 전체 DB 테스트는 별도 PostgreSQL 클러스터를 쓴다.
