# ZEN AI 로컬 실행과 조작 방법

이 절차는 Windows PowerShell과 로컬 개발용 서비스에 대한 안내다. 실제 회사 계정으로 로그인했더라도 앱이 사용하는 DB가 자동으로 운영 DB가 되는 것은 아니다. 반대로 localhost 앱이 운영 DB를 가리킬 수도 있으므로, 쓰기 작업 전에 연결 대상을 확인한다. 비밀값을 보여 달라고 요구하거나 `.env` 전체를 출력하지 않는다.

## 실행 전 확인

```powershell
Set-Location -LiteralPath 'C:\Users\염정운\project\zen-ai'
git status --short --branch
node --version
npm --version
docker ps --format '{{.Names}} | {{.Image}} | {{.Status}} | {{.Ports}}'
Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
    Where-Object { $_.LocalPort -in 3002,4000,5432,8788 } |
    Select-Object LocalAddress,LocalPort,OwningProcess
```

프로젝트는 Node `>=22 <23`을 요구한다. 이 PC에 사용했던 Node 22 경로는 아래와 같다. 해당 경로가 실제 존재할 때만 현재 셸의 PATH 앞에 둔다.

```powershell
$zenNodeDir = 'C:\Users\염정운\AppData\Local\Author Software\nvm\installs\v22.23.2'
$env:Path = "$zenNodeDir;$env:Path"
node --version
```

현재 PATH의 node가 `shim integrity check failed`로 끝나면 앱 오류와 구분한다. 위 실제 Node 22 경로로 실행되는지 먼저 확인하고, 그 이유만으로 소스·DB·의존성을 초기화하지 않는다.

Docker 접근 거절과 Docker 엔진 정지는 다르다. 접근 권한 오류만 보고 새 컨테이너를 중복 생성하거나 Docker 전체를 초기화하지 않는다. 기존 서비스 중 필요한 것만 확인하고, 중지된 이름을 확인한 뒤 그 컨테이너만 시작한다.

`node_modules`가 없거나 잠금파일에 맞춰 다시 설치해야 할 때는 `npm ci`를 사용한다. 실행 중인 다른 작업이 사용하는 의존성을 임의로 재설치하지 않는다.

## 필요한 서비스와 설정

| 구성 | 역할 | 확인할 설정 |
| --- | --- | --- |
| PostgreSQL | 앱 데이터·권한·실행 상태 | `POSTGRES_URL`, `POSTGRES_WORKER_URL`, `POSTGRES_MIGRATION_URL` |
| 모델 프록시 | 모델 목록과 추론 요청 | `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `MODELS`, `TASK_MODEL` |
| 로그인 | OIDC·쿠키·허용 신원 | `OPENID_*`, 허용 도메인, `APP_ORIGIN`, `COOKIE_*` |
| 스킬 파일 저장소 | 버전에 고정된 비공개 매뉴얼 파일 | `AGENT_SKILL_ROOT` |
| 시험 계산 실행기 | slow_sum의 접수·계산·완료 보고 | `SLOW_SUM_*`, 필요한 시험에서만 |
| 음성 인식 | 실제 녹음 이후 전사 | `AICORE_*`, 이번 하네스 검증과 분리 |

이 PC에서 LiteLLM은 과거 `http://localhost:4000/v1`로 사용했다. 이 주소나 PostgreSQL 포트를 현재 실행 중인 값으로 단정하지 않는다. 컨테이너 이름과 상태도 재부팅 후 다시 확인한다.

[.env.example](<C:/Users/염정운/project/zen-ai/.env.example>)에는 이름·설명만 있다. 실제 `.env`와 셸 환경변수는 비추적이며 문서에 복사하지 않는다. 기존 `.env`를 예제 파일로 덮어쓰지 않는다.

앱 런타임과 워커는 제한된 별도 DB 역할을 사용한다. DDL에는 관리 연결을 사용하며, 앱 실행을 편하게 하려고 소유자·superuser 연결을 상시 넣지 않는다. 역할 준비는 기존 프로비저닝 스크립트와 DB 런북을 따른다.

## 스킬 저장 폴더 준비

`AGENT_SKILL_ROOT`는 이미 존재하는 절대 디렉터리여야 한다. 기존 값이 있으면 그 위치와 권한부터 확인한다. 아래는 현재 저장소를 사용하는 로컬 예시이며 운영 경로가 아니다.

```powershell
New-Item -ItemType Directory -Force -Path 'C:\Users\염정운\project\zen-ai\.context\agent-skills\agent-specific'
```

로컬 `.env` 설정 예시:

```dotenv
AGENT_SKILL_ROOT=C:/Users/염정운/project/zen-ai/.context/agent-skills/agent-specific
```

이 폴더는 공개 정적 파일 경로나 소스 폴더가 아니다. `.context/`는 gitignore 대상이다. 앱과 워커가 같은 파일을 읽을 수 있어야 한다. 상세 저장 구조는 [[03. 에이전트 설정·저장·실행 구조]]를 따른다.

## 로컬 DB 최신화

먼저 대상이 승인된 로컬 DB인지 확인하고, 기존 데이터가 있으면 복구 가능한 백업을 준비한다. 테이블이 없다는 이유로 DB를 초기화하거나 Drizzle 이력을 삭제하지 않는다.

```powershell
npm run builtin-agents:compile
node --env-file=.env --experimental-strip-types scripts/migrate.ts
```

`npm run db:migrate`는 현재 `node --experimental-strip-types scripts/migrate.ts`를 실행한다. **이 스크립트는 스스로 `.env`를 읽지 않는다.** 셸에 `POSTGRES_MIGRATION_URL`이 없다면 위처럼 `--env-file=.env`를 명시해야 한다. 셸에 이미 설정한 환경변수와 파일 값의 우선순위도 확인한다.

마이그레이션은 스키마 적용 후 Builtin 정의 릴리스도 게시한다. 릴리스 게시 실패가 앞서 적용한 스키마를 자동 롤백하지 않는다. 같은 definitionRevision에 다른 digest를 넣는 오류는 DB 기록을 삭제해 우회하지 않는다.

역할 준비 실패는 [Builtin DB 역할 런북](<C:/Users/염정운/project/zen-ai/docs/runbooks/builtin-db-role-bootstrap.md>)을 따른다. 관리 비밀번호를 변경할 수 있는 프로비저닝 명령을 매번 무조건 재실행하지 않는다.

## 웹 서버 시작

일반 시작 명령:

```powershell
npm run dev
```

실행 순서는 Builtin 컴파일 → PDF 등 문서 미리보기 준비 → Next 개발 서버 3002 포트다. 과거 Windows에서 `preview:prepare`가 종료 코드 5로 끝나 Next가 시작되지 않은 사례가 있다. 프롬프트가 돌아왔고 Ready·리스닝이 없으면 서버가 뜬 것이 아니다.

미리보기 검증이 범위 밖일 때 사용하는 우회 명령:

```powershell
npm run builtin-agents:compile
npx next dev --webpack -p 3002
```

이는 미리보기 준비만 생략하는 명령이며 PDF 미리보기까지 정상이라는 의미가 아니다. 현재 package.json에는 별도 `dev:...` 스크립트가 없다. 존재하지 않는 과거 명령을 안내하지 않는다. Next 설정에 webpack 구성이 있으므로 번들러를 명시한다. 별도 파일럿 런처는 자체적으로 `--turbopack`을 선택하므로 그 명령과 섞지 않는다.

시작 후 `http://localhost:3002`와 `/manage/agents`를 열어 실제 화면까지 확인한다. `/healthcheck`, `/healthcheck/ready` 응답은 보조 근거이며 로그인·저장·모델 응답을 대신하지 않는다. 중지는 서버를 실행한 터미널에서 Ctrl+C다. 재시작할 때 기존 리스너를 확인하며, PID를 확인하지 않은 채 모든 node 프로세스를 종료하지 않는다.

## 로그인과 화면 조작

- 일반 로컬 로그인은 기존 회사 OIDC와 현재 로컬 회원·커뮤니티 상태를 사용한다.
- HTTP 로컬에서 `COOKIE_SECURE=true`이면 쿠키가 저장되지 않아 로그인 반복이 생길 수 있다. 로컬 설정만 검토하고 운영 HTTPS 정책을 완화하지 않는다.
- `localhost`와 `127.0.0.1`은 쿠키 호스트가 다르다. 로그인·후속 요청·테스트 링크에서 같은 호스트를 사용한다.
- 관리자·개발자 권한은 기존 권한 로직으로 판단한다. 화면 검증을 위해 회사 계정 전체에 권한을 주거나 `users.is_admin`만 직접 바꾸지 않는다.
- `/manage/agents`에서 기존 + 버튼 → 일반/하네스 토글을 확인한다. 스킬과 도구가 아직 결합된 현재 상태는 03·06번에 명시되어 있다.
- 실제 호출에는 사용자 호출 권한, 채널 참여, 에이전트의 채널 등록, 활성화·버전 준비가 모두 필요하다.

## 로컬 백그라운드 실행기

에이전트 화면에는 URL·키 입력란이 없다. 일반적인 향후 MCP 구조에서는 도구 서버가 실행기 연결을 관리한다. 현재 저장소의 로컬 slow_sum은 별도 시험 구현으로 `.env` 설정을 사용하며, 기존 Builtin DB 연결이 있으면 그것이 우선한다.

```dotenv
SLOW_SUM_EXECUTOR_URL=http://127.0.0.1:8788/jobs
SLOW_SUM_EXECUTOR_TOKEN=<비공개 64자리 소문자 hex 토큰>
SLOW_SUM_LOCAL_PORT=8788
SLOW_SUM_CALLBACK_URL=http://127.0.0.1:3002/api/builtin-background/complete
```

토큰은 앱과 실행기에 동일하게 설정하고 문서·trace·모델 입력에 남기지 않는다. `<...>`는 설명용 자리표시자이므로 그대로 실행하지 않는다.

별도 PowerShell 터미널에서:

```powershell
Set-Location -LiteralPath 'C:\Users\염정운\project\zen-ai'
node --env-file=.env src/lib/meeting-agent/slow-sum-executor.mjs --local
```

웹과 실행기는 각각 실행해야 한다. 이 실행기는 약 65초 뒤 덧셈을 끝내는 합성 서비스이며 작업은 메모리에 있어 프로세스를 종료하면 사라진다. 실제 Oracle 서버가 필요하지 않은 시험 경로지만 운영용 내구성 실행기를 대신하지 않는다.

시험에는 계산 도구 선택과 백그라운드 허용을 둘 다 켜야 한다. 설정 저장·재열기 후 요청하고 접수와 완료 답변을 따로 확인한다. 자세한 ON/OFF 조합은 04번을 따른다.

독립 합성 DB와 로그인 URL까지 준비하는 기존 런처는 [local-background-pilot 안내](<C:/Users/염정운/project/zen-ai/docs/local-background-pilot.md>)에 있다. 이 런처는 매번 새 DB를 만들고 생성 registry를 시험 상태로 바꾸며, 엄격한 시험 클러스터 조건을 요구한다. 일반 로컬 `.env`에 플래그만 추가해 무작정 실행하지 않는다.

## 환경값 해석 주의

Next는 `@next/env`를 통해 `$NAME` 확장을 할 수 있지만 `node --env-file`은 같은 방식으로 처리하지 않는다. 특히 AICORE 비밀값의 `$` 문제는 `.env.example` 설명과 실제 사용 프로세스를 확인한다. 값이 다르게 해석된다고 비밀을 로그에 출력해서 비교하지 않는다.

실제 마이크·전사의 로컬 환경 문제는 사용자가 하네스 수정 범위에서 제외했다. 녹음 제어 요청을 화면으로 전달한 성공과 실제 녹음·전사 성공을 구분한다.
