# ZEN AI 테스트와 브라우저 E2E 방법

검증은 자동 검사, 합성 도구 통합, 실제 모델 호출, 브라우저 사용자 조작을 구분해 기록한다. API 응답만 확인한 것을 브라우저 E2E라고 부르거나, 예외가 없었다는 이유로 복합 요구가 모두 처리됐다고 판정하지 않는다.

## DB와 권한부터 확인

`npm test`는 단순 읽기 전용 명령이 아니다. `vitest.global-setup.ts`는 다음 동작을 한다.

1. 셸에 POSTGRES_URL이 없으면 로컬 `.env`를 읽는다.
2. POSTGRES_MIGRATION_URL이 있으면 그것을 우선하고, 없으면 POSTGRES_URL에서 관리 접속을 파생한다.
3. **같은 클러스터의 고정 이름 zen_ai_test DB**를 찾거나 생성하고 마이그레이션과 Builtin 릴리스 게시를 한다.
4. 이번 실행이 DB를 새로 만들었다면 종료 시 해당 DB 연결을 끊고 DB를 삭제한다. 이미 존재했던 DB도 마이그레이션 대상이므로 안전한 무변경 실행이 아니다.

따라서 운영·공용 클러스터를 테스트 대상으로 지정하지 않는다. `POSTGRES_URL`만 바꾸고 예전 관리 URL을 남기는 실수를 피한다. 같은 클러스터를 대상으로 Vitest 두 프로세스를 동시에 돌리지 않는다.

독립 시험 역할 bootstrap에는 `BUILTIN_TEST_CLUSTER_OWNED` 또는 CI 전용 규약이 있다. `src/lib/db/test-role-bootstrap.ts`가 주소·역할·모드 등을 엄격히 검사한다. 새 역할을 생성하는 경로이므로 기존 클러스터에 플래그만 더해 재실행하지 않는다.

## 자동 게이트

Node 22, 안전한 DB·역할, 현재 Builtin 컴파일 산출물 조건을 갖춘 뒤 저장소 루트에서 각각 실행한다.

```powershell
npm run check
npm run lint
npm run knip
npm test
```

- check는 Next route typegen과 TypeScript 검사다.
- lint는 ESLint와 Prettier 검사다. 경고·오류·종료 코드를 구분한다.
- knip은 미사용 코드·의존성 검사다.
- test는 전체 Vitest이며 DB 통합 테스트도 포함한다.
- 네 npm 명령의 pre 단계는 Builtin을 다시 컴파일한다.

파일럿 ON registry를 사용 중인 폴더에서 위 명령을 실행하면 기본 정의로 돌아갈 수 있다. 파일럿 검증과 전체 회귀 검증은 실행 폴더·생성물 상태를 분리한다.

관련 테스트만 빠르게 재현할 때의 예:

```powershell
npm run builtin-agents:compile
npx vitest run src/lib/agents/tool-followup.test.ts src/lib/meeting-agent/tool-dialogue.test.ts src/lib/agents/worker-followup.test.ts src/lib/agent-harness/assembly.test.ts
```

파일을 제한해도 global setup의 DB 동작은 그대로다. 전체 통과 여부는 관련 테스트 결과만으로 대신하지 않는다. Windows 권한 오류가 난 검사도 실패 그대로 기록하고, 동일 명령을 적절한 권한으로 재실행했으면 두 결과를 구분한다.

## 검증 환경별로 증명하는 것

| 방식 | 증명하는 것 | 대신하지 못하는 것 |
| --- | --- | --- |
| 가짜 모델·단위 검사 | 종료 규약·권한 거절·상태 분기 재현 | 실제 모델의 지침 준수 |
| 실제 DB 통합 | 예약·버전·RLS·콜백·중복 방지 연결 | 실제 브라우저 표시 |
| 실제 모델 + 합성 자료 | 모델의 도구 선택과 복합 요구 처리, 호출 수 | 실제 업무 자료·마이크·미구축 외부 MCP |
| 브라우저 E2E | 사용자가 클릭·작성·저장·호출한 최종 화면 | 모든 자연어·운영 배포의 무오류 |

실제 모델 호출은 비용이 들며 회사 프록시를 거칠 수 있다. 이번 요청에서 승인한 범위를 확인한다. 과거 승인을 새 채널·다른 계정·운영 테스트 권한으로 확대하지 않는다.

## 브라우저 E2E 준비와 원복

1. 코드 커밋·DB 대상·앱 주소·모델·fixture 종류를 기록한다.
2. 개인정보가 없는 자료와 비공개 합성 채널을 사용한다.
3. 신규 합성 agent나 사용자 부여가 필요하면 승인 범위를 확인한다. 본인만 허용과 전체 허용을 혼동하지 않는다.
4. 바꿀 모델·공용 스킬 체크·내부 도구·백그라운드 정책·기존 권한을 먼저 기록한다. 비밀값은 기록하지 않는다.
5. 새로고침 후 올바른 서버·커뮤니티·계정인지 확인한다.
6. 테스트 후 기존 설정으로 복원하고, 다시 열어 복원됐는지 확인한다. 합성 데이터 삭제는 별도 요청이 없으면 임의로 하지 않는다.

과거 `skill-local-e2e`와 `followup_browser_fixed` 같은 합성 환경이 있었지만 현재 연결·수명은 보장하지 않는다. `scripts/agent-harness-fixture.ts`는 과거 특정 컨테이너 ID·포트에 묶인 작업용 fixture다. 범용 초기화 명령처럼 그대로 실행하지 않는다.

## Codex의 브라우저 조작

현재 세션에 제공된 컴퓨터·브라우저 도구와 해당 스킬 지침을 먼저 읽는다. 도구 이름·탭 ID·연결은 세션마다 달라질 수 있다. 지원되는 CUA 도구가 있으면 그 도구의 초기화 절차로 탭 목록이나 localhost 탭을 선택하고, 반환된 사용법에 따라 화면을 조작한다. 과거 세션의 숨겨진 API나 인증 쿠키를 재사용하지 않는다.

실제 브라우저에서 입력란 작성·체크·저장·재열기·메시지 전송·Trace 펼치기를 수행하고, 화면의 최종 결과를 확인한다. 요청 API만 직접 호출했다면 API 통합 검증으로 기록한다. 필요하면 개인정보가 없는 합성 화면만 캡처한다.

브라우저 확장 연결이 끊기거나 도구가 사라졌으면 현재 연결 상태를 확인하고, UI 검증을 미완료로 남긴다. 서버가 살아 있다는 사실로 브라우저 통과를 대신하지 않는다. 인증 우회 세션 생성은 격리된 합성 환경과 승인 범위가 있을 때만 사용한다.

## 화면 저장과 호출 공통 순서

생성 하네스는 **기존 + 버튼에서 토글 전환**으로 시작한다. 독립된 다른 생성 버튼만 확인해서 통과시키지 않는다.

```text
관리 화면 → 입력·체크 → 저장 → 닫기·재열기 → 값 확인
→ 호출 권한·채널 등록 확인 → 채널에서 @멘션
→ 모델·도구 실행 상태 확인 → 최종 답변 확인 → Trace 열기
→ 필요한 DB 상태 확인 → 원래 설정 복원
```

저장 응답 200만으로 충분하지 않다. 재열기 값과 실제 실행에 같은 설정이 적용되는지 확인한다. 실행 후에는 스피너 종료, 사용자에게 보이는 답변, 도구 실행 횟수, Trace 완료 상태를 각각 확인한다.

## 회의 Builtin과 생성 하네스의 시나리오 표

아래 표를 양쪽에 각각 적용한다. 녹음은 시작·일시정지·재개·정지의 **제어 전달**을 시험하고, 실제 마이크·전사는 별도 범위로 둔다.

| 분류 | 예시 | 확인할 결과 |
| --- | --- | --- |
| 무관한 일반 질문 | 짧은 인사·일반 상식 | 불필요한 스킬·업무 도구 없이 답변 |
| 전용 매뉴얼 | 해당 시나리오 설명 요청 | 맞는 매뉴얼 섹션 조회와 지침 적용 |
| 검색 단독 | 합성 회의 검색 | 1건·0건·여러 후보 각각 처리 |
| 회의 질문 | 선택 자료의 일정·담당자 질문 | 허용 자료로 답하며 원문 조회를 답변 완료로 오인하지 않음 |
| 녹음 단독 | 일시정지 요청 | 실제 화면 제어 전달·한계 안내 구분 |
| 공용 문서 | Word 작성법·요약 | 선택된 공용 스킬 이름 Trace, 실제 파일 미생성 시 사실대로 안내 |
| 미선택 도구 | 제공하지 않은 계산 도구 요청 | 존재를 아는 척하거나 실행했다고 꾸미지 않음 |
| HITL | 후보 제목·번호·자연어 취소·설명 요청 | 유효 선택·취소 처리, 모호하면 대기 유지, 고정 문구 반복 없음 |
| 복합 업무 | 검색+자료 질문, 녹음+Word 요약 | 모든 요구를 체크하고 하나의 도구 효과만으로 종료하지 않음 |
| 혼합 요청 | 접수+인사, 문서+일반 질문 | 결과와 독립인 요구는 현재 답변에서 처리 |
| 오류 복구 | 매뉴얼 미조회 후 올바른 조회 | 부작용 중복 없음, 원래 복합 요구 재확인 |

현재 스킬/도구 결합 동작은 기준 코드의 관찰 대상이다. **독립 도구 선택 변경을 구현한 뒤에는 아래 수용 검증을 추가해야 한다.**

- 매뉴얼에 연결하지 않은 도구도 독립 목록에서 선택·저장·호출된다.
- 매뉴얼만 있고 실행 도구가 없어도 조회·설명은 된다.
- 매뉴얼을 읽어도 미선택 도구 권한은 생기지 않는다.
- 스킬 변경만으로 기존 독립 도구 권한이 사라지지 않는다.
- 위 항목을 Builtin과 생성 하네스 양쪽에서 검증한다.

## 백그라운드 ON과 OFF 조합

| 도구 선택 | 허용 | 추가 조건 | 기대 |
| --- | --- | --- | --- |
| OFF | OFF 또는 ON | — | 해당 도구 실행·신규 예약 없음, 없는 도구를 수행했다고 하지 않음 |
| ON | OFF | 실행기 정상 | 새 접수 거절, 백그라운드 허용 부족을 사실대로 안내 |
| ON | ON | 실행기 정상 | 예약·접수 → 현재 run 종료 → 완료 보고 → 후속 답변 |
| ON | ON | 실행기 미설정 | 연결 준비 부족 안내, 완료를 꾸미지 않음 |
| ON | ON | 응답 유실·연결 장애 | 실제 상태에 따라 unknown 등 안내, 무조건 재시도 금지 |
| ON→OFF | — | 이미 접수된 작업 | 새 작업 차단과 기존 완료 전달을 구분 |
| OFF→ON | — | 다시 저장·재열기 | 새 요청이 정상 접수되는지 확인 |

추가로 같은 스레드 중복 요청, 완료 보고 중복·지연·선행 도착, 실패 결과, 완료 결과에 의존한 후속 요구, 사용자 대기 중지, HITL 대기 중 완료 도착, 권한 회수를 확인한다. 이들 중 브라우저·통합·fixture 어느 층에서 검증했는지 별도로 기록한다.

기존 slow_sum은 같은 스레드의 같은 입력을 재사용할 수 있다. 새 접수 시험은 새 스레드·새 입력을 사용한다. 결과 재보고를 업무 재실행으로 세지 않는다. 외부 실행기의 실제 계산 취소는 그 서버 계약 없이는 보장할 수 없다.

## followUp 절감 검증

단독 검색, 검색+질문, 녹음+매뉴얼 요약, 검색+인사를 반복하고 다음 값을 함께 기록한다.

- 실제 모델 HTTP 요청 수와 스킬 조회 수
- 업무 도구의 실제 부작용 횟수
- 최종 답변에 포함된 요구 목록
- 오류 복구 여부와 조기 종료 여부

정상 단독 검색에서 모델 2회가 관찰돼도 모든 대화에서 항상 2회라는 뜻은 아니다. 앞선 스킬 오류 복구가 있으면 호출이 늘어나는 것이 안전한 동작이다. 요구 누락이 있는 절감은 성공이 아니다.

## 일반 에이전트와 주변 회귀

일반 모드 생성·저장·즉시 재열기·재편집, 정상 MCP 도구 조회·선택·호출, 실패 MCP 서버와 정상 서버가 섞인 상태, 기존 사용자별 인증·권한 거절, 버전 고정 호출을 확인한다. 새 하네스 정책이 일반 경로로 새지 않는지 검사한다.

이 표의 Builtin은 **회의 Builtin**이다. SAP Builtin까지 같은 시험을 수행했다는 뜻이 아니며, SAP 수정 시 전용 런북·격리 검증을 추가한다.

## 결과 기록 양식

```text
기준 날짜와 commit:
앱 주소 / 격리 DB 이름 / 모델:
검증 방식: 단위·DB 통합·실제 모델·브라우저 중 해당 항목
시나리오:
기대 / 실제:
요청·run 식별자:
모델 호출 수 / 도구 부작용 수:
최종 답변 / Trace / DB 상태 확인:
임시 변경과 원복:
명령 종료 코드 / 실패·skip·경고:
남은 검증:
```

현재 수치는 [[06. 현재 상태·미완료 작업·문제 해결]]에 있다. “모든 경우”는 무한한 문장을 보장한다는 뜻이 아니라, 위 기능·상태 조합을 명시적으로 다룬다는 뜻이다.
