5. Builtin과 생성 하네스 양쪽에 적용하고 기존 일반 에이전트·실제 도구 권한은 보존한다.

## 최신 UI가 운영에 안 보일 때

```text
로컬 HEAD와 PR 변경
→ 원격 main에 실제 포함됐는지
→ 해당 main SHA의 CI 결과
→ 이미지 빌드와 배포 실행 SHA
→ DB migration과 Builtin release 게시
→ 앱 교체와 readiness
→ 커뮤니티 인스턴스의 활성 release/config
→ 브라우저가 받는 실제 자산과 화면
```

전체 배포가 DB·release 게시에서 막히면 일반 만들기 토글 같은 UI도 이전 앱 그대로일 수 있다. 다만 실제 배포 로그를 보지 않고 이것을 모든 UI 문제의 확정 원인으로 삼지 않는다.

Builtin의 definitionRevision, 게시 release epoch, 인스턴스 active release, config epoch, 일반 agentVersion, Git SHA는 서로 다른 번호다. 같은 revision의 다른 digest는 거부되므로 변경된 정의에는 적절한 새 revision이 필요하다. 과거 release 행을 수정·삭제하지 않는다. 회의 manifest가 8이라는 사실만으로 운영 DB에도 8이 게시·활성화됐다고 판단하지 않는다.

[정의 릴리스 런북](<C:/Users/염정운/project/zen-ai/docs/runbooks/builtin-definition-releases.md>)과 [EC2 배포 런북](<C:/Users/염정운/project/zen-ai/docs/runbooks/ec2-deploy.md>)을 따른다. 운영 DB 접근 권한이 없으면 로그·SHA 근거로 범위를 좁히고 확인 불가를 남긴다.
