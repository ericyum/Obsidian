# 토큰 사용량·SAP 가격 수집과 보관 계약

사용자 승인: 2026-10-27. 문서 동기화: 2026-10-28. PR #306의 구현은 기존 agent/agent-harness-fix에 통합됐다. 현재 상태는 [[06. 현재 상태·미완료 작업·문제 해결]], 실행별 증거는 [[08. 통합·HITL·Trace 검증과 세션 인계]], Jira는 [ZA-95](https://zenconsulting.atlassian.net/browse/ZA-95)를 따른다.

## 화면과 조회 단위

에이전트 모니터링의 네 번째 **토큰 사용량 및 가격** 탭, 전체 비교의 요약, 기존 실행 이력의 **적용 단가 보기**를 제공한다. 기간·에이전트·모델을 골라 비교하고 **에이전트 → 채팅 스레드(세션) → 사용자 요청 → 모델 호출**을 펼친다.

같은 taskId에 이어진 후속 질문은 triggerEventId와 agent 신원으로 나눈다. retry/continuation은 같은 요청 아래 묶고, 부모가 없는 호출을 임의 스레드에 붙이지 않는다. 입력·출력·총 토큰과 반환된 cache/reasoning 정보, 통화별 산정액, 미산정·usage 미수신 범위를 구분한다.

금액은 **SAP 단가 기준 추정 비용**이며 **실제 청구액과 다를 수 있음**을 표시한다. 토큰만으로 실제 청구액·ROI·업무 성공을 만들지 않는다. Claude Console의 사용량·비용 탐색은 참고 방향이며 그 계정의 청구자료를 가져오는 기능은 아니다.

## 가격을 어디서 언제 가져오는가

| 항목 | 계약 |
| --- | --- |
| 원본 | SAP AI Core GET /v2/lm/scenarios/foundation-models/models. LiteLLM /models 및 inference 요청과 다르다. |
| 인증 | 기존 서버의 AICORE OAuth client credentials와 resource group을 사용한다. 브라우저에 자격증명을 전달하지 않는다. |
| 시작·정상 갱신 | Node 서버 초기화에서 1회, 성공한 뒤 24시간마다 갱신한다. |
| 실패 | 마지막 성공 자료를 보존하고 15분 → 1시간 → 6시간 간격으로 재시도한다. |
| 중복·종료 | 프로세스 singleton과 진행 중 Promise로 동시 갱신을 합친다. 타이머는 unref하고 중지할 수 있다. |
| 요청 제한 | OAuth POST와 catalog GET에 각각 독립 10초 제한을 적용한다. URL/HTTPS 검증·redirect 금지·파싱·no-store 경계를 유지한다. |
| 화면 조회 | 탭 열기·필터 변경·모델 실행마다 외부 가격 GET을 새로 만들지 않는다. |

실제 카탈로그 조회 성공은 관측했다. 별도 API key 필드를 쓰지 않아도 OAuth 인증은 존재한다. 응답 성공이나 inference가 아니라는 사실만으로 계약상 **무료**를 확정할 수 없다. 카탈로그 요청의 과금정책·청구대사는 이 검증에서 확인하지 않았다.

## 어디에 저장하고 무엇에 사용하는가

| 데이터 | 위치와 수명 |
| --- | --- |
| 현재 카탈로그 | 서버 프로세스 메모리의 Symbol.for singleton. 모델/버전, 원본 cost/null, tier/tierDescription, observedAt를 보관한다. |
| 갱신 상태 | 같은 메모리에 lastAttempt·nextAttempt·error·refreshing·stale을 둔다. |
| 검증된 환산 기준 | 서버 설정 SAP_PRICING_BASIS_JSON. 카탈로그 응답에 없는 단위를 추측하지 않는다. |
| 호출별 사용량·적용 가격·비용 | 기존 실행 이력의 metadata/usage 구조와 usage_events metadata에 남긴다. 호출 시점 snapshot과 미산정 사유를 보존한다. |

**가격 카탈로그 전용 DB/table은 없다.** 정상 재시작·배포·프로세스 교체에도 메모리는 초기화된다. 여러 앱 인스턴스는 각자 GET할 수 있으며 재시작을 넘는 backoff·DB lease는 제공하지 않는다. 가격 준비가 실패해도 앱과 모델 실행을 막지 않는다. 성공한 새 응답의 요율이 null이면 옛 요율로 조용히 계산하지 않는다.

현재 메모리 캐시와 과거 비용 기록은 다르다. 모델 호출 시작 시 모델/버전·가격·검증 단위·출처·카탈로그 확인 시각을 고정하고, 종료 시 수신한 usage로 비용을 계산한다. observedAt는 가격 적용 시작일이 아니다. 새 가격으로 과거 비용을 다시 쓰지 않는다. 회계 목적으로 대화·인증자료·추론 원문을 복제하지 않는다.

같은 저장 결과를 가격 탭의 합계·추세·드릴다운, 전체 비교 요약, 기존 실행 상세의 적용 단가 보기에 사용한다. 목록 페이지나 상세 표시 상한이 기간 전체 합계·요청 소계를 줄이면 안 된다.

## 실제 SAP 금액이 미산정인 이유

카탈로그의 cost 숫자만으로 통화·기준 토큰 수·GenAI/CU 환산·계약·구간·캐시 규칙을 확정할 수 없다. 검증된 SAP_PRICING_BASIS_JSON에 통화·분모·환산계수·출처·확인 시각·확인된 적용기간·tier 판정 기준·필요한 캐시 요율이 있어야 계산한다.

현재 인계 기준으로 이 설정은 미설정이며 실제 비용 상태는 **normalization_unverified / 미산정**이다. 임의 USD/KRW, 공급자 공개요금, SAP 예시값을 기본값으로 넣지 않는다. 금액은 decimal 문자열과 정수 스케일·BigInt로 계산하고 통화는 분리한다. 실제 0과 미산정 null을 구분한다. cache/reasoning 토큰도 provider의 포함 관계와 검증된 요율에 따라 처리한다. 카탈로그 준비 완료와 개별 호출의 산정 가능 여부는 다르다.

## 기존 usage를 재사용하는 방법

일반·하네스·Builtin·회의 전사/요약/태그·메모리 요약 경로의 provider usage를 재사용한다. 회계용 LLM 호출을 추가하지 않는다. 실제 재시도는 시도별로 기록하고 같은 callback은 중복 반영하지 않는다. 태그 생성의 429/503에 대한 기존 SDK 기본 2회 재시도가 중간에 빠진 회귀는 후속 intent/harness로 복원했다.

실시간 trace의 256 span 상한 때문에 토큰 합계가 줄어들지 않도록 기존 루트/실행 metadata에 최소 accounting을 유지한다. span과 usage_events fallback은 이중 합산하지 않는다. 실패·취소여도 usage가 반환되면 포함한다. 과거 미기록·provider 미수신 값은 추측해서 0으로 채우지 않는다.

## 집계와 접근 경계

기간은 [from,to)이며 UI의 KST 날짜 경계를 따른다. DB가 선택 기간 전체 metadata를 집계한다. owner/admin만 현재 커뮤니티를 조회하고 member403·outsider/타 커뮤니티404·미인증401·역전 기간400을 구분한다. 삭제·접근 불가 원문의 제목·본문·snapshot/thread 연결을 다시 노출하지 않는다. 응답은 private no-store 및 Vary:Cookie를 유지한다.

적용 단가 보기는 모델/버전·단위·요율·tier·출처·확인일/확인된 적용일·cache 근거·갱신 상태와 과거 snapshot을 읽기 전용으로 보여준다. OAuth·계약서 원문·인증자료를 공개하지 않는다.

## 확인된 증거와 한계

합성 기간은 KST 10/25 00:00 이상~10/28 00:00 미만이다. 32호출, 입력 54,420 / 출력 27,210 / 총 81,630토큰, ALT 1.25와 TST 1.62를 별도로 표시했다. 미산정 3호출·usage 미수신 1호출, 31스레드의 25+6 페이지에서도 합계를 유지했다. 같은 스레드의 독립 요청은 3,000토큰/TST 0.06과 실제 0토큰/TST 0을 구분했다. **TST/ALT는 실제 SAP 단가가 아니다.**

기존 Chrome·API는 합계·페이지·드릴다운·실제 0/unknown·합성 snapshot·삭제 가림을 확인했다. 이전 Jira 댓글의 필터·연결 확인과 별개로, 마지막 후속 수정 빌드의 모든 필터·전체 비교·기존 이력 연결·실제 SAP 미산정 상세를 새 Chrome에서 재검사한 것은 아니다. 실제 SAP 단가 설정·청구서 대사·운영 검증은 남는다.

초기 SAP 401은 임시 실행기의 Node parseEnv가 escape를 다르게 읽은 문제였다. 제품과 같은 @next/env 로더로 해소했고 유효한 .env는 변경하지 않았다. OAuth 9초+GET 9초 성공 및 각 요청 자체의 timeout 거절은 독립 제한 회귀로 확인했다.
