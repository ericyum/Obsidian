상위 [ZA-6](https://zenconsulting.atlassian.net/browse/ZA-6), 상태 **Done**, 해결 댓글 10264.

## 증상과 재현
GPT-5.6 Sol 제거 이후 일반·생성 하네스 설정에서 GPT-6.1 Sol을 선택해 저장해도 오류가 발생하고, Builtin 회의/SAP 에이전트는 모델 선택과 실행 release 업그레이드가 서로 막히는 상황이 있었다. 관리 화면에서 기존 에이전트 편집→Sol 선택→저장, Builtin의 모델 변경/실행 버전 업그레이드로 재현했다.

## 원인
기존 기본/허용 모델과 현재 실행 release에 제거된 모델 참조가 남았다. UI에서 새 모델을 골라도 숨은 허용목록 payload에 예전 ID가 남아 서버 validator가 거절했다. Builtin은 현재 release와 최신 release의 지원 모델 차이 때문에 모델 저장과 release 전환을 따로 수행하면 복구가 교착됐다. 고정 LiteLLM 검증기에서도 신규 gpt-6.1-sol의 reasoning_effort 지원을 맞춰야 했다. 상급자의 운영 수동 복구(#333)와 재발 방지 코드 수정은 별도 작업이다.

## 해결
일반·하네스 편집/복제에서 제거 모델을 안내하고 명시적 대체 선택 시 stale ID를 제출하지 않도록 보완했다. Builtin 모델+실행 release를 한 트랜잭션으로 전환하며 epoch·권한·active run/HITL guard·실패 rollback·불변 이력을 유지한다. 활성 모델 참조 배포 전 검사와 LiteLLM Chat→Responses 추론 옵션 호환을 보완했다. 기존 운영 복구값과 다른 사람의 회의 변경은 보존했다.

## 검증 및 완료
PR #335, 최종 소스 b6709ec: check/lint/knip/vitest PASS, 543파일/6,466테스트 PASS, 조건부 27 SKIP, evaluator ACCEPT. 후속 #337과 #338은 별도 관련 카드에 기록한다. 최신 로컬 DB migration/Builtin 동기화와 정식 재빌드 후 일반·하네스 Sol 및 Builtin 회의 Sonnet의 실제 Chrome 최종 답변을 확인했다. 이번 운영 최종 배포는 main c5db1f07b1ec454c084c8541e23e55bd669fcd40, Deploy 41175438247 성공(2026-10-31 15:16:49 KST, workflow 영수증 기준). 하네스 Sol/Opus 실호출은 Codex 직접 확인, 남은 일반 sap-adt/Builtin 회의 모델별 운영 항목은 사용자가 직접 모두 확인했다고 알렸다. 사용자 확인을 Codex 직접 수행으로 기록하지 않는다. 사용자가 GPT6.1 우선 기조 종료를 지시해 해결 완료로 기록한다.

### [ZA-102](https://zenconsulting.atlassian.net/browse/ZA-102) — 운영 하네스 에이전트 생성 시 스킬 저장 경로 미준비로 서버 오류

## 증상·재현

## 원인과 확정 범위
하네스는 생성 시 전용 스킬 매뉴얼 파일을 저장하므로 일반 생성과 달리 쓰기 가능한 스킬 저장소가 필요하다. 배포 구성에 전용 영속 경로/볼륨이 준비되지 않았다. 운영 실패 당시 원본 로그는 직접 확보하지 않았으므로 동일 증상의 재현 원인과 구성 결함으로 기록한다.

## 해결
PR #338에서 Dockerfile의 /app/agent-skills를 비특권 node 소유·0700으로 준비하고, production/EC2 Compose에 AGENT_SKILL_ROOT 및 agent-skills named volume을 명시했다. 일반·하네스 API/DB/src 로직은 바꾸지 않았다. 이미지 배포만으로 호스트 Compose가 갱신되지 않으므로 전용 설정 동기화·기존 root/DB 백업·상대 키/본문/digest 보존 이관을 런북에 명시했다. 기존 파일/볼륨은 임의 삭제하지 않는다.

## 영속 저장과 재발 방지

- 모델 전환은 UI 카탈로그만 바꾸는 일이 아니다. LiteLLM 경로·MODELS·일반/하네스 기본/허용목록·Builtin 실행 release의 활성 참조를 함께 검증한다. 과거 불변 release/trace는 보존한다.
- 하네스의 전용 매뉴얼 저장과 작업 공간 마운트는 별개다. `/app/agent-skills`/0700/node 소유/영속 named volume을 유지한다. 이미지 교체만으로 호스트 Compose 동기화를 가정하지 않는다.
- 기존 스킬 경로를 전환할 때 root+DB 백업, 상대 키/원문/digest 보존과 기존 볼륨 소유권 확인이 필요하다. 이 문서 작성은 운영 설정 변경 지시가 아니다.
- 최신 정식 빌드 뒤 로컬 3종과 배포 후 운영 3종을 실제 클릭/호출로 확인한다. API 성공·사용자 확인·에이전트 직접 확인을 구분한다.
