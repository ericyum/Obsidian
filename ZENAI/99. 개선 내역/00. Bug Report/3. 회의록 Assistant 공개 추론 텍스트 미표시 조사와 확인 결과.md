# 회의록 Assistant 공개 추론 텍스트 미표시 조사와 확인 결과

작성일: 2026-11-05  
대상: 회의록 Assistant의 공개 추론 텍스트 수신·실시간 Trace 표시  
상태: 비 Sol 모델의 표시 동작 확인. 기본 모델·추론 설정 차이로 현상을 구분했으며, 이번 정리에 따른 제품 코드 변경은 없음.

## 증상

운영 회의록 Assistant를 호출했을 때 Trace에서 공개 추론 텍스트가 보이지 않아, 앱이나 LiteLLM이 제공자의 추론 텍스트를 누락하는 것으로 의심했다. 운영 기본 모델은 GPT 6.1 Sol이었다.

## 확인 결과

| --- | --- | --- |
| 로컬 실제 앱 | 여러 비 Sol 모델에서 추론 강도를 명시하고 회의록 Assistant를 호출했을 때 공개 추론 텍스트가 정상 표시됨 | 사용자가 기존 시험 채널에서 직접 확인 |

비교 대상으로 정한 비 Sol 모델은 Claude 4.8 Opus·4.6 Sonnet·4.5 Haiku, GPT 5.6 Luna·Terra다. 이번 추가 확인은 사용자가 수행한 여러 모델·추론 강도의 실제 호출 결과에 근거한다. 모델별 최소/높음 각 2건이라는 자동 검사 계획의 20/20 완료나 반환율 수치로 환산하지 않는다.

## 원인 구분과 대응

이번 현상은 **Sol 6.1을 기본 모델로 사용한 조건에서 공개 추론 텍스트가 반환되지 않은 관측**과 **비 Sol 모델에서 추론 강도를 지정했을 때 정상 표시된 관측**으로 정리한다. 따라서 앱의 공개 추론 표시 기능 전체가 고장 났다고 판단할 근거는 없다. 기존 동일 응답 대조에서도, 반환된 공개 텍스트를 중계나 Trace가 삭제했다는 증거는 발견하지 못했다.

공개 추론 텍스트를 확인하려면 반환이 확인된 모델을 선택하고 추론 강도를 명시한 뒤 실제 실행의 유효 모델·강도와 Trace를 함께 확인한다. 강도 미지정은 요청에서 관련 필드를 생략하는 조건이며, 최대 강도 설정만으로 기본 강도가 자동 지정되는 것은 아니다.

Sol 역시 과거 별도 산술 질문에서는 공개 텍스트를 반환한 사례가 있다. 따라서 결론은 “Sol은 항상 반환하지 않는다” 또는 “나머지 모델은 모든 입력에서 100% 반환한다”가 아니라, **이번 회의 요청과 사용자 확인 범위에서는 비 Sol 모델의 명시적 추론 강도 설정으로 정상 수신·표시를 확인했다**는 것이다. 이번 문서 작성에서는 제공자나 앱의 코드를 수정하지 않았다.

## 다운로드 기록과의 구분

- **실시간 Trace·에이전트 구동 로그:** 제공자가 반환하고 SDK가 수신한 공개 추론 텍스트를 확인하는 경로다. 구동 로그의 인증정보·서명·암호문 마스킹은 유지한다.
- **요청 기록 다운로드:** 기존 정책상 공개 추론 텍스트를 제외한다. 이 파일에서 텍스트가 없다는 사실만으로 제공자 미반환이나 Trace 누락을 판단하지 않는다.
- 추론 토큰 사용량과 공개 추론 본문 수신 여부는 별개다. 제공자가 반환하지 않는 내부 추론은 기록 대상에 포함할 수 없다.
