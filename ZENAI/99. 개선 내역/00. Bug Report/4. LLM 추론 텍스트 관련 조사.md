# LLM 추론 텍스트 관련 조사

작성일: 2026-11-05  
대상: SAP AI Core의 공개 추론 텍스트 반환 조건 및 ZEN AI의 설정·표시 동작  
상태: 기존 조사 결과 요약. 이번 문서 작성에서는 새로운 모델 호출이나 제품 코드 변경을 하지 않음.

## 1. 어떤 조사를 했는가

- **SAP AI Core 직접 호출:** GPT의 Foundation Models Native `/responses`와 Claude의 Orchestration `/v2/completion`을 중심으로 모델·추론 강도·공개 요약 설정별 반환 여부를 비교했다. JSON·스트리밍, 입력 유형, 대화·도구 사용 조건도 구분했다.
- **보조 파라미터 비교:** GPT의 `reasoning.summary`, `reasoning.context`, `reasoning.mode`, Claude의 `thinking.type`, `budget_tokens`, `display`, `output_config.effort`를 비교했다.
- **ZEN AI 설정 조사:** 에이전트의 기본·최대 추론 강도가 실제 요청에 어떻게 반영되는지, 모델별 선택지와 운영 모델 설정이 어디에서 정의되는지 확인했다.
- **수신·표시 경계 확인:** 기존 SAP 원본 → LiteLLM 변환, 실제 앱의 SDK → Trace 대조와 사용자의 로컬·운영 확인 결과를 검토했다. 요청 기록 다운로드는 별도 기록 정책과 구분했다.

## 2. 어떤 결과가 나왔는가

| 모델                  | 호출 경로                                 | 추론 텍스트 반환 여부        | 확인 조건·비고                                                                 |
| ------------------- | ------------------------------------- | ------------------- | ------------------------------------------------------------------------ |
| GPT 5.6 Sol (과거 조사) | Foundation Models Native `/responses` | **미반환·낮은 반환율 관측**   | 일반 강도에서 미반환이 잦았음. 별도 산술 질문의 `effort: "max"` + `summary: "auto"`에서는 반환 확인 |
| GPT 6.1 Sol         | Foundation Models Native `/responses` | **ZEN AI에서 미반환 관측** | 이번 ZEN AI 사용 조건 기준. 별도 산술 질문에서는 반환 사례가 있어 모델 자체의 미지원은 아님                 |
| GPT 5.6 Luna        | Foundation Models Native `/responses` | **반환 확인**           | 지원되는 `reasoning.effort` 지정 + `reasoning.summary: "auto"`                 |
| GPT 5.6 Terra       | Foundation Models Native `/responses` | **반환 확인**           | 지원되는 `reasoning.effort` 지정 + `reasoning.summary: "auto"`                 |
| Claude 4.5 Haiku    | Orchestration `/v2/completion`        | **반환 확인**           | 지원되는 `reasoning_effort` 지정                                               |
| Claude 4.6 Sonnet   | Orchestration `/v2/completion`        | **반환 확인**           | 지원되는 `reasoning_effort` 지정                                               |
| Claude 4.8 Opus     | Orchestration `/v2/completion`        | **반환 확인**           | 지원되는 `reasoning_effort` 지정                                               |

위 표는 기존 조사와 ZEN AI 사용·확인 범위의 관측 결과다. ‘반환 확인’은 모든 입력에서의 100% 반환 보장을 뜻하지 않는다.

- **기본 추론 강도 ‘없음’은 강도 파라미터 생략이다.** 추론 활성화를 명시하는 설정이 아니다. 최대 추론 강도만 설정해도 기본 강도가 자동 선택되지는 않는다.
- GPT의 `summary: "auto"`는 공개 추론 요약을 요청하는 옵션이며, 추론 강도와 별개다. 현재 조사한 ZEN AI 경로에서는 기본 추가된다. Claude는 공통 `reasoning_effort` 방식으로도 반환이 확인돼 고유 `thinking` 설정을 반드시 추가해야 한다는 근거는 없었다.
- 기존 동일 응답 대조에서는 반환된 공개 추론 텍스트가 LiteLLM이나 Trace에서 삭제됐다는 증거를 발견하지 못했다. 따라서 표시 기능 전체의 고장으로 결론 내리지 않았다.
- **요청 기록 다운로드는 기존 정책상 공개 추론 본문을 제외한다.** 다운로드 파일에 없다는 사실만으로 SAP 미반환이나 Trace 누락을 판단할 수 없다.

## 3. 결론

**기존 조사와 ZEN AI 사용 확인에서 Sol 계열(GPT 5.6 Sol·GPT 6.1 Sol)은 유독 SAP AI Core로부터 공개 추론 텍스트가 반환되지 않거나 반환이 불안정한 현상이 두드러졌다. 반면 나머지 5개 모델은 각 모델의 사용 경로에서 지원되는 ‘추론 강도’를 명시했을 때 정상 반환·표시를 확인했다.** 공개 추론 텍스트가 필요한 경우에는 우선 비 Sol 모델을 선택하고 기본 추론 강도를 명시하는 것이 실용적인 대응이다.

다만 두 Sol 모델 모두 일부 반환한 사례가 있다. 과거 GPT 5.6 Sol은 별도 산술 질문의 `max + auto`에서, GPT 6.1 Sol도 별도 산술 질문에서 반환됐다. 따라서 ‘Sol 계열에서 미반환이 두드러졌다’는 관측이며, Sol의 영구적인 미지원이나 나머지 모델의 모든 요청에 대한 무조건적인 100% 반환을 의미하지 않는다.
