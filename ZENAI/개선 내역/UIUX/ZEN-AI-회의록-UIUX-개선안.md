# ZEN AI 회의록 UI/UX 개선안

> `meeting-whisper`의 검증된 회의 흐름을 Zen AI의 에이전트 중심 워크스페이스에 확장한 화면 계획서

## 1. 문서 목적

Zen AI의 회의록 기능은 단순 녹음·전사 도구가 아니다. 워크스페이스에 사전 등록된 에이전트를 회의마다 선택해 전사와 요약을 수행하고, 결과를 참석자·공유자·채널과 연결하는 첫 번째 에이전트 기반 업무 기능이다.

이 계획은 다음 두 자료를 기준으로 한다.

- `C:\Users\염정운\project\meeting-whisper`: 목록 → 회의 설정 → 녹음 → 처리 → 결과의 실제 동작 흐름
- 팀원 상세 목업: 회의록 문서와 전사 원문을 나란히 검토하고, AI 초안을 사람이 확정하는 구조

이번 개선안의 차별점은 다음과 같다.

1. Discord처럼 좌측 내비게이션을 모든 화면에 고정한다.
2. 대량 회의 목록을 무한 스크롤이 아닌 페이지네이션으로 탐색한다.
3. 제목 검색을 기본 제공한다.
4. 새 회의 설정에서 사전 등록된 전사 에이전트와 요약 에이전트를 각각 선택한다.
5. 생성 모달 대신 독립된 새 회의 페이지를 사용한다.

---

## 2. 제품 내 역할

회의록은 Zen AI 전체 제품 안에서 하나의 기능 모듈이자 에이전트 실행 사례다.

```text
Zen AI 워크스페이스
├─ Inbox
├─ 회의록
│  ├─ 회의 목록
│  ├─ 새 회의 설정
│  ├─ 녹음
│  ├─ 전사·요약 처리
│  └─ 회의록 상세·확정
├─ 에이전트
│  ├─ 전사 에이전트
│  ├─ 요약 에이전트
│  └─ 기타 업무 에이전트
├─ 채널
└─ 다이렉트 메시지
```

에이전트의 모델·프롬프트·MCP 도구는 회의 생성 화면에서 직접 새로 만드는 것이 아니라, 좌측 `에이전트` 메뉴에서 미리 구성하고 검증한다. 회의 생성자는 그중 사용 권한이 있고 활성화된 에이전트만 조회·선택한다.

## 3. 핵심 UX 원칙

### 3-1. 위치를 잃지 않는 고정 내비게이션

- 좌측 내비게이션은 목록·설정·녹음·처리·상세 화면에서 계속 같은 자리를 차지한다.
- `회의록` 메뉴는 회의 흐름 전체에서 활성 상태를 유지한다.
- 본문만 교체하여 사용자가 Zen AI 안에 있다는 감각을 유지한다.
- 녹음 중 다른 메뉴로 이동하려 하면 녹음 유지 여부를 명확히 안내한다.

### 3-2. 오디오·전사는 원본, 회의록은 파생 문서

- 회의록의 결정·요약 문장에는 근거 전사 구간을 연결할 수 있다.
- AI 결과는 언제나 `초안`으로 시작하며 사람이 확정한다.
- 확정본은 재처리 결과로 덮어쓰지 않고 새 버전 초안을 만든다.

### 3-3. 에이전트는 능력 단위로 선택

- 전사와 요약 에이전트를 별도로 선택한다.
- 사용자는 모델명을 외우지 않아도 에이전트의 목적·품질·도구·관리자를 보고 선택할 수 있다.
- 고급 정보인 모델·프롬프트 버전·MCP 도구는 펼쳐서 확인한다.
- 실행 시 선택된 에이전트의 ID뿐 아니라 버전 스냅샷도 저장하여 결과 재현성을 확보한다.

### 3-4. 긴 작업은 백그라운드 처리

- 녹음 종료 후 화면을 붙잡아 두지 않는다.
- 처리 화면에서 진행 단계를 보여주되 `목록으로 이동`을 허용한다.
- 목록에서도 처리 상태를 확인할 수 있고 완료 시 Inbox 알림을 보낸다.

## 4. 전체 화면 흐름

```text
[회의록 목록]
   ├─ 회의 선택 ───────────────────────────────→ [회의록 상세]
   └─ + 새 회의록 만들기 → [새 회의 설정]
                               ├─ 녹음 시작 → [회의 중]
                               │                 └─ 종료 → [전사·요약 처리]
                               └─ 파일 전사 → [전사·요약 처리]
                                                       └─ 완료 → [회의록 상세/초안]
```

상태 전이는 다음을 기본으로 한다.

```text
설정 중 → 녹음 중 → 업로드 중 → 전사 중 → 요약 중 → 검토 필요(초안) → 확정
                              └──────── 실패 → 재시도
```

## 5. 공통 레이아웃

### 5-1. 좌측 고정 영역

- 워크스페이스/브랜드
- 전체 검색
- Inbox
- 나중에 볼 항목
- 회의록
- 에이전트와 등록 개수
- 채널 목록
- 다이렉트 메시지
- 하단 사용자 프로필

권장 너비는 데스크톱 기준 240px이다. 1024px 이하에서는 72px 아이콘 레일로 축소하고, 모바일에서는 드로어로 전환한다. 단, 녹음 화면에서는 좁은 화면에서도 녹음 상태가 가려지지 않아야 한다.

### 5-2. 접근 권한 표시

목록에 나타나는 회의는 다음 중 하나를 만족하는 회의로 제한한다.

- 회의 소유자
- 참여자
- 공유자
- 관련 채널의 열람 권한 보유자
- 관리자 정책에 의해 허용된 사용자

검색과 페이지네이션은 권한 필터가 적용된 결과를 기준으로 서버에서 처리한다.

## 6. 회의록 목록 화면

### 6-1. 화면 구성

상단에는 제목과 `+ 새 회의록 만들기` 버튼을 둔다. 그 아래에는 제목 검색, 상태 필터, 페이지당 표시 개수를 배치한다.

각 목록 행은 다음 정보를 제공한다.

- 회의 제목
- 회의 일시
- 길이
- 소유자 또는 주요 참석자
- 현재 상태: 회의 중 / 전사 중 / 요약 중 / 초안 / 확정 / 실패
- 사용된 전사·요약 에이전트 요약
- 액션 아이템 수

행 전체를 클릭하면 상세 화면으로 이동한다. 행 안의 보조 버튼과 행 클릭 영역은 충돌하지 않게 분리한다.

### 6-2. 제목 검색

- 기본 범위는 사용자가 요구한 대로 `제목`이다.
- 입력 후 300ms 디바운스를 적용하거나 Enter로 검색한다.
- 검색어는 URL 쿼리 `?q=`에 보존하여 새로고침·뒤로가기에도 유지한다.
- 검색 결과가 없을 때 검색어와 `검색 초기화` 버튼을 보여준다.
- 향후 참여자·전사 내용까지 확장할 경우 `검색 범위` 옵션으로 분리한다. 제목 검색 입력창에서 묵시적으로 전체 본문까지 찾게 하면 응답 속도와 결과 예측성이 나빠질 수 있다.

### 6-3. 페이지네이션

- 기본 10개, 선택 가능 10/20/50개를 권장한다.
- 하단에 `총 N개 · 현재 범위`와 `이전 / 페이지 번호 / 다음`을 표시한다.
- 페이지가 많으면 `1 … 8 9 10 … 42`처럼 줄인다.
- 검색어나 필터가 바뀌면 1페이지로 이동한다.
- 삭제 등으로 현재 페이지가 비면 직전 유효 페이지로 이동한다.
- URL에 `?page=2&pageSize=10&q=...&status=draft`를 보존한다.
- API는 클라이언트 전체 로딩이 아니라 서버 페이지네이션을 사용한다.

권장 API 예시:

```http
GET /api/meetings?page=2&pageSize=10&title=스프린트&status=draft&sort=startedAt:desc
```

```json
{
  "items": [],
  "page": 2,
  "pageSize": 10,
  "totalItems": 126,
  "totalPages": 13
}
```

### 6-4. 처리 중 회의

처리 중인 회의를 무조건 목록 상단에 고정하면 페이지 정렬이 흔들릴 수 있다. 따라서 다음 방식이 더 안정적이다.

- 목록 정렬은 사용자가 선택한 기준을 유지한다.
- 상단에 `진행 중인 회의 N개` 요약 스트립을 별도로 제공한다.
- 목록 행 상태는 폴링 또는 서버 이벤트로 갱신한다.

## 7. 새 회의 설정 화면

모달이 아니라 독립 화면으로 제공한다. 참여자·공유자·에이전트까지 설정해야 하므로 모달은 정보 밀도와 검토성이 부족하다.

### 7-1. 기본 정보

- 회의 제목: 필수 권장. 비워둘 경우 AI 제안 가능하나 목록 식별성이 떨어지므로 시작 전 입력을 우선한다.
- 참여자: 회의에 실제 참석하고 화자 매핑 후보가 되는 사용자
- 공유자: 참석하지 않아도 결과를 열람할 사용자
- 관련 채널: 확정 후 공유 카드를 게시할 위치
- 입력 방식: 브라우저 녹음 또는 녹음 파일 업로드

참여자와 공유자는 의미가 다르므로 필드를 분리한다. 같은 사람이 양쪽에 선택된 경우 중복 권한은 하나로 합치되 UI에서는 역할을 알 수 있게 한다.

### 7-2. 에이전트 선택

두 개의 선택 카드를 제공한다.

#### 전사 에이전트

- 오디오를 텍스트 세그먼트와 화자 정보로 변환
- 표시 정보: 이름, 설명, 지원 언어, 화자 분리 여부, 예상 속도
- 상세 정보: 모델, 프롬프트 버전, MCP 도구, 최종 수정자와 시각

#### 요약 에이전트

- 전사 원문을 요약·결정 사항·액션 아이템 구조로 변환
- 표시 정보: 이름, 출력 템플릿, 액션 아이템 추출 여부
- 상세 정보: 모델, 프롬프트 버전, MCP 도구, 최종 수정자와 시각

선택 목록에는 다음 조건을 만족하는 에이전트만 보인다.

- 현재 워크스페이스에 등록됨
- 해당 역할(`transcription` 또는 `summary`) 지원
- 활성 상태
- 사용자가 실행 권한을 보유

에이전트가 없을 때는 막힌 셀렉트만 보여주지 말고 `에이전트에서 먼저 만들기` 링크를 제공한다. 에이전트 편집 후 돌아왔을 때 입력 중인 회의 설정은 임시 저장되어야 한다.

### 7-3. 선택 시점의 버전 고정

회의 시작 시 아래 정보를 실행 스냅샷으로 저장한다.

```json
{
  "agentId": "agent_transcribe_01",
  "agentVersion": 7,
  "model": "gemini-2.5-flash",
  "promptVersion": "transcribe-ko-v4",
  "mcpToolIds": ["member-directory", "terminology-dictionary"]
}
```

이렇게 해야 관리자가 나중에 에이전트를 수정해도 과거 회의 결과가 어떤 구성으로 생성되었는지 설명할 수 있다.

### 7-4. 시작 전 검증

- 제목 입력
- 참여자 최소 1명 권장
- 전사 에이전트 선택 필수
- 요약 에이전트 선택 필수
- 녹음 시작 시 마이크 권한 확인
- 업로드 시 파일 형식·크기·예상 길이 확인
- 선택한 에이전트가 비활성화되거나 권한이 변경되었는지 서버에서 최종 재검증

## 8. 회의 중 녹음 화면

meeting-whisper의 녹음 화면 골자를 유지한다.

- 회의 제목
- `녹음 중` 또는 `일시정지` 상태
- 큰 경과 시간
- 오디오 레벨을 나타내는 파형
- 참여자 칩
- 선택된 전사·요약 에이전트 요약
- 일시정지/계속
- 회의 종료
- 선택적으로 실시간 임시 전사

중요한 개선점:

- `종료`는 오작동 비용이 크므로 확인 단계를 둔다.
- 녹음 중 브라우저를 닫으려 할 때 경고한다.
- 네트워크가 끊겨도 로컬 녹음이 유지되는지 상태를 표시한다.
- 실시간 임시 전사는 최종 전사와 다를 수 있음을 명시한다.
- 에이전트는 회의 시작 뒤 변경하지 못하게 잠근다. 변경이 필요하면 회의 종료 후 새 처리 버전을 만든다.

---

## 9. 전사·요약 처리 화면

녹음 종료 또는 파일 제출 뒤 다음 단계를 보여준다.

1. 녹음 파일 업로드
2. 전사 에이전트 실행
3. 화자 분리·매핑 준비
4. 요약 에이전트 실행
5. 회의록 초안 생성

각 단계에는 대기/진행/완료/실패 상태와 시작·완료 시각을 표시한다. 정확한 퍼센트를 알 수 없는 모델 작업에 가짜 퍼센트를 사용하지 않고 단계 기반 진행을 사용한다.

사용자는 처리 중 목록으로 돌아갈 수 있다. 실패하면 실패한 단계, 사용자에게 이해 가능한 사유, `재시도`, `다른 에이전트로 새 버전 실행`을 제공한다.

## 10. 회의록 상세 화면

참고 목업과 동일한 문서 + 전사 패널 구조를 기본으로 한다.

### 10-1. 문서 영역

- 초안/확정/처리 실패 배지
- 제목
- 일시, 길이, 참석자, 공유자, 관련 채널
- 사용된 전사·요약 에이전트와 버전
- 요약
- 안건별 논의
- 결정 사항
- 액션 아이템: 담당자, 마감일, 완료 여부
- 채널 공유 카드 미리보기
- 편집 및 확정

### 10-2. 우측 전사 원문 패널

- 전사 내용 검색
- 화자별 필터
- 화자 매핑
- 타임스탬프별 세그먼트
- 회의록 문장의 근거 구간 하이라이트
- 데스크톱에서는 360~400px 고정 패널, 좁은 화면에서는 접이식 패널

### 10-3. 초안과 확정

- AI가 만든 결과는 항상 `초안`이다.
- 편집 내용은 자동 저장하되 저장 상태를 보여준다.
- 확정 시 확정자·확정 시각·사용 에이전트 버전을 기록한다.
- 관련 채널과 공유자가 있으면 확정 결과를 전달한다.
- 확정 후에는 본문을 잠그고 액션 아이템 상태만 변경 가능하게 한다.
- 다시 생성할 때 기존 확정본을 덮어쓰지 않고 새 버전 초안을 만든다.

## 12. 데이터 및 API 설계 시 필요한 항목

### 회의

- ID, 워크스페이스 ID, 제목, 상태
- 소유자, 참여자, 공유자, 관련 채널

- 오디오 위치와 보존 정책
- 접근 권한

### 에이전트 실행

- 역할: 전사 또는 요약
- 에이전트 ID와 버전 스냅샷
- 모델·프롬프트·MCP 도구 스냅샷
- 실행 상태, 시작·종료 시각, 오류 코드
- 입력·출력 버전

### 회의록

- 전사 세그먼트와 화자 매핑
- 구조화 문서 버전
- 근거 세그먼트 연결
- 확정자·확정 시각
- 액션 아이템

목록 API에서 전사 전체나 문서 전체를 함께 내려주지 않는다. 페이지 목록에는 요약 메타만 제공하고 상세 진입 시 필요한 원문을 별도로 불러온다.

## 13. 접근성·반응형·오류 처리

- 모든 버튼과 입력에 명확한 한국어 레이블 제공
- 키보드만으로 검색, 페이지 이동, 에이전트 선택 가능

- 페이지 변경 시 목록 제목으로 초점 이동
- 녹음 권한 거부, 마이크 없음, 파일 초과, 에이전트 비활성, MCP 장애를 각각 구분
- 사용자용 오류와 관리자용 추적 ID를 분리

## 14. 더 매끄럽게 만들기 위한 제안

### 제안 1. 모델과 프롬프트를 회의 화면에서 직접 고르지 않는다

사용자의 목표는 에이전트를 선택하는 것이다. 회의마다 모델·프롬프트·도구를 다시 조합하게 하면 에이전트 사전 설정의 의미가 약해지고 실수 가능성이 커진다. 기본 화면에는 에이전트 이름과 목적을 보여주고 내부 구성은 읽기 전용 상세로 확인하게 하는 편이 좋다.

### 제안 2. 전사와 요약 에이전트를 분리하되 호환성을 검증한다

두 에이전트가 독립적이면 재사용성이 높지만 출력 계약이 맞지 않을 수 있다. 에이전트 등록 시 입출력 스키마를 선언하고, 새 회의 화면에서 조합 가능 여부를 미리 검증해야 한다.

### 제안 3. 기본 에이전트 프리셋을 제공한다

매번 두 에이전트를 선택하는 것은 반복 작업이다. 워크스페이스 기본값, 개인 최근 선택, 회의 유형별 프리셋을 제공하되 사용자가 필요할 때 변경할 수 있게 한다.

### 제안 4. 참여자와 공유자의 권한 의미를 화면에서 설명한다

참여자는 화자 매핑·담당자 추천 대상이고, 공유자는 결과 열람 대상이다. 이 차이를 짧은 도움말로 설명하지 않으면 사용자가 두 필드를 중복 입력하게 된다.

### 제안 5. 페이지네이션은 서버 기준으로 시작한다

초기에는 데이터가 적어 클라이언트 페이지네이션도 동작하지만, 전사 검색·권한 필터·다중 테넌트까지 고려하면 곧 한계가 온다. 첫 구현부터 목록 전용 서버 페이지네이션 계약을 두는 편이 안전하다.

### 제안 6. 녹음 종료 직후 상세 화면으로 보내지 않는다

전사와 요약에는 시간이 걸리므로 빈 상세 화면보다 독립 처리 화면이 상태를 이해하기 쉽다. 다만 사용자는 기다릴 필요 없이 목록으로 이동할 수 있어야 한다.

### 제안 7. 회의 시작과 파일 업로드를 한 화면에서 제공한다

둘은 입력 방식만 다르고 참여자·공유자·에이전트 설정은 같다. 설정 화면을 중복시키지 않고 상단의 `실시간 녹음 / 파일 업로드` 선택으로 합치는 것이 좋다.

### 제안 8. v1과 후순위를 명확히 나눈다

**v1 필수**

- 고정 좌측 내비게이션
- 제목 검색과 서버 페이지네이션
- 새 회의 독립 화면
- 참여자·공유자
- 전사·요약 에이전트 선택과 버전 스냅샷
- 녹음·업로드·처리 상태
- 문서 + 전사 상세
- 사람의 초안 확정

**후순위**

- 회의록 문장과 전사 근거 자동 연결
- 실시간 전사
- 회의 중 에이전트 개입
- Zoom/Meet 자동 연동
- 에이전트 성능 비교와 자동 추천
- 복수 요약 결과 A/B 비교

## 16. 목업에서 확인할 항목

- 사이드바가 모든 화면에서 유지되는가
- 검색 후 페이지가 1로 초기화되는가
- 페이지 번호와 결과 범위를 이해할 수 있는가
- 전사·요약 에이전트의 역할 차이가 명확한가
- 에이전트 내부 모델·프롬프트·MCP 구성을 확인할 수 있는가
- 회의 중 핵심 액션이 일시정지와 종료로 제한되는가
- 처리 중 목록으로 이동해도 진행 상태를 찾을 수 있는가
- 상세 화면에서 AI 문서와 원문 근거를 함께 검토할 수 있는가
