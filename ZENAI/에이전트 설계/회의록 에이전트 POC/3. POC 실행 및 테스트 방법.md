# 회의록 에이전트 POC 실행 및 테스트 방법

## 준비

POC 경로는 다음과 같다.

```text
C:\Users\Eric\github\zen-ai-meeting-agent-test
```

Windows PowerShell에서 실행한다.

```powershell
cd C:\Users\Eric\github\zen-ai-meeting-agent-test
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
```

## 기본 실행

### 더미 데이터 생성

```powershell
.\.venv\Scripts\meeting-agent.exe seed
```

### Search 다음 Question이 이어지는 복합 요청

```powershell
.\.venv\Scripts\meeting-agent.exe ask "meeting-001 회의록을 가져오고 결정 사항을 설명해줘"
```

이 실행에서는 Tool 1이 `meeting-001`을 검색·검증한 뒤 `authorized_meeting_ids`에 반영하고, 공통 Checkpoint 이후 LLM 판단으로 복귀해 Tool 2로 원문을 조회한다.

### 복수 후보 HITL

```powershell
.\.venv\Scripts\meeting-agent.exe ask "회의록 검색해줘"
```

후보가 여러 개이면 하나 이상의 `meeting_id`를 입력한다. 기존 허용 ID가 있으면 이어서 `add` 또는 `replace`를 선택한다.

### 대화형 실행

```powershell
.\.venv\Scripts\meeting-agent.exe chat
```

종료 명령은 `/quit` 또는 `/exit`다.

### 녹화 Workflow

```powershell
.\.venv\Scripts\meeting-agent.exe record start
.\.venv\Scripts\meeting-agent.exe record pause
.\.venv\Scripts\meeting-agent.exe record resume
.\.venv\Scripts\meeting-agent.exe record stop
```

정상 전이는 `none → recording ↔ pause → stop → none`이다.

### 현재 Agent State 확인

```powershell
.\.venv\Scripts\meeting-agent.exe state
```

출력되는 영속 State의 최상위 필드는 다음 세 개여야 한다.

```text
ScratchPad
authorized_meeting_ids
recording_modal_status
```

## 자동 테스트

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

현재 검증 항목은 11개다.

1. 하나의 목표에서 Search 다음 Question이 이어지는지
2. 상위 Agent State와 Checkpoint State에 설계의 세 필드만 남는지
3. `request_id`, 지속 `search/question`, `recording_state`가 Agent State에 없는지
4. 회의록 원문의 `transcript` 필드가 Agent Checkpoint State에 저장되지 않는지
5. 복수 후보에서 `interrupt()`가 발생하고 선택 후 재개되는지
6. 접근 권한 없는 회의록이 후보와 원문에서 차단되는지
7. 후보 수 해석이 Model 경계를 통과하는지
8. 질문 Model Context에 시스템 지시·ScratchPad·구조화 Tool 결과가 전달되는지
9. Tool 실패가 두 번 재시도되고 구조화 오류로 Model에 전달되는지
10. `ScratchPad`가 컨텍스트 예산 50%에서 Compact되는지
11. 녹화 정상 전이·정상 거부·실행 오류 상태 동기화가 올바른지

정상 결과는 다음과 같다.

```text
Ran 11 tests
OK
```

## 테스트 해석 시 주의사항

- 기본 모델은 실제 LLM이 아니라 `RuleBasedMeetingModel`이다.
- Compact의 POC 기준은 토큰이 아니라 직렬화한 문자 수 8,000자의 50%다. 실제 모델을 연결할 때 모델별 토큰 계산으로 교체한다.
- HITL 재개 Context는 프로세스 메모리에 있으므로 같은 실행 프로세스 안에서 재개해야 한다.
- 실제 배포 전에는 인증 세션, 분산 FIFO 큐, 멱등성, 운영 DB와 관측성을 추가해야 한다.
