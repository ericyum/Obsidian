## 2. 실제 DeepSeek 단일 요청 실행

기본 Provider는 DeepSeek이고 기본 모델은 `deepseek-v4-pro`다. 현재 POC의 CLI에는 이 컴퓨터의 실제 키 파일 경로가 기본값으로 설정되어 있으므로 별도 옵션 없이 실행할 수 있다.

```powershell
.\.venv\Scripts\python.exe -m meeting_agent `
  ask "meeting-001 회의록을 가져오고 결정 사항을 설명해줘"
```

다른 컴퓨터나 다른 키 파일을 사용할 때만 실제로 존재하는 경로를 명시한다. 아래의 `<실제 키 파일 경로>`는 그대로 입력하는 문자열이 아니라 교체할 자리다.

```powershell
.\.venv\Scripts\python.exe -m meeting_agent `
  --deepseek-key-file "<실제 키 파일 경로>" `
  --deepseek-model "deepseek-v4-pro" `
  ask "meeting-001 회의록을 가져오고 결정 사항을 설명해줘"
```

API 키 값은 코드, Agent State와 Checkpoint에 저장하지 않는다. 키 파일은 실행 시에만 읽는다.

## 3. 규칙 기반 테스트 대역 실행

외부 API 비용과 네트워크 영향 없이 Graph를 빠르게 확인할 때 사용한다.

```powershell
.\.venv\Scripts\python.exe -m meeting_agent `
  --model-provider rule-based `
  ask "meeting-001 회의록을 가져오고 결정 사항을 설명해줘"
```

## 5. 발표용 Trace 서버 기능 확인

Trace 서버 역시 POC의 실행 기능이므로 개발 단계에서는 여기서 기동 여부만 확인한다.

### 실제 DeepSeek 서버

`--model-provider`를 생략하면 기본값인 실제 DeepSeek을 사용한다.

```powershell
.\.venv\Scripts\python.exe -m meeting_agent `
  --app-db data\browser-deepseek-app.db `
  --checkpoint-db data\browser-deepseek-checkpoints.db `
  serve
```

> **서버가 즉시 켜지는 것은 정상이다.** 서버 기동 시에는 DeepSeek API를 호출하지 않는다. 브라우저에서 회의록 질문을 전송했을 때 `deepseek-v4-pro` API 호출이 시작되며, 이때 수 초에서 수십 초가 걸릴 수 있다.

### 규칙 기반 화면 점검 서버

다음 명령은 DeepSeek을 사용하지 않는다. `--model-provider rule-based`가 있으면 API를 호출하지 않는 테스트 대역이므로 질문도 매우 빠르게 끝난다.

```powershell
.\.venv\Scripts\python.exe -m meeting_agent `
  --model-provider rule-based `
  serve
```

- 기본 주소: `http://127.0.0.1:8765`
- 종료: 서버 PowerShell에서 `Ctrl+C`
- 다른 Port: `serve --port 8766`

서버가 열리고 질문 실행 시 Agent Graph, Search/Question Subgraph, Node, Edge와 State가 표시되면 정상이다. 발표 순서와 설명 포인트는 6번 문서를 참고한다.

| 실행 명령 | 실제 DeepSeek 사용 | 속도 판단 |
|---|---:|---|
| Provider 옵션 생략 또는 `--model-provider deepseek` | 사용 | 서버는 즉시 기동, 질문 시 API 호출 |
| `--model-provider rule-based` | 사용하지 않음 | 서버와 질문 모두 매우 빠름 |

## 6. 오프라인 전체 테스트

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

실제 API 통합 테스트는 키가 없으면 Skip된다. 나머지 테스트는 다음을 검증한다.

- Search → Question Graph Loop
- 영속 Agent State의 세 필드 제한
- 권한 없는 회의록 차단
- 회의록 원문 비저장
- 복수 후보 HITL 중단과 재개
- Tool 재시도와 구조화 오류
- ScratchPad Compact
- DeepSeek HTTP Adapter 계약
- 결정적 녹화 전이
- Trace에 상위 Graph와 두 Subgraph가 나타나는지
- Trace에 회의록 원문이 노출되지 않는지

## 8. 합격 기준

- 실제 API 테스트를 제외한 오프라인 테스트가 모두 성공한다.
- 실제 `deepseek-v4-pro` 통합 테스트가 성공한다.
- Search 다음 Question으로 이어지는 복합 목표가 완료된다.
- API 키와 회의록 원문이 Agent Checkpoint 및 Trace에 저장되지 않는다.
- 권한·녹화 Backend와 UI 대역을 실제 제품 코드로 오해하지 않는다.
