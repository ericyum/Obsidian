# 회의록 에이전트 POC 전체 구조와 코드 해설

## 1. 전체를 보는 관점

```text
사용자 경계
└─ cli.py · 실제 프론트엔드 대역

Agent 실행 경계
├─ runtime.py · 하네스
├─ agent_graph.py · 검색·질문 Agent Graph
├─ recording_graph.py · 결정적 녹화 Workflow
└─ state.py · State 계약

외부 기능 경계
├─ model.py · 실제 DeepSeek + 규칙 기반 대역
└─ repository.py · Backend·DB·모달 대역
```

## 2. 실제 코드와 대역 경계

Graph Node·Edge, State 갱신, Checkpoint, HITL, 재시도, Context 조립과 DeepSeek API 호출은 실제 검증 코드다. 사용자 UI, 녹화 모달, 인증·권한 서버와 회의록 DB는 SQLite와 CLI로 흉내 낸다.

## 3. 파일별 상세 역할

### `state.py`

- `AgentState`: 영속 세 필드
- `AgentContext`: 비영속 사용자·Thread·요청
- `SearchState`, `QuestionState`: Subgraph 내부 데이터
- `RecordingWorkflowState`: 녹화 Workflow 입출력
- `reduce_scratchpad`: 이벤트 추가와 Compact 교체

### `agent_graph.py`

- `_call_with_retry`: Tool·Backend 호출 재시도
- `build_search_subgraph`: 후보 검색, 분기, HITL, ID 갱신
- `build_question_subgraph`: 허용 ID 검사, 원문 조회, Context 조립
- `build_agent_graph`: 목표 판단과 후속 작업 Loop
- `business_checkpoint`: 업무 완료 이벤트
- `compact_scratchpad`: Context 예산 50%에서 과거 이벤트 압축

### `recording_graph.py`

LLM이나 Tool 선택 없이 Repository의 녹화 명령을 고정 호출한다. 실행 예외만 `recording_modal_status=error`로 변환한다.

### `runtime.py`

두 Graph, Repository, Model과 Checkpointer를 조립한다. 동일 Thread Lock, Agent 실행, HITL 재개와 녹화 결과 동기화를 담당한다.

### `model.py`

`MeetingModel`은 Graph가 기대하는 계약이다.

- `DeepSeekMeetingModel`: 실제 `deepseek-v4-pro` API 호출
- `RuleBasedMeetingModel`: 오프라인 단위 테스트 대역

DeepSeek의 구조화 판단값은 허용 enum인지 검사한다. 후보 개수처럼 코드가 확정적으로 아는 값은 모델을 호출하지 않는다.

### `repository.py`

실제 Backend의 대역이다. 접근 가능한 후보 검색, 선택 ID 재검증, 원문 조회와 녹화 상태 전이를 SQLite로 구현한다.

### `cli.py`

실제 채팅 Thread와 모달 UI 대역이다. DeepSeek을 기본 Provider로 생성하고 HITL 입력을 터미널에서 받는다.

## 4. 복합 요청 흐름

```text
1. Runtime이 AgentContext 생성
2. 요청을 ScratchPad에 기록
3. DeepSeek이 search 판단
4. Search Subgraph가 후보 검색·권한 검증
5. authorized_meeting_ids 갱신
6. 업무 Checkpoint 후 목표 재판단
7. DeepSeek이 question 판단
8. Question Subgraph가 권한 재검증 후 원문 조회
9. 원문을 지역 Model Context에 조립
10. DeepSeek이 답변 생성
11. 답변·문서 메타데이터만 ScratchPad에 저장
12. DeepSeek이 후속 작업 없음에 해당하는 none 판단 후 END
```

## 5. 설계 의도 평가

잘 반영된 부분:

- 검색·질문과 결정적 녹화를 분리했다.
- LLM은 판단값과 문장을 만들고 코드가 Edge와 권한을 통제한다.
- 원문과 API 키를 Checkpoint에 남기지 않는다.
- 하나의 사용자 목표에서 Search 다음 Question이 이어진다.
- 복수 후보와 추가·대체를 HITL 경계로 만들었다.

후속 개선 대상:

- Question Subgraph의 일부 Node는 아직 경계 표시 중심이다.
- Repository와 CLI는 제품 대역이다.
- 프로세스 재시작 후 HITL 재개와 분산 FIFO는 없다.
- Compact는 실제 모델 Token이 아니라 문자 수 기반이다.

실제 `zen-ai`의 구조와 이식 방식은 이 POC 코드 설명과 섞지 않고 5번 문서에서 별도로 다룬다.
