# Ponytail과 Codex VS Code 적용 방식

**문서 성격:** 회의록 Agent POC 개발 방식 해설  
**기준일:** 2026-09-01  
**대상 환경:** VS Code의 OpenAI Codex 확장과 `zen-ai-meeting-agent-test`

이 문서는 Ponytail이 무엇인지, 전체 플러그인과 단순 지침 파일 방식이 어떻게 다른지, 그리고 현재 회의록 Agent POC에서 어떤 방식으로 적용했는지를 정리한다.

현재 선택한 방식은 **Codex CLI나 Ponytail 전체 플러그인을 설치하지 않고, 저장소의 `AGENTS.md`에 Ponytail의 핵심 최소 구현 원칙을 프로젝트 규칙으로 넣는 것**이다.

## 1. 핵심 결론

```text
현재 사용 화면
→ VS Code의 OpenAI Codex 확장

현재 적용 방식
→ 저장소 루트의 AGENTS.md를 Codex가 읽음
→ Ponytail의 핵심 최소 구현 원칙을 작업 지침으로 따름

설치한 Ponytail VS Code 확장
→ GitHub Copilot Chat용 @ponytail 참여자
→ OpenAI Codex 대화에는 적용되지 않음

Codex용 Ponytail 전체 플러그인
→ Codex CLI 또는 지원되는 Codex 화면에서 설치
→ 현재 POC에서는 사용하지 않음
```

- Ponytail은 별도의 AI Model이나 IDE가 아니다.
- AI Coding Agent가 불필요하게 많은 코드·추상화·의존성을 만들지 않도록 하는 오픈소스 작업 지침과 이를 여러 Agent에 연결하는 Plugin·Skill·Hook 모음이다.
- Codex는 작업 전에 저장소의 `AGENTS.md`를 읽으므로, 그 안에 핵심 원칙을 적는 것만으로도 Codex의 구현 판단에 영향을 줄 수 있다.
- 다만 `AGENTS.md` 방식은 Ponytail 전체 플러그인을 설치한 것과 같지 않다. Mode 전환, Lifecycle Hook과 전용 명령은 생기지 않는다.
- 현재 POC처럼 VS Code Codex만 사용할 때는 `AGENTS.md` 방식이면 충분하다.

## 2. Ponytail이란 무엇인가?

Ponytail은 Dietrich Gebert가 공개한 MIT License 기반 프로젝트다. 핵심 목표는 AI Coding Agent가 문제를 충분히 이해한 다음 **요구사항을 충족하는 가장 작은 해법에서 멈추도록 유도하는 것**이다.

Ponytail이 정의한 원래 판단 순서는 다음과 같다.

1. 이 기능을 정말 만들어야 하는가? 필요하지 않으면 만들지 않는다.
2. 같은 기능이나 Pattern이 현재 Codebase에 이미 있는가? 있으면 재사용한다.
3. 표준 라이브러리가 해결하는가? 표준 라이브러리를 사용한다.
4. OS·Browser·Framework 같은 Platform의 기본 기능이 해결하는가? 기본 기능을 사용한다.
5. 이미 설치된 의존성이 해결하는가? 기존 의존성을 사용한다.
6. 한 줄로 충분한가? 불필요하게 확장하지 않는다.
7. 그 어느 것도 아니면 동작하는 최소 코드를 작성한다.

이 순서를 Ponytail 문서에서는 **Ladder**라고 부른다. 중요한 점은 단순히 코드 줄 수를 줄이는 것이 아니다.

> 문제와 실제 호출 흐름을 먼저 이해하고, 보안·검증·오류 처리·접근성을 희생하지 않은 상태에서 불필요한 구현만 제거하는 원칙이다.

따라서 Ponytail은 Code Golf 규칙이나 무조건 한 줄로 줄이는 도구가 아니다. 안전에 필요한 코드는 유지하고, 요청하지 않은 범용화와 미래를 가정한 구조를 피하는 쪽에 가깝다.

## 3. Ponytail은 하나의 프로그램만을 뜻하지 않는다

Ponytail GitHub Repository에는 같은 철학을 여러 Coding Agent에 적용하기 위한 여러 형태가 함께 들어 있다.

| 형태 | 내용 |
|---|---|
| 기본 규칙 파일 | `AGENTS.md`, Copilot Instructions, Cursor Rules 등 Agent별 Instruction 파일 |
| 전체 Plugin | 규칙과 Skill, Mode, Lifecycle Hook을 묶은 Plugin Package |
| 전용 Skill·Command | Review, Audit, Debt 확인 등 특정 작업을 수행하는 명령 |
| Editor Adapter | 특정 IDE 또는 Chat 환경에 맞춘 연결 방식 |

그러므로 “Ponytail을 사용한다”는 말은 다음 중 어느 것을 뜻하는지 구분해야 한다.

- 핵심 원칙만 Instruction 파일에 복사해 적용한다.
- Ponytail의 전체 규칙 문서를 적용한다.
- Hook과 명령까지 들어 있는 전체 Plugin을 설치한다.
- 특정 Editor Marketplace에서 제공되는 별도 확장을 설치한다.

현재 POC는 이 가운데 첫 번째 방식이다.

## 4. `AGENTS.md`에 몇 줄 적는 것으로 정말 적용되는가?

**Codex의 동작 지침으로는 실제로 적용된다.**

OpenAI 공식 문서에 따르면 Codex는 작업을 시작하기 전에 `AGENTS.md`를 읽는다. Git 저장소의 Root에서 현재 작업 Directory까지 파일을 탐색해 지침 Chain을 구성한다. 현재 저장소 Root에는 다음 파일이 있다.

```text
C:\Users\Eric\github\zen-ai-meeting-agent-test\AGENTS.md
```

따라서 이 저장소를 Workspace로 연 VS Code Codex는 해당 파일의 프로젝트 목적, 구현 경계, 보안 규칙, 테스트 방식과 Ponytail 최소 구현 원칙을 함께 작업 지침으로 사용한다.

다만 여기서 “적용된다”의 의미는 다음과 같다.

- Codex Prompt Context에 지속적인 프로젝트 지침으로 포함된다.
- Codex가 설계와 구현 방법을 선택할 때 그 지침을 따라야 한다.
- 별도 Ponytail Process가 실행되거나 Source Code를 정적 분석해 위반을 강제 차단하는 것은 아니다.
- Compiler, Linter 또는 Policy Engine처럼 100% 기계적으로 보장하는 기능은 아니다.

즉, `AGENTS.md`는 **Codex가 공식적으로 지원하는 Project Instruction 기능**이고, Ponytail 규칙은 그 기능에 올려 사용하는 내용이다.

### 4-1. 언제부터 적용되는가?

Codex는 실행 또는 Session을 시작할 때 `AGENTS.md` Instruction Chain을 구성한다. 파일을 수정한 뒤 이미 진행 중인 대화가 새 내용을 항상 다시 읽는다고 기대해서는 안 된다.

가장 확실한 사용 방법은 다음과 같다.

1. `AGENTS.md`를 저장한다.
2. 해당 저장소를 Workspace Root로 연다.
3. VS Code에서 새 Codex 대화를 시작한다.
4. 평소처럼 작업을 요청한다.

현재 방식에서는 매 Prompt에 `@ponytail`을 붙일 필요가 없다. 저장소의 `AGENTS.md`가 Project 전체에 항상 적용되는 지침 역할을 한다.

## 5. 현재 POC의 `AGENTS.md`에 적용된 내용

현재 `AGENTS.md`에는 `Ponytail 최소 구현 원칙` Section이 추가되어 있다.

```text
1. 이 기능이 정말 필요한지 확인한다.
2. 현재 코드베이스의 기존 구현과 패턴을 우선 재사용한다.
3. Python 표준 라이브러리로 해결 가능한지 확인한다.
4. 이미 설치된 의존성으로 해결 가능한지 확인한다.
5. 새로운 추상화와 의존성을 불필요하게 추가하지 않는다.
6. 요구사항을 충족하는 가장 작은 변경을 구현한다.
```

또한 최소 구현을 이유로 다음 항목을 축소하거나 생략하지 못하도록 예외가 명시되어 있다.

- 회의록 Agent 설계 불변 조건
- 사용자가 명시한 요구사항
- 보안 및 권한 검증
- 오류 처리와 데이터 손실 방지
- 지정된 테스트와 검증 절차

이 내용은 원본 Ponytail의 전체 문구를 그대로 복사한 것이 아니라, 현재 Python·LangGraph POC에 맞게 핵심을 추린 Project용 적용본이다.

### 5-1. 전체 Ponytail과 비교해 생략된 것

현재 Section만으로는 다음 기능이나 지침이 추가되지 않는다.

- `lite`, `full`, `ultra`, `off` Mode 전환
- Prompt와 Subagent 실행 시 규칙을 다시 주입하는 Lifecycle Hook
- `@ponytail-review`, `@ponytail-audit`, `@ponytail-debt`, `@ponytail-gain`, `@ponytail-help` 같은 전용 Skill
- 원본 규칙의 상세한 Bug Root Cause 조사 지침
- Code-first Output 등 전체 응답 형식 규칙
- Mode 설정의 영속 저장

현재 POC의 목적은 Ponytail 제품 전체를 시험하는 것이 아니라, 구현을 필요 이상으로 키우지 않는 원칙을 Codex 작업에 적용하는 것이다. 따라서 이 축약 방식이 현재 범위에 맞는다.

## 6. 설치한 VS Code Marketplace 확장은 무엇인가?

설치된 확장은 다음 Package다.

```text
표시 이름: Ponytail
Publisher: Volvo-AntoniaCanizares
Package: volvo-antoniacanizares.ponytail-vscode
확인한 Version: 1.2.0
```

이 확장의 설명에는 다음 전제조건이 명시되어 있다.

- GitHub Copilot Extension이 필요하다.
- Copilot Chat에서 `@ponytail`을 한 번 호출한다.
- 그 Chat에서 Ponytail 참여자를 계속 사용한다.

설치된 Source도 VS Code Chat Participant `ponytail.chat`을 등록하고, VS Code Language Model API에서 `gpt-4o` 계열 Model을 선택하는 구조다. 따라서 이 확장의 작동 경로는 다음과 같다.

```text
사용자
→ GitHub Copilot Chat의 @ponytail
→ Ponytail Instruction 주입
→ VS Code Language Model API / Copilot Model
```

현재 대화 경로는 다음과 다르다.

```text
사용자
→ OpenAI Codex VS Code 확장
→ Codex
```

따라서 Marketplace에서 설치한 해당 확장은 **GitHub Copilot Chat에서는 사용할 수 있지만 OpenAI Codex Chat에 Ponytail 규칙을 주입하지 않는다.** 설치되어 있다는 사실만으로 Codex에 적용되는 것은 아니다.

## 7. Codex CLI 오류의 의미

다음 오류는 Ponytail 자체의 문제가 아니다.

```text
'codex'은(는) 내부 또는 외부 명령, 실행할 수 있는 프로그램, 또는
배치 파일이 아닙니다.
```

이 메시지는 현재 Windows Terminal의 `PATH`에서 `codex` 실행 파일을 찾지 못했다는 뜻이다.

VS Code Codex 확장이 내부적으로 Codex 실행 파일을 포함할 수는 있지만, 확장을 설치했다고 해서 Windows Terminal에 전역 `codex` 명령이 자동 등록되는 것은 아니다. 따라서 Terminal에서 다음 명령을 사용하려면 별도의 Codex CLI 설치와 PATH 구성이 필요하다.

```text
codex plugin marketplace add DietrichGebert/ponytail
codex plugin add ponytail@ponytail
```

하지만 현재 사용자는 별도의 CLI Workflow를 사용하지 않기로 했다. 그러므로 이 오류를 해결하거나 Codex CLI를 추가 설치하는 것은 현재 POC의 Ponytail 적용에 필요하지 않다.

## 8. Ponytail 전체 Plugin과 현재 방식 비교

| 항목 | 현재 `AGENTS.md` 방식 | Codex용 전체 Ponytail Plugin | 설치한 VS Code Ponytail 확장 |
|---|---|---|---|
| 대상 | OpenAI Codex | Plugin을 지원하는 Codex 화면·CLI | GitHub Copilot Chat |
| 현재 VS Code Codex 적용 | O | IDE 확장은 Plugin 미지원 | X |
| 별도 설치 | 필요 없음 | Plugin 설치 필요 | VS Code Extension 설치 필요 |
| 기본 원칙 적용 | O | O | Copilot Chat에서 O |
| Mode 전환 | X | O | O |
| Lifecycle Hook | X | O | Codex에는 적용되지 않음 |
| 전용 Review·Audit Skill | X | O | 제공 방식이 다름 |
| Node.js | 필요 없음 | Hook 사용에 필요 | 별도 Node.js 불필요 |
| 적용 범위 | 현재 저장소 | 설치·설정 범위 | Copilot Chat |
| 현재 POC 권장 여부 | O | 필요 기능이 생길 때 검토 | Codex 용도로는 불필요 |

OpenAI 공식 문서 기준으로 Codex IDE Extension은 Plugin을 지원하지 않는다. Plugin Browser와 설치 기능은 Codex CLI 또는 지원되는 ChatGPT/Codex 화면에서 사용한다.

따라서 현재 VS Code Codex 환경에서 전체 Plugin 기능까지 원하면 CLI나 지원 화면으로 작업 방식을 바꿔야 하지만, 핵심 원칙만 필요하다면 바꿀 이유가 없다.

## 9. 보안과 외부 전송

### 9-1. 현재 `AGENTS.md` 방식

현재 방식은 저장소의 Markdown 문서에 작업 지침을 추가한 것이다.

- Ponytail 실행 Process가 추가되지 않는다.
- Ponytail Server나 Database에 연결하지 않는다.
- Ponytail 계정이나 API Key가 필요하지 않다.
- Ponytail용 Network 요청을 새로 만들지 않는다.
- 제3자 Hook Script를 실행하지 않는다.

따라서 **Ponytail 규칙을 `AGENTS.md`에 적었다는 이유로 고객 정보나 Source Code가 Ponytail 측 Database로 전송되지는 않는다.**

Codex가 원래 작업을 수행하기 위해 사용하는 OpenAI 경로와 Data Policy는 별도 문제다. `AGENTS.md` 방식은 그 기존 경로에 Project Instruction을 추가할 뿐, Ponytail이라는 새로운 외부 전송 경로를 만들지 않는다.

### 9-2. 전체 Plugin을 사용할 경우

Ponytail 전체 Plugin은 Session과 Prompt Lifecycle에 맞춰 Local Node.js Hook을 실행할 수 있다. OpenAI 공식 문서도 Plugin Hook을 활성화하기 전에 사용자가 내용을 검토하고 신뢰할 것을 요구한다.

향후 전체 Plugin을 도입한다면 다음을 확인한다.

- 설치할 GitHub Repository와 Version
- Plugin Manifest와 Hook 명령
- Hook Script가 읽는 파일과 실행하는 Process
- 외부 Network 요청 여부
- Update 시 변경된 권한과 Script

### 9-3. 설치한 Copilot용 VS Code 확장

이 확장은 VS Code Extension Host에서 실행되는 제3자 코드이며 Copilot/VS Code Language Model 경로로 Prompt를 전달한다. 확인한 설치 Source에서는 별도 Ponytail Database로 보내는 구현을 찾지 못했지만, Codex와는 별개인 Copilot 처리 경로가 생긴다.

SAP 고객 정보를 다루는 환경에서는 Ponytail 이름만 볼 것이 아니라 다음을 기준으로 판단해야 한다.

- 실제로 어느 Chat Provider를 사용하는가?
- Prompt와 첨부 Code가 OpenAI Codex로 가는가, GitHub Copilot로 가는가?
- 회사와 고객사의 AI 사용 정책이 해당 Provider 사용을 허용하는가?
- 설치한 제3자 Extension과 자동 Update를 허용하는가?

현재 POC가 더미 Data만 사용하고, Codex용으로는 `AGENTS.md`만 적용한다면 Ponytail 때문에 추가되는 외부 Data 경로는 없다.

## 10. 현재 POC의 권장 사용 방법

현재 환경에서는 다음처럼 사용한다.

1. `C:\Users\Eric\github\zen-ai-meeting-agent-test`를 VS Code Workspace로 연다.
2. 새 Codex Chat을 시작한다.
3. `@ponytail`을 입력하지 않고 평소처럼 구현·수정 요청을 한다.
4. Codex가 기존 Code와 Pattern을 먼저 재사용하는지 확인한다.
5. 새로운 Dependency나 추상화가 필요할 때 그 필요성을 설명하는지 확인한다.
6. 완료 전에 기존 `AGENTS.md`에 지정된 Test와 검증이 수행되는지 확인한다.

지침 로드 여부가 의심되면 새 Codex Chat에서 다음처럼 물어볼 수 있다.

```text
현재 저장소의 AGENTS.md에서 Ponytail 최소 구현 원칙을 요약해줘.
```

Codex가 현재 Section의 여섯 단계와 보안·테스트 예외를 설명한다면 Project Instruction을 읽은 것이다.

### 10-1. 현재 방식으로 충분한 경우

- 현재 POC처럼 작은 변경과 빠른 기술 검증이 목적이다.
- 불필요한 Dependency와 구조 확장을 줄이는 것이 핵심이다.
- VS Code Codex에서 계속 작업할 예정이다.
- Ponytail 전용 Review·Audit Command가 필요하지 않다.
- 매 Prompt에 Mode를 바꿀 필요가 없다.

### 10-2. 전체 Plugin을 검토할 조건

- `lite`, `full`, `ultra`를 작업별로 자주 바꿔야 한다.
- Ponytail 전용 Review·Audit Skill이 필요하다.
- Subagent와 모든 Prompt에 Hook으로 규칙을 반복 주입해야 한다.
- Codex CLI 또는 Plugin 지원 화면을 실제 기본 작업 환경으로 사용할 예정이다.

## 11. 오해하기 쉬운 부분

| 오해 | 실제 의미 |
|---|---|
| Ponytail은 별도 Coding IDE다 | AI Coding Agent용 규칙과 Integration 모음이다. |
| VS Code 확장을 설치하면 Codex에도 적용된다 | 설치한 확장은 GitHub Copilot Chat용이다. |
| `AGENTS.md` 몇 줄은 아무 효과가 없다 | Codex가 공식적으로 읽는 Project Instruction이므로 행동 지침으로 적용된다. |
| `AGENTS.md`를 추가하면 전체 Plugin이 설치된다 | Mode, Hook, Skill은 설치되지 않는다. |
| 매번 `@ponytail`을 입력해야 한다 | 현재 Codex의 `AGENTS.md` 방식에서는 필요 없다. |
| `codex` Terminal 명령이 안 되면 Ponytail을 못 쓴다 | CLI Plugin은 못 쓰지만 `AGENTS.md` 방식은 사용할 수 있다. |
| 최소 구현은 보안과 Test도 줄인다는 뜻이다 | Ponytail 원칙과 현재 Project 지침 모두 안전에 필요한 코드는 줄이지 않는다. |
| Ponytail 지침이 고객 Data를 Ponytail DB로 보낸다 | `AGENTS.md` 방식에는 그런 실행·전송 기능이 없다. |

## 12. 현재 결정

회의록 Agent POC에서는 다음 방식을 유지한다.

```text
VS Code OpenAI Codex
+ 저장소 루트 AGENTS.md
+ POC에 맞게 축약한 Ponytail 최소 구현 원칙
+ 기존 보안·설계·테스트 규칙 우선
```

사용하지 않는 것은 다음과 같다.

```text
Codex CLI 기반 Ponytail Plugin 설치
Ponytail Lifecycle Hook
Ponytail 전용 Mode와 Command
GitHub Copilot용 @ponytail을 Codex에 사용
```

이 결정은 나중에 변경할 수 있다. 전용 Skill과 Mode가 실제로 필요해지는 시점에 전체 Plugin을 검토하면 된다.

## 핵심 정리

> Ponytail은 불필요한 구현을 피하고 요구사항을 충족하는 가장 작은 안전한 변경을 선택하게 하는 Coding Agent용 규칙과 Integration 모음이다. 현재 회의록 Agent POC에서는 전체 Plugin이나 CLI를 사용하지 않고 저장소의 `AGENTS.md`에 핵심 원칙을 적용했다. 이 방식은 VS Code Codex에서 실제 Project Instruction으로 동작하지만 Mode·Hook·전용 Skill은 제공하지 않는다. 설치한 Marketplace 확장은 GitHub Copilot Chat용이므로 Codex에는 적용되지 않는다. `AGENTS.md` 방식 자체는 Ponytail Server나 Database에 연결하지 않으므로 Ponytail 때문에 추가되는 외부 Data 전송 경로도 없다.
