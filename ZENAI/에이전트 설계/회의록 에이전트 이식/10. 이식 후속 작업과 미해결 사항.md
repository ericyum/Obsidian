# 회의록 Agent 이식 후속 작업과 미해결 사항

## 남은 작업

- 새 Agent State·Workflow Checkpoint를 기준으로 HITL 유효/무효 입력과 재개를 검증하는 통합 테스트 보강.
- 기존 테스트의 `agent_runs.builtin_checkpoint` 직접 검사를 새 저장소 검사로 전환하고 호환성 테스트만 별도 유지.
- 올바른 PostgreSQL 테스트 환경에서 migration, RLS, 전체 E2E를 재실행한다. 현재는 `.env`의 DB 접속 정보와 실행 중인 PostgreSQL 컨테이너의 사용자·비밀번호·포트가 일치하지 않아 Vitest 전체를 완전히 재현하지 못했다. 다음 조건을 먼저 고정하고 검증해야 한다.
  - 테스트 전용 PostgreSQL 인스턴스가 실행 중이고 지정 포트로 접속 가능할 것
  - 테스트가 읽는 DB URL/사용자/비밀번호가 해당 인스턴스와 일치할 것
  - 최신 migration과 RLS 정책을 빈 DB에 처음부터 적용할 것
  - 기존 데이터나 개발용 DB를 사용하지 않고 테스트 격리를 보장할 것
  - `npm run check`, migration/RLS 테스트, 회의 Agent HITL E2E, 전체 Vitest를 각각 실행할 것
  - 전체 테스트가 인증 오류·연결 거부·환경 의존성 없이 재현되고, 실패 0건(의도된 skip만 별도 기록)일 때 통과로 판정할 것
- `channel-adapter.ts`의 저장·조회 경로가 새 저장소를 정본으로 사용하는지 최종 확인.
- MCP Tool 전환 시 Tool 결과·HITL 토큰·감사/Trace 전달 계약을 고정.

**Prettier 검사 실패 원인 조사 및 재검증**

- pre-push 검사에서 1,048개 파일의 포맷 불일치로 push가 실패했다. 원인은 아직 확정되지 않았다.
- lockfile 기준 Prettier 버전, 설정 파일, `.gitattributes`, Git 줄바꿈 설정과 실제 파일의 줄바꿈을 확인한다.
- 동일한 환경에서 기준 커밋과 회의록 Agent 변경 커밋을 비교해 기존 문제와 신규 변경 문제를 구분한다.
- 전체 파일을 무조건 포맷하지 않고, 원인을 확인한 후 필요한 범위만 수정한다.
- 수정 후 포맷 검사와 pre-push 검사를 다시 실행하고 결과를 기록한다.
- `--no-verify`로 push했더라도 검수가 통과한 것으로 간주하지 않는다.

## 현재 제약

레거시 `builtin_checkpoint`는 즉시 삭제하지 않고 동기화 목적으로 계속 기록한다. 따라서 세 저장소 분리는 논리적으로 적용되었지만 레거시 호환 단계이며, 완전 제거는 위 검증과 마이그레이션 완료 후 별도 결정한다.
