# 상태·목표·상황 기반 회의록 Agent 이식 행동 플랜

## 1. 상태·목표·상황

- **상태:** `message.posted` 대화, 안전한 Scratchpad, Tool이 소유한 `authorizedMeetingIds`, Pending HITL, 현재 Run 단계다.
- **목표:** 검색, 질문, 녹화 시작 또는 Tool 없는 직접 답변 가운데 남은 사용자 목표다. 종료 용어는 `none`이다.
- **상황:** 호출 사용자·커뮤니티·Channel·Thread, 현재 권한, 회의 후보, 모델·실행 한도와 취소 신호다.

## 2. 행동 원칙

1. LLM은 다음 행동과 답변을 판단하지만 권한과 상태 갱신을 승인하지 않는다.
2. Search·Question Tool은 사용자 권한과 `authorizedMeetingIds` 정합성을 직접 검사한다.
3. 여러 후보와 추가·대체는 HITL로 넘긴다.
4. 현재 Run의 Tool 결과는 다음 모델 호출에만 사용하고 최종 대화 원장에는 중간 Tool Message를 저장하지 않는다.
5. 회의록 원문은 현재 Question 호출이 끝나면 버린다.
6. 녹화 상태는 Recording Provider/Backend만 소유한다.

## 3. 최초 호출

```text
사용자 @MEETING 메시지
→ message.posted 저장과 Builtin mention 식별
→ compiled definition·instance config로 실행 Snapshot 확정
→ builtin agent_runs 생성
→ Builtin Worker claim
→ Executor Registry에서 meeting-agent-v1 선택
→ 같은 Thread 대화와 이전 안전한 Checkpoint 조회
→ Pending HITL이 없으면 목표 판단
   ├─ search → Search Tool
   ├─ question → Question Tool
   ├─ recording → 요청자 전용 녹화 시작 Event
   └─ direct → 모델 답변
→ Builtin operation receipt
→ 최종 message.posted와 agent_runs terminal을 같은 공통 경계에서 확정
```

최초 메시지가 Thread 루트이며 Agent 답변은 `parentEventId`로 그 루트에 연결된다. 별도의 Thread 레코드를 생성한다고 표현하지 않는다.

## 4. HITL 후속 질문

```text
Search Tool이 hitl_required 반환
→ Tool State Repository에 후보·정합성 정보와 일회용 토큰 저장
→ builtin_checkpoint에 공개 가능한 최소 재개 메타데이터 저장
→ HITL 질문 message.posted 출력, R1 완료

사용자 선택 메시지
→ R2 생성·claim
→ 이전 Checkpoint와 Tool Pending 상태 확인
→ 선택·add/replace 또는 /cancel 검증
→ Tool이 최신 권한을 다시 확인하고 상태 원자적 갱신
→ 남은 원래 목표가 있으면 Question으로 계속, 없으면 결과 답변
```

R1과 R2는 서로 다른 `agent_runs` 행이고 각각의 `triggerEventId`는 각 Run을 만든 사용자 메시지를 가리킨다. Worker lease를 HITL 대기 시간 동안 유지하지 않는다.

## 5. 구현 단계

### 1단계. 제품 경계 확정

- 기존 Builtin Platform과 SAP 전용 Executor의 실제 호출·완료 경계 확인
- 기존 `/meeting-start`, Meeting DB와 권한 함수 확인
- 문서 5~8과 현재 코드 충돌 제거

### 2단계. Definition과 호출 연결

- `agents/meeting/assistant` definition 추가
- Executor descriptor·factory·enqueue 등록
- 초대형 Builtin invocation admission에서 불필요한 SAP 전용 제한만 일반화

### 3단계. 회의록 Executor

- 목표 상태 머신과 구조화 모델 Adapter
- Thread Context와 Context 예산
- Realtime 진행 상태와 안전한 operation evidence

### 4단계. Tool·State·HITL

- 권한이 적용된 Search·Question Repository
- Local Tool State Repository
- Pending HITL 생성·재개·만료·취소
- 원문 비영속성 검증

### 5단계. Recording과 검증

- 요청자 전용 녹화 시작 Event를 기존 Provider에 연결
- 기존 SAP·일반 Agent 회귀 테스트
- check·lint·knip·전체 Vitest 반복

## 6. 한 문장 정리

회의록 판단과 Tool 상태만 새 Executor에 넣고, 이미 존재하는 Builtin Agent의 호출·Run·감사·최종 메시지 기반을 그대로 재사용한다.
