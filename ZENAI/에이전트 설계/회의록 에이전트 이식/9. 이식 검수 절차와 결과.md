# 회의록 Agent 이식 검수 절차와 결과

## 1. 검수 목적과 범위

Builtin Executor 진입부터 최종 메시지까지의 실행 흐름과 세 저장소의 책임 분리를 검증한다. 대상은 `@MEETING` 라우팅, Engine·Provider·Tool, HITL 중단/재개, 권한 재검증, Scratchpad, Workflow Checkpoint, Realtime, 감사 기록이다.

## 2. 사전 조건

- 최신 브랜치와 설계 문서 1~8번을 준비한다.
- 테스트 전용 PostgreSQL을 실행하고 `.env`의 URL·사용자·비밀번호·포트를 일치시킨다.
- 빈 DB에 최신 migration과 RLS를 처음부터 적용한다.
- 테스트 계정, 접근 가능한 회의록 1개 이상, 접근 불가능한 회의록, 복수 후보가 나오는 검색어를 준비한다.
- 개발 서버와 Realtime 연결을 실행한다.

## 3. 자동 검수 순서

1. `npm ci`로 lockfile 기준 의존성을 설치한다.
2. `npm run check`와 `npm run build`로 타입·컴파일을 확인한다.
3. migration/RLS 테스트로 세 저장소의 테이블·정책·트리거를 확인한다.
4. Engine·State Repository targeted test를 실행한다.
5. 전체 Vitest를 실행한다.
6. `npm run lint`, `npm run knip`, `git diff --check`를 실행한다.

인증 오류, `ECONNREFUSED`, 포트 불일치, 환경 변수 누락은 환경을 수정한 뒤 재실행한다. 의도된 skip을 제외한 실패 0건만 통과로 판정한다.

## 4. 기능 시나리오와 기대 결과

### A. 일반 질문

1. `@MEETING`과 단일 회의 질문을 입력한다.
2. Builtin definition과 `meeting-agent-v1` Executor가 선택되는지 확인한다.
3. Search·Question Tool 결과와 최종 답변을 확인한다.
4. Agent State의 Scratchpad가 갱신되고 Workflow Checkpoint가 `done`인지 확인한다.
5. `message.posted`에는 최종 대화만 있고 중간 Tool 결과가 저장되지 않는지 확인한다.

### B. 복수 후보 HITL

1. 복수 후보 검색어를 입력한다.
2. Search Tool이 후보를 자체 판단하고 상세 Snapshot을 Tool State Repository에 저장하는지 확인한다.
3. Engine이 별도 `select()`를 호출하지 않고 최소 HITL 참조만 Agent State에 저장하는지 확인한다.
4. Workflow Checkpoint가 `hitl_waiting`으로 기록되고 Run이 종료되는지 확인한다.

### C. HITL 재개

1. 잘못된 선택값을 새 메시지로 입력한다.
2. 입력 검증 실패, pending 상세 상태 유지, 재입력 안내를 확인한다.
3. 올바른 선택값을 다시 입력한다.
4. Tool State의 Snapshot이 소비/삭제되고 `authorizedMeetingIds`가 갱신되는지 확인한다.
5. Engine이 논리적으로 중단된 지점 다음부터 진행하고 새 Checkpoint가 `done`인지 확인한다.

### D. 권한과 보안

권한 없는 회의록 조회가 차단되고, HITL 선택 직후에도 권한이 재검증되는지 확인한다. API 키·회의록 원문·민감 Snapshot이 State, Checkpoint, Trace, 로그에 나타나지 않아야 한다.

### E. Recording

녹화 시작 명령을 입력해 Recording 이벤트가 전달되고, 성공 status 반환 후 불필요한 LLM 후속 실행 없이 Run이 종료되는지 확인한다.

## 5. 브라우저 검수

개발 서버를 실제로 띄우고 시크릿 창/테스트 계정으로 새 대화와 HITL 재개 대화를 각각 수행한다. 화면 결과뿐 아니라 Network·Console, Realtime `agent-delta`, 최종 `message.posted`, 세 저장소의 DB 레코드를 단계별로 대조한다. 무한 로딩·중복 응답·HTTP 오류가 있으면 실패다.

## 6. 현재 결과와 미완료 항목

- `npm run check` 통과.
- migration 적용 및 새 State/Checkpoint 테이블과 동기화 트리거 확인.
- Search가 후보 판단과 HITL 생성을 담당하며 Engine은 `select()`를 호출하지 않는다.
- 레거시 `agent_runs.builtin_checkpoint`는 호환성을 위해 유지·동기화된다.
- PostgreSQL 인증/환경 차이로 전체 Vitest와 운영과 동일한 브라우저 E2E의 완전한 재현은 아직 확보하지 못했다.

따라서 정적·구조 검수는 완료했으나, 동일한 테스트 DB 설정에서 자동·브라우저 E2E를 실패 0건으로 재현하기 전에는 최종 통과로 판정하지 않는다.
