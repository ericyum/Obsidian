# LLM 테스트 시도와 미완료 사유

기록 기준: 2026-09-14. **DeepSeek API의 기초 호출은 확인했지만, 실제 Meeting Agent 통합 5종 테스트와 최종 품질·안전성 판정은 완료하지 못했다.** 기존 모의 LLM 기반 이식 검증 결과는 [[9. 이식 테스트 과정과 결과]]에 별도로 남긴다.

## 목표와 실제 수행 범위

DeepSeek 실제 모델로 아래 다섯 항목을 검증하려 했다. 호출에 성공한 ID는 deepseek-chat, deepseek-reasoner, deepseek-flash, deepseek-v4-pro다. 네 ID가 서로 독립된 모델인지, 일부가 별칭인지는 확인하지 않았다.

| 검사 | 하려던 검증 | 실제 수행과 한계 |
| --- | --- | --- |
| 모델 호출 통합 | Provider·Engine·Worker·Tool·DB 연결과 오류·재시도 | 별도 HTTP 호출, 잘못된 모델 400, 강제 AbortError만 확인. 제품 경로·429/5xx 재시도 미검증 |
| 프롬프트 회귀 | 제품 프롬프트의 검색·선택·후속 질문 유지 | 짧은 합성 질문 5개 반복. 제품 프롬프트·HITL·버전 간 비교 미연결 |
| 평가셋(Eval) | 기대 사실·선택·거절 기준과 답변 비교 | 문자 수·일부 단어 탐지만 구현. 정답 기반 점수와 통과 기준 미완성 |
| 안전성 | 권한 우회·주입·저장소와 로그의 비밀 노출 | 단순 정규식과 고정 canary 미출력 확인. 실제 DB 권한·State·Checkpoint·Trace 미연결 |
| 비용·성능 | 비용·전체 지연·실패율·제한 부하 | 토큰 수·일부 지연·4개 병렬 요청 수집. 가격 적용 비용·충분한 표본의 p95·부하 한계 미산출 |

HTTP 200은 요청 성공이며 답변의 정확성·안전성 통과가 아니다. 같은 요청 결과를 다섯 범주에 복사해 기록한 실행기도 있었으므로 “5종 테스트 완료”로 해석하면 안 된다.

## 왜 끝내지 못했는가

**API 키·권한 부족이 아니라, 검증 실행기와 판정 기준을 충분히 구현하지 못한 것이 직접적인 이유다.**

1. .context/llm-eval에서 API만 호출했다. 기존 모의 모델 기반 DB 통합 fixture를 실제 DeepSeek 모드로 확장하지 않았다.
2. 제품 Provider는 모델의 JSON 결정을 파싱하고 Engine이 내부 Tool을 실행한다. 별도 search_meetings 함수 호출 실험은 이 제품 계약을 검증하지 않는다.
3. 작은 출력 예산이 추론 토큰으로 소진돼 일부 응답이 비었다. 예산과 종료 사유를 조정해 완결된 답변을 평가하는 절차를 끝내지 못했다.
4. 정답·채점표·회귀 기준·장애 주입을 완성하지 않은 채 호출을 반복했다. 실행 환경이 필요하다는 설명만으로 통합 작업 미완료를 대체할 수는 없다.

“모델이 지원하지 않아 불가능했다”거나 “사용자가 자료를 더 주지 않아 중단됐다”고 결론 내리지 않는다. 합성 평가셋과 연결 코드는 추가 개발로 준비할 수 있는 작업이었다.

## 이전 결과 설명의 정정

- **키 유출은 확인되지 않았다.** 실행 코드의 정규식은 실제 키 패턴뿐 아니라 API key·password라는 단어에도 참이었다. 정규식 변경이 실패한 상태에서 “sk- 문자열 탐지”라고 단정한 설명은 근거가 없다.
- 네 모델의 canary 미출력은 단순 요청의 결과일 뿐이다. 이전 탐지가 오탐이었음을 확정하거나 전반적인 주입 방어를 증명하지 않는다.
- 세 추론 모델의 Tool 호출 없음은 120토큰 제한에서 나온 결과다. Tool 지원 불가나 제품 결함을 뜻하지 않는다.
- 잘못된 모델 3회 호출은 자동 재시도 정책 검증이 아니다. 1ms 요청 취소도 제품의 timeout 복구 검증이 아니다.
- 일부 시간 측정은 응답 본문 처리 전에 끝나 전체 답변 지연이 아니다. 가격·총비용 상한도 실행기에 완성되지 않았다.

## 완료에 필요한 다음 작업

1. 제품 Provider·Engine·Worker·실제 Tool과 격리 DB fixture에 DeepSeek 호출을 연결한다.
2. 합성 회의 자료, 기대 사실·HITL·권한 결과와 채점 기준을 먼저 고정한다.
3. 추론 예산·종료 사유를 검사하고 429/5xx·timeout 장애 주입으로 재시도·중복 실행 방지를 검증한다.
4. 실제 권한 철회·사용자 간 격리·canary 주입과 저장 경계를 검사한다.
5. 모델별 반복 평가와 비용·전체 지연을 집계해 통과/실패/미실행을 구분한다.

## 남겨 둔 자료

프로젝트 .context/llm-eval/의 실행 스크립트와 report.json, fault-performance.json, scored.json, canary-tools.json을 보관한다. 일부 결과는 재실행으로 덮어써졌고 원문 답변도 보존하지 않아 모든 과거 응답을 재심사할 수는 없다. 기초 호출 기록이며 최종 품질·안전성 인증 자료가 아니다. API 키 값은 이 문서에 포함하지 않는다.
