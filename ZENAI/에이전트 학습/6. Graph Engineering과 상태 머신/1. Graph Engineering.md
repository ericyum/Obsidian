# Graph Engineering

> **Graph Engineering은 업무를 Node와 Edge로 구조화하고, 각 경로를 코드와 LLM 중 누가 결정할지 설계하는 방법이다.**

단순히 업무 흐름을 그림으로 나타내는 것이 목적은 아니다. **미리 정할 수 있는 경로는 코드로 고정**하고, 실행 중 의미 판단이 필요한 경로만 LLM에 맡겨 실행을 예측하고 통제할 수 있게 만드는 것이 핵심이다.

## 1. 업무 개요도에서 시작한다

Graph를 설계하기 전에 먼저 전체 업무를 개발자의 관점에서 큰 업무 단위로 나눈다.

```text
회의록 업무
├─ 회의 시작·진행·종료
├─ 관련 회의록 검색·선택
└─ 회의록 질문·답변
```

이 그림은 **무슨 업무들이 있고 어떻게 이어지는지 보여주는 업무 개요도**다. 아직 Node·Edge·State를 엄격하게 적용한 Graph Engineering 설계도는 아니다.

## 2. 업무 단위를 Graph로 바꾼다

업무 개요도에서 나눈 업무 단위를 검토하여 다음을 결정한다.

- 하나의 **Node**로 둘 것인가?
- 여러 Node로 구성된 **Subgraph**로 펼칠 것인가?
- 어떤 **State**에서 이 업무를 실행할 것인가?
- 어떤 **Edge**를 통해 다음 Node로 이동할 것인가?

```text
최상위 Agent Graph
│
├─ 입력 대기 Node
├─ 회의 녹화 Node
│   └─ 회의 녹화 Subgraph
│       ├─ 회의 시작 Node
│       ├─ 녹화 제어 Node
│       └─ 회의 종료 Node
│
├─ 회의록 검색 Node
│   └─ 검색 Subgraph
│       ├─ 검색 조건 해석 Node
│       ├─ 검색 실행 Node
│       └─ 후보 선택 Node
│
└─ 회의록 질문·답변 Node
```

상위 Node 하나를 펼치면 그 안에서 다시 Node·Edge·State를 가진 **Subgraph**가 나올 수 있다. 필요한 경우 Subgraph의 Node도 다시 더 작은 Subgraph로 펼칠 수 있다.

## 3. 핵심 구성 요소

| 구성 요소 | 의미 | 핵심 질문 |
|---|---|---|
| **State** | 현재 Graph가 어느 실행 단계에 있는지 나타내는 유한한 상태 | 지금 어느 단계인가? |
| **Node** | 현재 계층에서 하나로 묶은 작업 실행 단위 | 여기서 무슨 일을 하는가? |
| **Edge** | 한 Node에서 다음 Node로 이어지는 경로 | 다음에는 어디로 가는가? |
| **Checkpoint** | 중단 후 다시 시작할 수 있도록 실행 결과를 저장하는 지점 | 어디서 재개할 것인가? |

```text
입력 State
→ Node 실행
→ 출력 State
→ Edge
→ 다음 Node
```

Checkpoint는 실행 정보를 저장할 뿐 다음 방향을 정하지 않는다. **Edge는 경로이고, Checkpoint는 재개 지점**이다.

## 4. Node와 State의 범위는 계층에 따라 달라진다

Node의 경계는 원래부터 정해져 있는 것이 아니라 **개발자가 어느 범위까지 하나의 업무 단위로 볼 것인지에 따라 결정**된다.

예를 들어 상위 Graph에서는 회의 녹화 전체를 하나의 Node와 State로 볼 수 있다.

```text
상위 Graph의 State
recording
```

그러나 회의 녹화 Node를 Subgraph로 펼치면 내부에는 더 세밀한 State가 생긴다.

```text
회의 녹화 Subgraph의 State
ready / recording / paused / stopping
```

따라서 같은 시점에 상위 Graph에서는 `recording`, 내부 Subgraph에서는 `paused`로 표현할 수 있다.

### Node를 더 나눌 기준

- 내부에서 **다음 경로가 갈리는가?**
- 독립적인 **실패·재시도 처리**가 필요한가?
- **Human in the Loop**로 중단되는가?
- 별도 **Checkpoint**가 필요한가?
- 하나의 Node로 보기에는 책임이 너무 큰가?

이런 구분이 필요하지 않다면 더 펼치지 않고 하나의 Node 내부 로직으로 둔다.

## 5. Edge는 분기선만을 뜻하지 않는다

Edge에는 두 종류가 있다.

- **고정 Edge**: 항상 같은 다음 Node로 이동한다.
- **조건부 Edge**: State나 실행 결과에 따라 여러 후보 중 다음 Node를 선택한다.

즉, 갈 곳이 하나뿐인 화살표도 Edge다.

### Edge의 결정 주체

- 목적지와 조건을 미리 열거할 수 있다 → **코드가 Edge를 소유**한다.
- 실행 중 의미 판단이 있어야 목적지를 정할 수 있다 → **LLM이 Edge를 소유**한다.

> **이 갈림길은 LLM이 판단해야 하는가, 아니면 코드로 고정할 수 있는가?**

이 질문이 Graph Engineering의 핵심이다.

## 6. Node 안의 값과 Node 사이의 경로

Node 안에서 LLM이 문장을 생성하거나 Tool을 선택하더라도 다음 실행 Node가 바뀌지 않는다면 **Node 내부의 값 생성**이다.

반대로 그 결과에 따라 다음 실행 단위가 달라진다면 **Edge가 결정하는 경로**다.

```text
결과가 내용만 바꾼다
→ Node 내부의 값

결과가 다음 실행 단위를 바꾼다
→ Edge가 결정하는 경로
```

## 7. 그림은 계층과 목적에 따라 구분한다

### 7-1. 업무 개요도

전체 업무를 큰 업무 단위로 나눈다. Graph Engineering의 Node·Edge·State를 엄격하게 적용하지 않는다.

### 7-2. 최상위 Agent Graph

가장 바깥 계층에서 실행할 Node·Edge·State를 나타낸다.

### 7-3. Subgraph

상위 Node 하나를 펼쳐 그 내부의 Node·Edge·State를 나타낸다. 필요한 만큼 다시 하위 Subgraph로 펼칠 수 있다.

### 7-4. 내부 처리 순서도

더 이상 독립된 Graph로 나눌 필요가 없는 Node 내부의 실행 로직과 조건 처리를 상세히 나타낸다.

### 7-5. State 전이도

특정 Graph 또는 Subgraph에서 **State가 어떻게 바뀌는지만 따로 확인**할 때 사용하는 보조 그림이다.

State 전이도와 순서도는 비슷하게 보일 수 있지만 같은 그림은 아니다.

| 그림 | 중심 질문 | 사각형이 나타내는 것 |
|---|---|---|
| **순서도** | 내부 로직이 어떤 순서로 실행되는가? | 처리·판단 단계 |
| **State 전이도** | 어떤 State에서 어떤 State로 바뀌는가? | State |

## 8. 한 문장으로 정리

> **Graph Engineering은 업무 개요도에서 찾은 업무 단위를 계층적인 Agent Graph와 Subgraph로 구조화하고, 각 Node 사이의 Edge를 코드와 LLM 중 누가 결정할지 설계하는 방법이다.**
