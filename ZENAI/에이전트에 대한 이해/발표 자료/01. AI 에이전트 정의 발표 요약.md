# 01. AI 에이전트 정의 — 발표 요약

## 사용자가 던진 질문

> 에이전트란 무엇이며, 기존의 생짜 LLM 또는 단순 챗봇과 무엇이 다른가? 에이전트 내부에서는 어떤 단계가 진행되는가?

## 한 문장 답변

AI 에이전트는 **LLM을 판단 엔진으로 사용하면서, 목표와 현재 상태를 기준으로 다음 행동을 고르고, Tool 실행 결과를 다시 관찰하여 멈출 때까지 경로를 수정하는 통제된 시스템**이다.

## 발표에서 반드시 구분할 세 가지

| 구분 | 중심 기능 | 외부 행동 | 경로 변화 |
|---|---|---:|---:|
| 생짜 LLM | 입력을 받아 문장을 생성 | 없음 | 없음 |
| 단순 챗봇 | 대화 문맥을 이어 응답 | 보통 없음 | 사용자 입력에 의존 |
| AI 에이전트 | 목표를 달성하도록 다음 행동 선택 | Tool을 통해 가능 | 관찰 결과에 따라 스스로 분기 |

대화를 여러 번 이어간다는 사실만으로는 에이전트가 아니다. 핵심은 **현재 상태에 따라 다음 실행 경로를 선택하는가**이다.

## 내부 작동의 핵심 루프

```text
목표·제약 확인 → 상태 관찰 → 다음 행동 결정 → Tool 요청·검증·실행
      ↑                                              ↓
      └──── 종료·재시도·사람 승인 판단 ← 결과 관찰 ────┘
```

LLM은 주로 목표 해석과 행동 선택을 담당한다. 권한 검사, Schema 검증, 실제 실행, 호출 횟수 제한은 모델 바깥의 오케스트레이터와 서버가 담당해야 한다.

## 설계 관점의 핵심

- 경로가 미리 확정된 작업은 고정 워크플로가 더 단순하고 안정적이다.
- 상황에 따라 검색·질문·Tool·종료 중 하나를 선택해야 할 때 제한적 에이전트가 유용하다.
- 좋은 에이전트는 무조건 오래 도는 시스템이 아니라, **필요할 때 행동하고 충분하면 멈추는 시스템**이다.
- 자율성보다 먼저 정의할 것은 목표, 상태, 허용 행동, 종료 조건, 사람 승인 조건이다.

## 발표용 결론

> 에이전트의 정체성은 ‘대화’가 아니라 ‘다음 행동을 고르는 루프’에 있다.
