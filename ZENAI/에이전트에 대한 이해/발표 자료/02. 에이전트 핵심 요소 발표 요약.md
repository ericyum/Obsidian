# 02. 에이전트의 네 가지 핵심 요소 — 발표 요약

## 사용자가 던진 질문

> Loop는 어디까지 돌게 해야 하는가? Compact는 왜 필요한가? Tool은 어떤 역할인가? 상위·하위 에이전트는 비싼 모델과 싼 모델로 나눌 수 있는가?

## 한 문장 답변

네 요소는 각각 반복, 기억, 행동, 분업을 담당하지만, 실제 설계에서는 **어디까지 자동화할지 결정하는 Loop와 실제 세계에 영향을 주는 Tool**이 중심 통제 지점이다.

## 네 요소의 역할과 설계 질문

| 요소 | 역할 | 반드시 정할 설계 질문 |
|---|---|---|
| Loop | 관찰–판단–행동 반복 | 언제 시작하고, 재시도하고, 사람에게 넘기고, 멈출 것인가? |
| Compact | 긴 세션을 작업 상태 중심으로 압축 | 무엇을 버리고 어떤 근거·결정·미완료 작업을 보존할 것인가? |
| Tool | 조회·검색·생성·변경을 수행하는 팔 | 어떤 기능을 어떤 권한과 검증을 거쳐 실행하게 할 것인가? |
| Sub-agent | 역할을 분리하고 병렬·전문화 | 어떤 작업을 위임하고 결과를 누가 검증할 것인가? |

## 잘못된 단순화 바로잡기

- Loop는 무한 반복이 아니라 반복 횟수, 비용, 시간, 중복 행동과 종료 조건을 가진 제어 구조다.
- Compact는 단순 대화 요약이 아니라 목표, 확정 사실, 근거, 실행 결과, 남은 작업을 보존하는 상태 재구성이다.
- Tool은 LLM에 붙인 API 목록이 아니라 선택 설명, 입력 계약, 권한, 오류, 관찰 가능성을 포함한 실행 인터페이스다.
- Sub-agent는 ‘상위는 좋은 모델, 하위는 싼 모델’이라는 비용 구조만이 아니다. 역할 경계와 검증 책임이 먼저다.

## 실무적인 조합

```text
Loop가 다음 행동을 고른다
  ├─ Compact에서 필요한 상태를 읽는다
  ├─ Tool로 외부 세계를 조회·변경한다
  └─ 필요하면 Sub-agent에 제한된 작업을 위임한다
```

## 설계 우선순위

1. 고정 가능한 단계는 워크플로로 고정한다.
2. 불확실한 좁은 구간에만 Loop를 둔다.
3. Tool은 읽기부터 작게 연결한다.
4. Compact와 Sub-agent는 실제 실패·비용 데이터가 생긴 뒤 확장한다.

## 발표용 결론

> 네 요소를 많이 넣는 것이 목표가 아니라, 각 요소에 경계와 종료 조건을 주는 것이 설계다.
