# 회의록

## 요약

AI 기반 회의록 시스템 개발 회의에서 UI/UX 구상, AI 에이전트 설계 및 기능 정의, 프로젝트 관리 방안이 논의되었습니다. 특히, 에이전트 자체의 설계와 개발에 중점을 두며, 모든 작업은 Jira를 통해 관리하고 역할 분담을 명확히 하여 효율적인 협업을 추진하기로 했습니다.

## 결정 사항

- AI 기반 회의록 시스템의 UI/UX는 사이드바에 회의록 버튼을 고정 배치하고, 클릭 시 회의록 리스트와 시작 버튼이 있는 화면을 새 탭으로 띄우는 방식으로 구현한다.
- 회의록 시스템 개발은 UI/UX 구상 담당과 에이전트 설계 담당으로 역할을 분담하여 상호 협의 하에 진행한다.
- 프로젝트 관련 모든 작업 및 이슈는 Jira를 통해 관리하며, 각 하위 작업은 이미지를 포함하고 하나의 이슈만 기록한다.
- STT(음성 텍스트 변환) 모델은 비용 효율성을 고려하여 2.5 플래시를 사용하며, 코드 구현 시 LLM 토큰 대신 깃허브 이슈를 통한 직접 구현 방식을 따른다.
- 제품은 사용자가 직접 에이전트를 조합하지 않고 시스템이 최적화된 구성을 제공하며, 최종 사용자 인터페이스에서는 에이전트 생성 또는 수정 기능을 제공하지 않는다.

## 액션 아이템

- **화면 담당**: AI 기반 회의록 시스템의 UI/UX 화면을 구상하고 디자인한다.
- **에이전트 담당**: 회의록 에이전트의 기능을 정의하고 설계한다.
- **팀원**: 'UI/UX 부산' Jira 댓글에 UI/UX 아이디어를 브레인스토밍 방식으로 기록하고, 향후 회의 전까지 초안을 정리한다.

## 안건별 요점

### AI 기반 회의록 시스템 개요 및 목표
- 기존 대화 기반에서 프로세스 채널 기반의 AI 에이전트와 결합된 형태로 UI/UX를 구성한다.
- 본 프로젝트의 핵심은 단순 회의록 기능 구현을 넘어 AI 에이전트 자체의 설계와 개발에 중점을 둔다.
- 전체 에이전트 시스템 개발의 핵심 목표는 코드 구현보다는 이론적 사고, 설계 구상, 아키텍처 및 권한/보안 설계에 집중하는 것이다.

### UI/UX 구상 및 화면 제어
- 회의록 기능은 자주 사용될 것이므로 사이드바에 고정 배치하고, 클릭 시 회의록 리스트와 시작 버튼이 있는 화면을 새 탭으로 띄운다.
- UI/UX 구상 담당과 에이전트 설계 담당이 협의하여 진행하며, 상호 작용을 통해 기능을 구현한다.
- UI/UX 아이디어는 'UI/UX 부산' Jira 댓글에 브레인스토밍 방식으로 지속 기록하고, 정리된 초안은 3인 합의 후 구현을 확정한다.

### 회의록 에이전트 설계 및 기능
- 회의록 에이전트는 전사, 요약, 평가, 접근 권한 관리(인가된 사용자만 접근) 등의 기능을 수행해야 한다.
- API 호출을 통해 목록 조회 및 데이터 분석이 가능해야 하며, 권한 검사 기능이 핵심적으로 요구된다.
- 에이전트의 자가 개선 및 지속적인 관리가 중요하며, 궁극적으로 회의록 작성 자체를 AI에 맡기는 구조를 목표로 한다.

### STT 및 요약 모델 선정
- STT 모델은 비용 효율성을 고려하여 2.5 플래시를 사용하기로 결정되었다.
- 한국어 전사에는 제미나이 모델이 적합하다고 언급되었으나, 높은 비용이 문제점으로 지적되었다.
- 요약 기능은 비용 부담이 적으므로, 퀄리티 향상을 위해 4.7 모델을 사용하는 것을 고려할 수 있다.

### 프로젝트 관리 및 협업 방식
- 모든 작업 내역과 이슈는 Jira를 통해 기록하고 관리하며, 작업 이력을 남기는 것을 중요시한다.
- Jira에 이슈 등록 시 반드시 관련 이미지를 첨부하고, 하나의 하위 작업에는 하나의 이슈만 기록해야 한다.
- 코드 구현 시 LLM 토큰 사용을 지양하고, 깃허브 이슈 등록을 통해 기능 요청 및 담당자 직접 구현 방식을 따른다.

### 에이전트 시스템 아키텍처
- 제품은 사용자가 직접 에이전트를 조합하는 방식이 아닌, 시스템이 최적화된 에이전트 구성을 제공하는 방식으로 설계된다.
- 최종 사용자를 위한 인터페이스는 미리 구성된 에이전트 선택 방식만 허용하며, 에이전트 생성 또는 수정 기능을 제공하지 않는다.
- 향후 코드 구현은 Open-source(오페스) 솔루션을 우선적으로 활용하고, 모델은 추후 교체 가능하도록 유연하게 설계한다.

### 에이전트 모니터링 및 확장성
- 에이전트의 표출 방식과 프로세스 진행은 랭귀지 모델 등을 통해 모니터링할 수 있다.
- 향후 에이전트 간 순서를 지정하고 작업을 위임하는 '에이전트 팀' 구성을 통해 루프 형태로 기능을 확장할 수 있다.
- 에이전트를 위한 사이트를 목표로 하며, 애플리케이션 형태로의 발전 가능성도 고려한다.
