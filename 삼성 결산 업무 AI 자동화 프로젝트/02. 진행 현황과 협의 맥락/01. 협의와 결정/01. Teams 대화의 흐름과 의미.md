# Teams 대화의 흐름과 의미

갱신: **2026-11-17**. 초기 대화는 [[Teams 대화 원문 (11월 11일 이후 제공분)]], 최신 대화는 [[Teams 대화 원문 (11월 16~17일 추가 제공분)]]을 근거로 한다. 초기 묶음의 개별 날짜·발언자는 대부분 미확정이며, 최신 묶음은 사용자 제공 시각과 파일의 11/16·17 표기를 함께 사용했다.

## 1. ZEN 참여 전: SAP와 ASPN이 구상한 PoC를 인수

**10월 협의 PDF·11/4 수행방안·영상·소스 ZIP은 초기 배경과 참고 구현이다.** 사용자 확인에 따르면 SAP Korea가 당시 ASPN에 프로젝트를 설명하며 사용한 자료 묶음이다. ZEN의 최종 범위·일정이 이때 고정된 것은 아니다.

핵심 업무 흐름은 **결산 현황 확인 → 시뮬레이션 → 오류 분석·보정 → 재실행·결과 확인**이다. Kyma 예제의 여러 재무 도구 중 인수·참고 중심은 `financial_close_insights`이며, 다른 예제를 모두 구축한다는 의미는 없다.

## 2. 11/9~10: 우리 팀이 업무·소스·공수를 이해

차재영 매니저 등의 업무 이해 문서와 공수 파일은 **ZEN 내부 분석**이다. 반성훈 팀장님의 11/10 PPT는 담당 업무·일정을 정리하고 미구체화 영역에 대한 구상을 더해 내부 회의에 사용했다.

사용자는 후속 회의로 역할과 일정이 달라졌다고 설명했다. 따라서 당시 CF·IS 전환 계획과 날짜는 **계획이 변화한 배경**으로 보관한다. 공수 두 XLSX는 값·수식·저장된 계산 결과가 같아, 재수령을 새 산정으로 보지 않는다.

## 3. 11/11 이후: 환경·협업 방식·상태 정의를 확인

대화의 초점은 ‘어디에서, 어떤 기준으로, 누구와 개발할 것인가’였다.

| 전달·질문 | 당시 의미 | 뒤에 연결되는 일 |
| --- | --- | --- |
| HE4 / Client 400, 패키지 `ZAPL_C01_CLOSE`, ZC01 접두사 | 개발·단위 시험 환경과 표준 안내 | 실제 객체·서비스·Destination별 대조 |
| 기존 CF·BAIP 사용, Space 권한 확보 후 대시보드 접근 | 기존 환경 접근 문제의 진전 | 신규 앱·서비스 연결과 업무 권한은 별도 검증 |
| 기반 구축 → 고도화 → 시나리오 통합 시험 | 연계 불일치와 뒤늦은 요구 전달을 줄이려는 협업안 | API 계약·샘플·단위 검증 전달 |
| ‘고객 미팅 후 일단 제외된 범위 없음’ | 종전 제외 판단을 유지할 수 없다는 내부 전달 | 과제별 범위·공수·검수 조건의 구체화 |

HE4/400은 사용자가 안내받은 원격 Desktop의 SAP 환경이다. **ABAP 백엔드 작업 대상**이며 MCP 호스팅 위치를 뜻하지 않는다. IMG 등을 모두 cross-client라고 한 과거 발언은 당시 설명으로만 남기고, 실제 설정별 속성을 확인한다.

11/11~13 Fiori 조사에서는 **41/43건 차이·완료 기준 불일치·캘린더 조회 범위**가 드러났다. ‘모두 수정’ 지시가 아니라 설계 의도와 시연 범위를 확인할 질문이었다. 상세는 [[04. Fiori 검수 결과와 협의할 기준]].

## 4. 11/12~13: 팀장님이 구현·시연의 참고안을 제시

| 자료 | 작성 의도 | 문서의 지위 |

## 5. 11/16: 시나리오와 전체 과제의 기술 협의를 준비

**17시 회의에 무엇을 가져갈지 맞추며 문서가 목적별로 나뉘었다.** 아래는 회의 결과가 아니라 준비 과정이다.

| 시각·작성자 | 공유 내용 | 의미 |
| --- | --- | --- |
| 12:09 차재영 | 과제별 개발 범위와 R&R 검토 MD | ZEN 내부 담당과 SAP 확인 질문을 회의 전에 정렬 |
| 12:12 반성훈 | 자신의 정리와 합치겠다고 답변, 내부 사전 논의 제안 | 팀장 검토·통합 단계 |
| 12:16~18 차재영·반성훈 | 받은 Excel이 기존 시나리오 과제에 속하는지 확인 | 팀장 답변은 ‘기존 시나리오 내용은 맞음’. **기존 구현 여부는 불명확** |
| 12:42 반성훈 | TechnicalSpec v0.4-S, R&R 질의서 v0.3 공유 | 전자는 Excel 시나리오 기술 협의, 후자는 전체 과제·담당 협의. 메일 부분은 v0.3을 보라는 안내 |
| 13:54 반성훈 | TechnicalSpec v0.6-Z 공유, 염정운·안효서에게 검토 요청 | ZEN 내부 수행용. CF Custom MCP 구상을 별도로 포함 |
| 15:16 차재영, 편집됨 | TaskInstances 중 마스터 미연결 2건 설명 | 41/43건 차이의 원인 재확인. 수정 완료 보고는 아님 |

**v0.4-S와 v0.6-Z는 둘 다 필요하다.** 전자는 SAP IS MCP 연계를, 후자는 ZEN의 CF Custom MCP 신규 구축을 그린다. 내부본이 말하는 이전판은 v0.4-Z이며, 보유한 v0.4-S와 동일하다고 볼 근거가 없다.

## 6. 11/17: 보통예금 기능의 개발·이관 진행이 보고됨

홍종화 매니저님은 **10:19에 젠데모 배포 완료, HE4 미배포, 다음 날까지 마이그레이션 예정**이라고 알리고 기능 명세 XLSX를 전달했다.

이후 **11:06:54 최종 수정된 XLSX**에는 젠데모가 리포트·확정 클래스·RAP·OData까지, HE4는 리포트·확정 클래스 단계라고 적혀 있다. 서로 다른 시점의 보고로 보존한다. **HE4의 RAP/OData가 준비됐다는 결론은 아직 낼 수 없다.** 상세는 [[07. 보통예금 기능과 MCP 인수 기준]].

## 7. 현재 맥락에서 남은 연결

**시나리오 설명 → 백엔드 API 계약 → MCP 계약 → SAP의 Joule 연동 → 동일 조건 검수**로 이어가야 한다. 11/16 17시 회의의 최종 합의록, Skill 배정 충돌 해소, 실제 사용 가능한 HE4 API는 아직 별도 근거가 필요하다.
