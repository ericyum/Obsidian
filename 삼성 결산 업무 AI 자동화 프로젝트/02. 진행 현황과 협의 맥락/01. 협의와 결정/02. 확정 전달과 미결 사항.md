# 확정 전달과 미결 사항

갱신: **2026-11-17**. **사용자 확인·문서에 적힌 결정·제안·배포 보고·직접 실행 검증**을 구분한다. 원본은 [[06. 자료 목록과 버전 비교]], 시간 순서는 [[01. Teams 대화의 흐름과 의미]].

## 1. 담당을 판단하는 현재 기준

| 영역 | 현재 담당 기준 | 근거·주의점 |
| --- | --- | --- |
| 총괄 | **반성훈 파트너** | 사용자 직접 확인: 우리 팀장 |
| Fiori | **차재영 매니저** | 사용자 직접 확인. 초기 RAP/MCP만 한다는 요약을 보완 |
| RAP·ABAP·OData | **홍종화 매니저** | 사용자 직접 확인 |
| OData를 받아 MCP 구현 | **염정운 매니저** | 사용자 직접 확인. v0.6-Z는 안효서·염정운을 MCP 담당으로 기재 |
| Joule·Skill·Integration Suite | **SAP Korea** | 사용자 직접 확인. v0.6-Z의 Skill 내부 배정은 충돌 항목으로 보존 |

> [!warning] 역할 충돌
> **v0.6-Z가 Skill까지 안효서·염정운에게 배정하지만, 사용자는 SAP Korea 담당이라고 설명했다.** 역할 변경을 확인할 회의 결과가 없으므로 사용자 업무를 임의로 확대하지 않는다. 우선 **MCP 제공물과 SAP 연결 책임의 접점**을 맞춘다.

| 사용자 권한 | **최종 백엔드 통제 필요** | 로그인·회사 필터와 별개로 허용/거부·집계 범위 검증 |

## 3. MCP 구현 전에 우선 합의할 계약

| 순서 | 확인 질문 | 맞출 상대 | 필요한 산출물 |
| --- | --- | --- | --- |
| **1** | SAP IS MCP와 CF Custom MCP를 어떤 시나리오에서 어떻게 연결하는가? Skill은 누가 수행하는가? | 팀장·SAP Joule/IS·MCP | 시나리오별 경로·담당·연결 책임 |
| **2** | 어떤 OData가 어느 환경에서 사용 가능한가? 기간·상태·완료·사용자 범위는 무엇인가? | 홍종화·차재영·SAP 업무 담당 | `$metadata`·엔드포인트·필드 의미·정답 데이터 |
| **3** | RequestID는 누가 발급하고, 동일 ID 재시도와 명시적 재실행을 어떻게 구분하는가? | RAP·MCP·SAP Skill | 접수·결과 조회·중복 방지·결과 불명 처리 계약 |
| **4** | 결과 저장은 누가 언제 호출하고, 오래된 결과·중복 호출·메일 실패를 어떻게 처리하는가? | RAP·MCP·SAP IS/Skill | 상태·이력·알림 반영의 성공/실패 기준 |
| **5** | 실제 기표까지 시연하는가? 보통예금 확정은 어떤 대상·권한·확인 절차를 쓰는가? | 업무 담당·SAP·RAP | TEST/실행 범위, 사용자 확인, 서버 검증 |
| **6** | 회사·기간·현재 사용자와 행 수·페이지 한도는 어떻게 전달하는가? | RAP·MCP·SAP | 입력·출력·오류·완전성·권한 전달 계약 |

**10초 간격 12회 폴링, 조회 10초, 페이지 200건 등은 명세의 잠정값이다.** 합의된 SLA나 실측 성능으로 쓰지 않는다. 기간 `08/008/2`도 서비스별 메타데이터와 사례를 확인해 정규화한다.
