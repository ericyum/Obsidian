# 확정 전달과 미결 사항

**‘답변 있음’은 대화에서 답을 받았다는 뜻이다. 현재 접속으로 재확인하거나 고객 최종 승인을 검증했다는 뜻은 아니다.** 근거: [[01. Teams 대화의 흐름과 의미]], 공유된 Fiori 분석·검수 기록.

| 주제 | 현재 근거와 상태 | 다음 행동 |
|---|---|---|
| 개발·시험 시스템 | 답변 있음: HE4, Client 400, 단위 시험도 동일 | 실제 개발 계정·서비스 Destination이 이 환경을 보는지 대조 |
| 개발 표준 | 답변 있음: ZAPL_C01_CLOSE, HE4K9B00J2, ZC01 준용 | 새 객체별 명칭과 CTS 사용 권한 확인 |
| Fiori 배포 | 기존 CF Runtime, S/4 배포 회피 선호 | 신규 앱 ID·Space·라우트·Destination·서비스 바인딩 결정 |
| 기존 대시보드 접근 | Space 권한 수령 후 접속 확인 전달 | 배포 버전 일치와 사용자별 업무 권한은 별도 검증 |
| 데이터 | Custom Table 초기 데이터 구성됐다는 답변 | 시나리오별 정답·오류·권한 시험 데이터의 충분성 확인 |
| 범위 | 고객 미팅 후 ‘일단 제외 없음’ 내부 전달 | 과제별 포함 범위·검수 기준·공수로 남길 것. 1.1.4 제외 상태 재확인 |
| 구현모델 v1.1 | 참고 제안, 강제 규칙 아님 | 논쟁이 있는 과제별 로직 위치를 결정 기록으로 남김 |
| 고객 의도 시연안 | 내부 제안, SAP 공유·협의 예정 | 우선순위와 기존 과제 흡수분·추가분 분리 |
| IS 전환 | 협업 방식 제안과 전환 요구 존재 | 대상 Tool 목록·계약·인증·CF 대안·최종 승인 확인 |
| 지원 일정 | 육지현 파트너 11/30까지 지원 가능 전달 | 그 전까지 업무 판단과 원본 인수 질문 처리 |

## 합의 기록은 이 정도면 충분하다

`과제 ID / 사용자 시나리오 / 결정 내용 / 제외·보류 / 담당 / 기한 / 입력·출력·오류 / 정답과 검수 방법 / 근거 메시지·문서 / 결정자·날짜`를 한 행에 남긴다. 질문을 보냈다는 사실, 답변을 받았다는 사실, 구현했다는 사실, 시험이 통과했다는 사실을 각각 구분한다.
