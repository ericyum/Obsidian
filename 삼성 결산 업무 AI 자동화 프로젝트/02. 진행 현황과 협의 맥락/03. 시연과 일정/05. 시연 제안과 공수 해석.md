# 시연 제안과 공수 해석

## 고객 의도를 왜 별도 시연안으로 만들었나

Teams에서 작성자는 고객 미팅을 정리하며 **경험치 축적·지속가능 신뢰성·유지보수**를 보여줄 방법을 제안했다고 설명한다. 경험치 축적은 기존 1.1.3과 연결되고, 나머지 두 용어는 시연 관점에서 다시 정의했다. PDF의 요구 표현을 그대로 고객 승인 목록으로 옮기면 범위가 부풀 수 있다.

| 시연 관점 | PDF의 주요 후보 | 구현 전 정할 것 |
|---|---|---|
| 경험치 축적 | 오류 해결 후보·Notes fallback·해결 피드백·지식 저장·재시험 | 출처 접근 권한, 검토자, 검증된 해결의 기준 |
| 지속가능 신뢰성 | 실행 로그·성능 추세·골든셋·일일 자가검사·회귀 게이트 | 시험 데이터·분모·수집 기간·실패 판정·승인 기준 |
| 유지보수 | 설정 외부화·Runbook·변경 영향·유지보수 기록 | 실제 유지보수 담당, 변경·복구 절차, 계측 방식 |

11/12 참고모델의 ‘검토된 지식’ 원칙과 11/13 시연안의 자동 등록·벡터화/검토 선택 흐름은 합의가 필요하다. 사용자 “해결됐다” 또는 Job FINISHED만으로 재사용 가능한 회계 지식이 검증됐다고 판단하지 않는다.

## 숫자는 같은 범위의 공수인지 먼저 확인

| 수치·일정 | 출처와 의미 | 현재 해석 |
|---|---|---|
| 208.5 MD | 이전 Markdown의 기준 추정 | 구버전 범위·산정. 최신 공수라고 표시하지 않음 |
| 198.5 MD | 11/10 공수 엑셀 기준, 과제 122 + 공통 76.5 | 낙관 119·비관 343.5와 함께 가정 기반 추정. JWD Excel 미산정 항목 존재 |
| 49.5 MD | 같은 엑셀의 축소 시나리오 | 전체 과제 공수와 직접 비교·합산 불가. 12/11 목표와 계산된 12/28 사이 간격이 있음 |
| 88/90 MD | 고객 의도 PDF가 인용한 계획/가용 공수 | 참조 v3.4 원본이 없어 상세 재검산 불가 |
| 추가 약 26~30 MD, 선택 약 20~24 MD | 시연안의 후보·우선순위 제안 | 전량 승인이나 추가 인력 확보 의미 아님 |
| 11/20·11/25·11/27·12/3·12/4·12/8 | 보유 실행계획의 데모·IS 판정·freeze·최종·보고 일정 | 더 최신 계획으로 확정됐는지 확인 필요 |
| 이번주 분석·차주 개발, 지원 11/30까지 | Teams의 진행/지원 전달 | 상세 WBS·기한의 변경 승인과 구별 |

새로 받은 `수행과제별_확인사항과_공수.xlsx`는 기존 `_20261110.xlsx`와 **4개 시트의 셀 값·수식 변경이 0건**이다. SHA256와 내부 수정 시각은 다르므로 두 버전을 보존하지만, 새 공수 산정으로 해석하지 않는다. 서식·패키지 전체의 동일성까지 주장하지 않는다.

기존 검토에서 확인한 `#REF!` 참조가 포함된 셀도 새 파일의 동일 수식에 남아 있다. 숫자를 최종 약속으로 쓰기 전에 산정자에게 참조 오류·가정·투입 인력·검수 기간을 확인해야 한다. 원본 엑셀은 수정하지 않았다.

## 개발과 시연을 연결할 최소 기준

1. 기존 데모 기준의 한 시나리오를 실제 환경에서 재현한다.
2. 그 경로에 실행 ID·모드·회사·기간·결과·오류를 기록한다.
3. 정답과 비교하고 실패 사례·권한 거부·재실행을 검증한다.
4. 그 증거를 바탕으로 신뢰성·유지보수 시연 후보를 선택한다.

과거 회차를 새로 시험한 결과를 과거 실제 운영 실적으로 표시하지 않는다. 일일 건강 점검의 성공률을 곧바로 99% 서비스 가용성으로 표현하지 않는다. PDF의 정확도·응답시간 목표 예시는 합의된 SLA와 구분한다.
