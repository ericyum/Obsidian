```text
04_MCP_on_Kyma/
├─ ZIP · 구조 가이드 · PowerShell E2E 가이드 · 회사 company.yaml
└─ APL1.5_02_MCP_Distribution_fb08341_20261015/
   └─ APL1.5_02/                 ← <소스루트>
      ├─ apps/                  ← 두 MCP의 진입점·조립·공개 인터페이스
      │  ├─ business-insights-mcp/src/apl15_business_insights_mcp/
      │  └─ business-actions-mcp/src/apl15_business_actions_mcp/

      │  └─ 각 패키지/src/apl15_패키지명/
      │     └─ identity의 oauth/ ← OAuth 전용 하위 모듈
      ├─ catalogs/
      │  ├─ insights/           ← 서비스·조회 힌트·분석 계약
      │  └─ actions/            ← 허용된 변경 업무 계약
      ├─ config/
      │  ├─ environments/       ← 회사 프로필 템플릿
      │  └─ policies/           ← 권한·실행·토큰 예산 정책
      ├─ deploy/kyma/
      │  ├─ insights/           ← Dockerfile 및 chart/apl-business-insights/
      │  │  └─ chart/apl-business-insights/templates/
      │  └─ actions/            ← Dockerfile 및 chart/apl-business-actions/
      │     └─ chart/apl-business-actions/templates/
      └─ scripts/quality/       ← 이미지 내부 소스 import 검사기
```

`src/`는 실행 산출물 폴더가 아니라 Python 소스 배치 관례다. 그 아래 `apl15_.../`는 실제 import 이름이다. `apps/`와 `packages/`는 같은 가상환경에서 소스 경로를 등록해 함께 사용하며, 패키지마다 개별 `pyproject.toml`이 있는 구조가 아니다. `__init__.py`는 패키지 공개 항목을 정의한다. 아래 패키지 표의 경로는 해당 `src/apl15_.../`까지를 포함하므로 모든 내부 소스 디렉터리를 찾을 수 있다.

## 10. 목적별 읽기 경로

| 이해하려는 것 | 권장 순서 |
|---|---|
| 결산 조회가 어떻게 호출되는가 | Insights `server.py` → `runtime.py` → `closing_source_policy.py` → `dynamic_planning.py` → `resolvers.py` → SAP client |
| 무엇을 조회할 수 있는가 | `service-sets.yaml` → `service_schema.py` → live `$metadata` → `service-capabilities.yaml` |
| 외화평가/감가상각 결과 읽기 | Insights `server.py`의 `closing_run_read` → `runtime.py`의 제한 → `closing_auxiliary.py` → 회사 auxiliary binding |
| 왜 개인 Inbox/실행 요청이 멈추는가 | `closing_workflow.py`의 `required_closing_handoff` → 사용자 매핑·업무 기준일·외부 실행 계약 |
| 배포 시 무엇이 필요한가 | 회사 프로필 → `models.py/graph.py` → `render.py` → Dockerfile → chart → E2E 가이드 |
| Actions가 왜 보이지 않는가 | `actions.capabilities_enabled` → connection binding/enabled → Actions `server.py` 등록 조건 |
| 이어 읽기와 전체 수집 | `server.py` operation → `runtime.py` → `read_through.py` → `full_data_contract.py/dataset_delivery.py` |

> [!note] 문서 작성 범위
> 실제 디렉터리와 163개 파일을 기준으로 역할을 분류했다. 소스·Obsidian 원본에는 변경을 가하지 않았다. 테스트·설치·Docker/Helm 실행·회사 연결은 수행하지 않았으며, 문서의 구성 설명은 실환경 동작을 보증하지 않는다.
