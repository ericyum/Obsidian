# MCP 조사와 설계 길잡이

일반 조사 기준: **2026-11-15** · 프로젝트 적용 갱신: **2026-11-17**

> [!abstract] 무엇을 위한 설계인가?
> **좋은 MCP는 에이전트가 올바른 업무를 고르고, 허용된 범위에서 실행하며, 결과와 다음 행동을 정확히 이해하게 하는 계약이다.**
> 삼성물산에서는 **목적별 조회·실행·확정의 경계, 백엔드가 계산한 결과, 짧은 호출과 실행 ID, 항목별 실패와 재조회**를 우선 검증한다. 아래 권장안은 조사자의 제안이며 SAP 수용·배포 완료를 뜻하지 않는다.

## 1. 일반 기준을 실제 삼성물산 설계로 연결한다

```mermaid
flowchart LR
    A["MCP·하네스·연구의 일반 기준"] --> B["현재 API·검수·담당·환경 근거"]
    B --> C["설계 후보와 선택 이유"]
    C --> D["담당자 간 계약"]
    D --> E["정답·거절·복구·성능 검증"]
```

연구에서 얻은 원칙을 곧바로 기능으로 추가하지 않는다. **어떤 현장 문제를 줄이는지, 기존 RAP·Joule 기반으로 가능한지, 무엇으로 확인할지**까지 연결한다. 예를 들어 ‘작은 컨텍스트’는 보통예금의 확정자·시각·경로를 기존 조회에서 받으면 불필요한 이력 호출을 생략하는 설계로 구체화된다.

## 3. 현재 적용에서 먼저 구분할 것

- **담당:** 반성훈 팀장, 차재영 Fiori, 홍종화 RAP·ABAP·OData, 염정운 MCP, SAP Korea Joule·Skill·IS라는 사용자 확인이 기준이다. 내부 v0.6-Z의 Skill 배정 충돌은 미결이다.
- **경로:** v0.4-S의 SAP IS MCP안과 v0.6-Z의 CF Custom MCP 신규안은 목적이 다른 문서다. 후자를 전자의 단순 최신판이나 현재 배포도로 읽지 않는다.
- **준비:** 보통예금 XLSX는 HE4의 RAP/OData 미반영을 기재한다. 문서상 API와 HE4에서 인수 가능한 API를 구분한다.
- **범위:** Kyma는 `financial_close_insights` 중심의 계약 참고자료다. 다른 재무 예제 전체와 내부 명세의 Tool 13개를 자동 구현 범위로 확정하지 않는다.

## 4. 문서의 주장과 확인 수준

| 표시 | 뜻 |
| --- | --- |
| **공식 규격·연구** | 해당 버전·실험의 공개 근거. Joule 또는 우리 PoC의 성능 증거는 아님 |
| **프로젝트 자료** | 받은 명세·사용자 전달·다른 담당자의 검수 기록. 이번 직접 실행과 구분 |
| **설계 제안** | 이 문서가 권장하는 후보. 채택·구현·배포 전 |
| **가정 예시** | 설명용 시간·건수·입력. SLA·실측·권한 증거가 아님 |
| **미확인** | 실제 환경 또는 담당자 합의로 확인할 사항 |

**전체 연혁과 자료 비교는 02에, 설계 판단과 계약·검증은 03에 둔다.** ZENAI Enhancement 3·4·5와 설계 문서 작성 방법의 전개를 참고했으며, ZEN AI의 기능·운영 수치를 Joule에 옮겨 주장하지 않았다. 정확한 참조 경로와 갱신 범위는 [[13. 출처와 사실 판단 기록]].
