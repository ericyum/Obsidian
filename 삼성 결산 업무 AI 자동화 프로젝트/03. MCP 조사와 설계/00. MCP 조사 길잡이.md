# MCP 조사와 설계 길잡이

조사 기준: **2026-11-15** · 상태: **공식 자료 조사와 프로젝트 설계 제안. 구현·배포·성능 검증 전**

> [!abstract] 먼저 읽을 결론
> 좋은 MCP는 API를 많이 보여주는 서버가 아니라, **에이전트가 적은 문맥과 적은 왕복으로 올바른 업무를 선택하고, 실행 상태를 오해하지 않으며, 실패 후에도 안전하게 이어가게 하는 계약**이다.
> 우리 프로젝트의 우선 후보는 **소수의 업무 목적별 Tool + 짧은 동기 응답 + 영속 실행 ID + 별도 상태·결과 조회**다. Joule의 자동 재개 지원은 전제하지 않는다.

## 1. 왜 RAP 완성 전에 조사할 수 있는가?

우리 팀은 ABAP/RAP와 MCP를 맡고, 이 문서의 독자는 그중 **MCP 담당 개발자**다. RAP의 실제 URL·필드·Action 이름은 아직 합의 전이어도, Tool 경계·응답 크기·시간 예산·재시도·중복 방지·상태 보존·권한·관측 기준은 먼저 설계할 수 있다.

다만 메모리·최적화가 모두 MCP 안의 기능은 아니다. **Joule 하네스가 소유하는 모델 루프·압축·중단/재개와, 우리가 소유하는 서버 데이터·응답·실행 상태**를 나누는 것이 출발점이다.

## 3. 읽을 때 꼭 구분할 것

| 표시 | 뜻 |
|---|---|
| **공식 규격/문서** | 그 버전·제품에 쓰인 내용. 현장에 배포된 버전과 같다는 뜻은 아님 |
| **프로젝트 근거** | 제공 문서·소스·사용자 전달. 새 실환경 시험과 구별 |
| **설계 제안** | 이 조사에서 도출한 선택지. SAP·고객 승인 아님 |
| **가정 예시** | 숫자·식별자·시간을 설명하기 위한 예. 실측/SLA 아님 |
| **미확인** | 제품 버전·지원 기능·책임자와 시험으로 확인할 일 |

2026-11-06 Anthropic memory 글과 2026-09 OpenAI Agents API까지 확인했다. 공급자 자료 중 상당수는 **학술논문이 아닌 기술 글·제품 문서**다. MCP 연구 논문은 별도로 구분했으며, 각 논문 성능을 삼성물산의 기대 성능으로 가져오지 않았다.

사용자 제공 ZENAI Enhancement 2~5번의 **개념 → 판단 기준 → 현재 상태 → 후보 비교 → 행동 순서** 설명 구조를 참고했다. ZEN AI의 하네스 기능이나 운영 숫자를 Joule의 기능으로 이식하지 않았다.
