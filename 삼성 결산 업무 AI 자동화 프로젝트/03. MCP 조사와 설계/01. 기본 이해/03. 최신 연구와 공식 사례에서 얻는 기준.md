# 최신 연구와 공식 사례에서 얻는 기준

## 1. 어떤 근거를 우선 읽었는가?

**OpenAI·Anthropic의 최신 공식 연구·기술 자료를 먼저 읽고, MCP 규격과 독립 학술 연구로 보완**했다. 제목이나 `/research/` 경로만으로 논문이라고 부르지 않았다. 자료마다 환경·모델·평가가 달라, 공급자 수치를 그대로 비교하는 그래프는 만들지 않았다.

## 2. 공식 사례에서 얻은 설계 질문

| 자료·발표일 | 확인한 요지 | 우리에게 적용할 질문 |
|---|---|---|
| Anthropic memory, **2026-11-06** | 원문 기록·선별된 기억·후속 재조직을 구분하고 잘못된 기억을 원문으로 교정 | 실행 로그와 재사용할 해결 지식을 분리했는가? |
| OpenAI Agents API, **2026-09-10** | 하네스가 세션·문맥·도구 실행을 관리하는 제품 방향 | MCP 서버가 호스트 소유 기능까지 보장한다고 오해하지 않는가? |
| Anthropic harness, **2026-03-24** | 긴 작업에서 분할·구조화 인계·평가 분리가 중요 | 대화가 끊겨도 실행 ID와 상태를 읽어 이어갈 수 있는가? |
| OpenAI harness, **2026-02-11** | 도구·환경·검증 근거를 에이전트가 이해할 수 있게 만드는 사례 | 상태·오류·진단 정보가 실제 다음 행동에 도움이 되는가? |
| OpenAI data agent, **2026-01-29** | 스키마 외에도 지표 의미·조직 지식·실시간 문맥이 필요 | ‘완료율’ 분모와 회계기간 의미를 전달하는가? |
| Anthropic advanced tools, **2025-11-24** | 도구 검색과 코드 기반 호출은 문맥 비용을 줄이나 추가 실행 환경·지연을 수반 | Joule 지원 없이 같은 최적화를 가정하지 않는가? |
| Anthropic MCP code execution, **2025-11-04** | 모든 중간 데이터를 모델 문맥에 왕복시키는 비용을 줄이는 접근 | 서버에서 결정적으로 필터·집계하고 필요한 결과만 주는가? |
| Anthropic tools, **2025-09-11** | API 복제보다 목적이 뚜렷한 도구·의미 있는 반환·평가가 중요 | CRUD마다 Tool을 만드는 대신 시나리오로 경계를 정했는가? |

이는 **설계에 사용할 근거와 질문**이지 삼성물산의 성능 검증 결과는 아니다. 특히 임의 코드 실행·다중 에이전트·자동 학습은 우리 PoC의 기본 구성으로 채택하지 않는다.

## 3. 학술 연구는 무엇을 경고하는가?

| 연구 | 평가 접근과 의미 | 한계·적용 |
|---|---|---|
| **MCP-Atlas v3, 2026-05** | 36 서버·220 도구의 자연어 과제, claim 단위 평가. 도구 성공 후에도 종합·종료 판단에서 실패 가능 | 프리프린트. 한국어 SAP·Joule 성능을 증명하지 않음. 도구 성공률과 답변 사실성을 분리해 시험 |
| **ComplexMCP, ICML 2026** | 상태와 의존관계·API 실패가 있는 환경에서 도구 선택과 복구를 시험 | 공식 초록 확인 범위. 숫자를 우리 목표로 가져오지 않고 장애·의존관계 fixture의 필요성을 취함 |
| **DynamicMCPBench, EMNLP Industry 2026** | 최종 답변이나 고정 Tool 순서 대신 실행 효과와 금지 행동을 평가 | headline은 고정 replay 기반이며, 기록 밖 유효 경로와 reference 정합성의 한계 존재. 한 번 답변이 맞았다는 것보다 실제 상태와 반복 성공을 확인 |

이 세 논문은 OpenAI/Anthropic 논문으로 표시하지 않는다. 서로의 성공률은 과제·판정·모델·시점이 달라 직접 순위를 만들 수 없다.

## 4. 연구를 프로젝트 규칙으로 옮기는 방법

| 연구에서 나온 원칙 | 삼성물산용 제안 | 검증 방법 |
|---|---|---|
| 문맥을 선별하라 | 요약·식별자·시점·완전성 우선, 상세는 필요 시 조회 | 결과 크기와 답변 근거 누락을 함께 측정 |
| 실행 효과를 확인하라 | 접수/실행/업무 완료를 분리 | RequestID·TEST 모드·대상·HIST를 대조 |
| 경험을 재사용하라 | 검증된 해결 사례를 버전·적용 범위와 함께 검색 | 미검토 사례가 확정 해결법으로 나오지 않는지 시험 |
| 하네스를 고려하라 | short-call 계약과 재조회 가능한 결과 | 대화 종료·재시작·timeout 주입 |
| 작은 도구 집합부터 평가하라 | 핵심 시나리오 Tool부터 제공 | 목적별·CRUD형 후보를 같은 과제로 비교 |

| 필요한 문맥·왕복만 유지 | 예금 조회에 확정자·시각·경로 포함 | 이력 Tool 추가 호출 생략 — [[14. 보통예금 조회와 항목별 확정 설계]] |
| 실행 효과로 판정 | HTTP200 안에 UUID별 성공·거절 | 항목별 결과와 저장 상태 대조 — [[12. 검증 시나리오와 단계별 실행 계획]] |
| 근거·의미를 보존 | 41/43 누락, Agent/업무 완료 불일치 | 공통 CDS 집계·complete·출처 — [[05. 업무 목적별 Tool과 응답 계약]] |
| 끊겨도 안전하게 이어감 | FCV/AFAB RequestID·예금 응답 불명 | 같은 ID/선택항목 재조회, 완료 건 재실행 금지 — [[08. 동기 호출과 장시간 작업의 연결]] |
