# 삼성물산의 제약과 1분 제한 검증

프로젝트 기준: **2026-11-17 제공 자료** · 상태: **문서 대조와 설계 입력. 환경 검증 전**

> [!abstract] 현재 설계의 출발점
> **홍종화 담당자의 RAP/OData를 염정운 담당자가 MCP로 제공하는 계약을 구체화한다.** API 준비와 Joule 연결 능력을 확인하면서, 조회·실행·결과 반영·확정을 분리해 설계한다. 경로·한도·권한을 문서의 문구만으로 작동 완료 처리하지 않는다.

## 1. 무엇을 근거로 설계하는가?

| 현재 근거 | 설계에 주는 영향 | 다음 확인 |
| --- | --- | --- |
| 사용자 확인: Fiori 차재영 / RAP·ABAP·OData 홍종화 / MCP 염정운 / Joule·Skill·IS SAP Korea | 대화와 SAP 업무 로직을 MCP가 모두 떠맡지 않음 | v0.6-Z의 안효서·염정운 Skill 배정 충돌 |

## 3. 공개 자료의 60초는 모두 같은 제한인가?

**기본값·최대치·한 호출·전체 turn은 각각 확인해야 한다.**

| 근거 | 대상·값 | 확인 수준과 제한 |
| --- | --- | --- |
| 사용자 Teams 회의 전달 | Joule sync 약 1분 | 프로젝트 입력. 제품·제한 계층 미확인 |
| SAP A2A 기술 글·Architecture 색인 | 외부 code-based agent 동기 **A2A 60초** | 기존 공식 색인 확인. 일반 MCP 호출로 확대 불가 |
| SAP Help Joule Studio classic 색인 | MCP Tool 대기 **기본 200초** | 기존 검색 색인 확인. 현재 Connector 설정 증거 아님 |
| SAP IS 공식 GitHub 문서 | API 기반 MCP receiver **기본 60000ms** | 문서상 백엔드 대기 설정. 고정 상한이라는 뜻 아님 |
| Kyma 인수 설정 | Insights APIRule 60초 / Actions 30초 | 과거 정적 설정. 새 CF나 Joule 한도 아님 |
| 기존 결과 조회 안내 | pending이면 같은 RequestID로 60초 후 재조회 | 조회 간격. 자동 polling·재POST 아님 |
| S본 Q-16 / Z본 D-16 | 10초 간격×최대 12회 | **협의 전 잠정안.** 약 2분의 루프가 실제 turn에서 가능한지 미확인 |
| Z본 §12.8 / D-12 | 조회10초·접수15초·readback5초 등 | 내부 검토 수치. 실측·SLA 아님 |

## 4. 한도를 확정하려면 무엇을 확인하는가?

1. **실제 경로:** 기존 Joule Connector인가, 과제별 JWD인가? 제품·build·IS 중계 유무는?
2. **제한 위치:** 전체 turn·Tool 하나·receiver·proxy idle 중 어디인가? queue·모델 시간도 포함하는가?
3. **중단 효과:** 응답만 끊는가, Job 취소를 시도하는가? progress·SSE가 idle 대기와 최대 시간에 각각 미치는 효과는?
4. **후속 조회:** 다음 turn에서 같은 RequestID를 사용할 수 있는가? 자동 재개·메일·링크의 실제 지원 범위는?
5. **시험:** 격리 지연 응답과 실제 Connector로 각 계층의 시작·종료·오류 시각을 기록한다.

**제안:** 한 호출은 짧게 마치고 긴 업무는 영속 ID로 이어간다. ‘1분이 틀렸다’거나 ‘10초×12회가 가능하다’고 먼저 결론 내리지 않는다. 가령 전체 turn 60초라면 모델·네트워크·응답 시간을 제외한 Tool 합계만 예산으로 쓸 수 있다.

## 5. 환경 준비와 기능 완료를 따로 표시한다

보통예금은 젠데모/client100/회사ZEN1과 HE4/client400/회사4310·4320이 구분된다. **1710·ZEN1을 HE4에 고정하지 않는다.** 11/18 이관 목표와 과거 11/20·25·27 마일스톤을 현재 완료나 일정 약속으로 사용하지 않는다.

새 서비스의 URL·필드·권한은 명세와 환경을 대조한다. 접근 성공→metadata 확보→읽기 계약 검증→쓰기 계약 검증→Joule 통합 검증을 나누며, 단계별 기록은 [[12. 검증 시나리오와 단계별 실행 계획]]에 둔다.
