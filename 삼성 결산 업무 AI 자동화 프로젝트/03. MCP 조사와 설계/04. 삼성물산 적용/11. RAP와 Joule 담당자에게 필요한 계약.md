# RAP와 Joule 담당자에게 필요한 계약

## 1. 지금 합의해야 하는 것은 URL보다 의미다

**MCP는 ‘무엇을 요청하고 어떤 결과를 믿어도 되는지’를 먼저 제안할 수 있다.** 하지만 권한·정답·최종 상태·중복 방지를 MCP 담당자가 독자 확정하면 안 된다. 아래 표는 회의에 사용할 협업 초안이다.

| 구분 | MCP 담당자가 먼저 정리 | 공동 합의·확인 |
|---|---|---|
| 사용자 행동 | 대표 질문과 Tool 목적 | 실제 시연·검수 범위 |
| 입력 | 업무 필드·불명확 입력 처리 | RAP 키·필드 타입·회계기간 의미 |
| 결과 | 요약·근거·페이지·시점·완전성 | 지표 분모·상태·실행 결과 정답 |
| 긴 작업 | prepare/submit/get 흐름 | 영속 저장·worker·재개·취소 |
| 오류 | 분류·다음 행동·시간 예산 | backend 오류·retry 소유권 |
| 권한 | 필요한 호출 주체·scope | 실제 identity propagation·DCL/Action 권한 |

## 2. RAP 개발 전 요청할 계약표

| 항목 | 질문 | 없다면 생기는 문제 |
|---|---|---|
| 식별 | Cycle/Task/Execution의 유일 키와 관계는? | 다른 회차의 결과를 잘못 반영 |
| 날짜 | fiscal period·key date·timezone·특별기간은? | 달력 월로 잘못 조회 |
| 상태 | 실행 단계와 업무 최종 완료는 어떻게 구분? | Agent 완료를 최종 완료로 안내 |
| 조회 | 필터·projection·count·cursor·snapshot 지원은? | 전체를 읽으며 timeout, 일부를 전체로 집계 |
| 접수 | ACK는 어느 영속 저장 이후 반환? | 응답은 accepted인데 Job 유실 |
| 멱등 | 같은 intent key로 재전송·조회 가능한가? | timeout 후 중복 실행 |
| 결과 | RequestID로 scope·TEST·기표 여부를 확인 가능한가? | FINISHED만 보고 성공 단정 |
| 반영 | 결과→Task/HIST 갱신의 책임·트랜잭션은? | 결과는 성공인데 화면 상태가 다름 |
| 취소 | 실제 SAP Job 취소 능력·한계는? | 취소 요청을 취소 완료로 오해 |
| 인증 | 최종 SAP 실행 사용자는 누구인가? | 모델 user_id를 권한으로 오해 |
| 버전 | 계약·상태 코드 변경·동시 수정 충돌 처리? | 구버전 의도로 새 규칙 실행 |

## 3. Joule·IS에 확인할 capability 표

| 확인 항목 | 초기 상태 | 시험/질문 |
|---|---|---|
| 제품·build·MCP protocol | 미확인 | 실제 client 정보·협상 trace |
| transport·인증·중계 | 미확인 | stdio/HTTP/SSE, OAuth, IS 경계 |
| Tool 단위/turn timeout | 약 1분 회의 전달 | 각 계층 설정과 5/20/45/65/120초 지연 시험 |
| structuredContent·outputSchema | 미확인 | 모델에 전달되는 결과·검증 확인 |
| Resources·긴 결과 참조 | 미확인 | 권한 있는 상세 조회 가능 여부 |
| 중단·자동 재개·알림 | 미확인 | 대화 종료 후 같은 ID 조회, 이벤트 재개 |
| Tasks | 미확인 | 2025 실험 방식인지 2026 확장인지, 중계 보존 |
| Tool 목록 cache·갱신 | 미확인 | schema 변경·권한 변경 반영 |
| 확인 증거 전달 | 미확인 | 신뢰된 승인 주체·payload binding |

지연 시험은 격리 mock에서 먼저 한다. 실제 기표를 여러 번 실행해 timeout을 재현하지 않는다.

## 4. 예상 API와 확정 API를 함께 관리

과제별로 `논리 기능 / 예상 API 능력 / 실제 서비스·Action / 제공 예정일 / 담당 / mock fixture / 계약 버전 / 검증 상태`를 남긴다. 예상 항목에는 **PROPOSED**, 구현 후 계약 검증에는 **CONTRACT_VERIFIED**, 실환경 시나리오 통과에는 **INTEGRATION_VERIFIED**처럼 서로 다른 표기를 제안한다. 이를 이미 존재하는 프로젝트 공식 상태로 오해하지 않는다.

## 5. 합의가 없어도 할 수 있는 작업

대표 질문·Tool 설명 후보·응답 schema 초안·오류 taxonomy·timeout 매트릭스·평가 fixture를 준비할 수 있다. mock가 성공해도 실제 SAP·권한·멱등 구현이 성공했다고 표시하지 않는다. 실제 URL이나 클래스명을 추정으로 채워 배포하지 않는다.
