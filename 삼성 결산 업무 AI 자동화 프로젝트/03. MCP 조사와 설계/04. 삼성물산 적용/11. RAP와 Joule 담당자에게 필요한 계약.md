# RAP와 Joule 담당자에게 필요한 계약

갱신: **2026-11-17** · 상태: **협업용 질문·수용 조건. 최종 합의표 아님**

> [!abstract] 먼저 합의할 것
> **누가 어떤 사용자로, 어느 환경의 어떤 업무를 요청하고, 어떤 증거로 완료를 판정하며, 실패 뒤 무엇을 다시 읽는가?**
> URL·JSON과 함께 이 의미를 받아야 MCP 구현과 Joule 답변을 맞출 수 있다.

## 1. 담당과 문서의 권한을 먼저 구분한다

| 대상 | 사용자 확인 기준 | 이번 협업에서 필요한 것 |
| --- | --- | --- |
| 총괄 | **반성훈 팀장** | 경로·업무 범위·스택·미결 조율 |
| RAP·ABAP·OData | **홍종화** | metadata·정답·권한·실행·결과/이력 계약 |
| Fiori | **차재영** | 같은 CDS·KPI, 화면·필터 링크·수동 경로 대조 |
| MCP | **염정운** | 도구 설명·입력·응답·오류·추적·Connector 인수 자료 |
| Joule·Skill·IS | **SAP Korea** | 도구 등록·호출 순서·신뢰 사용자·확인·실제 turn 검증 |

v0.6-Z는 MCP에 **안효서·염정운**을 적고 Skill도 두 사람에게 배정한다. **Skill 배정은 사용자 확인과 충돌**하므로 변경 합의를 확인한다. 이 표가 내부본의 담당을 지워 확정하거나 SAP가 새 CF안을 수용했다는 뜻은 아니다.

| ID | 필요한 약속·인수물 | 담당 협업 | 근거·연결 | 없을 때의 실패 |
| --- | --- | --- | --- | --- |
| **K01 환경** | 개발/시연 tenant·client·회사·서비스·metadata·계약 버전·준비 상태 | RAP/MCP/SAP | Z D-01·13, 예금 XLSX 개요 | 젠데모 API를 HE4 완료로 오해 |
| **K02 의미** | Cycle/Task 키, 회계기간, join·분모·완료·승인·Agent 상태 매핑 | RAP/Fiori/MCP | Z D-02·20, 41/43·CASH010 | 화면과 답변의 숫자·완료 차이 |
| **K03 읽기** | 필터·projection·count·page·원천별 complete·as_of, 정상0/없음/거절 구분 | RAP/MCP | S/Z 공통 응답, 기존 조회 검수 | 일부 조회를 전체로 답함 |

| **K05 접수** | RequestID 발급·scope·모드 결합, ACK의 영속 시점, 같은ID 같은/다른payload 처리 | RAP/MCP/SAP | Z D-03·06 | 응답 유실 뒤 중복·다른 기간 실행 |
| **K06 결과** | exact readback, FINISHED와 업무 성공, 로그/Spool 상한·누락·파싱 대사 | RAP/MCP | Z D-03·04, S Q-16·17 | 기술 종료·빈 로그를 실제 성공으로 오해 |
| **K07 반영** | updateTaskResult 호출자, Task 매핑, 현재 실행 검증, TINS/HIST 원자성·중복·동시변경 | RAP/MCP/SAP | Z D-08, 결과 업데이트 과제 | 늦은 결과가 최신 상태 덮기·이력 중복 |
| **K08 확인/쓰기** | 신뢰 사용자 확인과 실제 UUID/모드/사유 결합, 항목별 결과·재조회 | SAP/RAP/MCP | 예금 confirmMultiple, S Q-17 | 확인한 대상과 다른 항목 확정 |

| **K10 인수/관측** | 정답 fixture·실행 trace·민감로그 제외·버전 변경 공지·회귀·장애 담당 | RAP/Fiori/MCP/SAP | Z D-05·17·18 | 누가 어떤 근거로 검수했는지 불명 |

**K01~K10은 이 문서의 협업 표 ID**다. Q/D는 원본 명세의 질문·내부 결정 번호이며 서로 대체하지 않는다. 세부 계약은 아래의 각 업무로 내려간다.

## 3. 실행·결과 반영 계약

| 확인 항목 | 합의할 내용 |
| --- | --- |
| 실제 FCV/AFAB 실행 | TEST mode와 지원 body; 실제 기표는 S Q-17을 확인. AFAB TestRun=false를 기존 제공 계약으로 가정하지 않음 |
| RequestID | 생성자·허용 형식·유일 범위·보관·조회 권한. 같은 ID 다른 payload는 충돌로 처리하는 후보 |
| 상태·성공 | PENDING/RUNNING/FINISHED/FAILED/CANCELLED의 원시/정규화 관계, 업무 성공 필드·메시지 완전성 |
| 결과 반영 | RequestID로 실행 유형·회사·기간·Task를 서버가 대조. 모델의 임의 `COMPLETED` 저장 금지 |
| 늦은 결과·동시 변경 | 현재 유효 실행 참조/버전과 비교, 이미 반영/충돌/옛 결과를 구분. CSRF·ETag·잠금·트랜잭션을 실제 Action 기준으로 약속 |
| 재시도 | 조회와 POST의 소유 계층·횟수·시간을 구분. timeout·5xx·취소 ACK 뒤 자동 새 실행 금지 |
| 알림 | R&R v0.3의 S/4 메일 방향·수신자·중복·업무 반영과 분리, Basis 설정과 실제 발송 검증 |

`REQUEST_ID_ONLY`는 기존 readback의 공개 입력 계약이다. **새 승인 토큰·signed receipt·별도 operation 저장소를 필수라고 되살리지 않는다.** 추가 영속 상태가 필요하면 backend의 기존 기록으로 충족 가능한지부터 확인한다. 흐름 기준은 [[08. 동기 호출과 장시간 작업의 연결]].

## 4. 보통예금에서 바로 인수할 수 있는 계약과 빈칸

| 자료에서 구체화된 부분 | 추가로 확인할 부분 |
| --- | --- |
| `ZAPI_C01_CCK_DEPOSIT_O4`, `CheckResult`, `Confirmation`, `confirmMultiple` | **HE4 실제 반영·URL·metadata·인증·권한** |
| UUID별 `Confirmed`·`Message`, DIFFERENT는 사유 있으면 확정 가능 | 최종 COMMIT 실패·응답 유실 뒤 기존 결과 확인 방법 |
| RequestedBy와 ExecutedBySAPUser 분리 | 신뢰된 확정 지시자 매핑·위조/대리 요청 차단 |
| 단건 ETag 정의, GUI DisplayedChangeAt 검사 | **다건 API의 오래된 조회/확인 방어**. GUI 메시지004를 API 보장으로 확대 금지 |
| 조회 결과에 확정자·시각·경로 포함 | 이력 Tool은 확정 시점 금액 등 실제 추가 정보가 필요한 때만 |

원본의 다건 POST는 미실행 예시다. ‘랩 통과’에는 읽기·기록 재생·연습용 snapshot이 섞여 있으므로 **실환경 쓰기 통과와 구분**한다. 상세 설계·근거 셀은 [[14. 보통예금 조회와 항목별 확정 설계]].

## 5. Joule 연결 인수 패키지

MCP 측은 **endpoint·인증 안내(비밀 제외)·Tool 목록/버전·입출력 예시·거절/부분/진행 응답·실행 효과·재조회 규칙**을 제공한다. SAP 측과 다음을 직접 확인한다.

- 실제 client/build와 공통 MCP 버전, transport·인증·중계 유무.
- structuredContent/outputSchema·Resources·Tool 변경 반영과 모델에 전달되는 실제 결과.
- 한 turn/Tool timeout, 다음 turn의 ID 유지, confirmation 전달, polling·resume·알림 지원.
- 같은 질문·사용자·데이터에 대한 Tool 선택과 금지 행동, 최종 한국어 답변.

**Dynamic Link**는 사용자 설명상 ‘Joule 링크에서 해당 조건의 대시보드 열기’다. R&R의 ‘PCE 업무 앱 잔여 링크’와 목적지를 구분하고, 회사·기간·Cycle·필터·접속 권한·직접 URL 허용 범위를 차재영/SAP와 확인한다.

## 6. 합의·검증 기록의 최소 단위

과제마다 **논리 기능 / 원본 근거·절 / 대상 환경 / 실제 API·schema 버전 / 담당 / 정답 fixture / 미결 / 검증 상태·증거**를 기록한다. 문서기재·mock통과·개발환경통과·Joule통합통과를 나누고, 아직 없는 API를 추정 URL로 배포하지 않는다.

시험의 수행 순서와 결과물은 [[12. 검증 시나리오와 단계별 실행 계획]], 프로젝트의 현재 협의 상태는 [[02. 확정 전달과 미결 사항]]을 기준으로 본다.
