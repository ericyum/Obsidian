# 2-2. initSessionMonitor와 touchSession 이벤트

## 함수를 인자로 연결

```javascript
initSessionMonitor({ keepAlive: keepSessionAlive });
```

왼쪽 `keepAlive`는 객체 속성명이고 오른쪽 `keepSessionAlive`는 `api.js`에서 가져온 함수다. `session.js`는 이를 `keepAliveHandler`에 보관한다.

```javascript
keepAliveHandler = keepAlive || keepAliveHandler;
```

이 순간 서버 요청은 없다. 나중에 세션을 확인할 때 호출할 함수를 기억하는 단계다.

## 이벤트 수신과 시간 감시

`initSessionMonitor()`는 다음을 등록한다.

```text
session-touch 이벤트
session-expired 이벤트
다른 탭의 localStorage 변경
탭이 다시 보일 때의 검사
30초 간격 checkSessionAge 타이머
```

`api.js`가 정상 요청 뒤 `markSessionTouched()`를 호출하면 CustomEvent가 발생한다. 이벤트 수신기가 `touchSession()`을 호출한다.

```text
API 성공
→ markSessionTouched(source)
→ session-touch 이벤트
→ addEventListener
→ touchSession(source, at)
```

`touchSession()`은 XSUAA나 Approuter의 실제 서버 세션을 직접 바꾸지 않는다. 브라우저의 마지막 정상 활동 시각을 갱신하고 `localStorage`에 저장하며 경고 UI를 숨긴다.

`"current-user"`, `"recording-start"` 같은 문자열은 세션 상태가 아니라 호출 출처다. 현재 함수의 `_source`는 계산에는 쓰이지 않는다.

```text
서버 세션 확인: HTTP 요청이 담당
브라우저 활동 시각 기록: touchSession이 담당
```
