# 2-3. refreshSession과 녹음 중 세션 유지

## 실제 세션 확인 호출

`refreshSession(reason)`은 보관해 둔 `keepAliveHandler()`를 호출한다. 배포 환경에서 이는 다음 체인으로 이어진다.

```text
refreshSession(reason)
→ keepAliveHandler()
→ keepSessionAlive()
→ getCurrentUser()
→ GET /user-api/currentUser
```

요청이 성공하면 두 경로로 `touchSession()`이 연달아 호출될 수 있다.

```text
getCurrentUser 성공
→ markSessionTouched("current-user")
→ 이벤트 수신기가 touchSession 실행

refreshSession으로 복귀
→ touchSession(reason) 직접 실행
```

직접 호출한 `touchSession(reason)`이 이벤트를 다시 발생시키는 것은 아니다. 이벤트 발생 함수는 `markSessionTouched()`다.

## 녹음 중 유지

`startRecordingSessionKeepAlive()`는 녹음 시작 시 즉시 `refreshSession("recording-start")`을 실행하고 이후 30분마다 `refreshSession("recording")`을 실행한다.

```text
긴 녹음 중 일반 API 활동이 없음
→ 세션이 만료될 위험
→ 주기적으로 currentUser 요청
→ 녹음 종료 후 업로드 시의 세션 만료 위험 감소
```

`checkSessionAge()`는 서버에 묻지 않고 브라우저의 `lastTouchAt`으로 남은 시간을 예상한다. 실제 유효 여부는 HTTP 요청의 성공 또는 401 응답으로 확인한다.
