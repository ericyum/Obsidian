# 4-1. API 요청과 forwardAuthToken

회의 데이터 요청은 `/user-api`와 다르게 CAP로 전달된다. `requestJson()`의 `fetch(url, prepared)`가 실제 브라우저 HTTP 요청을 만든다.

```text
GET /api/Meetings
→ Approuter의 /api route
→ srv-api destination
→ CAP MeetingService
```

`xs-app.json`의 관련 route는 XSUAA 인증을 요구하고 `srv-api`로 전달한다.

```json
{
  "source": "^/api/(.*)$",
  "target": "/api/$1",
  "destination": "srv-api",
  "authenticationType": "xsuaa"
}
```

`mta.yaml`의 다음 설정이 현재 로그인 사용자의 token을 CAP 요청에 전달한다.

```yaml
forwardAuthToken: true
```

`/user-api/currentUser`의 JSON을 CAP에 복사하는 것이 아니다.

```text
currentUser JSON
= 화면 표시용

forwardAuthToken의 JWT
= CAP 인증·권한 검사용
```

정상 응답이면 `requestJson()`은 JSON을 반환하고 `markSessionTouched(url)`을 호출한다. 401이면 세션 만료 이벤트를 발생시킨다.
