# 5-2. 상태 병합·데이터 변환·캐시와 목록 렌더링

## 각 회의를 변환하기 전 상태를 먼저 보강

`listMeetings()`는 `Meetings` 목록을 받은 뒤 각 회의에 `getMeetingStatus`를 호출한다.

```javascript
const status = await postAction("getMeetingStatus", {
  meetingId: meeting.ID || meeting.id
});

return capJobFromMeeting({
  ...meeting,
  ...(status?.value || status || {})
});
```

```text
기본 Meeting 데이터
→ getMeetingStatus 결과와 병합
→ capJobFromMeeting()
```

`capJobFromMeeting()`은 이어서 `Transcripts`, `Summaries`, `ReviewItems`를 조회한다. 그리고 JSON 문자열을 배열·객체로 파싱하고 CAP 필드명을 기존 프론트 형식으로 맞춘다.

```text
ID → id
ownerName → owner_name
sharedWith → shared_with
durationSec → duration_seconds
createdAt → created_at
status → stage
```

완성된 배열은 `meetingsCache = await listMeetings()`에 저장된다. `meetingsCache`는 DB가 아니라 현재 페이지 동안 사용하는 브라우저 메모리 배열이다.

그 후 세 함수가 실행된다.

```javascript
updatePeopleSuggestions();
renderMeetingCategoryFilter();
renderMeetingListView();
```

`renderMeetingCategoryFilter()`는 회의를 필터링하지 않는다. `meetingsCache`를 순회해 카테고리 종류와 개수를 세고 `<select>`의 `<option>`을 만든다.

실제 회의 검색·상태·카테고리 필터링은 `renderMeetingListView()`가 `meetingsCache.filter()`로 수행한다. 이어 `renderMeetingList(filtered)`가 HTML 문자열을 반환하고 다음 코드가 실제 DOM에 삽입한다.

```javascript
$("list-body").innerHTML = renderMeetingList(filtered, {
  filtered: hasFilters
});
```

마지막 `bindListEvents()`는 새로 삽입된 각 `.mtg` 요소의 클릭 Handler에 `openMeeting(id)` 호출을 연결한다. `openMeeting`은 이벤트 이름이 아니라 상세 화면을 여는 함수다.
