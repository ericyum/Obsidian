# 5-3. activePeoplePicker와 후보 목록 갱신

`activePeoplePicker`는 사람 목록이 아니라 현재 열려 있는 참여자 또는 공유자 선택창을 가리키는 객체다. 처음에는 `null`이다.

`attachPeopleMultiSelect()`는 참여자·공유자 입력창 각각에 숨겨진 메뉴 DOM과 `focus`, `click`, `input` 이벤트를 설치한다. 이 단계에서는 아직 활성 Picker가 없다.

사용자가 입력창과 상호작용하면 `open()`이 실행된다.

```javascript
activePeoplePicker = {
  menu,
  close,
  refresh: renderOptions
};
renderOptions();
```

`refresh`는 새 함수가 아니라 `renderOptions` 함수 참조를 저장한 속성이다. 최초 후보 표시는 `open()` 마지막의 직접 `renderOptions()` 호출이 담당한다.

다른 사람 선택창을 열면 기존 `activePeoplePicker.close()`가 검색어와 임시 체크를 지우고 기존 메뉴를 `hidden` 처리한다. 닫는 메뉴가 현재 활성 메뉴와 같을 때 `activePeoplePicker = null`로 만든 뒤 새 Picker 객체가 들어간다. 메뉴 DOM 자체를 삭제하는 것은 아니다.

`renderOptions()`의 흐름은 다음과 같다.

```text
knownPeopleValues()
→ meetingsCache의 owner·participants·shared_with 수집
→ 현재 작성 중인 participants·sharedWith도 수집
→ 중복 제거
→ 이미 선택한 사람 제외
→ 검색어 적용
→ 최대 40개 제한
→ 직접 입력한 새 값이 있으면 후보에 추가
→ menu.innerHTML 갱신
```

목록 로딩 뒤 호출되는 `updatePeopleSuggestions()`는 다음 한 줄이다.

```javascript
activePeoplePicker?.refresh();
```

Picker가 닫혀 `null`이면 아무 일도 하지 않는다. Picker가 이미 열려 있다면 `refresh()`, 즉 `renderOptions()`를 다시 실행해 최신 `meetingsCache`와 현재 선택값을 반영한다.

```text
최초 표시: open() → renderOptions()
열린 메뉴 재동기화: updatePeopleSuggestions() → refresh() → renderOptions()
```

따라서 `updatePeopleSuggestions()`는 이미 열린 후보 메뉴가 오래된 데이터를 보여주지 않게 하는 방어적 동기화 코드다.
