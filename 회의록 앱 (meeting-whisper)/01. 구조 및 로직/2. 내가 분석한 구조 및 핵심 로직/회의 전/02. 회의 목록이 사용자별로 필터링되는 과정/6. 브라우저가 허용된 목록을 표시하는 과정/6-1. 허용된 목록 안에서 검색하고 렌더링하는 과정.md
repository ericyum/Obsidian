# 6-1. 허용된 목록 안에서 검색하고 렌더링하는 과정

이 문서는 전체 흐름 중 8단계다. 1~7단계가 서버에서 현재 사용자가 접근할 수 있는 데이터의 범위를 결정했다면, 8단계는 그 결과를 브라우저 메모리에 넣고 검색어·처리 상태·카테고리에 따라 화면 표시 대상을 좁힌다.

```text
서버 권한 필터
→ 브라우저에 어떤 데이터를 보낼지 결정

브라우저 검색·화면 필터
→ 이미 받은 허용된 데이터 중 무엇을 화면에 그릴지 결정
```

따라서 이 단계는 권한 필터가 아니라 표시 필터다.

## 1. loadList()가 허용된 결과를 meetingsCache에 저장한다

브라우저에는 목록용 메모리 배열이 있다.

```javascript
let meetingsCache = [];
```

목록 화면으로 들어오면 `loadList()`가 다음 순서로 실행된다.

```javascript
async function loadList(options = {}) {
  if (!options.skipHistory) {
    writeRoute(
      { view: "list" },
      { replace: options.replaceHistory }
    );
  }

  stopPolling();
  show("view-list");
  restoreListFiltersFromUrl();
  await paintDraftBanner();

  if (!meetingsCache.length) {
    $("list-body").innerHTML =
      `<div class="skel w1"></div>
       <div class="skel w2"></div>
       <div class="skel w1"></div>`;
  }

  try {
    meetingsCache = await listMeetings();
    updatePeopleSuggestions();
    renderMeetingCategoryFilter();
    renderMeetingListView();
  } catch (err) {
    // 오류 표시와 재시도 처리
  }
}
```

핵심은 다음 한 줄이다.

```javascript
meetingsCache = await listMeetings();
```

여기에 들어가는 값은 앞 단계들을 이미 통과했다.

```text
Meetings
→ before READ의 사용자 WHERE 적용

회의별 상태
→ getMeetingStatus의 assertReadableMeeting 통과

전사·요약·검토 항목
→ 하위 엔티티 before READ 통과

최종 결과
→ meetingsCache
```

따라서 `meetingsCache`는 시스템 전체 회의가 아니라 현재 사용자가 서버에서 받은 회의 목록이다.

## 2. URL에 저장된 검색·필터 값을 복원한다

`loadList()`는 목록을 그리기 전에 다음 함수를 호출한다.

```javascript
function restoreListFiltersFromUrl() {
  const params = new URL(window.location.href).searchParams;

  const search = $("meeting-search");
  if (search) search.value = params.get("q") || "";

  const stage = $("meeting-stage-filter");
  if (stage) {
    const wanted = params.get("stage") || "all";
    stage.value = [...stage.options].some(
      (option) => option.value === wanted
    ) ? wanted : "all";
  }

  const category = $("meeting-category-filter");
  if (category) {
    category.dataset.pending = params.get("category") || "";
  }
}
```

예를 들어 URL이 다음과 같다면 검색 조건이 화면에 복원된다.

```text
/?q=배포&stage=done&category=프로젝트
```

카테고리 선택지는 `meetingsCache`를 받은 뒤 동적으로 만들기 때문에 우선 `dataset.pending`에 보관한다.

## 3. 카테고리 선택지도 허용된 목록에서만 만든다

```javascript
function renderMeetingCategoryFilter() {
  const select = $("meeting-category-filter");
  if (!select) return;

  const current = select.dataset.pending
    || select.value
    || "all";
  delete select.dataset.pending;

  const counts = new Map();
  let uncategorized = 0;

  for (const meeting of meetingsCache || []) {
    const category = String(meeting.category || "").trim();
    if (!category) {
      uncategorized += 1;
      continue;
    }
    counts.set(category, (counts.get(category) || 0) + 1);
  }

  const sorted = [...counts.keys()].sort(
    (a, b) => a.localeCompare(b, "ko")
  );

  select.innerHTML = [
    `<option value="all">전체 카테고리</option>`,
    ...sorted.map((category) =>
      `<option value="${esc(category)}">${esc(category)} (${counts.get(category)})</option>`
    ),
    ...(uncategorized
      ? [`<option value="uncategorized">미지정 (${uncategorized})</option>`]
      : []),
  ].join("");

  select.value = [...select.options].some(
    (option) => option.value === current
  ) ? current : "all";
}
```

카테고리 이름과 회의 개수도 `meetingsCache`만 기준으로 계산한다. 권한 없는 회의의 카테고리나 개수는 애초에 브라우저에 도착하지 않았으므로 선택지에도 나타나지 않는다.

참여자 자동완성 후보도 같은 `meetingsCache`에서 만들기 때문에 현재 사용자가 받은 회의 안의 사람 정보만 사용한다.

## 4. buildMeetingSearchText()가 회의의 검색 범위를 하나로 합친다

```javascript
function buildMeetingSearchText(meeting) {
  const note = meeting.note || {};

  const noteText = [
    note.summary || "",
    ...(note.decisions || []),
    ...(note.action_items || []).flatMap(
      (item) => [item.owner || "", item.task || ""]
    ),
    ...(note.topics || []).flatMap(
      (topic) => [
        topic.title || "",
        ...(topic.points || [])
      ]
    ),
  ];

  const transcriptText =
    (meeting.transcript?.segments || [])
      .map((seg) => seg.text || "");

  return [
    meeting.title || "",
    meeting.category || "",
    meeting.owner_name || "",
    ...(meeting.participants || []),
    ...(meeting.shared_with || []),
    meeting.created_at || "",
    fmtDate(meeting.created_at),
    ...noteText,
    ...transcriptText,
  ].join(" ").toLowerCase();
}
```

검색 대상은 다음과 같다.

```text
회의 제목
카테고리
소유자 표시 이름
참여자
공유 대상
생성 시각과 표시용 날짜
요약문
결정 사항
할 일 담당자와 할 일 내용
주제 제목과 세부 항목
전체 전사 세그먼트의 text
```

모든 값을 공백으로 연결하고 소문자로 변환한다. 따라서 제목뿐 아니라 요약과 실제 전사 내용도 검색할 수 있다.

## 5. renderMeetingListView()가 세 조건을 적용한다

```javascript
function renderMeetingListView() {
  const query = ($("meeting-search")?.value || "")
    .trim()
    .toLowerCase();
  const stage = $("meeting-stage-filter")?.value || "all";
  const category = $("meeting-category-filter")?.value || "all";
  const hasFilters = Boolean(query)
    || stage !== "all"
    || category !== "all";

  const filtered = meetingsCache.filter((meeting) => {
    const stageOk =
      stage === "all"
      || (stage === "active"
        && !["done", "failed"].includes(meeting.stage))
      || meeting.stage === stage;

    const categoryOk =
      category === "all"
      || (category === "uncategorized" && !meeting.category)
      || meeting.category === category;

    if (!stageOk || !categoryOk) return false;
    if (!query) return true;

    if (!meeting._searchText) {
      meeting._searchText = buildMeetingSearchText(meeting);
    }

    return meeting._searchText.includes(query);
  });

  $("list-body").innerHTML = renderMeetingList(
    filtered,
    { filtered: hasFilters }
  );

  updateListCount(filtered.length, hasFilters);

  $("list-body").querySelectorAll(".mtg").forEach((row) => {
    const meeting = filtered.find(
      (item) => item.id === row.dataset.open
    );
    if (meeting?.can_edit === false) {
      row.querySelector(".mtg-title-edit")?.remove();
    }
    if (meeting?.can_delete !== true) {
      row.querySelector(".mtg-del")?.remove();
    }
  });

  bindListEvents();
}
```

상태 필터는 다음과 같다.

```text
all
→ 모든 상태

done
→ 완료 상태만

failed
→ 실패 상태만

active
→ done·failed가 아닌 created·uploaded·queued·처리 중 상태
```

카테고리 필터는 다음과 같다.

```text
all
→ 모든 카테고리

uncategorized
→ category가 비어 있는 회의

특정 카테고리
→ meeting.category가 선택값과 정확히 같은 회의
```

검색어가 있을 때만 `_searchText`를 처음 만들고 회의 객체에 캐시한다. 이후 검색어가 바뀌어도 긴 전사문과 요약문을 매번 다시 연결하지 않고 `includes(query)`만 수행한다.

## 6. 필터를 바꿀 때 서버 API를 다시 호출하지 않는다

```javascript
$("meeting-search")?.addEventListener("input", () => {
  syncListFiltersToUrl();
  renderMeetingListView();
});

$("meeting-stage-filter")?.addEventListener("change", () => {
  syncListFiltersToUrl();
  renderMeetingListView();
});

$("meeting-category-filter")?.addEventListener("change", () => {
  syncListFiltersToUrl();
  renderMeetingListView();
});
```

이 이벤트에서 하는 일은 두 가지뿐이다.

```text
현재 필터를 URL Query Parameter에 기록
→ 현재 meetingsCache를 다시 필터링하고 렌더링
```

검색어를 입력할 때마다 `/api/Meetings`를 다시 호출하지 않는다. URL도 `history.replaceState()`로 바꾸므로 페이지를 새로고침하지 않는다.

```javascript
window.history.replaceState(
  window.history.state,
  "",
  `${url.pathname}${url.search}${url.hash}`
);
```

## 7. renderMeetingList()가 화면 HTML을 만든다

필터 결과는 다음 함수로 전달된다.

```javascript
$("list-body").innerHTML = renderMeetingList(
  filtered,
  { filtered: hasFilters }
);
```

`renderMeetingList()`는 각 Meeting을 다음 화면 정보로 변환한다.

```text
제목
카테고리
처리 상태 Badge
생성 날짜와 회의 길이
처리 진행률
전사 대기열 메시지
참여자 Chip
제목 수정 버튼
삭제 버튼
```

회의 제목·참여자·카테고리 같은 동적 값에는 `esc()`를 적용하고, URL의 Meeting ID에는 `encodeURIComponent()`를 적용한다.

```javascript
return `<div class="mtg" data-open="${esc(m.id)}">
  <a class="mtg-main"
     href="?meeting=${encodeURIComponent(m.id)}">
    <div class="mtg-title">
      ${esc(m.title || "(제목 없음)")}
      ${category}
      ${badge(m.stage)}
    </div>
    ${parts ? `<div class="mtg-parts">${parts}</div>` : ""}
  </a>
  <button class="mtg-title-edit"
          data-title-edit="${esc(m.id)}">수정</button>
  <button class="mtg-del"
          data-del="${esc(m.id)}">×</button>
</div>`;
```

## 8. can_edit·can_delete에 따라 버튼을 제거한다

HTML을 만든 직후 6단계에서 받은 플래그를 사용한다.

```javascript
if (meeting?.can_edit === false) {
  row.querySelector(".mtg-title-edit")?.remove();
}

if (meeting?.can_delete !== true) {
  row.querySelector(".mtg-del")?.remove();
}
```

```text
owner
→ 수정·삭제 버튼 표시

participant
→ 수정 버튼 표시, 삭제 버튼 제거

sharedWith
→ 수정·삭제 버튼 모두 제거
```

이 버튼 제거는 사용자 경험을 위한 표시 제어다. 개발자 도구로 버튼을 되살릴 수 있으므로 보안 판단은 실제 서버 Action이 다시 수행한다.

## 9. 회의를 열 때도 서버 권한을 다시 확인한다

목록 행의 클릭 이벤트는 `openMeeting()`으로 이어진다.

```javascript
$("list-body").querySelectorAll(".mtg").forEach((el) =>
  el.onclick = () => openMeeting(el.dataset.open)
);
```

`openMeeting()`은 캐시만 보고 상세 화면을 그리지 않고 `getJob(id)`를 다시 호출한다.

```javascript
async function openMeeting(id, options = {}) {
  if (!options.skipHistory) {
    syncMeetingRoute(id, {
      replace: options.replaceHistory
    });
  }

  resetResultView();
  show("view-result");

  try {
    const job = await getJob(id);
    paintResult(job);
    if (job.stage !== "done" && job.stage !== "failed") {
      poll();
    }
  } catch (err) {
    showResErr(err.message);
  }
}
```

CAP 모드의 호출 흐름은 다음과 같다.

```text
openMeeting(id)
→ getJob(id)
→ capGetJob(id)
→ getMeetingStatus({ meetingId: id })
→ assertReadableMeeting(req, meetingId)
→ 권한 통과 후 하위 데이터 READ
```

따라서 사용자가 URL의 `meeting` 값을 임의의 UUID로 바꾸거나, 목록을 불러온 뒤 권한이 변경되어도 상세 조회 시 서버 검사를 다시 통과해야 한다.

## 10. 보안 경계를 정확히 구분한다

```text
서버 권한 통제
├─ before READ Meetings
├─ getMeetingStatus의 assertReadableMeeting
├─ 하위 엔티티 before READ
└─ 편집·삭제 Action의 assert 함수

브라우저 표시 제어
├─ meetingsCache.filter()
├─ 검색어·상태·카테고리 필터
├─ can_edit·can_delete 버튼 제거
└─ renderMeetingList()
```

브라우저 코드를 조작하면 이미 `meetingsCache`에 들어 있는 허용된 회의를 필터와 무관하게 다시 표시할 수는 있다. 하지만 서버가 전달하지 않은 다른 사용자의 회의를 `meetingsCache`에서 찾아낼 수는 없고, 임의 ID로 서버 권한 검사를 우회할 수도 없다.

성능 측면에서는 목록 검색을 위해 각 회의의 전체 전사·요약을 브라우저가 받고 `_searchText`로 합친다. 회의 수와 전사문이 많아질 경우 목록 초기 요청 수와 브라우저 메모리 사용량은 추후 최적화 대상이 될 수 있다.

## 전체 1~8단계 연결

```text
1. loadList() → listMeetings()
2. readEntityList() → GET /api/Meetings
3. before READ Meetings → 사용자 WHERE 추가
4. userIdentityTokens(req.user) → 현재 사용자 Token 생성
5. buildAccessTokens() → Meeting의 접근 허용 Token 저장
6. getMeetingStatus → 읽기·편집·삭제 권한 재검사
7. 하위 READ → 허용된 meeting_ID 조건 추가
8. meetingsCache 안에서 검색·필터링·렌더링
```
