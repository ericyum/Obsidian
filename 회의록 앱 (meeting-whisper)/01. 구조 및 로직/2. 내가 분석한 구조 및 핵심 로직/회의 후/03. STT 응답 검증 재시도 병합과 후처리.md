# STT 응답 검증·재시도·병합과 후처리 — 실제 코드 워크스루

## 결론부터

STT 뒤에는 분명 후처리가 있다. 다만 그것은 “문장을 LLM으로 교정”하는 의미의 후처리가 아니라 주로 다음과 같은 **구조·timestamp 안전성 처리**다.

```text
모델 text
  → markdown JSON fence 제거
  → JSON object / segments 검사
  → 각 segment 정규화
  → timestamp 순서·범위 검사
  → 특정 MMSS 오해 패턴만 보정
  → 실패 시 같은 청크 재요청
  → 계속 실패하면 더 작은 청크로 재귀 분할
  → 청크 상대 시간을 전체 회의 시간으로 변환하여 병합
  → Worker에서 저장 전 재검증
  → CAP에서 다시 재검증
  → Transcripts 저장
```

맞춤법 교정, 문장 윤문, 고유명사 보정, 필러 제거 같은 별도 STT 교정 모델 호출은 이 저장 경로에 없다. 모델이 반환한 `text`는 `trim()`과 빈 문자열 제거 외에는 그대로 보존한다.

---

## 1단계. AI Core 응답 text를 transcript object로 바꾼다

### 1. 이 단계가 하는 일

AI Core 응답 envelope에서 content를 꺼낸 뒤, markdown fence가 있다면 벗기고 JSON object인지 확인한다.

### 2. 실제 호출자 코드

`workers/transcription/app/aicore_stt.py`:

```python
data = _parse_json(response_text)
content = _extract_aicore_content(data)
try:
    transcript = content_to_transcript(
        content,
        language=settings.whisper_language,
        duration_sec=duration_sec,
        engine="aicore",
        model=settings.aicore_stt_model,
    )
```

### 3. 전달되는 값과 상태

- `content`: 모델이 반환한 text 또는 content 배열
- `language`: 기본 `ko`
- `duration_sec`: 이번 전체 파일 또는 청크의 길이
- engine/model metadata

### 4. 실제 피호출자 코드

```python
def content_to_transcript(
    content: Any,
    *,
    language: str,
    duration_sec: float | None = None,
    engine: str = "aicore",
    model: str | None = None,
) -> dict[str, Any]:
    text = _content_to_text(content)
    parsed = _parse_json(strip_json_fence(text))
    if not isinstance(parsed, dict):
        raise TranscriptionResponseError("response was not a complete JSON object")

    raw_segments = parsed.get("segments")
    if not isinstance(raw_segments, list):
        raise TranscriptionResponseError("response did not contain a segments array")

    segments = _normalize_segments(raw_segments, duration_sec)
    return _with_metadata(
        {
            "language": str(parsed.get("language") or language),
            "segments": segments,
        },
        engine=engine,
        model=model,
    )


def strip_json_fence(content: str) -> str:
    text = str(content or "").strip()
    match = re.match(r"^```(?:json)?\s*([\s\S]*?)\s*```$", text, flags=re.IGNORECASE)
    return match.group(1).strip() if match else text
```

### 5. 경계

모델의 비정형 text → Worker의 신뢰 가능한 Python dict 경계다. 아직 DB에는 쓰지 않는다.

### 6. 반환을 받는 코드

정상 dict이면 호출부의 `transcript` 변수에 들어간다. 예외이면 같은 호출부의 `except TranscriptionResponseError`로 간다.

### 7. 다음 단계

정상 경로에서는 `_normalize_segments()`가 각 segment를 검사·정규화한다.

## 2단계. 각 segment의 text와 timestamp를 정규화한다

### 1. 이 단계가 하는 일

빈 text를 제거하고, 숫자 timestamp·구간 순서·전체 시간 순서를 강제한다.

### 2. 실제 호출자 코드

```python
segments = _normalize_segments(raw_segments, duration_sec)
```

### 3. 전달되는 값과 상태

- 모델의 `segments` 배열
- 현재 오디오 길이
- 앞 segment의 시작 시간 `previous_start`

### 4. 실제 피호출자 코드

```python
def _normalize_segments(raw_segments: list[Any], duration_sec: float | None) -> list[dict[str, Any]]:
    segments: list[dict[str, Any]] = []
    previous_start = 0.0
    duration_limit = _positive_duration(duration_sec)
    tolerance = max(5.0, duration_limit * 0.02) if duration_limit else None

    for index, item in enumerate(raw_segments):
        if not isinstance(item, dict):
            raise TranscriptionResponseError(f"segment {index} was not a JSON object")

        text = str(item.get("text") or "").strip()
        if not text:
            continue

        start = _timestamp_value(item.get("start", 0.0), f"segment {index} start")
        end = _timestamp_value(item.get("end", start), f"segment {index} end")
        if end + 0.001 < start:
            raise TranscriptionResponseError(
                f"segment {index} end timestamp {end:g} was before start {start:g}"
            )
        if segments and start + 0.25 < previous_start:
            raise TranscriptionResponseError(
                f"segment {index} timestamp moved backwards from {previous_start:g} to {start:g}"
            )

        segments.append({
            "start": round(start, 3),
            "end": round(end, 3),
            "text": text,
            "speaker": item.get("speaker"),
            "words": [],
        })
        previous_start = start
```

### 5. 경계

모델 segment → 앱의 표준 segment shape 경계다.

- timestamp는 소수 셋째 자리까지
- text는 앞뒤 공백만 제거
- `speaker`는 모델 값을 유지
- `words`는 항상 빈 배열

현재 배포는 `DIARIZE: false`이고 AI Core 경로에서 별도 diarization을 하지 않으므로 대체로 `speaker: null`이다.

### 6. 반환을 받는 코드

정상 segments 배열이 `content_to_transcript()`로 돌아간다. 길이를 크게 초과한 timestamp가 있으면 이어지는 보정 검사로 간다.

### 7. 다음 단계

`402.5`를 4분 2.5초로 잘못 표기한 것 같은 특정 패턴을 보정할지 결정한다.

## 3단계. compact MMSS로 보이는 timestamp만 제한적으로 보정한다

### 1. 이 단계가 하는 일

모델이 초 단위 대신 `MMSS.s`처럼 반환해 회의 길이를 초과한 경우, 충분히 일관된 패턴일 때만 `분 × 60 + 초`로 변환한다.

### 2. 실제 호출자 코드

`_normalize_segments()`의 이어지는 부분:

```python
if duration_limit and tolerance is not None:
    first_overflow = next(
        (
            (index, max(float(segment["start"]), float(segment["end"])))
            for index, segment in enumerate(segments)
            if max(float(segment["start"]), float(segment["end"])) > duration_limit + tolerance
        ),
        None,
    )
    if first_overflow:
        repaired = _repair_compact_mmss_timestamps(
            segments,
            duration_limit=duration_limit,
            tolerance=tolerance,
        )
        if repaired is None:
            index, timestamp = first_overflow
            raise TranscriptionResponseError(
                f"segment {index} timestamp exceeded audio duration "
                f"({timestamp:g}s > {duration_limit:g}s)"
            )
        segments = repaired

if len(segments) == 1 and _looks_like_raw_transcript_json(segments[0]["text"]):
    raise TranscriptionResponseError("response nested raw transcript JSON inside segment text")
return segments
```

### 3. 전달되는 값과 상태

- 전체 normalized segments
- 실제 오디오 길이와 2% 또는 최소 5초 tolerance

### 4. 실제 피호출자 코드

핵심 변환 함수:

```python
def _compact_mmss_to_seconds(value: float) -> float | None:
    if value < 100.0:
        return value
    minutes = int(value // 100)
    seconds = value - (minutes * 100)
    if seconds < 0.0 or seconds >= 60.0:
        return None
    return (minutes * 60.0) + seconds
```

`_repair_compact_mmss_timestamps()`는 단순히 모든 수를 변환하지 않는다. 분 경계로 보이는 jump가 적어도 두 번 있는지, 변환 후 순서가 단조 증가하는지, 변환 후에도 길이 범위 안인지 검사한 뒤에만 새 segments를 반환한다.

### 5. 경계

모델의 timestamp 오해 → 보수적으로 교정된 timestamp 경계다. 불확실하면 억지로 고치지 않고 예외로 만들어 재요청하게 한다.

### 6. 반환을 받는 코드

보정 성공이면 `_normalize_segments()`가 repaired segments를 반환한다. 실패면 `TranscriptionResponseError`가 모델 호출부로 올라간다.

### 7. 다음 단계

검증 오류는 같은 오디오를 대상으로 한 prompt 보강 재시도를 일으킨다.

## 4단계. 잘못된 모델 응답은 오류 내용을 넣어 다시 요청한다

### 1. 이 단계가 하는 일

JSON이 불완전하거나 timestamp가 틀리면 같은 오디오를 다시 보내되, 직전 검증 오류를 prompt에 추가한다.

### 2. 실제 호출자 코드

```python
try:
    transcript = content_to_transcript(
        content,
        language=settings.whisper_language,
        duration_sec=duration_sec,
        engine="aicore",
        model=settings.aicore_stt_model,
    )
except TranscriptionResponseError as error:
    last_error = error
    logger.warning(
        "AI Core returned an invalid transcript: attempt=%s/%s chunk=%s/%s "
        "chunk_start_sec=%s duration_sec=%s request_id=%s error=%s",
        attempt,
        max_attempts,
        chunk_index,
        total_chunks,
        chunk_start_sec,
        duration_sec,
        _extract_aicore_request_id(data, getattr(response, "headers", None)),
        error,
    )
    if attempt < max_attempts:
        continue
    break
```

### 3. 전달되는 값과 상태

- 배포 기본 최대 시도: 2회
- `last_error`: 이전 구조/timestamp 검증 오류
- 다음 `_aicore_stt_body()` 호출의 `retry_attempt > 1`

### 4. 실제 피호출자 코드

다음 시도에서 `after-02`에 본 이 문구가 최종 prompt 뒤에 붙는다.

```python
if retry_attempt > 1:
    error_detail = _truncate(str(validation_error or "unknown validation error"), 400)
    prompt = (
        f"{prompt} A previous response was invalid: {error_detail}. "
        "Correct that exact error. Carefully close every JSON array and object, "
        "keep timestamps monotonic, and return only the complete JSON object."
    )
```

### 5. 경계

검증기 오류 → 다음 LLM 입력 prompt 경계다. 예외 메시지는 400자로 잘라 무제한으로 prompt가 커지지 않게 한다.

### 6. 반환을 받는 코드

재시도가 성공하면 정상 transcript가 반환된다. 모든 시도가 실패하면 `_run_single_aicore_transcription()`이 `TranscriptionResponseError`를 던진다.

### 7. 다음 단계

전체가 청크 처리 중이었다면 실패한 청크를 더 작은 조각으로 나누는 fallback이 시작된다.

## 5단계. 계속 실패한 청크는 절반 크기로 재귀 분할한다

### 1. 이 단계가 하는 일

긴 청크 전체에서 JSON이 계속 깨지면 최소 60초까지 더 작은 청크로 쪼개 각 조각을 다시 전사한다.

### 2. 실제 호출자 코드

`_run_chunked_aicore_transcription()`:

```python
for index, chunk in enumerate(chunks, start=1):
    chunk_results = _transcribe_chunk_with_fallback(
        chunk,
        settings=settings,
        chunk_index=index,
        total_chunks=total_chunks,
    )
    transcripts.extend(chunk_results)
```

### 3. 전달되는 값과 상태

`AudioChunk`에는 임시 파일 path와 원본 회의 기준 `start_sec`, `end_sec`가 들어 있다.

### 4. 실제 피호출자 코드

```python
def _transcribe_chunk_with_fallback(
    chunk: AudioChunk,
    *,
    settings: Settings,
    chunk_index: int,
    total_chunks: int,
) -> list[tuple[AudioChunk, dict[str, Any]]]:
    chunk_duration = max(0.0, chunk.end_sec - chunk.start_sec)
    try:
        transcript = _run_single_aicore_transcription(
            chunk.path,
            settings=settings,
            duration_sec=chunk_duration,
            chunk_index=chunk_index,
            total_chunks=total_chunks,
            chunk_start_sec=chunk.start_sec,
        )
        return [(chunk, transcript)]
    except TranscriptionResponseError as original_error:
        fallback_seconds = max(60.0, chunk_duration / 2.0)
        if chunk_duration <= 60.0:
            raise

        smaller_chunks = _split_audio_chunks(
            chunk.path,
            settings,
            chunk_seconds=fallback_seconds,
        )
```

이후 각 `smaller_chunks`의 로컬 시간을 원본 회의 시간에 더해 `adjusted_chunks`를 만들고, 다시 `_transcribe_chunk_with_fallback()`을 호출한다.

### 5. 경계

하나의 실패한 오디오 파일 → 여러 더 작은 임시 파일 경계다. 각 임시 파일은 `finally`에서 정리한다.

### 6. 반환을 받는 코드

성공한 `(AudioChunk, transcript)` 묶음들이 원래 호출자 `transcripts` 배열에 쌓인다.

### 7. 다음 단계

모든 조각이 성공하면 상대 timestamp를 원본 회의 timeline으로 병합한다.

## 6단계. 청크 timestamp를 전체 회의 timestamp로 병합한다

### 1. 이 단계가 하는 일

각 청크가 `0초부터` 반환한 상대 시간을 해당 청크의 원본 시작 시간만큼 이동시킨다.

### 2. 실제 호출자 코드

```python
return _merge_chunk_transcripts(
    transcripts,
    duration_sec=actual_duration_sec or duration_sec,
    model=settings.aicore_stt_model,
)
```

### 3. 전달되는 값과 상태

각 항목은 `(chunk.start_sec/end_sec, chunk transcript)` 쌍이다.

### 4. 실제 피호출자 코드

```python
for chunk, transcript in transcripts:
    language = str(transcript.get("language") or language)
    usage_logs.extend(log for log in transcript.get("_aicore_usage_logs") or [] if isinstance(log, dict))
    for segment in transcript.get("segments") or []:
        if not isinstance(segment, dict):
            continue
        text = str(segment.get("text") or "").strip()
        if not text:
            continue
        start = chunk.start_sec + float(segment.get("start") or 0.0)
        end = chunk.start_sec + float(segment.get("end") or 0.0)
        if end + 0.001 < start:
            raise TranscriptionResponseError("merged transcript contained an invalid timestamp range")
        if segments and start + 0.25 < previous_start:
            raise TranscriptionResponseError("merged transcript timestamps were not monotonic")
        if _looks_like_raw_transcript_json(text):
            raise TranscriptionResponseError("merged transcript contained raw JSON as text")
        segments.append({
            "start": round(start, 3),
            "end": round(end, 3),
            "text": text,
            "speaker": segment.get("speaker"),
            "words": [],
        })
        previous_start = start
```

마지막 dict에는 `chunked: True`, `chunk_count`, engine/model metadata와 usage logs가 들어간다.

### 5. 경계

여러 모델 응답 → 하나의 전체 회의 transcript 경계다.

### 6. 반환을 받는 코드

병합 결과가 `run_aicore_transcription()` → `run_transcription()` → `_build_transcript()` → `_process_transcription()` 순서로 돌아온다.

### 7. 다음 단계

Worker와 CAP가 서로 다른 구현으로 결과를 두 번 더 검증한 뒤 DB에 저장한다.

## 7단계. Worker 검증과 CAP 검증을 모두 통과해야 저장된다

### 1. 이 단계가 하는 일

모델 구현 내부 검증만 믿지 않고, Worker orchestration과 CAP 저장 경계에서 각각 transcript를 다시 검사한다.

### 2. 실제 호출자 코드

`workers/transcription/app/main.py`:

```python
transcript = await _build_transcript_with_heartbeat(payload, audio, settings, cap)
_validate_transcript_for_storage(
    transcript,
    expected_duration_sec=payload.expected_duration_sec,
)
usage_logs = _pop_ai_usage_logs(transcript)
await _log_transcription_ai_usage(cap, payload, usage_logs)
await _send_heartbeat(
    cap,
    payload.meeting_id,
    payload.worker_run_id,
    stage="saving",
    message="Saving transcript",
    percent=75,
)
await cap.save_transcript(
    payload.meeting_id,
    worker_run_id=payload.worker_run_id,
    language=transcript.get("language", settings.whisper_language),
    content=json.dumps(transcript, ensure_ascii=False),
)
```

### 3. 전달되는 값과 상태

- usage logs는 `_pop_ai_usage_logs()`로 transcript 본문에서 제거한 뒤 별도 로깅한다.
- CAP에 보내는 `content`는 transcript JSON 문자열이다.
- 저장 직전 heartbeat는 `saving`, 75%다.

### 4. 실제 피호출자 코드

Worker 검증 `_validate_transcript_for_storage()`는 object/segments, speech text 존재, raw JSON 중첩, 유한한 비음수 timestamp, end≥start, 시간 역행, 녹음 길이 초과를 검사한다.

CAP는 `cap/srv/worker-internal-service.js`에서 다시 검사한다.

```js
this.on("saveTranscript", async (req) => {
  const { meetingId, workerRunId, language, content } = req.data;
  if (!meetingId) return req.error(400, "meetingId is required");
  if (!content) return req.error(400, "content is required");
  await assertCurrentWorkerRun(req, meetingId, workerRunId);

  const meeting = await SELECT.one.from(Meetings)
    .columns("createdAt", "processingSec", "owner", "category", "participants", "durationSec")
    .where({ ID: meetingId });
  if (!meeting) return req.error(404, "meeting not found");
  try {
    validateTranscriptContent(content, { durationSec: meeting.durationSec });
  } catch (error) {
    return req.error(422, `invalid transcript rejected: ${error.message}`);
  }

  await DELETE.from(Transcripts).where({ meeting_ID: meetingId });
  await INSERT.into(Transcripts).entries({
    meeting_ID: meetingId,
    language: language || "ko",
    content,
  });
  await UPDATE(Meetings, meetingId).set({
    status: STATUS.SUMMARIZING,
    percent: 80,
    error: null,
  });
```

### 5. 경계

Worker memory → Worker→CAP internal HTTP → CAP validation → DB `Transcripts` 경계다.

CAP의 `validateTranscriptContent()`도 JSON parse, segments 배열, speech text, raw JSON 중첩, timestamp 범위·순서, 회의 길이 초과를 독립적으로 검사한다. Worker 검사를 우회하거나 구현 차이가 생겨도 DB 경계가 한 번 더 막는다.

### 6. 반환을 받는 코드

저장이 끝나면 CAP는 회의를 `summarizing`, 80%로 바꾸고 `startWorkerSummaryTask(...)`를 호출한다. 그 후 최신 Meeting 행을 Worker에 반환한다.

### 7. 다음 단계

전사 JSON을 `Transcripts`에서 읽어 요약용 text chunks로 바꾸고, 요약 프롬프트를 조립하는 단계로 이어진다.

## “STT 후처리가 있나?”에 대한 정확한 답

| 처리 | 존재 여부 | 실제 동작 |
|---|---|---|
| JSON fence 제거 | 있음 | 바깥쪽 ```json fence 제거 |
| JSON/segments 구조 검증 | 있음 | object와 배열이 아니면 재시도 |
| text 정리 | 제한적 | `String(...).strip()`과 빈 text 제거 |
| timestamp 검사 | 있음 | 숫자·비음수·end≥start·단조 증가·길이 범위 |
| 특정 MMSS timestamp 보정 | 있음 | 충분히 일관된 패턴일 때만 초로 변환 |
| 청크 시간 병합 | 있음 | `chunk.start_sec + relative timestamp` |
| 맞춤법·문체 교정 | 없음 | 별도 교정 모델/사전 없음 |
| filler 제거 | 없음 | transcript text를 의미적으로 편집하지 않음 |
| 화자 분리 | 현재 배포 주 경로에서는 없음 | AI Core 경로 + `DIARIZE: false` |
| 저장 전 이중 검증 | 있음 | Worker 1회 + CAP 1회 |

## 다시 기억할 핵심

> 후처리의 목적은 “더 예쁜 문장”이 아니라 “DB에 안전하게 저장할 수 있는 transcript”다. 잘못된 결과를 억지로 저장하지 않고, 먼저 같은 오디오를 오류 피드백과 함께 재요청하고, 긴 청크라면 더 작게 나누어 재시도한 뒤, Worker와 CAP의 두 검증을 모두 통과한 결과만 저장한다.

## 직접 대조할 소스

- `workers/transcription/app/aicore_stt.py`: content 변환, segment 정규화, timestamp 보정, 재시도, 재귀 분할, 병합
- `workers/transcription/app/main.py`: 최종 Worker 검증과 CAP 저장 호출
- `workers/transcription/app/cap_client.py`: `save_transcript`
- `cap/srv/lib/meeting-note.js`: CAP `validateTranscriptContent`
- `cap/srv/worker-internal-service.js`: `saveTranscript` action과 DB 저장
