# Before — 일시정지 중 RAF loop 계측 테스트

## 테스트 목적

녹음을 일시정지했을 때 `MediaRecorder`만 멈추고 음량 분석용 `requestAnimationFrame(loop)`는 계속 실행되는지 실제 `recorder.js`를 이용해 계측한다.

연결된 개선안: [[03. 일시정지 음량 분석 loop 중단 최종안]]

## 왜 화면만 봐서는 확인할 수 없는가

`app.js`의 `updateMicLevel()`에는 다음 방어가 있다.

```javascript
if (!levelBars.length || !recorder || recorder.isPaused()) return;
```

따라서 일시정지 중 내부 loop가 계속 실행돼도 화면 막대는 갱신되지 않는다. 화면이 멈췄다는 사실만으로 RAF가 중단됐다고 판단할 수 없다.

## 계측 방법

실제 `createRecorder()`를 불러오고 다음 호출 횟수를 기록했다.

```text
analyser.getByteFrequencyData()
onLevel()
requestAnimationFrame callback
```

녹음 시작 후 frame을 실행하고, `pause()`를 호출한 뒤 frame을 세 번 더 실행했다.

## 실행 결과

```text
✔ Before: pause 뒤에도 analyser RAF loop가 계속 실행된다
tests 1
pass 1
fail 0
duration_ms 68.7869
```

테스트에서 pause 이후에도 다음 두 값이 모두 증가했다.

```text
analyserReads > readsBeforePause
levelCallbacks > callbacksBeforePause
```

Chrome 기본 E2E에서도 실제 녹음의 일시정지·재개는 정상 작동했고 Console 오류는 없었다. 즉 기능이 깨지는 오류는 아니지만, 일시정지 중에도 불필요한 음량 분석 작업이 계속되는 것은 확인됐다.

## Before 결론

**재현 성공.** 일시정지 상태에서도 analyser RAF loop가 계속 실행된다.

## After 테스트 기준

동일한 테스트에서 다음을 만족해야 한다.

```text
pause 이후 analyserReads 증가 없음
pause 이후 levelCallbacks 증가 없음
resume 이후 다시 증가
stop 이후 예약된 RAF 없음
```
