# 01. 로그아웃 후 다시 로그인하지 못하던 문제

> 현재 상태: **해결·`main` 반영 완료**

## 문제 현상

배포 환경에서 로그아웃한 뒤 세션 만료 안내창의 `다시 로그인`을 눌러도 XSUAA 로그인 화면으로 가지 않고 같은 화면에 머물 수 있었다.

```text
로그아웃
→ 세션 만료 안내
→ 다시 로그인 클릭
→ 캐시된 index.html 재사용
→ Approuter에 새 요청이 도달하지 않음
→ XSUAA가 로그인 여부를 다시 판단하지 못함
```

## 원인 1: 같은 URL을 다시 열었다

초기 `session.js`는 현재 주소를 그대로 다시 열었다.

```js
window.location.assign(window.location.href);
```

브라우저가 `index.html`을 캐시하고 있으면 새로운 서버 요청 대신 캐시된 페이지를 재사용할 수 있다. 이러면 Approuter와 XSUAA가 새 로그인이 필요한지 판단할 기회가 없다.

## 수정 1: 매번 다른 주소로 서버에 재요청

```js
window.location.assign(`/?_=${Date.now()}`);
```

`Date.now()`로 매번 다른 쿼리 값을 붙여 브라우저가 진입 페이지를 다시 요청하게 했다.

```text
다시 로그인
→ /?_=<현재시각>
→ Approuter에 새 요청
→ XSUAA 세션 확인
→ 세션이 없으면 IdP 로그인 화면로 이동
```

## 원인 2: `index.html`이 캐시될 수 있었다

버튼에서 캐시를 회피해도 앱의 진입점이 계속 캐시되면 로그인·배포 직후에 오래된 화면을 볼 수 있다. Approuter의 로컬과 배포용 `xs-app.json`에 `index.html` 전용 라우트를 추가했다.

```json
{
  "source": "^/(index\\.html)?$",
  "target": "/index.html",
  "localDir": "resources",
  "authenticationType": "xsuaa",
  "cacheControl": "no-store"
}
```

JS·CSS 전체의 캐시를 끄지 않고 `/`와 `/index.html`만 `no-store`로 처리했다.

## 원인 3: 401 정보가 상위 로직에 전달되지 않았다

`getCurrentUser()`가 401을 받아도 상위의 `refreshSession()`은 일반 네트워크 오류와 세션 만료를 정확하게 구분하지 못했다. 현재는 Error 객체에 HTTP 상태를 담아 전달한다.

```js
const error = new Error(`current user unavailable: ${response.status}`);
error.status = response.status;
throw error;
```

```js
showExpired({
  source: reason,
  status: error?.status,
  message: error?.message || ""
});
```

```text
401
→ 로그인 세션 만료 안내

기타 오류
→ 세션 확인 실패 안내
```

## 검증

- `다시 로그인` 클릭 후 IdP 로그인 페이지로 이동
- `index.html` 응답에 `Cache-Control: no-store` 확인
- JS 정적 자원에는 불필요한 `no-store`가 붙지 않음
- 401과 비-401의 사용자 메시지가 다르게 표시됨
