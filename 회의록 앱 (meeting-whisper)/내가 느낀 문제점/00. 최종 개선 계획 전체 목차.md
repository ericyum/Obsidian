## 이번 최종안에서 제외한 항목

### 화자 분리

WhisperX 등을 이용한 화자 분리는 과거에 실제 구현했으나 처리 시간이 너무 길고 효용성이 낮아 의도적으로 제품에서 제거한 기능이다. 따라서 현재 `false` 고정 상태를 미완성 버그로 보지 않으며 이번 개선 대상에서 제외한다.

### 권한 토큰 함수 네 개의 분리 문제

함수 분리 자체는 문제가 아니다. 전체 이메일만 저장·비교하도록 정책을 단순화하면 각 함수의 책임도 자연스럽게 단순해진다. 따라서 독립 개선안으로 두지 않고 1번 문서에 포함한다.

## 최종 정책 요약

```text
[권한 신원]
이름·표시 이름·이메일 앞부분 사용 중단
→ XSUAA에서 얻은 전체 이메일만 사용
→ DB 스키마와 accessTokens LargeString은 유지

[회의 쓰기 API]
표준 CREATE·READ 유지
→ 표준 UPDATE·DELETE 외부 요청 거부
→ 기존 커스텀 Action만 공식 수정·삭제 경로로 사용

[참여자와 공유자]
한 사용자는 둘 중 하나의 역할만 가짐
→ 중복 시 participant 우선
→ 프론트와 백엔드 양쪽에서 강제

[녹음 일시정지]
MediaRecorder 기록과 함께 음량 분석 RAF도 중지
→ 재개할 때 같은 analyser로 RAF만 다시 시작
```

## 권장 구현 순서

```text
1. accessTokens 전체 이메일 전환
→ 기존 데이터 재생성

2. 참여자·공유자 중복 제거
→ 같은 이메일 정규화 함수를 재사용

3. Meetings 표준 UPDATE·DELETE 차단
→ Action 회귀 테스트

4. 일시정지 RAF 중단
→ 녹음·시간·파형 회귀 테스트
```

1번과 3번은 권한과 데이터 정합성에 직접 연결되므로 우선 적용한다. 4번은 기능 오류보다는 장시간 녹음의 CPU·배터리 최적화 항목이다.
