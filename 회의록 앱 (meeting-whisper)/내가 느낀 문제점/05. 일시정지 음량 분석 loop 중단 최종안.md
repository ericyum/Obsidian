# 05. 일시정지 음량 분석 loop 중단 최종안

> 수정 전 재현 결과: [[해결 과정/02. Before — 일시정지 중 RAF loop 계측 테스트]]
>
> 수정 후 검증 결과: [[해결 과정/05. After — 일시정지 중 RAF loop 중단 검증]]

## 최종 결론

녹음을 일시정지하면 MediaRecorder의 데이터 기록뿐 아니라 음량 분석용 `requestAnimationFrame(loop)` 반복도 중단한다.

재개할 때 기존 `MediaStream`, `AudioContext`, `AnalyserNode`는 그대로 사용하고 RAF 반복만 다시 시작한다.

```text
pause
→ 마지막 음성 조각 요청
→ MediaRecorder 일시정지
→ 실제 녹음 시간 누적
→ 음량 분석 RAF 취소

resume
→ 같은 MediaRecorder 재개
→ 새 녹음 구간 시작 시각 기록
→ 같은 analyser로 RAF 다시 예약
```

## 현재 문제

현재 `pause()`는 MediaRecorder만 멈춘다.

```javascript
rec.requestData();
rec.pause();
activeMs += Date.now() - segmentStartMs;
state = "paused";
```

음량 분석 `loop()`는 다음 화면마다 계속 실행된다.

```javascript
function loop() {
  analyser.getByteFrequencyData(buf);
  const level = buf.reduce((a, b) => a + b, 0) / buf.length / 255;
  onLevel && onLevel(level);
  raf = requestAnimationFrame(loop);
}
```

`app.js`의 `updateMicLevel()`이 일시정지 여부를 보고 화면 변경만 건너뛴다.

```javascript
if (!levelBars.length || !recorder || recorder.isPaused()) return;
```

따라서 일시정지 중에도 다음 연산은 반복된다.

```text
requestAnimationFrame callback
→ getByteFrequencyData
→ 배열 평균 계산
→ onLevel callback
→ updateMicLevel에서 return
```

화면은 멈춰 보이지만 분석 비용은 계속 발생한다.

## 이 문제의 우선순위

`fftSize = 64`로 계산량이 작기 때문에 짧은 일시정지에서는 체감 문제가 거의 없을 수 있다. 데이터 손실이나 보안 문제도 아니다.

그러나 회의 녹음은 장시간 실행될 수 있고 RAF는 초당 수십 회 호출될 수 있다. 노트북 배터리와 CPU 관점에서 불필요한 반복이므로 성능 개선 항목으로 적용한다.

## 확정 구현 방식

음량 분석 반복의 시작과 중지를 함수로 분리한다.

```javascript
function startLevelLoop() {
  if (raf) return;
  raf = requestAnimationFrame(loop);
}

function stopLevelLoop() {
  if (!raf) return;
  cancelAnimationFrame(raf);
  raf = null;
}
```

`if (raf) return`은 여러 번 재개했을 때 RAF 반복이 중복으로 생기는 것을 막는다. 취소 후 `raf = null`로 만들어 다음 resume이 정상적으로 다시 시작할 수 있게 한다.

## 상태별 연결

### start

```text
rec.start(timeslice)
→ state = recording
→ segmentStartMs 기록
→ startLevelLoop()
```

### pause

```text
rec.requestData()
→ 아직 방출하지 않은 음성을 dataavailable로 요청
→ rec.pause()
→ activeMs에 현재 녹음 구간 누적
→ state = paused
→ stopLevelLoop()
```

기존 메모리 chunks와 IndexedDB 조각은 삭제하지 않는다. `MediaStream`, `AudioContext`, `analyser`도 유지한다.

### resume

```text
rec.resume()
→ segmentStartMs를 현재 시각으로 갱신
→ state = recording
→ startLevelLoop()
```

기존 녹음기를 새로 만드는 것이 아니라 같은 MediaRecorder가 기록을 이어간다. 파형도 과거 level을 복원하지 않고 현재 마이크 음량부터 새로 읽는다.

### stop

```text
남은 음성 조각 요청
→ rec.stop()
→ stopLevelLoop()
→ 마이크 track 종료
→ AudioContext 종료
→ 메모리 chunks를 최종 Blob으로 결합
```

`closeResources()`에서도 `stopLevelLoop()`를 호출하여 어떤 종료 경로에서도 RAF가 남지 않게 한다.

## 저장해야 하는 값과 저장하지 않는 값

### 녹음 시간

일시정지 전까지의 실제 녹음 시간은 `activeMs`에 누적해야 한다.

```text
과거 녹음 구간
→ 이후 elapsed() 계산에 필요
```

### 음성 조각

기존 chunks와 IndexedDB 데이터는 그대로 유지한다. 재개 후 생성된 조각이 뒤에 추가되고 종료 시 하나의 Blob으로 합쳐진다.

### 파형 level

별도 저장하지 않는다.

```text
파형
→ 현재 순간의 마이크 음량을 보여주는 UI
→ resume 후 현재 analyser 값부터 다시 측정
```

일시정지 직전의 막대 모양을 그대로 둘지 낮은 높이로 초기화할지는 UI 선택 사항이다. 기능상 RAF 중단과는 별개다.

## 선택적 추가 최적화

긴 일시정지에서 분석 회로 자체도 쉬게 하려면 다음을 고려할 수 있다.

```text
pause
→ stopLevelLoop()
→ audioContext.suspend()

resume
→ audioContext.resume()
→ startLevelLoop()
```

그러나 `AudioContext.resume()`은 브라우저 사용자 제스처 정책과 Promise 오류 처리가 필요하다. 이번 기본 개선안은 위험이 작은 RAF 중단·재시작까지만 적용하고 AudioContext suspend는 별도 성능 측정 후 판단한다.

## 구현 주의점

- RAF 예약 ID를 항상 `raf` 하나로 관리한다.
- pause를 여러 번 눌러도 중복 취소 오류가 없어야 한다.
- resume을 여러 번 호출해도 loop가 두 개 이상 생기면 안 된다.
- loop가 다음 RAF를 예약한 뒤 stop이 호출되는 순서를 테스트한다.
- 종료 시 `cancelAnimationFrame`, 마이크 track stop, AudioContext close가 모두 실행되어야 한다.
- 기존 `elapsed()`의 일시정지 시간 제외 동작을 바꾸면 안 된다.

## 검증 시나리오

### 기본 동작

```text
녹음 시작
→ 파형 움직임
→ 약 1초마다 음성 조각 생성
```

### 일시정지

```text
pause 클릭
→ 마지막 조각 방출
→ MediaRecorder paused
→ RAF callback 반복 중지
→ 타이머의 실제 녹음 시간 정지
```

개발 도구나 계측 counter로 pause 후 `loop()` 호출 횟수가 증가하지 않는지 확인한다.

### 재개

```text
resume 클릭
→ 같은 MediaRecorder 재개
→ RAF 하나만 시작
→ 현재 음량에 따라 파형 다시 움직임
→ 새 음성 조각이 기존 조각 뒤에 저장
```

### 반복 pause·resume

여러 번 반복해도 다음 조건을 만족해야 한다.

```text
RAF 중복 없음
음성 조각 순서 유지
activeMs 계산 정상
일시정지 시간 제외
최종 Blob 정상 재생
```

### 종료

```text
stop
→ RAF 없음
→ MediaStream track 종료
→ AudioContext closed
→ 최종 Blob 생성
```

## 완료 조건

- 일시정지 중 `loop()`가 반복 실행되지 않는다.
- 재개 시 RAF가 정확히 하나만 다시 시작된다.
- 기존 MediaRecorder·stream·analyser를 재사용한다.
- chunks와 IndexedDB 복구 저장은 기존대로 유지된다.
- `elapsed()`가 일시정지 시간을 제외한다.
- stop 후 RAF, 마이크, AudioContext 자원이 남지 않는다.
