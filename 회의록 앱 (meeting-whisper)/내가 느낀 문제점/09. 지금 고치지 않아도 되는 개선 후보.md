# 09. 지금 고치지 않아도 되는 개선 후보

## 이 문서의 목적

여기에 있는 항목이 중요하지 않다는 뜻은 아니다. 현재 사용자가 정상 UI로 한 번의 회의를 녹음하고 회의록을 만드는 과정에서 즉시 실패를 만들 가능성이 상대적으로 낮으므로 긴급 개선과 분리한 것이다.

## 배포 전 또는 보안 점검 때 처리할 항목

| 항목 | 이유 | 권장 시점 |
|---|---|---|
| `accessTokens`를 전체 이메일만 사용하도록 변경 | 이름·이메일 앞부분 충돌 가능성을 제거하지만 현재 사내 정상 UI 흐름의 즉시 장애는 아님 | 사용자 확대 전 |
| `Meetings` 일반 `UPDATE`, `DELETE` 차단 | UI는 이미 커스텀 Action을 사용하므로 API 우회 방어 성격이 큼 | 정식 배포 전 |
| `Transcripts`, `Summaries`, `ReviewItems` 일반 쓰기 차단 | 정상 UI는 Action을 사용하지만 직접 API 호출 방어가 필요 | 보안 점검 시 |
| Worker 내부 projection을 `readonly`로 제한 | Worker 자격증명 오용 방지 | 운영 보안 강화 시 |
| `getAudio`에 `workerRunId` 추가 | Worker API의 최소 권한 강화 | Worker 인증 정리 시 |

## 규모가 커질 때 처리할 항목

| 항목 | 현재 판단 | 다시 볼 조건 |
|---|---|---|
| 다중 CAP 인스턴스의 조건부 dispatch claim | 현재 단일 인스턴스라면 바로 재현되기 어려움 | CAP를 2개 이상 scale-out할 때 |
| HANA Full-Text Index | 현재 회의 수가 적으면 일반 검색으로 충분 | 회의가 수천 건 이상 쌓이고 검색이 느려질 때 |
| Worker HPA 확대 | 현재 `maxReplicas: 1` | 동시 전사량이 늘어날 때 |
| Composition of one DB unique 제약 | 동시 요청이 많지 않으면 표면화 가능성이 낮음 | 중복 자식 행이 실제 관측될 때 또는 스키마 정비 시 |

## 자원과 효율 개선

| 항목 | 판단 |
|---|---|
| 일시정지 중 음량 RAF loop 중단 | 장시간 일시정지의 CPU·배터리 절약이며 데이터 손상 문제는 아님 |
| 모듈 역할 분리와 `app.js` 정리 | 유지보수성 개선이며 현재 기능 오류와 직접 연결되지 않음 |
| 진단 로그 정리 | 운영 로그 가독성과 비용 개선 |
| 의존성 버전 고정 | 재빌드 재현성 개선이며 현재 실행 중 오류는 아님 |

## 데이터 보관 정책

`AiCoreUsageLogs`에는 `promptPayload`, `responsePreview` 등 회의 내용 일부가 중복 저장될 수 있다. 개인정보 및 보관 기간 정책은 필요하지만 현재 회의 처리 실패를 만드는 문제는 아니다.

다음 시점에 별도 검토하는 것이 좋다.

```text
정식 운영 전 개인정보 점검
MeetingAdmin 권한 범위 확정
로그 보관 기간 결정
AI 비용 대시보드 설계
```

## Object Store 정합성 보강

음원 교체 도중 DB 저장 실패 또는 Object Store 삭제 실패가 발생하면 고아 파일이나 메타데이터 불일치가 생길 가능성이 있다.

이는 수정 가치가 있지만 일반적인 성공 흐름보다 인프라 장애·부분 실패 상황에서 나타난다. 먼저 즉시 대응 문서의 업로드 단계 재시도를 안정화한 후 다음 단계로 처리하는 편이 좋다.

## 참여자와 공유자 중복

정상 UI에서 직접 보이는 문제이므로 완전히 미뤄야 하는 항목은 아니다. 다만 녹음·전사·요약을 실패시키지는 않는다.

```text
긴급 장애 수정 완료
→ 참여자·공유자 상호 배타 처리
→ 전체 이메일 권한 전환
```

순서가 적절하다.

## 우선순위가 다시 올라가는 조건

아래 조건이 생기면 이 문서의 항목을 즉시 대응 대상으로 옮긴다.

- 외부 사용자 또는 다른 조직 사용자가 들어온다.
- CAP 또는 Worker를 여러 인스턴스로 확장한다.
- 다른 시스템이 UI를 거치지 않고 API를 직접 호출한다.
- Object Store 삭제 실패나 중복 음원이 실제 운영 로그에서 발견된다.
- AI 사용 로그에 개인정보가 과도하게 남는다는 보안 검토 결과가 나온다.
- 사용자 수와 회의 데이터가 크게 늘어난다.
