# After — 일시정지 중 RAF loop 중단 검증

## 수정 대상

```text
C:\Users\염정운\project\meeting-whisper-yina
app/meeting-ui/js/recorder.js
```

연결된 개선안: [[../05. 일시정지 음량 분석 loop 중단 최종안]]

## 수정 내용

음량 분석 loop의 시작과 중단을 다음 두 함수로 분리했다.

```text
startLevelLoop()
stopLevelLoop()
```

상태별 동작:

```text
start
→ RAF loop 시작

pause
→ 예약된 RAF 취소
→ raf = null

resume
→ RAF loop 한 번만 다시 시작

stop
→ RAF 취소 후 마이크와 AudioContext 정리
```

## 검증 파일

```text
tests/recorder-pause-loop.test.js
```

실제 `recorder.js`를 불러와 RAF 예약 수, analyser 읽기 횟수, `onLevel` 호출 횟수를 계측했다.

## 실행 명령

```powershell
node --test tests\recorder-pause-loop.test.js
```

```text

```

확인한 조건:


## 정적 UI 동기화

`node scripts\copy-web-assets.js`를 실행했다.

```text
approuter/resources/js/recorder.js
approuter/dev/resources/js/recorder.js
```

두 파일 모두 원본 `app/meeting-ui/js/recorder.js`와 SHA-256이 일치한다.

## 결론

Before에서 확인한 pause 중 analyser loop 지속 현상은 수정됐다. pause·resume·stop 상태 전환에 대한 자동 회귀 테스트도 통과했다.

## 실제 Chrome 로컬 E2E

수정된 yina 코드로 CAP와 mock Worker를 실행한 뒤 실제 Chrome에서 다음 흐름을 확인했다.

```text
새 회의 생성
→ 실제 마이크 녹음
→ 일시정지 표시와 타이머 정지 확인
→ 재개 후 녹음 상태와 타이머 진행 확인
→ 종료
→ /api/binary 음원 업로드
→ Worker mock 전사
→ 요약과 전사본 표시
```

Chrome Console의 오류·경고는 0건이었다. 최종 회의는 `done` 상태가 됐고 mock 전사 결과가 화면에 표시됐다.

## 배포 환경 동일성 점검

RAF 중단은 브라우저의 `requestAnimationFrame`, `MediaRecorder`, `AudioContext`만 사용하는 프론트 로직이다. CAP, Worker, XSUAA의 실행 방식에 따라 달라지는 코드가 아니므로 동일한 `recorder.js`가 전달되면 배포 환경에서도 같은 동작을 한다.

빌드·배포 과정에서는 `scripts/copy-web-assets.js`가 다음 두 경로로 소스를 복사한다.

```text
app/meeting-ui/js/recorder.js
→ approuter/resources/js/recorder.js
→ approuter/dev/resources/js/recorder.js
```

현재 세 파일의 SHA-256은 모두 일치한다.

주의할 점은 `app.js`의 recorder import URL이 아직 다음 버전을 사용한다는 것이다.

```text
/js/recorder.js?v=20260630-ux-fixes
```

배포 후 브라우저 캐시에 구버전이 남는 환경까지 확실히 배제하려면 배포 전에 이 query version을 새 값으로 갱신하는 것이 안전하다. 기능 구현 자체의 문제는 아니며 정적 자산 갱신 보장에 관한 배포 점검 항목이다.

## 최종 결론

자동 계측과 실제 Chrome E2E 모두 통과했다. 수정된 정적 파일이 사용자 브라우저에 전달된다는 조건에서는 배포 환경에서도 동일하게 동작할 가능성이 높다. 배포 전에 recorder import cache-buster를 갱신하면 구버전 캐시 위험까지 제거할 수 있다.
