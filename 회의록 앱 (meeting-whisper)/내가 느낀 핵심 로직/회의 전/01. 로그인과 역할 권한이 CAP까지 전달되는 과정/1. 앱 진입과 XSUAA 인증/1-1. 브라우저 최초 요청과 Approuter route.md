# 1-1. 브라우저 최초 요청과 Approuter route

## 시작점은 JavaScript 함수가 아니다

사용자가 배포된 앱 URL을 여는 것이 최초 호출이다. 이 요청을 CAP가 아니라 Approuter가 먼저 받는다.

```text
브라우저 주소창
→ GET /
→ Approuter
```

`approuter/xs-app.json`의 핵심 설정은 다음과 같다.

```json
{
  "welcomeFile": "/index.html",
  "authenticationMethod": "route"
}
```

`welcomeFile` 때문에 `/` 요청은 `/index.html` 요청처럼 처리된다. `authenticationMethod: route`는 아래 `routes` 배열의 경로별 인증 규칙을 사용한다는 뜻이다.

정적 파일 요청은 마지막 규칙에 걸린다.

```json
{
  "source": "^/(.*)$",
  "target": "/$1",
  "localDir": "resources",
  "authenticationType": "xsuaa"
}
```

```text
/index.html 요청
→ 마지막 route와 일치
→ XSUAA 인증 필요
→ 인증 후 resources/index.html 반환
```

`source`는 요청 조건, `target`은 내부 대상 경로, `localDir`은 파일을 찾는 폴더다. `authenticationType`은 파일을 주기 전에 통과해야 하는 인증이다.

## 로그인 코드는 프로젝트 안에 없다

이 프로젝트에는 ID와 비밀번호를 검사하는 `login()` 함수가 없다. 로그인 화면, 자격 확인, token 발급과 복귀는 Approuter와 SAP XSUAA가 담당한다. 저장소에서 확인할 수 있는 것은 그 앞뒤의 설정 경계다.

```text
Approuter
→ 로그인되지 않았으면 XSUAA로 이동
→ XSUAA 인증
→ Approuter로 복귀
→ 원래 요청 계속 처리
```
