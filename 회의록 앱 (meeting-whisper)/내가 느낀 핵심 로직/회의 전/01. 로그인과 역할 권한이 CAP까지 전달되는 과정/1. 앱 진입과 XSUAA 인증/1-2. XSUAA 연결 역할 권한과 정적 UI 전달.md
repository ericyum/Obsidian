# 1-2. XSUAA 연결·역할 권한과 정적 UI 전달

## Approuter가 사용할 서비스 연결

`mta.yaml`의 Approuter 모듈은 다음 두 연결을 요구한다.

```yaml
requires:
  - name: meeting-whisper-auth
  - name: srv-api
    group: destinations
    properties:
      name: srv-api
      url: ~{srv-url}
      forwardAuthToken: true
```

```text
meeting-whisper-auth
= 로그인에 사용할 XSUAA 서비스

srv-api
= CAP 백엔드 목적지
```

`xs-security.json`에는 `MeetingUser`, `Worker`, `MeetingAdmin` scope와 role template이 정의되어 있다. 운영에서는 BTP 사용자에게 Role Collection이 할당되고, 연결된 scope가 로그인 token에 포함된다.

```text
BTP 사용자
→ Role Collection
→ Role Template
→ Scope
→ JWT
```

## 인증 후 UI가 내려오는 과정

로그인에 성공하면 Approuter는 원래의 `/index.html` 요청 처리를 계속한다. 배포 시 실제로 제공하는 파일은 `approuter/resources`에 있다.

```text
원본 UI: app/meeting-ui
→ copy-web-assets.js
→ 배포용 UI: approuter/resources
→ 브라우저
```

브라우저가 `index.html`, JavaScript와 CSS를 받은 다음에야 `app.js`가 시작된다. 즉 프론트엔드의 `initUserProfile()`보다 XSUAA 인증이 먼저다.
