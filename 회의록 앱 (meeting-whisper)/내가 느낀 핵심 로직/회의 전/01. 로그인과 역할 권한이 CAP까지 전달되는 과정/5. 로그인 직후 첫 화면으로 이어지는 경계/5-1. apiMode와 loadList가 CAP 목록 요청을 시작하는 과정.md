# 5-1. apiMode와 loadList가 CAP 목록 요청을 시작하는 과정

로그인 후 `applyRoute()`는 URL에 `meeting` ID가 없으면 `loadList()`를 호출한다.

```text
app.js 초기화
→ routeFromLocation()
→ applyRoute({ view: "list" })
→ loadList()
→ listMeetings()
```

`listMeetings()`는 `useCapApi()`를 호출하고, 그 안에서 `apiMode()`가 실행된다. `apiMode()`는 서버에서 모드를 받아오는 함수가 아니라 현재 브라우저 URL로 판단한다.

우선순위는 다음과 같다.

```text
URL의 ?api= 값
→ localhost의 4004·5000 포트면 cap
→ 원격 배포 도메인이면 cap
→ 그 밖에는 localStorage 또는 fastapi 기본값
```

배포 URL은 `localhost`가 아니므로 `"cap"`을 반환한다. `useCapApi()`는 `"cap" === "cap"`을 비교해 `true`를 반환한다.

```text
listMeetings()
→ useCapApi()
→ apiMode()
→ "cap"
→ true
→ readEntityList("Meetings", { orderby: "createdAt desc" })
→ requestJson("/api/Meetings?...")
```

Legacy 분기의 `/api/meetings`와 현재 CAP Entity 경로 `/api/Meetings`를 구분해야 한다.
