# 5-4. 참여자 Picker에서 추가와 삭제가 화면에 반영되는 과정

이 문서는 `activePeoplePicker`가 열린 다음, 참여자를 실제로 추가하거나 삭제했을 때 어떤 코드가 어떤 코드로 이어지는지를 설명한다.

## 먼저 구분해야 할 세 가지

```text
menu
= 참여자 후보 체크박스와 선택 추가 버튼이 들어가는 드롭다운 DOM

pending
= 체크했지만 아직 확정하지 않은 사람을 임시로 담는 Map

participants
= 새 회의에 최종적으로 포함할 참여자 배열
```

`menu`는 원래 `index.html`에 완성된 후보 목록으로 들어 있는 것이 아니다. `attachPeopleMultiSelect()`가 다음처럼 새 `<div>`를 만들고 참여자 입력창이 있는 `.chips` 안에 붙인다.

```javascript
const menu = document.createElement("div");
menu.className = "people-picker-menu hidden";
host.appendChild(menu);
```

처음에는 숨겨진 빈 메뉴이며, 사용자가 입력창을 누르면 실행되는 `renderOptions()`가 `menu.innerHTML`을 채운다.

## 참여자 Picker를 준비하는 과정

`app.js`는 참여자 입력창에 Picker를 연결한다.

```javascript
const chipInput = $("chip-input");

attachPeopleMultiSelect(chipInput, {
  getItems: () => participants,
  selectedLabel: "참여자",
  onApply: renderEntryPeopleChips,
});
```

여기서 `onApply: renderEntryPeopleChips`는 함수를 바로 실행하는 코드가 아니다. 선택을 확정한 뒤 호출할 수 있도록 함수 참조를 전달하는 코드다.

`attachPeopleMultiSelect()`는 준비를 마친 뒤 입력창에 이벤트를 연결한다.

```javascript
input.addEventListener("focus", open);
input.addEventListener("click", open);
input.addEventListener("input", open);
```

따라서 앱 초기화 시점에는 Picker를 준비하기만 하고, `open()`은 사용자가 입력창에 초점을 두거나 클릭하거나 글자를 입력했을 때 실행된다.

## 추가 시나리오

### 1. 입력창을 누르면 후보 메뉴가 열린다

```text
chip-input의 focus·click·input 이벤트
→ open()
→ activePeoplePicker에 현재 menu·close·renderOptions 등록
→ renderOptions()
```

```javascript
activePeoplePicker = {
  menu,
  close,
  refresh: renderOptions
};

renderOptions();
```

객체에 `refresh: renderOptions`를 넣는 것은 함수 참조를 저장하는 일이다. 실제 최초 후보 목록 생성은 바로 다음 줄의 `renderOptions()`가 담당한다.

### 2. renderOptions가 menu를 채운다

```text
renderOptions()
→ knownPeopleValues()
→ 사람 후보 수집
→ 이미 선택한 사람과 검색 조건 반영
→ menu.innerHTML에 체크박스와 선택 추가 버튼 생성
```

### 3. 후보를 체크하면 pending에만 들어간다

```javascript
checkbox.addEventListener("change", () => {
  const optionIndex = Number(checkbox.dataset.peopleOption);
  togglePending(optionValues[optionIndex]);
  renderOptions();
});
```

김철수를 체크한 시점의 상태는 다음과 같다.

```text
pending: 김철수 있음
participants: 아직 김철수 없음
```

체크는 선택 확정이 아니라 임시 선택이다.

### 4. 선택 추가를 눌러야 participants에 들어간다

```javascript
const target = getItems();

for (const value of pending.values()) {
  if (!target.some((item) => item.toLowerCase() === value.toLowerCase())) {
    target.push(value);
  }
}

close();
updatePeopleSuggestions();
onApply();
```

참여자 Picker에서 `getItems()`는 `participants`를 반환한다. 따라서 `target.push(value)`에서 선택한 사람이 최종 참여자 배열에 들어간다.

`close()`는 `pending`과 검색어를 비우고 메뉴를 숨기며 현재 Picker를 `null`로 만든다. 메뉴 DOM 자체를 삭제하지는 않는다.

### 5. onApply가 선택된 참여자 칩을 그린다

`onApply()`는 앞에서 전달한 `renderEntryPeopleChips()`를 실행한다.

```javascript
function renderEntryPeopleChips() {
  renderChips();
  renderShareChips();
  updatePeopleSuggestions();
}
```

그중 `renderChips()`가 변경된 `participants` 배열을 읽고 `#chips` 안에 김철수 칩을 만든다.

```text
입력창 클릭
→ open()
→ renderOptions()
→ 김철수 체크
→ togglePending()
→ pending에 임시 저장
→ 선택 추가 클릭
→ participants에 김철수 추가
→ close()
→ onApply()
→ renderEntryPeopleChips()
→ renderChips()
→ 화면에 김철수 칩 표시
```

## 삭제 시나리오

삭제는 Picker와 `pending`을 거치지 않는다. `renderChips()`가 참여자 칩을 만들 때 삭제용 `×` 요소와 배열 위치를 함께 넣는다.

```javascript
el.innerHTML = `<i></i>${esc(p)}<span class="x" data-i="${i}">×</span>`;
```

그리고 각 `×`에 다음 클릭 동작을 연결한다.

```javascript
box.querySelectorAll(".x").forEach((x) => x.onclick = () => {
  participants.splice(Number(x.dataset.i), 1);
  renderChips();
  updatePeopleSuggestions();
});
```

김철수 칩의 `×`를 누르면 다음 순서로 이어진다.

```text
김철수 칩의 × 클릭
→ x.onclick
→ data-i로 participants 안의 위치 확인
→ participants.splice()로 즉시 제거
→ renderChips()
→ 변경된 배열 기준으로 칩 전체 다시 생성
→ updatePeopleSuggestions()
→ Picker가 열려 있으면 후보 목록 갱신
```

삭제 후 열린 Picker가 있다면 김철수는 더 이상 선택된 사람이 아니므로 다시 후보로 나타날 수 있다. Picker가 닫혀 있으면 `activePeoplePicker`가 `null`이므로 `updatePeopleSuggestions()`는 아무 일도 하지 않는다.

## 추가와 삭제의 핵심 차이

```text
추가
후보 체크 → pending 임시 저장 → 선택 추가 → participants 추가 → 칩 다시 그리기

삭제
칩의 × 클릭 → participants에서 즉시 제거 → 칩 다시 그리기
```

추가에는 여러 사람을 체크한 뒤 한 번에 확정하기 위한 `pending` 단계가 있다. 삭제는 이미 확정된 한 칩을 대상으로 하므로 `pending` 없이 즉시 배열을 수정한다.

이것으로 01 문서에서 추가 대화를 통해 확인한 Picker의 생성·활성화·후보 표시·추가·삭제 흐름까지 연결된다.
