# 2-1. before READ가 사용자 WHERE 조건을 추가하는 과정

CAP는 OData URL을 DB 조회문 객체인 `req.query`로 바꾼 뒤 실제 DB 조회 전에 다음 Hook을 실행한다.

```javascript
this.before("READ", "Meetings", (req) => {
  if (canAccessAllMeetings(req)) return;
  req.query.where(meetingAccessWhere(req));
});
```

```text
MeetingAdmin
→ Hook에서 return
→ 사용자별 WHERE를 추가하지 않음

일반 MeetingUser
→ meetingAccessWhere(req) 실행
→ req.query.where(...)에 조건 추가
```

`meetingAccessWhere()`는 개념적으로 다음 조건을 만든다.

```sql
(
  owner = 현재 사용자 ID
  OR accessTokens LIKE 현재 사용자 Token 1
  OR accessTokens LIKE 현재 사용자 Token 2
)
```

CQN에서 `{ ref: ["owner"] }`는 DB 컬럼을, `{ val: 값 }`은 비교할 실제 값을 뜻한다. `req.query.where()`는 즉시 DB를 조회하는 것이 아니라 기존 조회문을 수정한다.

```text
요청 도착
→ req.query 생성
→ before READ로 WHERE 추가
→ 수정된 조회문을 HANA에 실행
→ 허용된 Meeting 행만 브라우저에 반환
```

따라서 `renderMeetingListView()`의 화면 필터를 조작해도 권한 없는 행은 볼 수 없다. 그 데이터는 브라우저에 도착하지 않는다.
