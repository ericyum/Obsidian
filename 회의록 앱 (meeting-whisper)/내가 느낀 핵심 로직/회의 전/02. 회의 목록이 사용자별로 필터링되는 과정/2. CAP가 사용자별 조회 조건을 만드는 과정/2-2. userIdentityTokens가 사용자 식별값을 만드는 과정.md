# 2-2. userIdentityTokens가 사용자 식별값을 만드는 과정

`meetingAccessWhere()`는 현재 사용자를 나타내는 여러 문자열을 만들기 위해 다음 함수를 호출한다.

```javascript
userIdentityTokens(req.user)
```

후보값은 다음과 같다.

```text
user.id
attr.email
attr.user_name
attr.name
attr.display_name
given_name + family_name
family_name + given_name
family_name과 given_name 사이에 공백을 둔 형식
```

수집한 값은 `expandAccessTokens()`로 전달된다. 각 값에 `normalizeAccessToken()`을 적용한다.

```text
문자열 변환
→ 앞뒤 공백 제거
→ 소문자화
→ 줄바꿈·%·_ 정리
→ 연속 공백 하나로 축소
→ 최대 160자 제한
```

이메일 Token이면 `@` 앞부분도 추가한다.

```text
user@example.com
→ user@example.com
→ user도 추가
```

`Set`이 중복을 제거한 뒤 배열로 반환한다. 예시는 다음과 같다.

```javascript
[
  "user@example.com",
  "user",
  "염정운",
  "정운 염",
  "염 정운"
]
```

각 값은 다음 검색 조건 하나가 된다.

```javascript
{
  ref: ["accessTokens"]
},
"like",
{
  val: `%\n${token}\n%`
}
```

Token 앞뒤 줄바꿈은 `user`가 `admin-user` 같은 더 긴 문자열의 일부로 우연히 일치하는 일을 줄이는 경계다.
