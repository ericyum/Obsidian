# 1-1. 새 회의록 버튼과 view-entry 화면 전환

## 먼저 결론

사용자가 `+ 새 회의록` 버튼을 누르면 새 HTML 페이지로 이동하는 것이 아니다. 하나의 `index.html` 안에서 목록 영역을 숨기고 새 회의 입력 영역만 보이게 한다.

```text
처음 보이는 영역: view-list
사용자가 new-meeting 클릭
→ app.js의 onclick 실행
→ show("view-entry")
→ view-list 숨김
→ view-entry 표시
```

## 1. 버튼의 출발점은 index.html이다

`app/meeting-ui/index.html`에는 다음 버튼이 있다.

```html
<button class="btn primary sm" id="new-meeting">+ 새 회의록</button>
```

HTML은 버튼의 모양과 ID를 제공한다. 클릭했을 때 무엇을 할지는 `app.js`가 연결한다.

## 2. app.js가 버튼에 클릭 동작을 넣는다

`app/meeting-ui/js/app.js`에는 다음 코드가 있다.

```javascript
$("new-meeting").onclick = () => {
  // 이전 상태 초기화 코드
  show("view-entry");
};
```

여기서 `$()`는 `ui.js`의 DOM 도우미다.

```javascript
export const $ = (id) => document.getElementById(id);
```

따라서 다음 두 표현은 같은 의미다.

```javascript
$("new-meeting")

document.getElementById("new-meeting")
```

`onclick = () => { ... }`는 클릭 즉시 코드를 실행하는 것이 아니다. 나중에 사용자가 이 버튼을 클릭했을 때 실행할 함수를 등록하는 것이다.

## 3. show가 네 화면 중 하나만 남긴다

`show()`는 `app/meeting-ui/js/ui.js`에 있다.

```javascript
export function show(id) {
  ["view-list", "view-entry", "view-recording", "view-result"].forEach((v) => {
    $(v).classList.toggle("hidden", v !== id);
  });
}
```

`show("view-entry")`가 실행되면 각 영역은 다음처럼 처리된다.

| 영역 | `v !== "view-entry"` | 결과 |
|---|---:|---|
| `view-list` | `true` | `hidden` 추가 |
| `view-entry` | `false` | `hidden` 제거 |
| `view-recording` | `true` | `hidden` 추가 |
| `view-result` | `true` | `hidden` 추가 |

즉, `index.html`의 틀과 다른 영역의 DOM은 삭제되지 않는다. CSS의 `hidden` 클래스로 보이는 영역만 바꾼다.

## 정확한 코드 흐름

```text
브라우저가 index.html 로드
→ new-meeting ID를 가진 버튼 DOM 생성
→ app.js 실행
→ $("new-meeting").onclick에 함수 등록

사용자가 + 새 회의록 클릭
→ 등록된 onclick 함수 실행
→ 이전 입력 상태 초기화
→ show("view-entry")
→ ui.js가 네 view의 hidden 상태 변경
→ 새 회의 입력 화면만 보임
```

## 이 시점에 서버로 요청하는가

아니다. 이 과정은 브라우저 안의 JavaScript와 DOM 상태만 바꾼다.

```text
Approuter 요청 없음
CAP 요청 없음
DB 저장 없음
마이크 요청 없음
```
