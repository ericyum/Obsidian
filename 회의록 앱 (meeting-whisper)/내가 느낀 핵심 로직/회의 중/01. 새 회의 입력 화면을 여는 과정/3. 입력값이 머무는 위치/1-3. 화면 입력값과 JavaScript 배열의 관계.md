# 1-3. 화면 입력값과 JavaScript 배열의 관계

## 먼저 결론

새 회의 입력 화면에서 사용자가 값을 입력했다고 곧바로 CAP나 DB에 저장되는 것은 아니다. `회의 시작` 버튼을 누르기 전까지 값은 주로 두 위치에 머문다.

```text
일반 문자·선택 입력
→ index.html의 DOM 입력 요소

참여자·공유자
→ app.js의 participants·sharedWith 배열
→ 화면에는 칩으로 표시
```

## 입력값별 위치

| 사용자가 입력하는 값 | 시작 전 실제 위치 |
|---|---|
| 카테고리 | `#meeting-category`, `#meeting-category-custom` DOM |
| 회의 제목 | `#title` DOM |
| 참여자 | `participants` JavaScript 배열 |
| 공유자 | `sharedWith` JavaScript 배열 |
| 선택한 녹음 파일 | `#audio-file.files[0]` |
| 화자 수 옵션 | `#min-speakers`, `#max-speakers` DOM |
| 녹음 초안 | 아직 없음 |
| CAP Meeting 행 | 아직 없음 |

## 제목과 카테고리는 DOM에서 읽는다

예를 들어 제목은 다음처럼 입력 요소의 현재 값으로 존재한다.

```javascript
$("title").value
```

카테고리는 `selectedMeetingCategory()`가 DOM을 읽어 반환한다.

```javascript
function selectedMeetingCategory() {
  const selected = $("meeting-category")?.value || "";
  if (selected !== CUSTOM_CATEGORY_VALUE) return selected;
  return ($("meeting-category-custom")?.value || "")
    .trim()
    .replace(/\s+/g, " ");
}
```

일반 카테고리를 골랐다면 선택 상자의 값을 반환하고, `기타`를 골랐다면 직접 입력 칸의 값을 정리해 반환한다.

## 참여자와 공유자는 배열이 원본이다

```javascript
let participants = [];
let sharedWith = [];
```

Picker에서 `선택 추가`를 누르면 `participants` 또는 `sharedWith`에 사람이 들어가고, `renderChips()` 또는 `renderShareChips()`가 배열을 화면 칩으로 표현한다.

따라서 칩 HTML이 원본 데이터인 것이 아니다.

```text
원본 상태: participants 배열
화면 표현: renderChips()가 만든 참여자 칩
```

## 파일 선택은 같은 시작 버튼의 의미를 바꾼다

```javascript
function selectedAudioFile() {
  return $("audio-file")?.files?.[0] || null;
}
```

파일을 선택하지 않으면 시작 버튼은 새 녹음을 시작한다. 파일을 선택하면 같은 버튼이 파일 업로드 흐름을 시작한다.

```javascript
function syncFileUploadCta() {
  if (uploadInFlight) return;
  const file = selectedAudioFile();
  setStartButtonLabel(file ? START_FILE_LABEL : START_RECORDING_LABEL);
}
```

즉, 화면에 시작 버튼이 두 개 있는 것이 아니라 `#audio-file`의 현재 상태에 따라 하나의 `#start` 버튼 역할이 달라진다.

## 언제 하나의 초안으로 모이는가

사용자가 파일을 선택하지 않은 상태에서 `회의 시작`을 누르면 다음 단계에서 제목·카테고리·참여자·공유자·옵션을 읽어 `currentDraft`로 복사한다.

```text
현재 단계
DOM 입력값 + JavaScript 배열

다음 단계에서 회의 시작 클릭
→ 값을 한데 모음
→ currentDraft 생성
→ localStorage 저장
```

따라서 1단계의 핵심은 다음과 같다.

> 새 회의 화면은 입력을 받을 준비만 하는 단계이며, 아직 녹음도 서버 저장도 시작되지 않았다.
