# 회의 정보 입력부터 녹음 중 저장 구조까지 — 실제 코드 워크스루

## 이 문서가 따라가는 호출 체인

```text
start.onclick
→ 폼 값을 currentDraft로 복사
→ saveDraftMeta(currentDraft)
→ localStorage
→ createRecorder({ timeslice: 1000, onChunk })
→ getUserMedia()·MediaRecorder
→ recorder.start()
→ MediaRecorder dataavailable
→ app.js의 onChunk callback
→ saveDraftChunk()
→ IndexedDB
→ stop.onclick
→ recorder.stop()
→ 하나의 Blob
→ createJob()
→ POST Meetings → raw binary audio → enqueueTranscription
```

핵심 사실은 `recorder.start()` 시점에는 CAP `Meetings` 행이 없다는 것이다. 서버 행은 마지막 `createJob()` 안에서 처음 만들어진다.

## 단계 1. 시작 버튼이 폼 값을 브라우저 초안으로 복사한다

### 1) 이 단계가 하는 일

세션을 갱신하고 제목·카테고리·참석자·공유자·녹음 옵션을 `currentDraft` 객체에 복사한다.

### 2) 실제 호출부 코드

`app/meeting-ui/js/app.js` 1273~1305행:

`currentDraft`는 서버 DTO가 아니라 브라우저 메모리 객체다. `participants`와 `sharedWith`는 전역 배열의 복사본이고, `sessionId`는 IndexedDB 조각 키의 접두사가 된다.

### 4) 실제 피호출부 코드


### 5) 경계

`createRecorder()`에 1초 timeslice, 마이크 레벨 callback, 음성 조각 callback을 전달한다.

## 단계 2. `createRecorder()`가 마이크와 MediaRecorder를 준비한다

### 1) 이 단계가 하는 일

마이크 권한을 얻고 지원되는 MIME type으로 MediaRecorder를 만든다. 아직 녹음을 시작하지는 않고 제어 객체를 반환한다.

### 2) 실제 호출부 코드

`app/meeting-ui/js/app.js` 1307~1334행:

```javascript
recorder = await createRecorder({
  timeslice: 1000,
  onLevel: (level) => updateMicLevel(level),
  onChunk: async (blob, index) => {
    const draft = currentDraft;
    if (!draft) return;
    const next = {
      ...draft,
      mimeType: recorder?.mimeType || blob.type || "audio/webm",
      durationSeconds: recorder?.elapsed() || draft.durationSeconds,
      chunkCount: Math.max(draft.chunkCount || 0, index + 1),
      lastChunkAt: new Date().toISOString(),
    };
    try {
      await saveDraftChunk(draft.sessionId, index, blob);
      if (!currentDraft || currentDraft.sessionId !== draft.sessionId) return;
      currentDraft = next;
      saveDraftMeta(currentDraft);
    } catch (err) {
      if (!currentDraft || currentDraft.sessionId !== draft.sessionId) return;
      currentDraft = {
        ...currentDraft,
        draftError: err?.message || "녹음 조각 저장 실패",
      };
      saveDraftMeta(currentDraft);
    }
  },
});
```

### 3) 전달되는 인자와 상태

| 인자 | 역할 |
|---|---|
| `timeslice: 1000` | 약 1초마다 `dataavailable` 발생 |
| `onLevel` | 주파수 분석 결과를 UI 파형으로 전달 |
| `onChunk(blob, index)` | 각 음성 Blob 조각을 IndexedDB에 저장 |

### 4) 실제 피호출부 코드

`app/meeting-ui/js/recorder.js` 2~23행:

```javascript
export function pickMimeType() {
  const types = ["audio/webm;codecs=opus", "audio/webm", "audio/mp4"];
  for (const t of types) {
    if (window.MediaRecorder && MediaRecorder.isTypeSupported(t)) return t;
  }
  return "";
}

export async function createRecorder({ onLevel, onChunk, timeslice = 5000 } = {}) {
  if (!navigator.mediaDevices || !window.MediaRecorder) {
    throw new Error("이 브라우저는 녹음을 지원하지 않습니다. 최신 Chrome 또는 Safari를 사용하세요.");
  }

  const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
  const mimeType = pickMimeType();
  const rec = new MediaRecorder(stream, mimeType ? { mimeType } : undefined);
  const chunks = [];

  rec.ondataavailable = (e) => {
    if (!e.data.size) return;
    chunks.push(e.data);
    onChunk && onChunk(e.data, chunks.length - 1);
  };
```

### 5) 경계

`getUserMedia()`에서 **브라우저 JavaScript → 운영체제 마이크 권한/미디어 장치 경계**를 넘는다. 생성된 `MediaStream`과 `MediaRecorder`는 브라우저 메모리에 있다.

### 6) 반환값을 받는 코드

`createRecorder()`가 반환하는 객체가 전역 `recorder`에 저장된다. 이 객체의 `mimeType`, `start`, `pause`, `resume`, `stop`, `elapsed`를 이후 UI handler가 사용한다.

### 7) 다음 단계

초안에 실제 MIME type을 기록한 뒤 `recorder.start()`를 호출한다.

## 단계 3. Recorder가 1초 조각을 메모리와 IndexedDB에 함께 저장한다

### 1) 이 단계가 하는 일

MediaRecorder가 약 1초마다 Blob을 방출한다. Recorder 내부 배열은 최종 Blob 생성을 위해 보관하고, app callback은 같은 Blob을 IndexedDB에 넣어 중단 복구용으로 보관한다.

### 2) 실제 호출부 코드

`app/meeting-ui/js/app.js` 1335~1347행:

```javascript
currentDraft.mimeType = recorder.mimeType;

show("view-recording");
paintLiveTranscript();
$("rec-title").textContent = currentDraft.title || "회의";
$("rec-chips").innerHTML = participants.map((p) => `<span class="chip"><i></i>${esc(p)}</span>`).join("");
$("timer").textContent = "00:00";
$("pause-resume").textContent = "일시정지";
setRecordingStatus(false);
recorder.start();
startLiveTranscript();
timerInt = setInterval(updateRecordingTimer, 500);
initMicGraph();
```

### 3) 전달되는 인자와 상태

`recorder.start()`에는 UI가 직접 인자를 넘기지 않지만, `createRecorder()` closure 안에는 `timeslice=1000`, `onChunk`, `chunks`, 실제 MediaRecorder `rec`가 캡처되어 있다.

### 4) 실제 피호출부 코드

`app/meeting-ui/js/recorder.js` 51~58행:

```javascript
return {
  mimeType: mimeType || "audio/webm",
  start() {
    rec.start(timeslice);
    state = "recording";
    segmentStartMs = Date.now();
    raf = requestAnimationFrame(loop);
  },
```

조각이 나오면 단계 2에서 등록한 다음 코드가 실행된다.

```javascript
rec.ondataavailable = (e) => {
  if (!e.data.size) return;
  chunks.push(e.data);
  onChunk && onChunk(e.data, chunks.length - 1);
};
```

`onChunk`가 호출하는 `saveDraftChunk()`의 실제 구현은 `app/meeting-ui/js/drafts.js` 54~57행이다.

```javascript
export async function saveDraftChunk(sessionId, index, blob) {
  await withStore("readwrite", (store) => {
    store.put({ key: `${sessionId}:${index}`, sessionId, index, blob });
  });
}
```

### 5) 경계

- `chunks.push(e.data)`: MediaRecorder → JavaScript heap
- `store.put(...)`: JavaScript → IndexedDB 영속 저장
- `saveDraftMeta(currentDraft)`: 갱신된 조각 수·길이 → localStorage

서버 경계는 아직 넘지 않는다.

### 6) 반환값을 받는 코드

IndexedDB transaction 완료 후 `onChunk`가 `currentDraft = next`로 갱신하고 메타데이터를 다시 localStorage에 저장한다.

### 7) 다음 단계

녹음 중에는 같은 과정이 반복된다. 사용자가 일시정지하면 Recorder 시간 누적과 SpeechRecognition 중지가 함께 일어난다.

## 단계 5. 중단된 페이지는 IndexedDB 조각을 다시 합칠 수 있다

### 1) 이 단계가 하는 일

홈 화면이 localStorage 메타를 발견하면 IndexedDB에 실제 조각이 있는지 확인하고 복구 UI를 표시한다.

### 2) 실제 호출부 코드

`app/meeting-ui/js/app.js` 476~488행:

```javascript
async function paintDraftBanner() {
  const box = $("draft-banner");
  const meta = getDraftMeta();

    box.classList.add("hidden");
    box.innerHTML = "";
```

### 3) 전달되는 인자와 상태

`meta.sessionId`가 IndexedDB 행을 고르는 기준이다.

### 4) 실제 피호출부 코드

`app/meeting-ui/js/drafts.js` 60~77행:

```javascript
export async function loadDraftChunks(sessionId) {
  const db = await openDB();
  return new Promise((resolve, reject) => {
    const tx = db.transaction(STORE, "readonly");
    const store = tx.objectStore(STORE);
    const req = store.getAll();
    req.onsuccess = () => {
      const rows = req.result
        .filter((row) => row.sessionId === sessionId)
        .sort((a, b) => a.index - b.index);
      db.close();
      resolve(rows.map((row) => row.blob));
    };
    req.onerror = () => {
      db.close();
      reject(req.error);
    };
  });
}
```

### 5) 경계

**IndexedDB → JavaScript Blob 배열 경계**다.

### 6) 반환값을 받는 코드

복구 업로드에서는 반환 조각을 하나의 Blob으로 합친다.

## 단계 7. `createJob()`에서 처음 CAP 회의가 생긴다

### 1) 이 단계가 하는 일

최종 Blob과 초안 메타를 서버의 회의 행·음성·dispatch 큐로 옮긴다.

### 2) 실제 호출부 코드

`app/meeting-ui/js/app.js` 1394~1421행:

```javascript
resetResultView();
show("view-result");
const speakerBounds = {
  minSpeakers: currentDraft?.minSpeakers || null,
  maxSpeakers: currentDraft?.maxSpeakers || null,
};
const transcriptionOptions = {
  diarize: Boolean(currentDraft?.diarize),
};
try {
  await ensureFreshSession("recording-upload");
  currentJob = await createJob(
    blob,
    $("title").value.trim(),
    participants,
    ext,
    duration,
    speakerBounds,
```

### 3) 전달되는 인자와 상태

- `blob`: 전체 녹음
- 제목·카테고리·참석자·공유자
- `duration`: pause를 제외한 녹음 시간
- 화자 옵션: 호출부에는 있지만 CAP 구현에서 현재 강제로 비활성화

### 4) 실제 피호출부 코드

`app/meeting-ui/js/api.js` 425~445행:

```javascript
export async function createJob(blob, title, participants, ext, duration, speakerBounds = {}, sharedWith = [], transcriptionOptions = {}, category = "") {
  const diarize = false;
  if (useCapApi()) {
    const meeting = await requestJson("/api/Meetings", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        title: title || "",
        category: category || "",
        participants: JSON.stringify(participants || []),
        sharedWith: JSON.stringify(sharedWith || []),
        durationSec: Math.round(duration || 0),
        minSpeakers: null,
        maxSpeakers: null,
        diarize,
      }),
    });
    const meetingId = meeting.ID;
    await uploadCapAudio(meetingId, blob, ext);
    await postAction("enqueueTranscription", { meetingId });
    return meetingId;
  }
```

### 5) 경계

여기서 처음으로 세 서버 경계를 순서대로 넘는다.

1. JSON HTTP → CAP `Meetings`/HANA
2. raw binary HTTP → CAP/Object Store 또는 AudioObjects
3. JSON action HTTP → `TranscriptionDispatches`

### 6) 반환값을 받는 코드

`createJob()`은 `meetingId`만 반환한다. 호출부가 이를 `currentJob`에 넣고 URL을 회의 상세 route로 바꾼 뒤 polling을 시작한다.

### 7) 다음 단계

회의 후 문서 `01. 회의 종료부터 Worker 전사 시작까지.md`가 `uploadCapAudio()`의 Express route부터 Worker 실행까지 이어서 설명한다.

## 최종 저장 위치 표

| 데이터 | 녹음 중 | 중지 후 `createJob()` 성공 |
|---|---|---|
| 회의 메타 | JS + localStorage | HANA Meetings |
| 음성 | JS chunks + IndexedDB | Object Store 우선, DB fallback |
| 임시 전사 | JS + localStorage `liveText` | 전송되지 않음 |
| 전사 작업 | 없음 | HANA TranscriptionDispatches |
