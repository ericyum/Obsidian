# 4-1. timeslice와 dataavailable로 음성 조각이 생기는 과정

## 실제 녹음 시작

```javascript
recorder.start();
```

프로젝트의 `recorder.start()` 안에서는 다음 코드가 실행된다.

```javascript
rec.start(timeslice);
state = "recording";
segmentStartMs = Date.now();
```

`app.js`가 `createRecorder()`에 `timeslice: 1000`을 전달했으므로 브라우저 MediaRecorder는 대략 1초마다 현재 음성 데이터를 내보낸다.

## dataavailable 이벤트

```javascript
rec.ondataavailable = (e) => {
  if (!e.data.size) return;
  chunks.push(e.data);
  onChunk && onChunk(e.data, chunks.length - 1);
};
```

```text
마이크 소리
→ MediaRecorder가 인코딩
→ 약 1초마다 dataavailable
→ e.data에 Blob 조각
```

크기가 0인 조각은 무시한다. 정상 조각은 먼저 `recorder.js` 내부의 `chunks` 배열에 넣는다.

## 메모리 chunks의 목적

이 배열은 정상적으로 녹음을 종료할 때 모든 조각을 하나의 최종 음성으로 합치기 위한 것이다.

```text
chunks[0]
chunks[1]
chunks[2]
...
→ recorder.stop()
→ new Blob(chunks)
```

그다음 `onChunk(blob, index)` callback을 불러 같은 조각을 `app.js`로 넘긴다. 여기서 `index`는 조각의 순서를 나타낸다.

## app.js에는 별도의 음성 chunks 배열이 없다

`event.data`가 `chunks.push()`와 `onChunk()` 양쪽으로 전달되므로 두 개의 JavaScript 배열에 저장된다고 오해하기 쉽다. 실제로 배열은 `recorder.js` 내부의 `chunks` 하나뿐이다.

`app.js`가 전달한 `onChunk()`는 같은 Blob을 다른 배열에 넣는 함수가 아니라 `saveDraftChunk()`를 호출해 IndexedDB에 저장하는 callback이다.

```javascript
onChunk: async (blob, index) => {
  const draft = currentDraft;
  if (!draft) return;

  await saveDraftChunk(draft.sessionId, index, blob);
  // currentDraft와 localStorage 메타데이터 갱신
}
```

따라서 하나의 `event.data`는 다음 두 저장 경로로 갈라진다.

```text
MediaRecorder의 event.data
├─ chunks.push(event.data)
│  → recorder.js의 JavaScript 메모리 배열
│  → 정상 종료 때 new Blob(chunks) 생성
│
└─ onChunk(event.data, index)
   → app.js callback
   → saveDraftChunk()
   → IndexedDB의 chunks object store
   → 페이지 종료 후 복구
```

두 곳에서 `chunks`라는 이름이 등장하지만 서로 다른 대상이다.

```text
recorder.js의 chunks
= JavaScript 메모리 배열

drafts.js의 STORE = "chunks"
= IndexedDB 내부 저장소 이름
```

정상 종료용 메모리 배열과 비정상 종료 복구용 브라우저 DB에 같은 음성 조각을 이중 보관하는 구조다.
