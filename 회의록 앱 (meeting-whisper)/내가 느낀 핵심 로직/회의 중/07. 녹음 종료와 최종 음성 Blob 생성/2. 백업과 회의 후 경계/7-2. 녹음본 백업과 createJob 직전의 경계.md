# 7-2. 녹음본 백업과 createJob 직전의 경계

## 확장자 결정

```javascript
const ext = recorder.mimeType.includes("mp4") ? "mp4" : "webm";
```

녹음기가 사용한 MIME type을 기준으로 사용자 백업과 업로드에 사용할 확장자를 정한다.

## 사용자에게 로컬 백업 여부를 묻는다

```javascript
await promptRecordingBackup({ blob, ext, title });
```

사용자가 다운로드를 선택하면 날짜와 제목으로 파일명을 만들고 저장 위치 선택 또는 일반 다운로드를 시도한다. 저장이 실패하거나 취소되면 다시 시도할지 묻지만, 저장하지 않고도 서버 전사 처리는 계속할 수 있다.

이 백업은 IndexedDB 복구 조각과 목적이 다르다.

```text
IndexedDB 조각
→ 비정상 중단 복구용 내부 데이터

로컬 백업 파일
→ 사용자가 이후 확인·보관·재전사할 수 있는 완성 음원
```

## 회의 중의 마지막 지점

백업 질문이 끝난 시점에는 다음 값들이 준비되어 있다.

```text
blob       최종 음성
ext        webm 또는 mp4
duration   실제 녹음 시간
currentDraft 회의 입력 정보
```

## 회의 후의 시작

다음 코드부터 CAP와 서버 저장으로 넘어간다.

```javascript
await ensureFreshSession("recording-upload");
currentJob = await createJob(blob, ...);
```

```text
회의 중 마지막
→ 최종 Blob 확보와 선택적 로컬 백업

회의 후 시작
→ 세션 재확인
→ Meetings 행 생성
→ raw binary 음성 업로드
→ enqueueTranscription
```

정상 업로드가 성공한 뒤에야 `deleteDraft(sessionId)`로 localStorage와 IndexedDB 복구 데이터를 지운다. 실패하면 `pendingUpload`에 Blob과 메타데이터를 보관하여 다시 업로드할 수 있게 한다.
