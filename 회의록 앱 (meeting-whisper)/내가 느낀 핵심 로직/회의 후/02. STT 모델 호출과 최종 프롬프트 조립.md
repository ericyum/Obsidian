# STT 모델 호출과 최종 프롬프트 조립

## 이 문서의 질문

현재 배포에서 어떤 STT 엔진을 사용하고, 여러 코드 조각이 어떻게 합쳐져 실제 모델에 전달되는 하나의 프롬프트와 요청 payload가 되는가?

## 먼저 기억할 결론

현재 CF 배포 설정의 최종 STT 경로는 로컬 Whisper 모델이 아니라 다음 조합이다.

- 실행 서비스: Python Transcription Worker
- 엔진 선택: `TRANSCRIPTION_ENGINE=aicore`
- 모델 이름: `AICORE_STT_MODEL=gemini-2.5-flash`
- 호출 방식: SAP AI Core Orchestration의 direct completion payload

프로젝트 이름과 대체 코드에는 Whisper가 남아 있지만, **현재 `mta.yaml`의 운영 설정**은 AI Core의 멀티모달 모델에 음성 파일과 전사 지시문을 함께 보내는 경로다. 로컬에서는 설정에 따라 faster-whisper 또는 WhisperX 경로도 사용할 수 있다.

## 1. Worker가 엔진을 고르는 위치

`run_transcription()`은 `settings.transcription_engine`을 보고 분기한다.

| 설정 | 실행 함수 | 특징 |
|---|---|---|
| `aicore`, `aicore-stt` | `run_aicore_transcription()` | 음성과 프롬프트를 AI Core 모델에 전달 |
| `whisperx` | WhisperX 전사·정렬, 조건부 화자 분리 | 로컬 Python 모델 |
| 그 외 기본 `fast` | faster-whisper | 로컬 Python 모델 |

운영 `mta.yaml`은 `aicore`로 고정한다. 또한 UI의 CAP 경로는 현재 `diarize=false`를 강제하므로 운영 주 경로에서 WhisperX 화자 분리까지 가지 않는다.

## 2. 한 번에 보낼지 청크로 나눌지 판단한다

AI Core STT 함수는 실제 또는 기대 녹음 길이와 파일 크기를 확인한다.

- 기본 청크 길이: 720초, 즉 12분
- inline 크기 기준: 24MiB
- 전체 허용 최대 크기: 150MiB

길이가 720초를 넘거나 파일이 inline 기준을 넘으면 음성을 16kHz, mono, 16-bit WAV 청크로 나눈다. 청크들은 겹치지 않는 연속 구간이며 각 청크마다 모델을 따로 호출한다.

미디어 길이를 읽지 못해도 UI가 보낸 `expectedDurationSec`가 720초를 넘으면 청크 경로를 선택한다. ffprobe를 먼저 사용하고 실패하면 PyAV로 길이를 확인한다.

## 3. 기본 프롬프트 본문

`AICORE_STT_PROMPT` 환경변수가 없으면 다음 의미의 영문 지시문이 기본 본문이 된다.

```text
첨부된 회의 음성을 원래 언어로 전사한다.
language와 segments 배열을 가진 JSON만 반환한다.
각 segment는 start, end, text, speaker를 가진다.
한국어 음성이면 한국어 텍스트를 쓴다.
요약하거나 없는 말을 만들지 않는다.
시간은 첨부 음성 시작부터의 총 초 숫자여야 한다.
MM:SS 또는 M.SSS 형식을 쓰지 않는다.
한 단어당 한 segment가 아니라 문장 크기로 나눈다.
마크다운과 설명 없이 완전한 JSON 하나만 반환한다.
정확한 시간이 불가능하면 의미 있는 전사 덩어리를 만들고 시간은 0으로 둔다.
```

요구하는 예시 구조는 다음과 같다.

```json
{
  "language": "ko",
  "segments": [
    { "start": 0.0, "end": 0.0, "text": "...", "speaker": null }
  ]
}
```

환경변수로 기본 본문을 바꿀 수 있지만, 뒤에서 붙는 길이·청크·재시도 문장은 계속 조립된다.

## 4. 음성 길이 문장이 붙는다

유효한 길이를 알면 기본 프롬프트 뒤에 다음 정보가 추가된다.

```text
첨부 음성 길이는 정확히 N초이다.
모든 start/end는 0과 N 사이여야 한다.
4분 2.5초는 242.5이지 402.5가 아니다.
```

이 문장은 실제로 발생했던 `402.5` 같은 compact MMSS 오해를 줄이고, 이후 검증 코드가 판단할 경계를 모델에 미리 알려 준다.

## 5. 청크 정보가 붙는다

청크 호출이면 다음 정보가 추가된다.

```text
전체 중 i / total 번째 음성 청크이다.
원본 녹음에서 이 청크는 chunkStartSec초에 시작한다.
반환 시간은 원본 전체가 아니라 현재 첨부 청크를 기준으로 한다.
```

여기서 중요한 설계는 모델이 매 청크에 대해 0부터 시작하는 상대 시간을 반환하게 한다는 것이다. 모델 응답을 합칠 때 Python 코드가 `chunk.start_sec`를 더해 원본 회의의 절대 시간으로 바꾼다.

## 6. 검증 실패 재시도 문장이 붙는다

첫 응답이 JSON이 아니거나 시간 범위를 어기는 등 검증에 실패하면 같은 청크를 다시 호출한다. 두 번째 프롬프트에는 직전 오류를 최대 400자까지 넣는다.

```text
이전 응답은 다음 이유로 유효하지 않았다: {구체적인 오류}.
그 오류를 정확히 고친다.
모든 JSON 배열과 객체를 닫고, 시간은 단조 증가하게 하며,
완전한 JSON 객체만 반환한다.
```

현재 배포의 `AICORE_STT_MAX_ATTEMPTS`는 2다. 따라서 기본 호출 1회와 오류 피드백을 포함한 재호출 1회가 한 청크의 1차 한도다. 그래도 실패하면 더 작은 음성 청크로 나누는 fallback이 별도로 동작한다.

## 7. 최종 요청에서 텍스트와 음성이 만나는 방식

완성된 프롬프트 문자열 뒤에 음성 파일을 Base64 data URI로 바꾸어 **하나의 user message** 안에 넣는다.

```text
role: user
content:
  1. type=text, text=완성된 STT 프롬프트
  2. type=file,
     file_data=data:{mimeType};base64,{음성 데이터}
     filename={청크 파일명}
```

그리고 AI Core payload는 대략 다음 구조가 된다.

```text
config.modules.prompt_templating
  prompt.template = [위 user message]
  prompt.response_format = text
  model.name = gemini-2.5-flash
  model.version = latest
messages_history = []
```

STT 경로에는 별도의 system message가 없다. 전사 규칙, 출력 형식, 길이, 청크 문맥, 재시도 오류가 모두 하나의 user 텍스트로 합쳐진다.

## 8. “원시 바이너리 업로드”와 “AI Core Base64”는 다른 경계다

브라우저에서 CAP로 업로드할 때는 `/api-binary`가 Blob 스트림을 받아 Object Store로 넘기므로 Base64 JSON을 피한다. 그러나 Worker가 AI Core 멀티모달 completion에 음성을 넣을 때는 AI Core 요청 형식에 맞춰 각 파일을 `data:...;base64,...`로 인라인한다.

즉 다음 두 문장은 동시에 참이다.

- 사용자 업로드 경로는 원시 바이너리 스트리밍으로 최적화되어 있다.
- STT 모델 호출 경계에서는 선택한 음성 또는 WAV 청크를 Base64 data URI로 만든다.

청크 크기와 24MiB 기준은 이 AI Core 인라인 payload의 크기·메모리 부담을 통제하는 역할도 한다.

## 9. 프롬프트에 들어가지 않는 정보

현재 STT 기본 프롬프트에는 다음 정보가 들어가지 않는다.

- 회의 제목
- 카테고리
- 참석자 이름
- 공유자
- 회의 중 임시 전사 `liveText`
- 사용자 정의 용어 사전

STT 모델은 음성과 공통 전사 규칙, 음성 길이와 청크 문맥만 받는다. 카테고리와 참석자는 이후 요약 프롬프트에서 사용된다.

## 내가 기억할 핵심

> 운영 STT 프롬프트는 기본 전사·JSON 규칙에 정확한 음성 길이, 청크 번호와 원본 시작 위치, 필요하면 직전 검증 오류를 차례로 붙여 만든다. 이 텍스트와 Base64 음성 파일이 한 user message가 되어 AI Core의 `gemini-2.5-flash`로 전달된다.
