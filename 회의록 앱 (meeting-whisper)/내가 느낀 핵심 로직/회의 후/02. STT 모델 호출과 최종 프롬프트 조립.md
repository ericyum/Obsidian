# STT 모델 호출과 최종 프롬프트 조립 — 실제 코드 워크스루

## 먼저 바로잡을 핵심

이 프로젝트는 이름에 Whisper가 있지만, **현재 `mta.yaml`의 배포 설정은 `TRANSCRIPTION_ENGINE: aicore`**다. 따라서 배포 주 경로는 로컬 Whisper 모델이 아니라 SAP AI Core의 `gemini-2.5-flash` 모델을 호출한다. 코드에는 `faster-whisper`와 `WhisperX` 경로도 남아 있고 설정을 바꾸면 사용할 수 있다.

현재 배포 주 경로:

```text
_build_transcript()
  → run_transcription()
  → engine == "aicore"
  → _transcribe_aicore()
  → run_aicore_transcription()
  → 단일 또는 청크 경로 선택
  → _aicore_stt_body()
  → 기본 프롬프트 + 길이 + 청크 + 재시도 문구 조립
  → 오디오를 data URI로 첨부
  → AI Core completion endpoint POST
```

---

## 1단계. Worker가 임시 오디오 파일과 설정을 `run_transcription()`에 넘긴다

### 1. 이 단계가 하는 일

CAP에서 받은 오디오를 임시 파일로 준비한 다음, 동기식 모델 호출을 별도 thread에서 실행한다.

### 2. 실제 호출자 코드

`workers/transcription/app/main.py`:

```python
async def _build_transcript(
    payload: TranscriptionRequest,
    audio: dict,
    tmp_dir: str | None,
    progress_callback=None,
) -> dict:
    settings = get_settings()
    settings = settings.model_copy(update={
        "diarize": settings.diarize if payload.diarize is None else payload.diarize,
        "whisper_model_size": payload.whisper_model_size or settings.whisper_model_size,
    })
    tmp_path, audio_size = await _prepare_temp_audio(audio, tmp_dir)
    try:
        if settings.worker_mock_transcript:
            return _mock_transcript(payload, audio, audio_size, settings.whisper_language)

        return await asyncio.to_thread(
            run_transcription,
            str(tmp_path),
            settings=settings,
            expected_duration_sec=payload.expected_duration_sec,
            min_speakers=payload.min_speakers,
            max_speakers=payload.max_speakers,
            progress_callback=progress_callback,
        )
    finally:
        _unlink_temp_audio(tmp_path)
```

### 3. 전달되는 값과 상태

- `audio_path`: Worker 임시 디렉터리의 실제 오디오 파일
- `settings`: 환경변수와 기본값을 합친 Pydantic 설정
- `expected_duration_sec`: UI가 저장한 회의 길이
- 화자 수와 diarization 옵션
- `progress_callback`: 처리 진척을 CAP heartbeat로 전달하는 callback

### 4. 실제 피호출자 코드

`workers/transcription/app/transcriber.py`:

```python
def run_transcription(
    audio_path: str,
    *,
    settings: Settings,
    expected_duration_sec: float | None = None,
    min_speakers: int | None = None,
    max_speakers: int | None = None,
    progress_callback: Callable[[float, float], None] | None = None,
) -> dict[str, Any]:
    engine = (settings.transcription_engine or "fast").lower()
    if engine in {"aicore", "aicore-stt", "aicore_stt"}:
        transcript = _transcribe_aicore(
            audio_path,
            settings=settings,
            expected_duration_sec=expected_duration_sec,
            progress_callback=progress_callback,
        )
    elif engine == "whisperx":
        transcript = _transcribe_and_align(
            audio_path,
            model_size=settings.whisper_model_size,
            language=settings.whisper_language,
            device=settings.whisper_device,
            compute_type=settings.whisper_compute_type,
        )
    else:
        transcript = _transcribe_fast(
            audio_path,
            model_size=settings.whisper_model_size,
            language=settings.whisper_language,
            device=settings.whisper_device,
            compute_type=settings.whisper_compute_type,
            beam_size=settings.fast_whisper_beam_size,
            vad_filter=settings.fast_whisper_vad_filter,
            condition_on_previous_text=settings.fast_whisper_condition_on_previous_text,
            progress_callback=progress_callback,
        )
```

### 5. 경계

비동기 HTTP Worker event loop → 별도 thread의 CPU/네트워크 모델 처리 경계다. 임시 파일은 `finally`에서 성공·실패와 무관하게 삭제된다.

### 6. 반환을 받는 코드

선택된 엔진은 모두 공통 transcript dict를 반환한다. `_build_transcript()`가 이를 받고, 앞 문서의 `_process_transcription()`으로 돌려준다.

### 7. 다음 단계

현재 배포에서는 `engine == "aicore"`이므로 `_transcribe_aicore()`로 간다.

## 3단계. 전체 오디오 호출인지 청크 호출인지 결정한다

### 1. 이 단계가 하는 일

너무 큰 파일은 즉시 거부하고, 길거나 inline 기준을 넘는 오디오는 여러 청크로 나눈다.

### 2. 실제 호출자 코드

```python
return run_aicore_transcription(
    audio_path,
    settings=settings,
    expected_duration_sec=expected_duration_sec,
    progress_callback=progress_callback,
)
```

### 3. 전달되는 값과 상태

- 실제 파일 크기
- 오디오에서 측정한 길이
- 회의 메타데이터의 예상 길이
- 청크 길이와 inline 최대 byte 설정

### 4. 실제 피호출자 코드

`workers/transcription/app/aicore_stt.py`:

```python
def run_aicore_transcription(
    audio_path: str,
    *,
    settings: Settings,
    expected_duration_sec: float | None = None,
    progress_callback=None,
) -> dict[str, Any]:
    path = Path(audio_path)
    if not path.exists():
        raise RuntimeError(f"audio file does not exist: {audio_path}")

    max_bytes = settings.aicore_stt_max_audio_bytes
    file_size = path.stat().st_size
    if max_bytes and max_bytes > 0 and file_size > max_bytes:
        raise RuntimeError(
            f"audio file is {file_size} bytes, larger than AICORE_STT_MAX_AUDIO_BYTES={max_bytes}"
        )

    measured_duration_sec = _audio_duration_sec(path)
    duration_sec = _duration_hint(measured_duration_sec, expected_duration_sec)
    if _should_chunk_audio(
        path,
        measured_duration_sec,
        settings,
        expected_duration_sec=expected_duration_sec,
    ):
        return _run_chunked_aicore_transcription(
            path,
            settings=settings,
            duration_sec=duration_sec,
            progress_callback=progress_callback,
        )

    transcript = _run_single_aicore_transcription(
        path,
        settings=settings,
        duration_sec=duration_sec,
    )
    if progress_callback:
        progress_callback(duration_sec or 1.0, duration_sec or 1.0)
    return transcript
```

### 5. 경계

Worker 임시 파일과 `ffprobe`/파일 메타데이터를 읽는 로컬 파일 경계다. 청크 경로는 `ffmpeg`로 임시 조각들을 만든다.

### 6. 반환을 받는 코드

단일 경로는 transcript 하나를 반환한다. 청크 경로는 각 청크 transcript를 받은 뒤 병합하여 같은 형태의 transcript 하나를 반환한다.

### 7. 다음 단계

각 단일/청크 호출은 `_run_single_aicore_transcription()`에서 최종 request body를 만든다.

## 4단계. 모델 호출 시도마다 최종 프롬프트를 조립한다

### 1. 이 단계가 하는 일

고정된 기본 지시문에 현재 오디오 길이, 현재 청크 위치, 이전 응답의 검증 오류를 조건부로 이어 붙인다.

### 2. 실제 호출자 코드

`workers/transcription/app/aicore_stt.py`:

```python
for attempt in range(1, max_attempts + 1):
    body = _aicore_stt_body(
        path,
        settings,
        duration_sec=duration_sec,
        chunk_index=chunk_index,
        total_chunks=total_chunks,
        chunk_start_sec=chunk_start_sec,
        retry_attempt=attempt,
        validation_error=str(last_error) if last_error else None,
    )
```

### 3. 전달되는 값과 상태

- `settings.aicore_stt_prompt`: 있으면 기본 문구 전체를 대체하는 override
- `duration_sec`: 현재 첨부 오디오의 정확한 길이
- `chunk_index`, `total_chunks`, `chunk_start_sec`: 청크일 때만 존재
- `retry_attempt`, `validation_error`: 이전 모델 응답이 잘못됐을 때만 존재

### 4. 실제 피호출자 코드 — 기본 프롬프트 원문

```python
model = settings.aicore_stt_model
prompt = settings.aicore_stt_prompt or (
    "Transcribe the attached meeting audio in its original language. "
    "Return JSON only with this shape: "
    '{"language":"ko","segments":[{"start":0.0,"end":0.0,"text":"...","speaker":null}]}. '
    "Use Korean text when the audio is Korean. Do not summarize. Do not invent words. "
    "Use elapsed seconds from the start of the attached audio for start and end. "
    "Timestamps must be JSON numbers in total seconds, never MM:SS or M.SSS. "
    "Keep segments sentence-sized instead of returning one segment per word. "
    "Return one complete valid JSON object with no markdown or explanation. "
    "If exact timestamps are unavailable, return coherent transcript chunks and set timestamps to 0."
)
```

한국어로 뜻을 풀면 다음 요구다.

- 원래 언어로 회의 오디오를 전사한다.
- 요약하거나 말을 만들어내지 않는다.
- `language`와 `segments[]`를 가진 JSON 하나만 반환한다.
- 시간은 `MM:SS`가 아니라 전체 초 단위 숫자로 쓴다.
- 한 단어당 한 segment가 아니라 문장 크기로 나눈다.
- 정확한 시간이 없으면 일관된 transcript 조각과 0 timestamp를 사용한다.

### 5. 경계

여기까지는 전부 Worker 메모리 안의 Python 문자열 조립이다. 아직 모델 HTTP 요청은 나가지 않았다.

### 6. 반환을 받는 코드

조립된 `prompt`는 같은 함수 아래에서 AI Core request body의 text content로 들어간다.

### 7. 다음 단계

길이·청크·재시도 조건이 있으면 기본 prompt 뒤에 추가 문장이 붙는다.

## 5단계. 길이·청크·재시도 문구가 조건부로 합쳐진다

### 1. 이 단계가 하는 일

모델의 timestamp 착각과 불완전 JSON을 줄이기 위해 이번 호출의 구체적인 제약을 추가한다.

### 2. 실제 호출자 코드

바로 위에서 만든 `prompt` 변수를 그대로 이어 쓴다.

### 3. 전달되는 값과 상태

각 조건이 없으면 해당 문구도 붙지 않는다. 따라서 “최종 프롬프트”는 호출마다 달라질 수 있다.

### 4. 실제 피호출자 코드

```python
duration_limit = _positive_duration(duration_sec)
if duration_limit:
    prompt = (
        f"{prompt} The attached audio duration is exactly {duration_limit:g} seconds. "
        f"Every start and end value must be between 0 and {duration_limit:g}. "
        "For example, 4 minutes 2.5 seconds must be returned as 242.5, never 402.5."
    )
if chunk_index and total_chunks:
    prompt = (
        f"{prompt} This is audio chunk {chunk_index} of {total_chunks}, "
        f"starting at {chunk_start_sec or 0.0:.1f} seconds in the original recording. "
        "Return timestamps relative to this attached chunk, not the original recording."
    )
if retry_attempt > 1:
    error_detail = _truncate(str(validation_error or "unknown validation error"), 400)
    prompt = (
        f"{prompt} A previous response was invalid: {error_detail}. "
        "Correct that exact error. Carefully close every JSON array and object, "
        "keep timestamps monotonic, and return only the complete JSON object."
    )
```

### 5. 경계

아직 Python 문자열 경계다. 중요한 점은 이 조립이 여러 파일의 임의 문장을 마구 수집하는 구조가 아니라, **이 함수 안에서 네 조각**을 명확한 순서로 합치는 구조라는 것이다.

```text
1. 환경변수 override 또는 기본 prompt
2. 오디오 길이 제약
3. 청크 위치·상대 timestamp 지시
4. 이전 검증 오류를 고치라는 재시도 지시
```

### 6. 반환을 받는 코드

완성된 문자열은 오디오 data URI와 함께 request JSON으로 포장된다.

### 7. 다음 단계

AI Core orchestration 형식의 body가 생성된다.

## 6단계. 프롬프트와 오디오가 하나의 AI Core request body가 된다

### 1. 이 단계가 하는 일

텍스트 지시문과 오디오 파일을 같은 user message content 배열에 넣는다.

### 2. 실제 호출자 코드

위 `_aicore_stt_body()`의 마지막 부분이다.

### 3. 전달되는 값과 상태

- `prompt`: 앞 단계의 최종 문자열
- `file_data`: `data:{mime};base64,...` 형식의 오디오
- `model`: `settings.aicore_stt_model`

### 4. 실제 피호출자 코드

```python
mime_type = _mime_type_for_path(path)
file_data = f"data:{mime_type};base64,{base64.b64encode(path.read_bytes()).decode('ascii')}"

return {
    "config": {
        "modules": {
            "prompt_templating": {
                "prompt": {
                    "template": [
                        {
                            "role": "user",
                            "content": [
                                {"type": "text", "text": prompt},
                                {
                                    "type": "file",
                                    "file": {
                                        "file_data": file_data,
                                        "filename": path.name,
                                    },
                                },
                            ],
                        }
                    ],
                    "defaults": {},
                    "response_format": {"type": "text"},
                },
                "model": {
                    "name": model,
                    "version": "latest",
                },
            }
        }
    },
    "messages_history": [],
}
```

### 5. 경계

여기서는 raw binary 업로드와 달리 Worker가 AI Core에 보낼 때 오디오를 Base64 data URI로 만든다. 청킹과 inline 최대 크기 제한이 이 메모리·payload 부담을 제어한다.

### 6. 반환을 받는 코드

`_run_single_aicore_transcription()`의 `body` 변수에 완성된 dict가 돌아온다.

### 7. 다음 단계

그 dict를 AI Core completion endpoint에 HTTP POST한다.

## 7단계. 모델 호출 응답을 transcript JSON으로 변환한다

### 1. 이 단계가 하는 일

AI Core에 request를 보내고, 모델의 text content에서 JSON transcript를 추출한다.

### 2. 실제 호출자 코드

```python
body = _aicore_stt_body(
    path,
    settings,
    duration_sec=duration_sec,
    chunk_index=chunk_index,
    total_chunks=total_chunks,
    chunk_start_sec=chunk_start_sec,
    retry_attempt=attempt,
    validation_error=str(last_error) if last_error else None,
)
started_at = time.time()
```

### 3. 전달되는 값과 상태

인증 token과 resource group은 런타임 설정에서 header로 들어간다. 이 문서에는 실제 자격증명이나 배포 식별값을 적지 않는다.

### 4. 실제 피호출자 코드

```python
with httpx.Client(timeout=settings.aicore_stt_request_timeout_sec) as client:
    response = client.post(
        endpoint,
        headers={
            "authorization": f"Bearer {token}",
            "content-type": "application/json",
            "AI-Resource-Group": config["resource_group"],
        },
        json=body,
    )
finished_at = time.time()

response_text = response.text
if response.status_code >= 400:
    raise RuntimeError(
        f"AI Core STT failed with {response.status_code}: {_aicore_error_message(response_text)}"
    )

data = _parse_json(response_text)
content = _extract_aicore_content(data)
try:
    transcript = content_to_transcript(
        content,
        language=settings.whisper_language,
        duration_sec=duration_sec,
        engine="aicore",
        model=settings.aicore_stt_model,
    )
```

### 5. 경계

Worker process → AI Core HTTPS → 생성 모델 → Worker process 경계다.

### 6. 반환을 받는 코드

`content_to_transcript()`가 검증 가능한 dict를 만들면 usage metadata를 붙인 뒤 반환한다. 잘못된 응답이면 다음 시도에서 오류 내용이 5단계의 재시도 프롬프트에 포함된다.

### 7. 다음 단계

다음 문서는 모델 응답의 JSON fence 제거, timestamp 교정, segment 정규화, 재귀 분할, 청크 병합, 최종 저장 전 검증을 실제 코드로 따라간다.

## 예시로 보는 최종 프롬프트의 조립 형태

240초짜리 전체 오디오의 첫 시도라면:

```text
[기본 prompt]
+ "The attached audio duration is exactly 240 seconds ..."
```

전체 녹음의 720초 지점에서 시작하는 3개 중 2번째 청크라면:

```text
[기본 prompt]
+ [현재 청크 길이 제약]
+ "This is audio chunk 2 of 3, starting at 720.0 seconds ..."
```

첫 응답이 timestamp 역전으로 거절되어 두 번째 시도라면:

```text
[위에서 만들어진 prompt]
+ "A previous response was invalid: [잘린 검증 오류] ..."
```

이 예시는 조립 순서를 보여주기 위한 것이며, 실제 프롬프트 원문은 위 코드 블록의 문자열이다.

## 다시 기억할 핵심

> 현재 배포의 STT 최종 프롬프트는 `aicore_stt.py`의 `_aicore_stt_body()` 한곳에서 만들어진다. 기본 지시문에 오디오 길이, 청크 위치, 재시도 오류를 순서대로 붙이고 오디오를 Base64 data URI로 함께 전송한다. `AICORE_STT_PROMPT`가 설정되면 기본 지시문만 통째로 대체되며, 뒤의 길이·청크·재시도 제약은 계속 붙는다.
