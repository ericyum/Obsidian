# 일시정지 음량 분석 loop 중단 최종안

> 현재 상태: **수정·자동 테스트·Chrome 로컬 E2E 검증 완료**

## 한 문장 결론

녹음 일시정지 때 `MediaRecorder`만 멈추지 않고 화면 음량 표시용 `requestAnimationFrame` 예약도 취소하고, 재개할 때 정확히 하나만 다시 예약하도록 수정했다.

## 무엇이 문제였는가

기존 `pause()`는 녹음 청크 생성을 멈췄지만 음량 막대를 갱신하는 `loop()`는 계속 실행했다.

```text
MediaRecorder
→ paused

음량 분석 RAF loop
→ 계속 실행
```

기능이 즉시 망가지는 오류는 아니지만, 사용자가 일시정지한 동안에도 `analyser.getByteFrequencyData()`와 `onLevel()`이 화면 주사율에 맞춰 반복되어 불필요한 CPU 작업이 생겼다.

## `raf`에는 무엇이 들어가는가

```javascript
raf = requestAnimationFrame(loop);
```

`raf`에 들어가는 값은 `loop()`의 실행 결과가 아니다. 브라우저가 다음 화면 갱신 시점에 실행하도록 등록한 콜백의 **예약 ID**다.

```text
requestAnimationFrame(loop)
→ 브라우저에 loop 예약
→ 예약 번호 반환
→ raf에 저장
```

이 번호가 있어야 `cancelAnimationFrame(raf)`로 아직 실행되지 않은 다음 예약을 취소할 수 있다.

## 최종 구현

음량 분석의 시작과 중단을 두 함수로 분리했다.

```javascript
function startLevelLoop() {
  if (raf) return;
  raf = requestAnimationFrame(loop);
}

function stopLevelLoop() {
  if (!raf) return;
  cancelAnimationFrame(raf);
  raf = null;
}
```

`if (raf) return`은 이미 loop가 실행 중일 때 두 번째 RAF 체인을 만드는 것을 막는다. `raf = null`은 현재 예약이 없다는 상태를 명확히 하여 이후 `resume()`에서 다시 시작할 수 있게 한다.

## 상태별 코드 흐름

### 녹음 시작

```text
recorder.start()
→ MediaRecorder.start(timeslice)
→ state = recording
→ startLevelLoop()
→ RAF 1개 예약
```

### 일시정지

```text
recorder.pause()
→ 남은 녹음 데이터 requestData()
→ MediaRecorder.pause()
→ 현재까지의 실제 녹음 시간 누적
→ state = paused
→ stopLevelLoop()
→ 예약된 RAF 취소, raf = null
```

### 녹음 재개

```text
recorder.resume()
→ MediaRecorder.resume()
→ 새 녹음 구간 시작 시각 기록
→ state = recording
→ startLevelLoop()
→ RAF 1개만 다시 예약
```

### 녹음 종료

```text
recorder.stop()
→ MediaRecorder.stop()
→ closeResources()
→ stopLevelLoop()
→ 마이크 track 종료
→ AudioContext 종료
```

## 녹음 청크와 시간에는 영향이 없는가

영향이 없다. 이번 변경은 음량 표시용 RAF 예약만 제어한다.

```text
녹음 청크 생성·일시정지
→ MediaRecorder가 담당

실제 녹음 시간 계산
→ activeMs와 segmentStartMs가 담당

화면 음량 막대
→ AudioContext analyser와 RAF loop가 담당
```

따라서 일시정지할 때 이미 모인 `chunks`를 지우거나 임시 저장했다가 복원하는 변경이 아니다. `requestData()`로 마지막 조각을 요청하고 기존 `activeMs` 계산도 그대로 유지한다.

## 왜 `AudioContext.suspend()`까지 사용하지 않았는가

이번 수정의 목표는 코드 영향 범위를 작게 유지하면서 확인된 낭비를 제거하는 것이다. RAF를 취소하면 JavaScript의 반복 분석과 UI 갱신은 멈춘다.

`AudioContext.suspend()`와 `resume()`까지 추가하면 더 강한 절전이 가능할 수 있지만, 브라우저별 비동기 상태 전환과 재개 실패를 새로 다뤄야 한다. 현재 수정에는 포함하지 않았다.

## 자동 회귀 테스트

`tests/recorder-pause-loop.test.js`가 실제 `recorder.js`를 불러와 다음을 계측한다.

- 예약된 RAF callback 수
- analyser 읽기 횟수
- `onLevel` 호출 횟수

검증 결과는 다음과 같다.

```text
녹음 중
→ analyser와 onLevel 실행

pause 직후
→ 예약 RAF 0개
→ analyser와 onLevel 횟수 증가 없음

resume 직후
→ RAF 정확히 1개
→ 다음 frame부터 analyser와 onLevel 다시 증가

stop 후
→ 예약 RAF 0개
```

## 실제 브라우저 검증

로컬 CAP와 mock Worker를 실행하고 Chrome에서 다음 흐름을 확인했다.

```text
새 회의 생성
→ 실제 마이크 녹음
→ 일시정지
→ 재개
→ 녹음 종료
→ /api/binary 업로드
→ mock 전사
→ 결과 화면 표시
```

일시정지 표시와 타이머가 정상 동작했고, 재개 후 녹음이 이어졌으며, 최종 회의가 `done` 상태가 되었다. Console 오류와 경고는 없었다.

## 배포 환경에서도 같은가

수정 코드는 브라우저의 `requestAnimationFrame`, `MediaRecorder`, `AudioContext`만 사용한다. CAP·Worker·XSUAA 환경에 의존하지 않는다. 따라서 수정된 `recorder.js`가 Approuter 정적 자원에 포함되어 사용자에게 전달되면 동일하게 동작한다.

배포 전에는 다음 복사 결과가 원본과 일치하는지 확인한다.

```text
app/meeting-ui/js/recorder.js
→ approuter/resources/js/recorder.js
→ approuter/dev/resources/js/recorder.js
```

브라우저가 이전 파일을 캐시할 수 있으므로 import query version과 정적 자산 복사 여부도 배포 점검 대상이다. 이는 RAF 로직 자체와 별개의 전달 문제다.

## 최종 판단

```text
recording
→ 녹음과 음량 분석 모두 실행

paused
→ 녹음 청크 생성과 음량 분석 모두 일시정지

resumed
→ 둘 다 정상 재개, RAF는 한 줄기만 유지

stopped
→ RAF·마이크·AudioContext 모두 정리
```

기존 녹음 데이터 흐름을 바꾸지 않고, 일시정지 상태에서 불필요하게 계속 돌던 화면 음량 분석만 안전하게 중단했다.
