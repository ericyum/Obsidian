> [!summary] 한눈에
>
> - AI Core STT `gemini-2.5-flash` 2026-06-17 shutdown 대응. 3개 모델(2.5/3.1-flash-lite/3.5) 비용·지연·품질 비교.
> - **케이스 2종**(1분 영업회의·28분 주간회의) 기준. **길이에 따라 품질 우위가 역전** — 짧은(1분)엔 3.1-lite 1위, 긴(28분)엔 2.5 1위.

### 공통 환경

- 로컬 3터널(CAP/Worker/Router), `cds bind --exec --profile hybrid`, `local:worker:real`(.env 읽음), SQLite :memory:.
- 모델 선택: UI `#aicore-model` select. 회의별 모델 지정 → Worker `settings.model_copy` override.
- 비교 대상: `gemini-2.5-flash`(구형/shutdown), `gemini-3.1-flash-lite`(저가), `gemini-3.5-flash`(최신 정식).
- 데이터 소스: Worker `DEBUG usage` 로그(`aicore_stt.py`), 회의록 md(`tests/modelTest/`).

> [!note] 로컬 업로드 한계 해소 (2026-08-04)
> 1차 보고서(2026-08-03)는 CAP media stream ~1MB 한계로 1분까지만 가능. **이 한계는 `binary-upload-route`가 인증 미가용 시 body를 drain하지 않아 approuter가 큰 body pipe 중 abort하던 것** → `drainReq` 추가로 해소(상세 `1. Whisper-조사-안효서-정리.md` F5). 이로 28분/20MB 업로드 가능해져 케이스 B 추가.

> [!warning] 평가 기준 = 전사본
> 품질 평가의 정답은 **전사본(Worker가 전사한 결과)** 기준. 요약이 전사본(입력)을 얼마나 잘 반영했나를 본다. 전사본 자체의 오디오 인식 오류는 별개(전사 모델 영역).

- **지연**: 3.1-lite 5.6초(최단) < 2.5 9.7초 < 3.5 27.7초(최장).

- **reasoning 토큰**: 3.5 4,340(대부분) > 2.5 857 > 3.1-lite 0. 3.5가 reasoning 많이 소모 → 지연·비용 증가.

> 상대 비용(3.1-lite 기준 1): 3.1-lite **1.0** / 2.5 **1.76** / 3.5 **3.17**.

### 3.1 비용 변환 — CU·원화 (1분 오디오 전사 1회)

> [!info] 계산 기준 (SAP-AI-Core-Cost-Report-v2.8 준용)
> - SAP AI Core 요율(`sap-aicore-models.json`, per 1k 토큰): 2.5-flash in=0.00027/out=0.00167, 3.1-flash-lite in=0.0002/out=0.00108.
> - 변환 상수: **1 GenAI Token = 1.90385 CU**. `CU = (prompt/1000×in + completion/1000×out) × 1.90385`.
> - 단가: TDD 0.53 EUR/CU(0~400 CU 무료), 일반 BTP 1.35 EUR/CU(운영). 환율 1 EUR=1,753 KRW / 1 USD=1,511 KRW. BTPEA(1.04)는 v2.8 기준 비교 제외.
> - 공식 API USD(1M당, v2.5 검증): 2.5-flash in $0.30/out $2.50, 3.1-flash-lite in $0.25/out $1.50, 3.5-flash in $1.50/out $9.00(계산기 미등록 → 공식만). reasoning 토큰은 output으로 청구.
> - 3.5-flash는 SAP 계산기 미등록 → CU·TDD·일반 BTP 계산 불가, 공식 API USD로만.
> - 토큰 양은 1분 실측. v2.8 시나리오1(10k/2k)과 토큰 양 달라 수치 다름, 계산 방식 동일.

| 모델                 | GenAI 토큰 |          CU |  TDD(원) | 일반 BTP(원) | 공식 API(원) |  TDD/API |
| ------------------ | -------: | ----------: | ------: | --------: | --------: | -------: |
| **3.1-flash-lite** |  0.00080 | **0.00152** | **1.4** |   **3.6** |       1.6 | ✅ 12% 절감 |
| 2.5-flash          |  0.00381 |     0.00726 |     6.7 |      17.2 |       8.4 | ✅ 20% 절감 |
| 3.5-flash          |        — |       (미등록) |       — |         — |  **71.8** |        — |

- **3.1-lite**: 1회 1.4원(TDD)/3.6원(운영). 2.5 대비 **비용 21%**(79% 절감). 공식 API 대비 12% 절감.
- **2.5**: 1회 6.7원/17.2원. 3.1-lite의 4.8배. 전사는 출력 토큰 비중 커서 SAP율(출력 낮음) 이점 확대.
- **3.5**: SAP CU 계산 불가(계산기 미등록). 공식 API 71.8원(reasoning 4,340 토큰이 output으로 청구돼 급증). 3.1-lite 공식 대비 약 45배.

### 3.3 케이스 B(28분/20MB) 비용·지연 — 2차 측정

> [!info] 측정 조건
> 28분 주간회의 오디오(20MB), **단일 전사**(`chunk=None/None`, 분할 안 됨 — duration 힌트 미잡음). Worker DEBUG usage 로그.

| 모델                 |     지연(ms) |      total | prompt | completion | reasoning |         CU |   TDD(원) | 일반 BTP(원) | 공식 API(원) |
| ------------------ | ---------: | ---------: | -----: | ---------: | --------: | ---------: | -------: | --------: | --------: |
| **3.1-flash-lite** | **57,342** | **48,071** | 35,581 |     12,490 |     **0** | **0.0392** | **36.5** |  **92.8** |  **41.7** |

- **지연**: 3.1-lite **57.3초(최단)** < 3.5 94.6초 < 2.5 111.6초. 3.1-lite가 2.5의 51%, 3.5의 61%. reasoning 0이라 한결같이 최단.
- **지연 역전(2.5 vs 3.5)**: 1분에선 3.5(27.7초) > 2.5(9.7초). **28분에선 2.5(111.6초) > 3.5(94.6초)** 역전. 2.5(구형)가 긴 입력·큰 completion(22,860, 3.5의 1.23배)에서 느려짐.
- **비용**: 3.1-lite TDD **36.5원(최저)** = 2.5(84.6원)의 43%, 3.5 공식(333원)의 11%. 2.5 TDD 84.6원(1분 6.7원의 **12.5배** — 비례 증가에 가까움). 2.5 공식 102.5원(TDD의 1.21배, 운영 전환해도 공식 직접보다 SAP가 21% 싼 참고치). 3.5 공식 333원(1분 71.8원의 4.6배 — reasoning 비중 상대적 감소로 비율 낮음).

- **completion**: 3.1-lite 12,490(가장 간결) < 3.5 18,586 < 2.5 22,860. 3.1-lite가 출력 가장 적게.
- **분할 안 됨**: 28분(1680초) > `CHUNK_SECONDS`(720)인데도 `chunk=None/None`. duration 힌트 미잡음 → 단일 전사 → 2.5 타임스탬프 역전 원인. `AICORE_STT_CHUNK_SECONDS` 낮춤 또는 duration 힌트 보정 필요.

> [!note] 케이스 B 비용·지연 vs 품질 분리
> 비용·지연은 **3.1-lite 한결같이 1위**(길이 상관없이). 품질만 길이 의존 역전(1분 3.1-lite 1위, 28분 2.5 1위·3.1-lite 환각). 즉 3.1-lite는 긴 오디오에서도 싸고 빠르지만 **품질(환각)이 문제** — 비용으로는 교체 사유 안 됨, 품질이 판단 기준.

**비용·지연**(길이 상관없이, 3.1-lite 한결같이 1위):

|---|---|---|
| 1분 | 3.1-lite(5.6초) | 3.1-lite(1.4원) |
| 28분 | 3.1-lite(57.3초) | 3.1-lite(36.5원) |

- 품질만 길이 의존 역전. 비용·지연은 3.1-lite가 길이 상관없이 한결같이 1위(reasoning 0). **한 모델로 통일 불가** — 비용으론 3.1-lite, 품질으론 길이별 분리.

### 5.2 원인 추정

- **3.1-lite**(소형, reasoning 0): 짧은 입력은 정밀 처리. 긴 입력(28분 전사본)은 context 한계 도달 시 **구조(schema)를 채우기 위해 없는 정보(팀/기한)를 지어냄** — 환각.
- **2.5**(reasoning 857): 짧은 입력에선 reasoning이 생각이 지나쳐 오탐(금액 1/10 오탐). 긴 입력에선 reasoning이 맥락을 잡는 데 도움 → 잡담 필터·핵심 구조화 안정.
- **3.5**(reasoning 4,340): reasoning 과다. 짧·긴 전부 비용·지연 부담. 긴 건 잡담 필터 약함.

### 5.3 2.5 교체 정당성 — 다시 검토

- 1차 보고서(1분만)에선 "2.5 최악, 교체 정당" 단언.
- **28분 케이스 추가로 2.5가 긴 오디오 요약에 안정**이 확인됨. 2.5 자체가 맞지 않음이라기보다 **짧은 정형 회의에 약점**.
- 다만 2.5는 shutdown 대상이라 교체는 필수. 교체 후보가 긴 오디오 요약 안정성을 가져야 함 — 3.1-lite는 긴 오디오 환각으로 맞지 않음, **별도 후보 필요**(3.1-pro 등 다시 검증).

### 5.4 3.5 특성 — 전사·요약 맞지 않음, 검토 전용 후보

- **reasoning 중심**: reasoning 4,340 토큰(전체 65%). 지연 27.7초·공식 API 3.1-lite 대비 ~45배. 비용·지연 부담이 품질 이득을 넘어섬.
- **케이스 A(1분)**: 매출 4,230만(1/10 오탐) 치명. 결정 2건 잡는 건 형식적 이점이나 내용 오탐(예산 1,500만 증액 — 전사본은 100만). 4분기 오탐(3→4). 채용 "두 명" 환각.
- **케이스 B(28분)**: 결정/액션 "없음". 주식·코인 잡담을 안건에 섞어 넣어 **잡담 분리 실패**. reasoning이 긴 입력에서 오히려 잡담을 안건으로 끌어들임.
- **전사**: 1차 보고서에서 1분30초 빈 응답 `RuntimeError`(reasoning만 있고 segments 빈) 발생. 전사 맞지 않음 확정.
- **요약**: 두 케이스 전부 맞지 않음(매출 오탐·잡담 섞임).
- **검토(ReviewItems)**: reasoning이 사고 과정 거치는 작업엔 유리 가능성. 현재 보고서는 요약만 비교, **검토 영역 실측 안 함**. 다음에서 검토 작업 제한 다시 평가. 단 비용·지연 부담 감수 필요.

### 5.5 전사 vs 요약 분리

- **전사 모델**(오디오→텍스트): flash-lite가 케이스 A·B 전사본 모두 안정(전사본 자체가 flash-lite). 2.5 전사는 긴 단일(28분, 20MB)에서 타임스탬프 역전 `end < start` → **청크 분할(`AICORE_STT_CHUNK_SECONDS` 낮춤)로 해결**.
- **요약 모델**(텍스트→회의록): 길이 의존. 짧은 3.1-lite, 긴 2.5.

## 6. 결론 및 다음 검증

> [!warning] 제한 — 케이스 2개
> 본 결론은 **케이스 2종(1분·28분), 각 1회** 기준. 모델 우위는 입력 길이·안건 성격·오디오 품질·운영 환경에 따라 달라짐. **중간 길이·다양 안건·운영 테스트·샘플 수 확보 전 확정 불가. 다음 케이스 필요.**

### 6.1 길이별 1차 후보

- **짧은 회의(1분~수 분, 정형)**: `gemini-3.1-flash-lite`. 비용·지연·품질 전부 앞섬. 케이스 B에서도 비용·지연은 1위(길이 상관없이) — 단 품질은 환각.
- **긴 회의(20분~, 비정형)**: 2.5 안정이나 shutdown. **3.1-lite는 환각 맞지 않음**(비용·지연은 1위이나 품질 역). 별도 후보(3.1-pro 등) 긴 오디오 다시 검증 필요.
- **전사(공통)**: flash-lite 안정. 2.5 긴 단일은 청크 분할로.
- **3.5-flash**: 전사·요약 **맞지 않음**(두 케이스 전부 오탐·잡담 섞임·빈 응답). **검토(ReviewItems) 작업 제한 후보** — reasoning이 사고 작업에 유리 가능성, 단 비용·지연 부담. 검토 영역 실측 후 판단.

### 6.2 한 모델 통일 불가

길이 의존 역전으로 단일 모델 선택 시 일부 구간 손실. 옵션:
- (A) 길이별 모델 전환(짧은 3.1-lite / 긴 2.5 다음 모델) — 복잡, 자동 길이 판단 필요.
- (B) 2.5 다음 모델(긴 오디오 안정) 단일 — 짧은 정형 회의 품질 손실 감수.
- (C) 3.1-lite 단일 — 긴 오디오 환각 위험. 맞지 않음.

운영(실제 회의는 긴 게 많음)에선 (B) 합리적이나, 짧은 회의 품질 저하. 추가 케이스로 판단.

### 6.3 다음 검증 필요

- **중간 길이(5~10분)**: 역전 경계 확인. 1분↔28분 사이 어디서 우위가 바뀌나.
- **다양 안건**: 정형(숫자 밀집) vs 비정형(잡담 혼재) 외 다른 패턴.
- **긴 오디오 청크 분할 시 누적 비용·지연**: 케이스 B 단일 전사(분할 안 됨) 측정 완료. 청크 분할(`AICORE_STT_CHUNK_SECONDS=300`) 시 누적 토큰·지연 다시 측정 필요 — 단일 대비 증가폭.
- **운영 환경**: TDD(0.53)→일반 BTP(1.35) 비용 2.5배. 비용 우위 역전 가능성.
- **샘플 수**: 각 케이스 1회. 통신 안정성·오디오 다양성(잡음·복수 화자·억양) 미포함.
- **2.5 다음 모델**: 긴 오디오 요약 안정 + shutdown 대응 모델(3.1-pro 등) 검증.
- **3.5 검토 영역 실측**: 현재는 요약만 비교. 검토(`runReview`) 작업 제한 3.5 성능 다시 측정 — reasoning이 사고 작업에 유리한지. 비용·지연 부담 감수 가치 평가.
- **청크 분할 임계**: `AICORE_STT_CHUNK_SECONDS` 720→? 최적값(2.5 전사 역전 방지 최소값).

### 6.4 다음 작업 (범위 내)

- **UI 기본값**: 짧은 회의 앞섬 고려 시 3.1-lite, 긴 회의 비중 고려 시 2.5 다음 모델. 추가 케이스 후 권고.
- **요약 모델**: config `meeting-whisper-summary-ko-v1` = 2.5. shutdown 영향. 긴 오디오 안정성 필요 → 2.5 다음 모델 교체(3.1-lite 긴 환각 맞지 않음).
- **공통 약점**: 반복 일정·연도·단위 혼동은 프롬프트 개선·후처리 영역.
- **전사 청크 분할**: `AICORE_STT_CHUNK_SECONDS=300`(5분) 시도로 2.5 긴 오디오 역전 해소 검증(진행 중).
