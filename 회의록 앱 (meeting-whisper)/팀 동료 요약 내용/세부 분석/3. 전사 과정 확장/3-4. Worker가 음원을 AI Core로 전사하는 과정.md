# 3-4. Worker가 음원을 AI Core로 전사하는 과정

## 음원을 가져오는 방법

작업을 확보한 Worker는 CAP의 `getAudio`를 호출한다.

Object Store를 사용하는 운영 환경에서는 제한 시간 동안만 유효한 다운로드 주소를 받는다. 대체 환경에서는 base64 음원 내용이 전달될 수 있다.

Worker는 이를 임시 파일로 만들고 작업이 끝나면 삭제한다.

## 분할 여부 판단

Worker는 다음 값을 함께 본다.

- 파일에서 측정한 음원 길이
- CAP가 전달한 예상 길이
- 파일 크기
- 운영 환경의 구간 길이와 인라인 최대 크기

긴 음원은 PyAV를 이용해 16kHz, mono WAV 구간으로 나눈다.

## STT에서도 프롬프트를 사용한다

AI Core STT 경로는 음원만 보내지 않는다. `aicore_stt.py`가 전사 지시문과 음원 파일을 함께 보낸다.

현재 기본 지시문의 핵심은 다음과 같다.

```text
원래 언어 그대로 전사한다.
한국어 음성이면 한국어로 쓴다.
요약하지 않는다.
들리지 않은 단어를 만들지 않는다.
문장 크기의 segment로 나눈다.
시작·종료 시간을 초 단위 JSON 숫자로 반환한다.
정확한 시간을 모르면 임의로 만들지 않는다.
설명이나 Markdown 없이 완전한 JSON만 반환한다.
```

이 방향은 STT가 회의 카테고리에 끌려 내용을 각색하지 않고 최대한 들리는 대로 옮기게 하려는 것이다.

## 현재 프롬프트에 없는 정보

현재 Worker 요청과 STT 프롬프트에는 다음 회의별 정보가 들어가지 않는다.

- 회의 카테고리와 구체적인 주제
- 참석자 이름
- 회사명과 제품명
- 전문용어 목록
- 사용자 정의 단어장

따라서 현재 STT 프롬프트는 전문용어 교정 프롬프트가 아니라 전사의 충실도와 출력 형식을 제어하는 공통 프롬프트다.

## AI Core 호출

Worker는 음원 파일을 base64 data URL로 만들고 프롬프트 텍스트와 함께 AI Core Orchestration의 `prompt_templating` 모듈에 전달한다.

모델명, AI Core deployment, resource group과 timeout은 환경 설정에서 읽는다.

## 구간마다 시간이 0부터 시작하는 이유

AI 모델은 첨부된 각 음원 조각만 본다. 두 번째 조각도 그 파일 안에서는 0초부터 시작한다.

프롬프트에는 현재 조각 번호와 원본 회의에서의 시작 위치를 알려 주지만, 모델이 반환하는 시간은 해당 조각 기준으로 요청한다. 전체 회의 시간으로 바꾸는 일은 병합 단계에서 Worker가 확정적으로 수행한다.

## 현재 결정한 후처리 방향과의 관계

STT는 그대로 전사하는 공통 프롬프트를 유지하고, 전문용어와 문맥 오류는 전사 후 별도 모델이 후보를 제안하도록 하는 방향이 적절하다.

단, 텍스트 후처리만으로 실제 음성을 다시 들을 수는 없으므로 자동 확정이 아니라 의심 표현과 근거를 표시하고 사용자가 승인하는 구조가 안전하다.

## 핵심 정리

> 현재 AI Core STT도 프롬프트를 사용하지만, 목적은 회의식 요약이 아니라 음성을 각색하지 않고 일정한 JSON 전사로 받는 것이다.
