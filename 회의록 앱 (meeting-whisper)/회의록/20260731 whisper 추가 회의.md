# 회의록

  

## 요약

  

이번 회의에서는 플래시 라이트의 임시 전사 성능 및 활용 방안, AI 모델 프로바이더 파라미터 템플릿화의 필요성, 그리고 프로젝트의 아키텍처 및 코드 구조 개선에 대해 논의했습니다. 특히, 미니멀리즘 아키텍처 유지와 사용자 인터페이스(UI) 개선에 집중하기로 합의했습니다.

  

## 결정 사항

  

- AI 모델 프로바이더별 파라미터 설정을 위한 템플릿을 개발하여 재사용성과 편의성을 높이기로 했습니다.

- 프로젝트 아키텍처는 UI와 M 라우터를 분리하지 않고 현재와 같이 통합된 미니멀한 구조를 유지하기로 결정했습니다.

- 향후 개발은 사용자에게 직접적으로 영향을 미치는 UI/프론트엔드 개선에 우선순위를 두기로 합의했습니다.

- app.js와 UI.js 파일 간 역할을 명확히 분리하여, app.js는 컨트롤러 역할에 집중하고 UI.js는 UI 표시 기능을 전담하도록 코드를 정리하기로 했습니다.

  

## 액션 아이템

  

- 없음

  

## 안건별 요점

  

### 플래시 라이트 (임시 전사) 성능 및 활용

- 현황: 임시 전사 성능이 개선된 것으로 보이며, 특히 빠른 처리 속도가 장점입니다.

- 이슈: 최종 전사 시 구조화에서 약점이 있어 정확도 차이가 발생할 수 있습니다.

- 다음: 다양한 AI 모델의 사용 방식과 성능을 직접 테스트하며 최적의 활용 방안을 모색할 예정입니다.

  

### AI 모델 파라미터 템플릿화

- 현황: 각 프로바이더 모델마다 파라미터 설정 방식이 달라 사용에 불편함이 있습니다.

- 다음: 기본 파라미터를 포함한 템플릿을 만들어 재사용성을 높이고 모델 변경 시 편의성을 확보할 계획입니다.

  

### 프로젝트 저장소 브랜치 관리

- 이슈: 현재 저장소에 메인 브랜치만 존재하며, 푸시 전에 적절한 브랜치 분리가 필요합니다.

- 다음: 개인 레포지토리 클론 후 작업하거나 브랜치를 새로 생성하여 작업하는 방안이 논의되었습니다.

  

### 프로젝트 아키텍처 및 UI/백엔드 구조

- 현황: 현재 UI가 M 라우터 내에 통합된 미니멀리즘 아키텍처를 지향하고 있습니다.

- 이슈: UI와 M 라우터 분리 구조가 제안되었으나, 프로젝트 규모 및 리소스 효율성을 고려하여 현재 통합 구조를 유지하기로 결정했습니다.

- 다음: 배보다 배꼽이 커지는 것을 방지하고 효율적인 리소스 사용을 위해 현 아키텍처를 유지할 방침입니다.

  

### 코드 구조 및 역할 분리 (app.js, UI.js)

- 이슈: `app.js`에 UI 표시 기능 일부가 혼재되어 있어 파일 간 역할 구분이 모호합니다.

- 다음: `app.js`를 컨트롤러 역할로, `UI.js`를 UI 표시 전담으로 역할을 명확히 분리하여 코드 가독성을 높일 필요가 있습니다.

  

### 워커 (백엔드) 통신 로직 개선

- 이슈: 워커와 CP 백엔드 간 통신 로직이 복잡하며, 불필요한 변경은 예측 불가능한 리스크를 초래할 수 있습니다.

- 다음: 현재 안정화된 워커 로직은 굳이 변경하지 않으며, 향후 사용자가 직접적으로 체감할 수 있는 UI/프론트엔드 개선에 집중하기로 했습니다.

  

### 코드 다이어트 및 불필요한 코드 제거

- 이슈: `EAB` 파일, `server.js`, `AI Core JS` 라이브러리 등에서 사용되지 않는 불필요한 코드나 경로가 발견되었습니다.

- 다음: 현재 기능에 직접적인 영향을 주지 않으므로, 더 중요한 개발 작업에 우선 집중하고 코드 다이어트는 추후 필요에 따라 진행할 예정입니다.
